# Sky130 Balanced Frontend Latch Rerun

This page records the next bounded test after the extracted balanced frontend preserved both input signs but produced only about `15–16 uV` of sense differential.

The existing Sky130 clocked-latch runner was rerun with an explicit input difference of `+/-0.015 mV`, matching the measured extracted balanced-frontend sense-node magnitude. Both cases resolved with the expected polarity and full logic separation:

- negative input: correct polarity
- positive input: correct polarity
- measured cases: `2/2`
- resolution threshold: `0.9 V`

The evidence is [sky130-balanced-frontend-latch-rerun.json](../../evidence/aimc-simulator-adapters/sky130-balanced-frontend-latch-rerun.json), generated by `scripts/run_sky130_clocked_comparator_latch_ngspice.py` with `AIMC_LATCH_INPUT_DIFF_MV=0.015` and a separate output stem.

## What This Changes

The balanced extracted frontend is not rejected merely because its signal is smaller than the earlier `0.153 mV` latch target. The ideal latch proxy can regenerate a decision from the measured `15–16 uV` signal under the tested transient setup.

## What It Does Not Change

This remains a schematic-level latch rerun driven by ideal voltage sources. It does not connect the actual extracted balanced frontend to the latch, and therefore does not prove extracted latch kickback, offset, noise, mismatch, clock sensitivity, DRC/LVS, SAR conversion, or accepted post-layout converter evidence.

The next physical test is a single deck containing the balanced extracted frontend, the transistor latch, the real clock/reset handoff, and the sampled nodes. Its acceptance gate must require both polarity correctness and sampled-node kickback below the 12-bit half-LSB limit.
