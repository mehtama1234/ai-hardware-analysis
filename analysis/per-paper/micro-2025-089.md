# micro-2025-089: OmniSim: Simulating Hardware with C Speed and RTL Accuracy for High-Level Synthesis Designs

**Venue:** MICRO 2025  
**Authors:** Rishov Sarkar, Cong Hao  
**Confidence:** high (full text)

## Problem
HLS tools cannot correctly simulate complex dataflow designs at the C level—especially those with non-blocking FIFO accesses, infinite loops, and cyclic module dependencies—because OS-level thread scheduling diverges from hardware timing, producing incorrect functional results and inaccurate cycle counts. C/RTL co-simulation is correct but takes hours to days.

## Motivation
HLS adoption is growing rapidly for domain-specific accelerators, but the inability to simulate Type B and Type C dataflow designs at C level forces designers back to slow RTL co-simulation, undermining HLS's productivity advantage.

## Method
OmniSim classifies dataflow designs into three types: Type A (blocking-only/acyclic), Type B (non-blocking or cyclic, single behavior), Type C (non-blocking with behavior dependent on FIFO outcome). It launches one Func Sim thread per dataflow module and a dedicated Perf Sim thread. FIFO read/write timing tables record the hardware cycle of each FIFO event independently of OS scheduling. Func Sim threads pause on non-blocking FIFO accesses, placing queries into a Query Pool; the Perf Sim thread resolves queries by comparing hardware-cycle timestamps from the FIFO tables. Func Sim and Perf Sim threads overlap execution for additional speedup. LLVM passes instrument basic block traces and rewrite dataflow functions to launch concurrent threads. Deadlock detection and incremental FIFO-size simulation are included.

## Key Novelty
A dedicated performance simulation thread synchronizes non-blocking FIFO events using hardware-cycle FIFO tables, tightly coupling and overlapping functionality and performance simulation to enable correct simulation of previously-unsupported Type B and C HLS dataflow designs at near-C speed.

## Contributions
1. First taxonomy and classification of HLS dataflow designs into Types A/B/C with formal simulation requirements
2. OmniSim: correct functionality + cycle-accurate performance simulation of all dataflow types, including those explicitly unsupported by Vitis HLS and Catapult HLS
3. Up to 35.9x speedup over C/RTL co-simulation; up to 6.61x over LightningSim
4. Deadlock detection and incremental FIFO-size DSE with 4 orders of magnitude speedup

## Hardware Target
FPGA, ASIC (targets HLS design simulation, evaluated on Vitis HLS designs)

## Techniques
compiler, dataflow

## Workloads
CNN, LLM-inference, HPC (domain-specific accelerators, network switches, cache controllers)

## Key Metrics
- Speedup: up to 35.9x over C/RTL co-simulation; up to 6.61x over LightningSim; avg 30.7x over co-sim on 11-design benchmark
- Accuracy: near-RTL (99.9% cycle accuracy for Type A; functionally and cycle-accurate for Types B and C)
- Incremental DSE: 4 orders of magnitude speedup over full re-simulation

## Baselines
C/RTL co-simulation (Vitis HLS, Catapult HLS), LightningSim, FLASH, FastSim, TAPA, Allo

## Limitations
Requires static scheduling info from C synthesis; does not detect livelocks (only deadlocks); Perf Sim thread throughput depends on OS scheduling of overlapping threads.
