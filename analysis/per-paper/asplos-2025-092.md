# asplos-2025-092 — Fusion: An Analytics Object Store Optimized for Query Pushdown

**Venue:** ASPLOS  
**Confidence:** low (abstract only)  
**Primary Theme:** Erasure-coding-aware analytics object store for query pushdown

## Problem
Disaggregated cloud storage uses erasure coding that partitions analytics file objects into fixed-size blocks across storage nodes; when query predicates are pushed down to storage (computation pushdown), the storage system must reassemble objects across nodes, incurring high network latency that undermines pushdown's intended benefits for ad-hoc and highly-selective OLAP queries.

## Motivation
Cloud OLAP databases increasingly rely on computation pushdown to reduce latency on large object queries, but erasure-coded disaggregated storage fundamentally conflicts with this approach because reassembly overhead negates pushdown gains.

## Method
Fusion is an analytics object store that co-designs storage layout and query pushdown execution for erasure-coded environments. It reorganizes how analytics file objects (e.g., Parquet files) are partitioned and distributed across storage nodes so that query-relevant data stripes can be accessed and evaluated locally at storage nodes without full object reassembly. Pushdown execution is coordinated across storage nodes in a way that respects erasure coding boundaries, enabling predicate evaluation close to data while minimizing cross-node communication.

## Key Novelty
Co-designing erasure-coded object storage layout with query pushdown execution so predicates can be evaluated at storage nodes without full object reassembly.

## Contributions
- Identification of erasure coding as a fundamental barrier to efficient computation pushdown in cloud OLAP storage
- Fusion: an object store layout and pushdown architecture co-designed for erasure-coded disaggregated storage
- Pushdown execution protocol that partitions predicate evaluation across storage nodes along erasure coding boundaries
- Reduced network latency for ad-hoc and highly-selective OLAP queries on large objects
