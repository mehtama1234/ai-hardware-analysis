# Wasp: Efficient Asynchronous Single-Source Shortest Path on Multicore Systems via Work Stealing

**Venue:** SC 2025  
**Authors:** D'Antonio, Thai Mai, Tsigas, Vandierendonck

## Problem
Δ-stepping (state-of-the-art parallel SSSP) uses priority coarsening for parallelism, creating redundant work across threads. This becomes a scalability bottleneck on modern multicore CPUs with many cores.

## Approach
**Wasp** reformulates SSSP with asynchronous execution and priority-aware work stealing:

1. **Asynchronous Priority Handling** – Threads process locally available high-priority work without synchronization
2. **Demand-Driven Stealing** – Redundant computations only triggered when a thread exhausts local high-priority work
3. **Priority-Aware Stealing Mechanism** – Steals highest-priority work available, maintaining algorithmic correctness
4. **Load Balancing** – Natural work distribution through work stealing without explicit load balancing overhead

## Key Insight
**Redundancy is necessary but not sufficient** – Wasp only induces redundancy when threads are work-starved, vastly reducing wasted parallelism compared to priority coarsening methods.

### Comparisons
- Competitive or superior to: GAP, GBBS, MultiQueues, Galois, Δ*-stepping, ρ-stepping
- Across 13 diverse graphs (size/topology range not specified)

## Hardware Targets
- AMD Zen 3 (high core count)
- Intel Sapphire Rapids (128 cores per socket)
- General multicore CPU architectures

## Algorithm Characteristics
- **Asynchronous**: No global synchronization barriers
- **Work-stealing**: Standard work-stealing queue discipline
- **Priority-aware**: Respects SSSP priority ordering
- **Scalable**: Speedup maintains through 128 threads

## Limitations
- CPU-only (no GPU evaluation)
- 13 graphs may not represent full diversity of real-world instances
- Platform-specific results; scalability on different core counts/topologies unclear
- No explicit memory overhead analysis
