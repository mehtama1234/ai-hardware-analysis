# GCStack+GCScaler: Fast and Accurate GPU Performance Analyses Using Fine-Grained Stall Cycle Accounting and Interval Analysis

**Venue:** ISCA  
**Confidence:** low (abstract-only analysis)

## Problem
Existing GPU performance analysis tools use coarse-grained, priority-based cycle stacks that exaggerate memory-side stalls, hide concurrent stall events, and require expensive per-design cycle-level simulation repetition for design-space exploration.

## Motivation
GPU architects need fast and accurate design-space exploration tools; current simulation approaches are too slow (iterative per-design cycle simulation) and too inaccurate (misleading bottleneck attribution) to guide next-generation GPU design.

## Method
GCStack accurately identifies GPU performance bottlenecks by tracking all the different types of slowdowns (memory delays, synchronization waits, and idle cycles) that happen simultaneously in each cycle, instead of just the most important one. GCScaler predicts how these slowdowns change across different GPU designs using mathematics, without re-running expensive simulations. Together, they enable exploration of 1,000 GPU designs from a single baseline simulation.

## Key Novelty
By tracking all the slowdowns that happen simultaneously and mathematically scaling those patterns to new GPU designs, the method enables accurate performance analysis and rapid exploration of 1,000 design options from a single simulation.

## Contributions
1. GCStack: fine-grained cycle stack capturing all concurrently occurring stall events, eliminating priority-based distortion
2. GCScaler: interval-analysis-driven analytical scaling for alternative GPU designs
3. Analytical scaling models for idle and synchronization stalls not captured by prior interval analysis
4. 32.7x design-space exploration speedup at 6.37% mean absolute error across 47 benchmarks and 1,000 GPU designs

## Metrics
- **Speedup:** 32.7x faster than repetitive timing simulation for 1,000-design exploration
- **Accuracy:** 6.37% mean absolute performance estimation error

## Baselines
- Repetitive cycle-level timing simulation
- Existing coarse-grained priority-based cycle stacks

## Limitations
Accuracy of 6.37% MAPE may degrade for GPU microarchitecture changes that fundamentally alter memory hierarchy behavior beyond what interval analysis can model.
