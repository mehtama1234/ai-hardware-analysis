# Interleaved Bitstream Execution for Multi-Pattern Regex Matching on GPUs

**Venue:** MICRO 2025  
**Confidence:** Low (abstract-only)

## Problem
Bitparallel regex engines compile regular expressions into bitstream programs with fine-grained parallelism suited to GPUs, but the naive sequential (per-instruction loop-over-data) execution model suffers from poor data reuse — each data block is loaded multiple times across instructions — and high memory consumption from intermediate bitstream state, limiting GPU throughput.

## Motivation
Pattern matching is a critical and performance-sensitive operation in unstructured data analytics (log processing, network intrusion detection, text search), and GPU-accelerated regex engines are increasingly important, but fundamental memory access inefficiencies prevent them from reaching peak GPU throughput.

## Method
The paper fuses all the pattern-matching instructions into a single loop that processes one data block at a time, so each block gets loaded once from memory and processed by all instructions before moving to the next block. To handle the fact that later instructions depend on results from earlier blocks, they use selective recomputation—recalculating parts of the dependency chain when needed rather than having threads communicate with each other. They also restructure these dependency chains to reduce the depth of synchronization barriers between groups of GPU threads (warps), and skip computation entirely on data blocks that are all zeros, since sparse patterns often produce zero results.

## Key Novelty
Instead of running one pattern-matching instruction across all data blocks before running the next instruction, this approach fuses all instructions into a single loop that processes one block at a time, improving data reuse and avoiding intermediate storage, while resolving dependencies through selective recalculation rather than inter-thread communication.

## Contributions
- Interleaved bitstream execution model that fuses all regex instructions into a single data-block-wise GPU loop.
- Dependency-Aware Thread-Data Mapping for correct cross-block dependency resolution.
- Shift Rebalancing to reduce synchronization barrier count.
- Zero Block Skipping for exploiting bitstream sparsity; 19.5x geometric mean speedup over state-of-the-art GPU regex engine.
