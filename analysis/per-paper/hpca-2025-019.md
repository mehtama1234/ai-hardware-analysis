# hpca-2025-019 — AsyncDIMM: Achieving Asynchronous Execution in DIMM-Based Near-Memory Processing

**Venue:** HPCA  
**Confidence:** low (abstract-only)

## Problem
DIMM-based NMP cannot support asynchronous host-NMA execution because independent memory controllers on both sides cause bus contention and DRAM state races. Existing designs use synchronous execution, wasting compute on whichever side is idle.

## Motivation
Near-memory processing is attractive for bandwidth-bound workloads, but synchronous host-NMA execution severely underutilizes hardware by serializing access to DRAM.

## Method
AsyncDIMM provides single, concurrent, and hybrid memory access modes on existing memory buses. An offload-schedule-return mechanism with explicit and implicit synchronization ensures correct access semantics. Optimized timing constraints, locality-aware switch-recovery, and adaptive TDM-based batch notifications reduce latency and maximize bandwidth. Hardware modifications target only the host and NMA memory controllers; validated on FPGA.

## Key Novelty
Offload-schedule-return with dual (explicit/implicit) synchronization enabling correct concurrent host+NMA DRAM access on unmodified existing memory buses.

## Contributions
- Identification of bus contention and DRAM state races as barriers to asynchronous DIMM-NMP.
- AsyncDIMM: three access modes with offload-schedule-return synchronization.
- Optimized timing constraints, locality-aware switch-recovery, and adaptive batch with TDM notifications.
- 1.19x-1.92x speedup; 2.25x bandwidth utilization; 47% latency reduction; FPGA-validated.

## Hardware Target

## Metrics
- Speedup: 1.19x-1.92x over four NMP baselines
- Bandwidth: up to 2.25x utilization uplift
- Latency: 47% access latency reduction

## Baselines
Four DIMM-NMP baseline configurations with synchronous execution

## Limitations
Requires memory controller modifications on both host and NMA sides; evaluation uses FPGA emulation, not real DIMM-NMP silicon.
