# hpca-2025-019 — AsyncDIMM: Achieving Asynchronous Execution in DIMM-Based Near-Memory Processing

**Venue:** HPCA  
**Confidence:** low (abstract-only)

## Problem
DIMM-based NMP cannot support asynchronous host-NMA execution because independent memory controllers on both sides cause bus contention and DRAM state races. Existing designs use synchronous execution, wasting compute on whichever side is idle.

## Motivation
Near-memory processing is attractive for bandwidth-bound workloads, but synchronous host-NMA execution severely underutilizes hardware by serializing access to DRAM.

## Method
AsyncDIMM lets the host CPU and a near-memory accelerator (a specialized processor attached to memory) share the memory bus through three modes: one device alone, both at once, or switching between them seamlessly. It manages concurrent access using an offload-schedule-return mechanism (host sends work, accelerator executes, accelerator returns results) with explicit synchronization (host waits for a signal) and implicit synchronization (timing coordinates handoffs). Three optimizations minimize delays: expedited work offload, reduced mode-switching overhead via locality-aware methods, and improved result throughput through adaptive batching and timing-division multiplexing notifications. The implementation modifies only existing memory controllers and was validated on an FPGA.

## Key Novelty
AsyncDIMM achieves concurrent host and near-memory accelerator access on existing unmodified memory buses through an offload-schedule-return mechanism with dual synchronization modes (explicit and implicit).

## Contributions
- Identification of bus contention and DRAM state races as barriers to asynchronous DIMM-NMP.
- AsyncDIMM: three access modes with offload-schedule-return synchronization.
- Optimized timing constraints, locality-aware switch-recovery, and adaptive batch with TDM notifications.
- 1.19x-1.92x speedup; 2.25x bandwidth utilization; 47% latency reduction; FPGA-validated.
