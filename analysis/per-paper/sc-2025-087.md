# Scalable, High-Fidelity Monitoring of Application Communication Patterns in Vernier

**Venue:** SC 2025  
**Authors:** Dominguez-Trujillo, Schafer, Shipley, Marshall, Bacon, Moraru, Shipman, Skjellum

## Problem
Understanding HPC application communication at scale requires navigating a fundamental trade-off:

**Exhaustive Tracing:**
- Pros: Complete event-by-event communication record
- Cons: Massive I/O overhead, scalability to 1000s of nodes poor, storage prohibitive

**Aggregated Statistics:**
- Pros: Scalable, low overhead
- Cons: Generic (all communication averaged), lacks structure, can't identify bottlenecks in specific code regions

**Need:** Targeted, high-fidelity communication data for specific application regions without full-trace overhead.

## Approach
**Vernier: Configurable Histogram-Based Monitoring**

### Core Design
Instead of tracing individual messages, collect **statistical distributions** of communication characteristics:
```
Communication pattern annotation in application:
  annotate_region("matmul_allreduce")
  
Vernier collects histograms:
  - Message sizes: distribution of bytes sent
  - Collective types: AllReduce count, ReduceScatter count
  - Latencies: communication delay distribution
  - Bandwidths: effective bandwidth distribution
```

### Key Features

1. **Configurable Collection**
   - Specify which regions to monitor (code annotations)
   - Select which metrics to collect (size, latency, type, etc.)
   - Enable/disable per application or runtime

2. **Histogram Representation**
   - Bounded memory footprint (fixed-size histograms)
   - Scales to 1000s of processes (minimal aggregation overhead)
   - Preserves statistical distribution (not just mean)

3. **Multiple Analysis Modes**
   - **Online analysis** – Real-time feedback during execution
   - **Offline analysis** – Post-mortem investigation
   - **Network simulation** – Feed patterns into network simulators
   - **Benchmarking** – Compare patterns across runs/systems

## Technical Innovation

### vs. Exhaustive Tracing
Tracing stores every message event:
```
Rank 0: send(msg_id=1, size=1MB, dest=1, t=0.001s)
Rank 0: send(msg_id=2, size=1MB, dest=2, t=0.002s)
... (millions of events)
```

Vernier stores distributions:
```
Region "matmul_allreduce" message sizes:
  [0-1KB]:   100
  [1-10KB]:  5000
  [10-100KB]: 8000
  [100KB-1MB]: 12000
  [1-10MB]: 3000
Bandwidth distribution, latency distribution, etc.
```

### Statistical Sufficiency
For simulation/optimization, **statistical characterization often sufficient:**
- Network simulator needs message size distribution (not individual messages)
- Optimizer needs to understand communication phase types
- Bandwidth profiler needs aggregate throughput patterns
