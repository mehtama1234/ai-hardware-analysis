# Mako: Speculative Distributed Transactions with Geo-Replication

**Problem:** Distributed transactions across geographically replicated systems face high latency from synchronous coordination needed to maintain consistency. Traditional approaches require waiting for acknowledgment from multiple geo-distributed replicas before transaction commitment.

**Method:** The system speculatively executes transactions (starts them running before getting final approval) at different server locations that hold copies of the data, which cuts down the time spent waiting for all servers to agree. If a transaction's tentative results turn out to conflict with others, the system aborts it without applying the changes. Read-only transactions (queries) and transactions that change data use different strategies, with coordination checks to ensure everything stays correct.

**Novelty:** Mako reduces latency in geo-replicated systems (databases across geographically distant locations) by starting transactions at local copies before waiting for all locations to approve, catching conflicts to ensure consistency.
