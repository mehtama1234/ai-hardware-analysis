# Memory Safety Instrumentations in Practice: Usability, Performance, and Security Guarantees

**Venue:** CGO
**Confidence:** low

## Problem
Memory safety violations (spatial safety) remain widespread despite extensive research; existing sanitizers promise ease-of-use and low overhead but face adoption challenges due to spurious error reports and practical usability issues.

## Motivation
C's undefined behavior and spatial safety violations continue causing security breaches; understanding real-world adoption barriers is needed to improve sanitizer design.

## Method
The paper builds an LLVM-based framework (a compiler tool that instruments code) to systematically test two memory-safety approaches: Low-Fat Pointers and SoftBound. The framework automates the common tasks that these approaches share—figuring out where to add safety checks and removing redundant ones—so researchers can compare them fairly. It then measures what fraction of memory accesses don't actually need checking (are provably safe) and breaks down where the performance cost comes from.

## Key Novelty
The paper's key idea is an LLVM framework that automates the shared tasks between different memory-safety approaches, making it possible to compare them fairly and identify exactly where practical adoption breaks down.

## Contributions
- Identification of usability pain points in Low-Fat Pointers and SoftBound
- Open-source LLVM instrumentation framework for memory safety analysis
- Quantitative insights on provably-safe accesses and overhead attribution
