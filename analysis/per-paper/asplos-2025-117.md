# asplos-2025-117: DarwinGame: Playing Tournaments for Tuning Applications in Noisy Cloud Environments

**Venue:** ASPLOS  
**Confidence:** high (full text)  
**Primary Theme:** tournament-based application tuning robust to cloud interference

## Problem
Existing application performance tuners (OpenTuner, ActiveHarmony, BLISS) implicitly assume a dedicated interference-free execution environment; when used in shared cloud environments with unpredictable co-tenant interference, they produce suboptimal tuning configurations more than 40% away from optimal because interference levels differ across configuration evaluations, causing the tuner to misrank configurations.

## Motivation
Application developers increasingly tune on shared cloud infrastructure (due to cost, device availability, and deployment-environment fidelity), but uncontrollable background interference invalidates the relative performance measurements that all existing tuners rely upon.

## Method
DarwinGame runs multiple copies of an application with different configurations on the same virtual machine simultaneously, so they all face the same interference—this lets you directly compare them rather than guessing their performance from separate runs with different interference levels. It searches 10,000 configurations through four tournament stages: (1) a Swiss-style regional phase where the search space divides into 10,000 regions and configurations compete in parallel with early stopping when a winner emerges (judged by how much work gets done), (2) a double-elimination phase where both winners and losers advance to re-compete (judged on speed and consistency), (3) a barrage-style playoff where top survivors compete head-to-head without early stopping, and (4) a final match. This finds configurations that are both fast and reliable under cloud interference.

## Key Novelty
The core innovation is running multiple application copies with different configurations on the same virtual machine so they experience identical interference, enabling direct comparison, then using a tournament structure (Swiss regional, double-elimination global, barrage playoff, finals) to find configurations that are both fast and reliable under unpredictable cloud interference.

## Contributions
- Introduction of interference-aware cloud performance tuning as a new research area and first solution.
- Tournament-based design with Swiss, double-elimination, and barrage phases identifying configurations with low execution time and low interference sensitivity.
- Integration mechanism allowing DarwinGame to enhance existing tuners (OpenTuner, BLISS) as a subspace search oracle.
- Evaluation on AWS m5.8xlarge (32 vCPUs) with Redis, GROMACS, FFmpeg, LAMMPS: >27% execution time reduction, <0.5% variability.

- **Execution time:** >27% reduction vs. OpenTuner/BLISS/ActiveHarmony in cloud; 4.2% above optimal on average
- **Variability:** <0.5% performance variability
- **Integration gain:** >15% improvement when combined with existing tuners

## Baselines
- OpenTuner
- ActiveHarmony
- BLISS
- Exhaustive search (all configs in cloud)
- Optimal (dedicated interference-free environment)

## Limitations
Targets static tunable parameters only; no provable theoretical convergence bounds due to unpredictable cloud interference; co-location within a VM introduces additional noise for smaller co-located configurations.
