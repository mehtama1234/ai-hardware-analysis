# Separate but Together: Integrating Remote Attestation into TLS

**Problem:** Remote attestation and TLS are typically deployed as separate security mechanisms, requiring distinct verification flows. The challenge is cleanly integrating attestation verification into the TLS handshake without duplicating functionality or degrading performance.

**Method:** The approach modifies the TLS handshake—the initial security exchange when connecting to a server—to include hardware attestation credentials (proof from a TPM security chip or CPU that the hardware is legitimate and unmodified). Rather than sending attestation evidence in separate messages, it's bundled directly into the certificate exchange that already occurs during TLS setup. This allows clients to verify both the server's identity and its hardware integrity in one integrated verification, eliminating the need for separate attestation workflows.

**Novelty:** The single core idea is embedding remote attestation—verification that hardware hasn't been tampered with—directly into the TLS handshake instead of requiring it as a separate verification mechanism.
