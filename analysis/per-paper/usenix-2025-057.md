# HotRAP: Hot Record Retention and Promotion for LSM-trees with Tiered Storage

**Problem:** Frequently accessed records in LSM-trees are compacted to slower storage over time, and existing promotion algorithms are inefficient at moving them back to fast storage, leading to degraded read performance.

**Method:** HotRAP, built on RocksDB, continuously tracks which records are accessed most frequently using an on-disk index organized as an LSM-tree (a structure that efficiently handles data updates). When frequently accessed records end up on slower storage after the system reorganizes data (compaction), the system promotes them back to fast storage using one of three different methods, selected based on access patterns. This ensures frequently accessed data stays fast while less-accessed data can remain on cheaper, slower storage.

**Novelty:** Using an LSM-tree to track which records are accessed most frequently, combined with three distinct promotion strategies that efficiently move hot data between storage tiers.
