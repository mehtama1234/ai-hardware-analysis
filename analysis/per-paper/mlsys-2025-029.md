# mlsys-2025-029 — Optimizing LLM Queries in Relational Data Analytics Workloads

**Venue:** MLSYS 2025

**One-line problem:** Maximize KV cache prefix hit rates in LLM batch analytics by reordering both rows and per-row field orderings to exploit relational data repetition patterns.

## Method
Two algorithms operating on a table's rows and fields. PHC (Prefix Hit Count) objective sums squared prefix lengths reused from the prior row, capturing quadratic attention cost savings. OPHR (Optimal Prefix Hit Recursion) is provably optimal but exponential. GGR (Greedy Group Recursion) greedily selects the highest-hit-count value/field at each step, using functional dependencies (foreign/primary keys) to batch correlated fields into prefixes, and cardinality/length statistics for early stopping. Implemented as a PySpark UDF calling a vLLM backend. GGR runs in <15s for tables up to 30K rows and 57 fields.

## Key Novelty
First approach leveraging relational data structure (functional dependencies, field statistics) to perform per-row field reordering for KV cache prefix maximization — showing fixed field ordering can be up to m times worse in prefix hit count.

## Metrics
- 1.5–3.4x end-to-end latency speedup vs Cache (Original); 1.8–3.8x vs No Cache
- 30–75% higher prefix hit rates across datasets
- 32% cost savings on OpenAI GPT-4o-mini; up to 79% estimated savings with Anthropic
- Within 5% accuracy of original ordering across models
