# mlsys-2025-029 — Optimizing LLM Queries in Relational Data Analytics Workloads

**Venue:** MLSYS 2025

**One-line problem:** Maximize KV cache prefix hit rates in LLM batch analytics by reordering both rows and per-row field orderings to exploit relational data repetition patterns.

## Method
The method reorders rows and fields to maximize KV cache prefix hits—reusing previously computed results when the same data patterns repeat. It uses two algorithms: OPHR (Optimal Prefix Hit Recursion) recursively splits the table by distinct field values for the mathematically optimal ordering but is exponentially slow, while GGR (Greedy Group Recursion) approximates this by greedily selecting the highest-impact field and value at each step. GGR further optimizes by using functional dependencies to group related fields and value statistics to skip unnecessary work, processing tables up to 30K rows with 57 fields in under 15 seconds via PySpark and vLLM.

## Key Novelty
The key contribution is using relational database structure—how fields depend on each other, and value distributions—to reorder rows and fields, so language models can reuse more previously computed results when processing data in batches.

## Metrics
- 1.5–3.4x end-to-end latency speedup vs Cache (Original); 1.8–3.8x vs No Cache
- 30–75% higher prefix hit rates across datasets
- 32% cost savings on OpenAI GPT-4o-mini; up to 79% estimated savings with Anthropic
- Within 5% accuracy of original ordering across models
