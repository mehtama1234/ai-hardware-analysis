# Marconi: Prefix Caching for the Era of Hybrid LLMs

**Problem:** Hybrid Attention+SSM LLMs (Mamba, Jamba) cannot use standard prefix caching because SSM in-place state updates preclude partial-sequence reuse; only exact-match hits are valid, causing a cache explosion with low reuse.

**Method:** Marconi maintains a tree structure (a radix tree) that stores cached data for attention layers (KV-cache blocks) and SSM layers (state checkpoints). Before processing the input, it speculatively identifies points in the tree where SSM state checkpoints are needed. It only keeps two types of cached prefixes: those shared unchanged across conversations (system prompts, shared context) and those varying per conversation (multi-turn history). When cache fills, eviction uses a score combining recency with FLOP-efficiency (computing power saved per byte stored), prioritizing high-return entries and only deleting leaves or single-child nodes to avoid invalidating subtrees.

**Key novelty:** First hybrid Attention+SSM prefix cache; FLOP-efficiency eviction metric (FLOPs saved per cache byte) combining recency and compute-return value.

**Metrics:**
- Up to 34.4x higher token hit rates vs vLLM+ prefix caching
- 71.1% lower P95 TTFT vs vLLM+
- 617 ms lower P95 TTFT vs vLLM+
