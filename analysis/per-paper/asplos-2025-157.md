# asplos-2025-157: Mosaic: Exploiting Instruction-Level Parallelism on Deep Learning Accelerators with iTex Tessellation

**Venue:** ASPLOS  
**Confidence:** low (abstract-only)

## Problem
DL compilers use homogeneous tiling that maps tensor computations to a single arithmetic unit type (scalar, vector, or tensor), failing to exploit simultaneous parallel use of all available compute units and leaving substantial ILP on the table.

## Motivation
Commodity CPUs and GPUs provide scalar, vector, and tensor units that can execute concurrently; homogeneous compiler strategies waste available ILP and peak FLOP throughput.

## Method
Mosaic uses iTex (instruction-level texture) tessellation, a compiler technique that partitions a tensor computation into sub-pieces, each optimized for a different arithmetic unit type: scalar for single values, vector for multiple values in parallel, and tensor for matrix operations. The compiler analyzes the operation and hardware capabilities to determine the optimal partitioning. It then generates code that executes all these pieces simultaneously within a single kernel, overlapping their execution to exploit all available instruction-level parallelism.

## Key Novelty
iTex tessellation splits tensor operations into sub-pieces optimized for different arithmetic unit types (scalar, vector, tensor) to execute in parallel within a kernel, exploiting instruction-level parallelism.

## Contributions
- iTex tessellation compiler technique for heterogeneous sub-tile mapping
- Mosaic compiler system for DL workloads on CPUs and GPUs
- ILP exploitation across scalar, vector, and tensor units simultaneously
- Tessellation strategy analysis for different operation shapes and platforms
