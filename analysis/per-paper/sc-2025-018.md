# gLLM: Global Balanced Pipeline Parallelism Systems for Distributed LLMs Serving with Token Throttling

## Overview
Token-aware pipeline parallelism system for LLM serving reducing pipeline bubbles via dynamic token throttling and asynchronous execution.

## Problem & Motivation
- **Challenge**: Pipeline parallelism for LLMs suffers from bubbles (idle compute stages) due to imbalanced computation; hybrid scheduling (Sarathi-Serve) with fixed token budgets causes oscillations
- **Opportunity**: Global token-level scheduling with independent prefill/decode regulation can maintain compute balance and near-saturate pipeline stages
- **Scale**: Distributed multi-node GPU inference serving

## Architecture & Method
**Token Throttling**
- Independent regulation of prefill vs decode tokens
- Decode: maintain near-consistent token count across batches
- Prefill: dynamic batch sizing by (pending queue depth, KV cache utilization)
- Fine-grained scheduling preventing both compute starvation and queue buildup

**System Architecture**
- Asynchronous execution (non-blocking compute stages)
- Message passing between pipeline stages
- Optimized for pipeline parallelism communication patterns

**KV Cache Management**
- Memory-aware prefill batch sizing
- Prevents cache exhaustion causing pipeline stalls

## Key Contributions
1. **Token Throttling**: Fine-grained independent prefill/decode scheduling
2. **Dynamic batch sizing** by KV cache memory pressure
3. **Asynchronous message-passing** architecture for pipeline efficiency
4. **11-398% throughput improvement** vs state-of-the-art
5. **Lower latency** maintained vs baselines
6. **Open-source**: Code released at GitHub (improved accessibility)

## Performance & Results
- **Throughput**: 11-398% improvement vs state-of-the-art pipeline/tensor parallelism
- **Latency**: Lower than baselines

## System Insights
- Pipeline bubbles from token distribution imbalance, not just workload imbalance
- Independent control of prefill/decode workloads enables better balancing
- KV cache memory becomes bottleneck in large batch scenarios
