# SampleAttention: Near-Lossless Acceleration of Long Context LLM Inference with Adaptive Structured Sparse Attention

**ID:** mlsys-2025-060  
**Venue:** MLSYS 2025  
**Confidence:** high (full text analyzed)

## Problem
Long-context LLM prefill latency scales quadratically with sequence length; existing sparse attention methods use static patterns or fixed sparsity budgets that cannot adapt to per-head, per-input, and per-model variability in sparsity ratio and structured pattern.

## Method
SampleAttention speeds up attention computation by sparsifying (keeping only important) connections in the attention matrix. Stage 1 partitions queries into chunks and computes full attention only for representative blocks at chunk boundaries, then aggregates scores by blocks (128 tokens) in column and diagonal directions to identify important regions. Stage 2 independently selects the minimum blocks in each direction needed to preserve a target fraction of attention probability per query (measured by Cumulative Residual Attention, or CRA), builds a sparse mask, and runs the efficient FlashAttention2 kernel, with efficiency boosted by fusing operations together and precomputing patterns per model and sequence-length range.

## Key Novelty
The core innovation is the Cumulative Residual Attention (CRA) metric—the minimum fraction of attention probability to retain per query—which can be computed at runtime and reliably predicts downstream task accuracy, enabling fully adaptive sparsity patterns that vary per query and per input without requiring model retraining.

## Metrics
| Metric | Value |
|--------|-------|
| TTFT speedup vs. FlashAttention2 | 5.29x at 1M tokens; 1.15x–3.94x at 32K–512K |
| Accuracy retention | >99% of full attention (MLPerf near-lossless) on RULER, LongBench, InfiniteBench |
| Sampling overhead share | 21.6%–39.1% of total attention time at 32K–128K; shrinks with length |

## Baselines
FlashAttention2, MInference, BigBird, StreamingLLM, HyperAttention, Hash-Sparse

## Limitations
Prefill-only; no KV-cache compression for decoding; negligible gains at sequences shorter than ~32K; offline per-model, per-length-range hyperparameter tuning required.
