# isca-2025-037 — SpecASan: Mitigating Transient Execution Attacks Using Speculative Address Sanitization

**Venue:** ISCA  
**Confidence:** low (abstract-only)

## Problem
Transient execution attacks (Spectre, Meltdown, MDS) exploit speculative execution to leak sensitive data through residual microarchitectural state, and existing defenses either delay speculative execution or require costly shadow structures and dynamic information flow tracking. Providing strong security against transient execution attacks without significant performance overhead remains an open problem.

## Motivation
Speculative execution is essential for modern processor performance, but hardware defenses against Spectre-class attacks typically impose 10-50% performance overheads, making a lightweight yet comprehensive solution highly desirable.

## Method
SpecASan extends ARM's Memory Tagging Extension (MTE)—a hardware feature that assigns security tags to memory locations—from normal execution into speculative execution (where the CPU predicts ahead). When the CPU speculatively accesses memory, the hardware checks whether the pointer's security tag matches the memory location's tag; if they don't match, that access is held up until the prediction completes, preventing it from leaving traces in caches and memory translation buffers. This combines with Control-Flow Integrity rules that block gadget sequences (code chains attackers link together), using only the existing MTE tag-checking hardware with minimal new additions.

## Key Novelty
SpecASan is the first to repurpose ARM MTE tag checks on the speculative execution path to selectively delay potentially leaking memory accesses, enforcing security rules without disabling speculation or adding hardware structures to track data access.

## Contributions
1. Security model framing transient execution attacks as software-defined security contract violations
2. Hardware mechanism extending ARM MTE tag checking to the speculative execution path
3. Combined SpecASan+CFI defense covering Spectre, Meltdown, and MDS without new shadow structures
4. Low performance overhead with minimal hardware complexity
