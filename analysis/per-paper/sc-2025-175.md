# Towards Enabling Hostile Multi-tenancy in Kubernetes

**Venue:** SC

## Problem
Kubernetes native constructs (namespaces, RBAC) provide logical separation but lack strong isolation guarantees for hostile multi-tenancy

## Motivation
Enable secure, zero-trust Kubernetes deployments in untrusted, adversarial cloud/edge environments

## Method
Each tenant gets their own isolated Kubernetes control plane (a virtual control plane or vCluster) that manages only their containers, preventing one tenant from interfering with another. Containers run inside virtual machines (like Azure Container Instances) rather than on shared infrastructure, adding a hardware boundary for stronger isolation. A policy engine (Kyverno) automatically applies security rules across all tenants.

## Key Novelty
The core idea is combining per-tenant virtual control planes with VM-backed container isolation to achieve hostile multi-tenancy in Kubernetes while keeping it compatible with standard Kubernetes tools and maintaining negligible performance overhead.

## Contributions
- Per-tenant virtual control plane design for Kubernetes
- VM-based sandbox architecture for container isolation
- Automated policy enforcement with Kyverno for namespace hardening
