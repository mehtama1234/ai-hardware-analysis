# mlsys-2025-026 — Lumos: Efficient Performance Modeling and Estimation for Large-Scale LLM Training

**Venue:** MLSYS 2025

**One-line problem:** Accurately model and simulate distributed LLM training performance — including compute-communication overlap — to enable low-cost what-if configuration exploration.

## Method
Lumos records detailed execution traces from LLM training runs using PyTorch's Kineto profiler (about 10 lines of instrumentation code), capturing CPU operations, GPU kernels, and CUDA runtime events. It builds a task dependency graph that maps what must happen in sequence: CPU-to-CPU work (cudaLaunchKernel), CPU-to-GPU (correlation IDs), GPU-to-CPU synchronization (cudaStreamSync), and GPU-to-GPU coordination across parallel streams (cudaEventRecord/cudaStreamWaitEvent). The graph can be modified to simulate parallelism strategy, architecture, or layer configuration changes, then replayed to estimate performance under those new conditions.

## Key Novelty
Lumos is the first to accurately model how GPU operations on parallel streams overlap computation and communication (via cudaEventRecord/cudaStreamWaitEvent), achieving 3.3% average error and enabling what-if analysis for parallelism and architecture changes.

## Metrics
- 3.3% average replay error on GPT-3 (15B–175B) with up to 512 NVIDIA H100 GPUs
- dPRO baseline: 14% average error
- Scale-out what-if estimation: 4.2% average error
