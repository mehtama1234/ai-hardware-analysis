# mlsys-2025-026 — Lumos: Efficient Performance Modeling and Estimation for Large-Scale LLM Training

**Venue:** MLSYS 2025

**One-line problem:** Accurately model and simulate distributed LLM training performance — including compute-communication overlap — to enable low-cost what-if configuration exploration.

## Method
Lumos uses PyTorch Kineto traces (only ~10 lines of hook code) to build a task-level execution graph with four dependency types: CPU-to-CPU (intra/inter-thread), CPU-to-GPU (cudaLaunchKernel correlation IDs), GPU-to-CPU (cudaStreamSync), and GPU-to-GPU including inter-stream via cudaEventRecord/cudaStreamWaitEvent. A dependency-respecting event-driven simulator replays the graph. Graph manipulation supports adjusting data parallelism (communication times), pipeline parallelism (layer partitioning + schedule update), and model architecture (tensor dimensions for GEMM kernels, layer duplication).

## Key Novelty
First trace-driven tool to accurately capture LLM inter-stream compute-communication dependencies, achieving 3.3% average replay error vs 14% for dPRO, and supporting flexible what-if estimation without hardware re-runs.

## Metrics
- 3.3% average replay error on GPT-3 (15B–175B) with up to 512 NVIDIA H100 GPUs
- dPRO baseline: 14% average error
- Scale-out what-if estimation: 4.2% average error
