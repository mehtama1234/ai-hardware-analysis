# SC-2025-252: MPI Correctness Benchmarking for Fortran

**Closing the Gaps in MPI Tool Evaluation**

## Summary
This work extends MPI-BugBench (the most recent MPI correctness benchmarking suite) from C to Fortran. Through porting and evaluation, it identifies language-specific porting challenges and discovers gaps in both tool accuracy and MPI binding implementations.

## Problem
MPI (Message Passing Interface) is the standard for distributed memory programming in HPC. Tools that detect MPI bugs are critical for scientific computing reliability:
1. **Benchmark Gap**: Existing MPI correctness benchmarks limited to C
2. **Fortran Neglect**: MPI standard explicitly supports Fortran, but tool evaluation skips it
3. **Risk to Science**: Fortran remains dominant in scientific computing (climate, weather, materials)
4. **Unknown Tool Quality**: MUST and other correctness tools may behave differently on Fortran
5. **Binding Assumptions**: Fortran MPI bindings potentially less tested than C

## Approach
### MPI-BugBench Overview
MPI-BugBench is established benchmark for MPI correctness tools:
- Collection of C programs with intentional bugs
- Test categories: deadlock, data races, mismatched operations, etc.
- Evaluates tool's ability to detect each bug type
- Metrics: true positives, false positives, tool overhead

### Porting to Fortran
**Task**: Translate test generation logic from C to Fortran
**Challenges** (expected):
- Fortran array semantics differ from C pointers
- Fortran MPI API (call-based vs C function)
- Type system differences (fixed vs dynamic typing)
- Module system vs header files
- Implicit vs explicit type declarations

**Implementation**:
- Port parameterized test generators
- Adapt for Fortran syntax and semantics
- Maintain test intent (same bugs tested, different syntax)

### Evaluation: MUST on Fortran
**MUST** (MPI Unified Screening Toolkit):
- Dynamic MPI correctness tool (runtime instrumentation)
- Detects: deadlocks, data races, type mismatches, etc.
- Established tool with good performance

**Study**:
- Run ported tests with MUST
- Compare accuracy (detection rate) vs C results
- Identify tool behavior differences

## Scientific Significance

### Why Fortran Matters
Fortran dominance in scientific codes:
- **Weather/Climate**: WRF (Weather Research & Forecasting), GCMs
- **Materials**: VASP, QUANTUM ESPRESSO
- **Seismic**: SPECFEM3D
- **Combustion**: CHEMKIN, cantera
- **CFD**: ANSYS, OpenFOAM (mixed)

These codes are decades old, written in Fortran for good reasons:
- Performance (highly optimized compilers)
- Legacy investment (millions of lines)
- Language features for numerics (array operations, complex numbers)

### MPI Bug Risk
Fortran MPI code faces same risks:
- Deadlocks from mismatched send/receive
- Data races in shared memory windows
- Type mismatches (Fortran INTEGER ≠ C int always)
- Buffer sizing errors

But these risks were **unevaluated** before this work.

## Detailed Contributions

### 1. Porting Challenges
**Fortran Specific Issues**:
- **Array passing**: Fortran passes by reference; C by pointer
  - MPI calls expect pointer to data
  - Fortran requires special attention
- **Type matching**: Fortran INTEGER vs C int, REAL vs float
  - MPI-Fortran binding must handle conversions
  - Type mismatch detection different
- **Module vs Header**:
  - Fortran MPI via `use mpi` module
  - C MPI via `#include <mpi.h>`
  - Test framework must handle both
- **Implicit typing**:
  - Fortran allows implicit types (dangerous)
  - Harder for tools to reason about types

### 2. MUST Accuracy Finding
**Key Result**: "Largely consistent across languages"
- **Implication**: MUST works well for Fortran
- **Caveat**: Type checking exception
  - Likely depends on Fortran runtime library feature
  - Missing debugger info (type names lost)
  - Affects detection of MPI_DATATYPE mismatches

### 3. Bug Discoveries

#### OpenMPI Fortran Binding Bugs
- Specific issues not enumerated in abstract
- Likely categories:

- **Impact**: Fixes benefit all OpenMPI Fortran users
