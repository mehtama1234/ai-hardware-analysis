# Bubble: Towards Scalable Evolving Graph Processing via Mini-Batch Sorting

**Venue:** SC 2025  
**Authors:** Deng, Li, Zhang, Xu, Lui

## Problem
Evolving graph systems suffer on multicore systems due to:
1. **Cache contention** – Multiple threads competing for shared cache (L3)
2. **Workload imbalance** – Uneven edge distribution across threads
3. **Poor scalability** – State-of-the-art systems don't scale linearly with core count

Applications: social networks, temporal networks, streaming data analysis.

## Approach
**Bubble Engine with Mini-Batch Sorting:**

### Core Innovation
Sort incoming edges by destination vertex to maximize cache locality:
- Edges targeting same vertex batch together
- Single thread processes batch, stays in private L1/L2 cache
- Minimizes cache line bouncing between cores
- Private L3 cache per core partition exploited efficiently

### Algorithm
```
For each mini-batch of edges:
  1. Sort by destination vertex
  2. Assign threads to disjoint vertex ranges
  3. Each thread processes assigned edges locally
  4. Private caches stay hot for related updates
```

### Dual Performance
- **Ingestion:** Process stream of updates efficiently via sorting
- **Analytics:** Run graph algorithms (BFS, PageRank, etc.) on sorted structure

## Performance Results

### Ingestion Throughput
| Baseline | Bubble Speedup |
|----------|----------------|
| LSGraph | 2.46x |
| GraphOne | 4.15x (midpoint) |
| XPGraph | 8.86x |

**Geometric mean:** ~4.5x improvement

### Analytics Performance
| Baseline | Bubble Relative Performance |
|----------|---------------------------|
| LSGraph | 0.77x-1.5x |
| GraphOne | 1.0x-2.5x |
| XPGraph | 1.2x-3.29x |

Note: Some cases show lower analytics performance (0.77x) – trade-off of sorting overhead for ingestion gains.

## Technical Insights

### Why Mini-Batch Sorting Works
1. **Cache locality** – Contiguous vertex updates stay in L1/L2
2. **Reduced coherency traffic** – Minimize cache line invalidations
3. **Thread affinity** – Naturally map sorted edges to cores
4. **Scalability** – Near-linear with edge ingestion rate

### Hardware Assumptions
- Multi-socket NUMA systems
- Private L3 per-core (or per small core group)
- Sufficient memory bandwidth for streaming edges

## Limitations

### Performance Trade-offs
- Analytics performance sometimes degrades (0.77x) – suggests sorting overhead
- Best gains on ingestion-heavy workloads (not balanced workloads)
