# A TRRIP Down Memory Lane: Temperature-Based Re-Reference Interval Prediction For Instruction Caching

**Venue:** MICRO  
**Confidence:** high (full text)

## Problem
Modern mobile CPU workloads (interpreters, JIT compilers, UI frameworks) have large instruction footprints with long reuse distances that defeat hardware-only cache replacement policies, causing persistent L2 instruction cache miss stalls even after PGO code layout optimization.

## Motivation
Mobile code complexity and footprint grow faster than on-chip cache capacity; hardware-centric predictors see only short execution windows and cannot track the global temperature of code sections, leaving significant frontend stalls unaddressed.

## Method
A compiler analyzes code execution frequency and marks each piece as hot, warm, or cold, grouping them in separate program sections. The operating system reads these markings and encodes them as 2-bit temperature values into existing ARM PBHA bits in page table entries—reusing unused hardware fields with zero additional storage cost. When the L2 cache needs to decide what instruction to evict, the memory management unit sends these temperature bits along with the memory request; the cache prioritizes keeping hot code (RRPV=0), then warm code (RRPV=1), then cold code (RRPV=2), following the existing RRIP replacement mechanism. This strategy works because the compiler has information about code importance that hardware-only caches cannot access.

## Key Novelty
The innovation is using existing, unused ARM PBHA bits in page tables as a zero-cost communication channel to pass compiler-derived code temperature (hot/warm/cold) to the cache replacement policy, eliminating the need for additional hardware storage or ISA modifications.

## Contributions
1. Characterization of instruction cache miss patterns in PGO-optimized mobile system software showing persistent frontend stalls due to high hot-code reuse distance
2. TRRIP: a practical compiler-OS-hardware co-design technique that reduces L2 instruction MPKI by 26.5-27.3% via temperature-aware RRIP insertion priority
3. Demonstration of geomean 3.9% speedup on 10 mobile proxy benchmarks, with negligible hardware area overhead compared to SHiP and Emissary

## Hardware Target

## Metrics
- **Speedup:** 3.9% geomean over SRRIP (PGO-compiled mobile benchmarks)
- **L2 instruction MPKI reduction:** 26.5% (TRRIP-1), 27.3% (TRRIP-2)

## Baselines

## Limitations
Evaluated only on a simulated mobile SoC using proxy benchmarks; real silicon results and interaction with proprietary system software are not shown.
