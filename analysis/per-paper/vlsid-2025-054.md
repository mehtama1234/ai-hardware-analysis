# DNA-CIM: DNA Sequence Analysis Using RRAM-Based Compute In-Memory Accelerator

**ID**: vlsid-2025-054 | **Venue**: VLSID | **Confidence**: low (abstract only)

## Problem Statement
DNA sequence analysis (matching, mutation detection) is computationally intensive with massive data volumes, causing severe memory wall problems in conventional architectures. Off-chip memory access dominates latency and energy in genome processing applications.

## Motivation
Genomics applications including disease diagnosis, evolutionary analysis, and personalized medicine require rapid analysis of gigabases of sequence data. Specialized hardware can eliminate von Neumann bottleneck by computing within memory arrays.

## Method
DNA sequences are converted to binary numbers (0s and 1s) and compared using fast bitwise logic operations (XOR and AND operations, which identify matching and different bits) performed directly inside resistive memory rather than the CPU. Specialized circuits detect the results in-memory without moving data, and mutation classification—identifying where sequences differ—happens at the memory level. The architecture was designed and verified through simulation at 65-nanometer technology.

## Key Results
**Performance**:
- **Energy Efficiency**: 2.042 TCUPS/W (tera-comparisons per watt)
- **Throughput**: 38.4 GCUPS (giga-comparisons per unit)
- **Advantage**: High parallelism, reduced latency, enhanced scalability

## Novelty & Contributions
1. **First RRAM-CIM genomics accelerator** combining in-memory alignment with near-memory mutation analysis
2. **Binary encoding scheme** enabling efficient bitwise operations in RRAM
3. **MLSC integration** for practical sense-amp scaling
4. **Variability mitigation** techniques for RRAM reliability
5. **Unified pipeline** from sequence matching to mutation classification

## Limitations
- **Outdated technology**: 65nm node; scaling to modern processes (28nm, 7nm, 5nm) not addressed
- **RRAM reliability unclear**: Variability "addressed" but detailed failure mode analysis absent
- **Simulation-only**: No silicon results, post-silicon validation, or actual genomic dataset experiments
- **Limited encoding**: Binary representation discards quality scores, base-call confidence, alignment info
- **Mutation scope narrow**: Classification only; no phylogenetic or functional impact prediction
- **Missing baselines**: No quantitative comparison with GPU (NVIDIA), FPGA (Xilinx), or specialized tools (BLAST, bowtie2)
- **Capacity undefined**: Memory required for realistic genome sizes (human genome: 3Gb) not estimated
- **Scalability questions**: Multi-chip tiling, network bandwidth, and distributed analysis not addressed
