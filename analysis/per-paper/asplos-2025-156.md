# asplos-2025-156: Design and Operation of Shared Machine Learning Clusters on Campus

**Venue:** ASPLOS  
**Confidence:** low (abstract-only)

## Problem
Campus GPU clusters must be shared fairly among diverse users, but existing solutions target large industrial settings and don't address academic constraints: limited staffing, heterogeneous hardware, and fair multi-user allocation.

## Motivation
Universities are investing heavily in GPU clusters; ineffective sharing causes poor utilization and inequitable access without a full-stack campus-tailored solution.

## Method
SING provides four extensible layers: infrastructure (automated config/monitoring), scheduling (fair multi-user allocation), interface (job submission/access control), and operations (incident detection/management). Routine automation minimizes staffing burden while workload-aware scheduling maximizes utilization.

## Key Novelty
Full-stack campus GPU cluster management system with four extensible layers tailored to academic operational realities.

## Contributions
- SING four-layer full-stack solution for campus GPU cluster management
- Real-world usage pattern analysis and incident management strategies from deployment
- Fair resource allocation policies for diverse academic ML workloads
- Open-source release of SING resources
