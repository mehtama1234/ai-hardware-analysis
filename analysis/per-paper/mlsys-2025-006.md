# ProtoRAIL: A Risk-cognizant Imitation Agent for Adaptive vCPU Oversubscription In the Cloud

**Problem:** Cloud vCPU oversubscription policies must jointly minimize hot node overloading and maximize stranded resource recovery, but dynamic demand patterns across VM types make static heuristics fail on both objectives.

**Method:** ProtoRAIL encodes CPU usage sequences using a neural network (LSTM or Transformer) into embeddings, then groups them into K prototypes representing typical VM behavior; oversubscription decisions are made by comparing how similar current usage is to each prototype. It learns from expert decisions via imitation learning (behavior cloning or adversarial training) while pursuing four goals: keeping prototypes close to real data, far apart from each other, grounded in actual trajectories for interpretability, and good at predicting actual demand. When it encounters uncertain situations (mixed or overlapping prototypes) or risky predictions (predicted oversubscription below actual usage), it asks domain experts to vote on prototypes, suggest actions, or restructure clusters (merge/split), then automatically adjusts how strongly each training goal is weighted to apply this feedback—only requesting help when genuinely uncertain or risky.

**Key novelty:** Prototypical IL with interpretable usage-pattern equivalence classes; active expert-in-the-loop de-risking with prototype-level merge/split/vote feedback using minimal query budget.

**Metrics:**
- 0% hot node rate (best baseline: 0.89% Coop-MARL)
- 8161 remain cores (benefit) vs 7938 for Dagger
- 9.4% vCPU utilization improvement on 300 production clusters
- Benefit-risk ratio 31.34 vs 18.95 heuristic, 7.79 manual
- <=10 KITL queries to reach stable policy
