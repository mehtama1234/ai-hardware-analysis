# Reload+Reload: Exploiting Cache and Memory Contention Side Channel on AMD SEV

**ID:** asplos-2025-030  
**Venue:** ASPLOS  
**Confidence:** low (abstract-only)  
**Primary Theme:** Cache and memory contention side-channel attacks on AMD SEV-SNP

## Problem
AMD Secure Encrypted Virtualization (SEV) is designed to protect guest VMs in multi-tenant clouds via memory encryption, but two previously unknown side channels—cache flush timing and memory contention—expose information even through the SEV-SNP isolation boundary.

## Motivation
Cloud TEE solutions like AMD SEV are deployed in production to guard sensitive workloads, making any new cross-VM side channel a critical security threat that undermines encrypted VM isolation.

## Method
The authors discover and formalize two AMD-specific side channels: (1) a cache flush side channel exploitable via flush-set timing (RRFS), and (2) a memory contention side channel (RRMB). They construct two Reload+Reload attack variants that exploit these channels to observe memory access patterns without relying on the disabled Flush+Reload primitive. RRFS is used to build a covert channel for a Spectre attack; RRMB is used for AES-128 key extraction by timing memory block contention across VM boundaries under SEV-SNP.

## Key Novelty
Discovery of two new AMD SEV side channels (cache flush timing and memory block contention) enabling Reload+Reload attacks that bypass SEV-SNP isolation and outperform Prime+Probe in noise resistance and bandwidth.

## Contributions
- Identification of two previously unknown side channels in AMD processors with SEV/SEV-SNP support.
- Construction of two Reload+Reload attack variants (RRFS, RRMB) exploiting these channels against SEV-SNP VMs.
- Demonstration of a Spectre covert channel with superior noise resistance over Prime+Probe using RRFS.
- Successful AES-128 secret key extraction from SEV-SNP protected VMs using RRMB.
