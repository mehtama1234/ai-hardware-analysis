# isca-2025-113 — When Mitigations Backfire: Timing Channel Attacks and Defense for PRAC-Based RowHammer Mitigations

**Venue:** ISCA  
**Confidence:** low (abstract-only)

## Problem
The JEDEC DDR5 Per Row Activation Counting (PRAC) mechanism and its Alert Back-Off (ABO) protocol and Refresh Management (RFM) commands introduce observable timing differences that create a new timing side-channel, allowing attackers to monitor memory access latencies and infer sensitive information such as cryptographic keys.

## Motivation
PRAC was designed to robustly mitigate Rowhammer, but the very protocol-level signaling it uses to trigger mitigations creates a timing channel that undermines the security of co-located software, requiring a defense that closes the channel without sacrificing Rowhammer protection.

## Method
The paper describes PRACLeak, an attack that exploits timing variations caused by PRAC's ABO protocol and RFM commands (which manage memory refresh) to extract cryptographic keys from AES implementations by measuring how long memory operations take. The authors then propose TPRAC, a defense that eliminates this leak by issuing RFM refresh commands on a fixed schedule regardless of memory activity, breaking the timing pattern attackers rely on. TPRAC uses a single-entry mitigation queue per memory bank and works with existing DRAM standards.

## Key Novelty
PRAC's ABO and RFM commands create a timing side-channel that leaks information tied to memory access patterns, which TPRAC fixes by issuing refresh commands on a regular clock schedule instead of responding to memory activity.

## Contributions
- PRACLeak: a novel timing channel attack exploiting ABO and RFM latency differences in PRAC-based DRAM systems to leak cryptographic key material.
- TPRAC: a timing-safe PRAC variant using periodic, activity-independent Timing-Based RFMs to eliminate the side-channel.
- Single-entry in-DRAM mitigation queue design that is compatible with existing DRAM standards.
- Evaluation showing TPRAC closes the timing channel with only 3.4% performance overhead at RH threshold 1024.
