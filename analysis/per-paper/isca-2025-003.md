# Reconfigurable Stream Network Architecture

**Venue:** ISCA  
**Confidence:** high (full text read)

## Problem
FPGA-based DNN overlay accelerators suffer from layer-granularity serialization: von Neumann-style coarse-grained ISAs treat each layer instruction atomically, preventing dynamic layer fusion, inter-layer pipelining, and fine-grained bandwidth orchestration across heterogeneous resources (FPGA fabric + AI Engines).

## Motivation
AI hardware increasingly combines heterogeneous components (e.g., AMD Versal with FPGA fabric + hardened AI Engines), but no existing ISA abstraction unifies resource orchestration and execution-phase transitions at sub-layer granularity, leaving compute units idle during pipeline drains and phase switches.

## Method
RSN treats the hardware as a network of computing units (called functional units) connected by data pipelines, where each computation specifies its own path through the network—multiple paths run in parallel as long as they don't conflict. Programming is streamlined through instruction compression: RSN combines multiple instruction streams into compact packets, using just 1 byte to drive up to 1.6 billion floating-point operations. On the Versal VCK190 prototype (RSN-XNN), the FPGA's memory blocks, arithmetic units, and AI Engine accelerator tiles all connect through the same pipeline interface, treated as compatible computing units. This allows different neural network layers to run at the same time and share memory bandwidth, rather than waiting for each layer to finish before starting the next.

## Key Novelty
RSN introduces a streaming network instruction abstraction where different neural network layers route data through the same FPGA hardware network, enabling simultaneous execution and memory sharing without per-layer reprogramming.

## Contributions
- RSN ISA abstraction with stateful FU network and latency-insensitive streams
- First FPGA overlay with dynamic sequential layer pipelining and fine-grained off-chip bandwidth mapping
- RSN-XNN on VCK190: 6.1x latency reduction; 2.4x–3.2x throughput vs. SOTA on same platform
- 2.1x higher energy efficiency vs. A100 GPU at same 7nm; latency parity with T4 at 18% of its memory bandwidth
- Open-source release

## Hardware Target

## Technique Category

## Workloads
transformer (BERT, ViT), CNN, recommendation (NCF), MLP

## Metrics
- Speedup: 6.1x latency vs. SOTA VCK190; 2.4x–3.2x throughput for BERT/ViT/NCF/MLP
- Energy: 2.1x vs. A100 at 7nm in FP32
- Bandwidth: Matches T4 latency at 18% of T4's memory bandwidth

## Baselines
SOTA FPGA DNN overlay on VCK190, NVIDIA T4, A100, V100, L4 GPUs

## Limitations
RSN-XNN omits tile-level interleaving to save circuits, which may limit performance for workloads requiring fine-grained tile-level data reuse.
