# Multi-Dimensional Vector ISA Extension for Mobile In-Cache Computing

**Venue:** HPCA 2025  
**Authors:** Alireza Khadem, Daichi Fujiki, Hilbert Chen, Yufeng Gu, Nishil Talati, Scott Mahlke, Reetuparna Das (U. Michigan / Institute of Science Tokyo)

## Problem
Existing long-vector ISA extensions (RISC-V RVV, Arm SVE) provide only 1D strided/random memory accesses, which cannot efficiently utilize the 8192-lane SIMD width of in-SRAM vector engines built from mobile L2 caches. Mobile data-parallel kernels expose limited 1D parallelism (average 635 elements) across multi-dimensional structures, leaving SIMD lane utilization at only 23% with bit-serial in-cache computing under RVV.

## Motivation
In-cache computing repurposes SRAM arrays into wide vector engines at low area cost (3.5% overhead for an 8192-lane engine), but without multi-dimensional memory access instructions the instruction issue bottleneck prevents realizing their throughput advantage over conventional 128-bit mobile SIMD.

## Method
MVE (Multi-dimensional Vector ISA Extension) enables processors to efficiently handle data arranged in up to 4 dimensions at once (like nested tables), rather than the 1D arrays that conventional processors are limited to. Execution control happens at the dimension level, using a compact mask register to activate or deactivate entire groups of iterations simultaneously, instead of controlling individual processing lanes. A specialized controller in the L2 cache converts multi-dimensional logical accesses into physical storage locations in the SRAM, using a transpose unit (with 8T bit-cells and a crossbar) to route data through all 8192 processing lanes (each 32 bits wide) in the right order, while managing L1 cache interactions to keep data consistent. The compiler supports this through data-lifetime analysis, hybrid instruction scheduling that mixes different strategies, and efficient register allocation to prevent unnecessary spills to main memory.

## Key Novelty
A vector instruction set that supports up to 4D memory accesses (with various stepping patterns and random access) and dimension-level masked execution (turning entire iteration groups on or off), hiding cache storage details from programmers while raising processing efficiency from 23% to 60% for mobile workloads.

## Contributions
- MVE ISA: 4D strided/random accesses with dimension-level masking, improving bit-serial utilization from 23% to 60% and perf by 3.8x over RVV on the same in-cache engine
- Cache architecture: TMU, crossbar, and MVE controller abstracting cache geometry with L1/L2 coherency maintenance
- Compiler: liveness analysis, list-hybrid scheduling, greedy register allocation for in-cache register management
- 44-kernel evaluation on 12 real mobile libraries: 2.9x speedup and 8.8x energy reduction vs Arm Neon; 9.3x speedup vs Adreno 640 GPU at 3.6% area overhead

## Results

|--------|------------|-------------------|------------------------------|
| Speedup | 2.9x | 9.3x (kernel only: 2.4x) | 2.0x average |
| Energy | 8.8x reduction | 5.2x reduction | — |
| Area overhead | — | — | 3.6% to mobile core |

## Hardware Target
CPU / CIM (compute-in-memory in L2 SRAM) / SoC (Snapdragon 855 platform)

## Baselines
Arm Neon (Cortex-A76), Adreno 640 GPU, RISC-V RVV on same bit-serial in-cache engine, Duality Cache (SIMT), VRAM (bit-parallel), EVE (bit-hybrid), CAPE (associative computing)

## Limitations
Switching from compute-cache to normal-cache mode requires flushing dirty L2 lines (under 2% overhead in benchmarks); workloads with large scalar instruction fractions (e.g., zlib reduction kernel) see only 37% improvement.
