# micro-2025-090: Citadel: Rethinking Memory Allocation to Safeguard Against Inter-Domain Rowhammer Exploits

**Venue:** MICRO 2025  
**Authors:** Anish Saxena, Walter Wang, Alexandros Daglis  
**Confidence:** low (abstract only)

## Problem
Rowhammer attacks exploit DRAM physical row adjacency to corrupt memory rows in different security domains. Hardware mitigations are costly, slow to adopt commercially, and repeatedly circumvented; software mitigations incur large performance or memory overhead or provide only partial protection.

## Motivation
Increasing DRAM density raises Rowhammer attack probability; cloud servers host thousands of isolated tenants sharing physical DRAM, and no existing approach simultaneously achieves comprehensive cross-domain isolation, low overhead, and broad platform compatibility.

## Method
Citadel is a software memory allocator that prevents Rowhammer attacks (exploits where repeated memory access corrupts nearby DRAM rows) by physically isolating different security domains—separate applications or users—in distant memory regions so they never occupy adjacent rows. It works by tracking the physical layout of rows in DRAM and partitioning the address space (the mapping of memory addresses to physical locations) so domain boundaries are always separated by guard rows or page-aligned gaps. The system supports thousands of simultaneous security domains with only 7.2% additional memory overhead and no measurable performance loss, while working on any DRAM platform without requiring hardware modifications.

## Key Novelty
Citadel prevents cross-domain Rowhammer attacks using a software memory allocator that physically isolates security domains in separate DRAM regions, providing protection without hardware modifications, performance loss, or the excessive overhead of earlier approaches.

## Contributions
1. Citadel allocator: security-by-design via physical domain isolation in disjoint DRAM regions
2. Support for thousands of security domains at 7.2% average memory overhead with no performance loss
3. Flexible security domain abstraction compatible with legacy, current, and future platforms
4. 4-6x lower overhead vs. recent domain isolation schemes for supported workload scenarios
