# Seamless end-to-end containerized HPC environments

**Venue:** SC
**Paper ID:** sc-2025-001
**Confidence:** low

## Problem Statement
HPC environments struggle with conflicting demands: stability, customization, and reproducibility; traditional monolithic software stacks are inflexible

## Motivation
Diverse scientific workflows require different software configurations; reproducibility and portability are critical for scientific computing

## Method
Split containerization into five separate layers: building environments with Spack (a tool for managing software dependencies) and CI/CD pipelines (automated deployment workflows), enabling user sessions with authentication (PAM) and Kubernetes for container orchestration, connecting to Slurm (HPC's standard job scheduler), and handling system integration and security. Rather than one monolithic system, each layer uses standard open-source tools. Build and evaluate prototypes to validate this modular approach.

## Key Novelty
By breaking HPC containerization into five modular layers using open-standard tools, the framework eliminates the traditional tradeoff between stability, customization, and reproducibility.
