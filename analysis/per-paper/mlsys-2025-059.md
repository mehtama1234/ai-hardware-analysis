# APOLLO: SGD-like Memory, AdamW-level Performance

**Venue:** MLSYS 2025

## One-line Problem
AdamW's first and second moments triple LLM training memory (28 GB optimizer states for LLaMA-7B), forcing small batch sizes or more GPUs; existing memory-efficient alternatives require expensive SVD or have performance gaps.

## Method
APOLLO realizes that AdamW's per-element learning rate adjustment—where each weight gets its own learning rate—can be simplified to per-channel or per-tensor adjustment without hurting training quality. To avoid expensive SVD calculations, APOLLO uses a shortcut: randomly project the gradient into a smaller space using a Gaussian random matrix, apply AdamW's momentum-tracking to the compressed gradient, extract scaling factors, then apply those factors to the full gradient. The Gaussian random matrix is resampled every 200 steps. APOLLO-Mini uses rank-1 (tensor-wise) scaling to match SGD's memory footprint, and a Norm-growth Limiter stabilizes training.

## Novelty
Theoretical proof via Johnson-Lindenstrauss lemma that random projection preserves gradient scaling factors up to a bounded ratio, enabling SVD-free, rank-insensitive low-rank approximation that achieves SGD-level memory with AdamW-surpassing performance.

## Key Metrics
- Training throughput: **~3x improvement** on LLaMA-7B (8xA100) via 4x larger batch sizes
- Optimizer memory (LLaMA-7B): **1.6 GB** (APOLLO) / **~0 GB** (APOLLO-Mini) vs 28 GB (AdamW)
- First LLaMA-7B pre-training on single GPU in **<12 GB** (with INT8 quantization)
- First LLaMA-13B pre-training with naive DDP on A100-80GB
- Up to **3.62 perplexity improvement** over GaLore at same memory budget
