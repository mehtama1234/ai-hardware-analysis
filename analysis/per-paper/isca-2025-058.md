# NMP-PaK: Near-Memory Processing Acceleration of Scalable De Novo Genome Assembly

**Venue:** ISCA 2025  
**Authors:** Heewoo Kim, Sanjay Sri Vallabh Singapuram, Haojie Ye, Joseph Izraelevitz, Trevor Mudge, Ronald Dreslinski, Nishil Talati  
**Confidence:** high (full text)

## Problem
De novo genome assembly using De Bruijn graph (DBG) algorithms is both memory-latency-bound and memory-footprint-intensive: processing 10% of the human genome (38.3 GB input) requires 528 GB of DRAM, and the Iterative Compaction step—which dominates 48% of runtime—achieves only 2.5% of available memory bandwidth (5.2 GB/s out of 204.8 GB/s) due to fine-grained, irregular access patterns across large, dynamic MacroNode data structures.

## Motivation
Genomic datasets are growing faster than Moore's Law (doubling every 7 months), and state-of-the-art distributed assemblers require tens of thousands of CPU cores and hundreds of terabytes of memory, making personalized medicine and microbiome analysis prohibitively costly on single-node systems.

## Method
The system places small processors (Processing Elements or PEs) inside DIMM buffer chips at the channel level (a near-memory processing architecture), keeping data right at the computation site instead of shuttling it back to the main CPU. Each processor runs a three-stage pipeline on data chunks called MacroNodes: Invalidation Check (discarding outdated data), TransferNode Extraction (pulling data to transfer), and Routing and Update (directing results and updating state). Within each chip, a crossbar switch routes data between processors; across different chips, a network bridge forwards TransferNodes between DIMMs. Software optimizations enhance efficiency: batching the genome into 10% chunks reduces peak memory by 14 times, pointer deduplication removes redundant MacroNode copies, and large MacroNodes (over 1 KB) are sent to the main CPU rather than overloading the processor buffers.

## Key Novelty
The core idea is placing pipelined processors in DIMM buffer chips (channel-level near-memory processing) and designing them specifically for MacroNode data structures, enabling the Iterative Compaction step to process many pieces in parallel with routing between chips and CPU backup for large outliers.

## Contributions
1. Systematic analysis showing PaKman Iterative Compaction is memory-latency-bound (54.2% stall time, 2.5% bandwidth utilization).
2. Channel-level NMP with 3-stage pipelined systolic PEs, intra-DIMM crossbar, and inter-DIMM network bridge.
3. Software stack: customized batch processing (14x memory reduction), pointer-aliasing deduplication, hybrid CPU-NMP processing.
4. 16x speedup over CPU, 5.7x over GPU (A100), 8.3x throughput over PaKman supercomputer at same resource constraints.

## Metrics
- Speedup: 16x over CPU baseline; 5.7x over NVIDIA A100 GPU; 8.3x throughput vs PaKman supercomputer
- Memory footprint: 14x reduction
- Memory operations: 2.4x reduction
- Bandwidth utilization: 44% (NMP-PaK) vs 6.5% (CPU)

## Baselines
- Software-optimized PaKman on Intel Xeon Platinum 8380 (40 cores, 1 TB DDR4)
- NVIDIA A100 40 GB GPU
- PaKman distributed system on supercomputer (16,384 cores, 1,024 nodes)

## Limitations
NMP-PaK is a single-node system; the supercomputer completes full human genome assembly 123x faster in wall time; the 8.3x advantage reflects resource (per-node) efficiency only.
