# Dyninst on the RISC-V: Binary Instrumentation in Support of Performance, Debugging, and Other Tools

**Venue:** SC 2025  
**Authors:** Cheng-Hsun Angus He, Ronak Chauhan, James A. Kupsch, Hsuan-Heng Wu, Barton P. Miller

## Problem
Dyninst binary instrumentation toolkit lacks support for RISC-V architecture, limiting ability to profile, debug, and trace programs on RISC-V systems, particularly when source code is unavailable.

## Motivation
RISC-V is an emerging open-source ISA gaining adoption in HPC and research environments. Existing Dyninst supports x86, ARM, and Power, but extension to new ISAs requires solving architecture-specific challenges. Tools for performance profiling, debugging, tracing, and architectural simulation are critical infrastructure for HPC systems.

## Method
The team adapted Dyninst (a tool that modifies and analyzes executable programs without needing their source code) to support RISC-V processors. They solved three architecture-specific challenges: correctly parsing RISC-V instructions in binary files, modifying those instructions while the program runs, and updating memory addresses when instrumented code is relocated. By solving these problems, Dyninst now works on RISC-V the same way it does on other processors like x86 and ARM.

## Key Novelty
This shows that Dyninst can be extended to new processor architectures like RISC-V while keeping the same core design.

## Contributions
1. Dyninst RISC-V architecture support
2. Documentation of RISC-V-specific implementation challenges
3. Seamless integration with existing Dyninst tools for performance, debugging, and analysis
