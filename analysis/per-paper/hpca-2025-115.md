# hpca-2025-115: Gemina: A Coordinated and High-Performance Memory Deduplication Engine

**Venue:** HPCA  
**Confidence:** low (abstract-only)

## Problem
Memory deduplication (via KSM) eliminates duplicate pages but forces huge pages to split into 4KB base pages, degrading TLB hit rates and memory access performance by up to 43%; asynchronous huge page promotion cannot recover this loss because deduplication breaks the uniformity of page attributes required for promotion.

## Motivation
Huge pages are critical for TLB efficiency in modern servers, and deduplication is essential for memory overcommit in cloud/VM environments, but their interaction is fundamentally conflicted and degrades both memory savings and access performance simultaneously.

## Method
Gemina coordinates memory deduplication (removing duplicate pages) and huge pages (larger blocks for faster access) by treating them as separate decisions. Its three components are: (1) a fine-grained detector that classifies pages by redundancy and access frequency, enabling independent deduplication choices; (2) a distributor that carefully processes pages to avoid expensive switches between hot/cold patterns or page sizes; and (3) an adapter that rearranges memory to enable fast conversion from 4KB pages to huge pages. By selectively skipping deduplication on frequently-accessed pages, the system preserves huge-page benefits while retaining most memory savings.

## Key Novelty
The core idea is coordinating memory deduplication and huge-page management through a three-component system that preserves huge-page performance while retaining nearly all memory savings.

## Contributions
- Fine-grained detector classifying pages by both redundancy and hotness for coordinated policy decisions
- Conservative distributor preventing frequent page-attribute state transitions
- Memory adapter enabling fast huge page reconstruction after selective deduplication
- 96.1% of KSM memory savings retained while recovering 43.1% of access performance lost in naive KSM
