# A Bring-Your-Own-Model Approach for ML-Driven Storage Placement in Warehouse-Scale Computers

**ID:** mlsys-2025-048 | **Venue:** MLSYS 2025

## Problem
ML-based SSD/HDD tiering cannot be practically deployed at hyperscale because a monolithic storage-layer model must be retrained whenever workloads change, breaks separation of concerns, and is a single point of failure across thousands of heterogeneous workloads.

## Method
Bring-Your-Own-Model (BYOM): each workload trains its own lightweight gradient-boosted trees model at the application layer predicting an importance ranking category for each shuffle job (features: execution metadata, allocated resources, historical I/O metrics). Category labels are designed from oracle ILP placement decisions under varying SSD quotas: category 0 = negative TCO savings, categories 1-N = I/O density quantiles. At the storage layer, an Adaptive Category Selection (ACS) algorithm adjusts the admission threshold based on real-time SSD spillover TCIO feedback, independently of model retraining.

## Key Novelty
Cross-layer separation where application-layer per-workload ML models predict environment-agnostic importance rankings and a storage-layer adaptive algorithm translates those rankings to placement decisions using real-time capacity feedback.

## Results
- **3.47x** TCO savings over SOTA heuristic (2.59x average across 10 production clusters at Google)
- Model inference latency: **4ms/job** (vs 99ms for Transformer baseline)
- Prototype deployed in Google's production data processing framework
- Baselines: FirstFit, CacheSack-style heuristic, lifetime prediction ML

## Hardware Target
Warehouse-scale data centers; Google production clusters with HDD/SSD storage servers
