# A Bring-Your-Own-Model Approach for ML-Driven Storage Placement in Warehouse-Scale Computers

**ID:** mlsys-2025-048 | **Venue:** MLSYS 2025

## Problem
ML-based SSD/HDD tiering cannot be practically deployed at hyperscale because a monolithic storage-layer model must be retrained whenever workloads change, breaks separation of concerns, and is a single point of failure across thousands of heterogeneous workloads.

## Method
Each workload trains its own lightweight gradient-boosted trees model (a machine learning method combining multiple decision trees) at the application layer to rank shuffle jobs by importance. The model learns from application-level information: job execution details, allocated resources, disk read/write patterns, and timestamps, assigning each job an importance category—category 0 for jobs that lose money on fast SSD, categories 1 through N for increasingly disk-intensive workloads. At the storage layer, an Adaptive Category Selection algorithm monitors SSD usage, including overflow events (spillover), and cost metrics (TCIO feedback), dynamically adjusting an admission threshold to decide which categories go to SSD. Because the application model is independent of the storage system, it doesn't need retraining when SSD capacity or costs change—only the threshold needs adjustment.

## Key Novelty
Each workload trains its own gradient-boosted trees model to predict job importance independent of the storage system, while an Adaptive Category Selection algorithm translates those importance levels into SSD or HDD placement using real-time feedback, separating machine learning from storage decisions.

## Results
- **3.47x** TCO savings over SOTA heuristic (2.59x average across 10 production clusters at Google)
- Model inference latency: **4ms/job** (vs 99ms for Transformer baseline)
- Prototype deployed in Google's production data processing framework
- Baselines: FirstFit, CacheSack-style heuristic, lifetime prediction ML

## Hardware Target
Warehouse-scale data centers; Google production clusters with HDD/SSD storage servers
