# asplos-2025-113: MOAT: Securely Mitigating Rowhammer with Per-Row Activation Counters

**Venue:** ASPLOS  
**Confidence:** high (full text)  
**Primary Theme:** provably secure in-DRAM Rowhammer mitigation via dual-threshold per-row counting

## Problem
The JEDEC PRAC+ABO (Per-Row Activation Counting + Alert-Back-Off) framework for DDR5 Rowhammer mitigation is only a specification framework, not a proven secure implementation; the prior Panopticon design that inspired it is shown to be insecure via a new "Jailbreak" attack that causes 9x more activations than the configured threshold of 128. A provably secure, low-overhead DRAM-side Rowhammer mitigation using the PRAC+ABO framework does not yet exist.

## Motivation
Rowhammer thresholds have dropped from 139K to 4.8K activations over the past decade and will continue falling, requiring provably secure in-DRAM mitigations that tolerate sub-100 thresholds with minimal SRAM and performance overhead.

## Method
MOAT (Mitigating Rowhammer with Dual Thresholds) uses per-row activation counters (PRAC) with two internal thresholds: ETH (Eligibility Threshold) for proactive mitigation during REF operations and ATH (ALERT Threshold) for triggering the ALERT-Back-Off reactive protocol. Instead of Panopticon's 8-entry per-bank queue, MOAT tracks only a single entry per bank via a Current Tracked Addr (CTA) register that always holds the row with the highest counter value, plus a Current Mitigated Addr (CMA) register, requiring only 7 bytes of SRAM per bank total. A safe counter-reset-on-refresh mechanism preserves counter integrity across refresh groups by copying boundary-row counters to 2-byte SRAM registers. The Ratchet attack analysis, exploiting inter-ALERT activations permitted by JEDEC ABO specs, establishes that MOAT with ATH=64 safely tolerates a Rowhammer threshold of 99.

## Key Novelty
Replacing Panopticon's multi-entry queue with a single-entry CTA register that tracks the highest-activation-count row, enabling a provably secure dual-threshold (ETH/ATH) design with only 7 bytes SRAM per bank.

## Contributions
- Jailbreak attack demonstrating Panopticon is insecure: inflicts 1152 activations (9x over threshold=128) for both deterministic and randomized variants.
- MOAT design with dual ETH/ATH thresholds and single-entry CTA/CMA tracking achieving provably secure Rowhammer mitigation.
- Ratchet attack analysis quantifying impact of JEDEC-permitted inter-ALERT activations on tolerated TRH; ATH=64 tolerates TRH=99.
- Evaluation on 15 SPEC-2017 and 6 GAP benchmarks: 0.28% average slowdown, 7 bytes SRAM/bank, 2.3% activation increase.

## Limitations
