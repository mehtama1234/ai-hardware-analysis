# SC-2025-248: PGT-I - Scaling Spatiotemporal GNNs

**Memory-Efficient Distributed Training for Large-Scale Temporal Graphs**

## Summary
PGT-I (PyTorch Geometric Temporal Index) enables training of spatiotemporal graph neural networks (ST-GNNs) on realistic large-scale datasets through memory-efficient distributed strategies. The framework demonstrates 89% memory reduction and 11.78x speedup on the complete PeMS traffic dataset with 128 GPUs.

## Problem
Spatiotemporal GNNs are powerful for modeling phenomena with spatial and temporal dependencies (traffic flow, weather, energy grids, pandemic spread). However:
1. **Memory Bottleneck**: Training even moderate-sized ST-GNNs exhausts GPU memory quickly
2. **Snapshot Construction Overhead**: Building temporal snapshots for batches is computationally expensive
3. **Framework Limitations**: PyTorch Geometric Temporal lacks distributed training support
4. **Partitioning Hurdles**: Graph partitioning (traditional scaling approach) is expensive and complex for temporal graphs
5. **Dataset Underutilization**: Realistic datasets (PeMS ~1000s sensors, 10k+ timesteps) too large to fit in memory

## Approach
### Core Insight: Dynamic Snapshot Construction
Instead of pre-constructing all temporal snapshots:
- Construct snapshots **on-the-fly** during batching
- Exploit spatiotemporal locality to reduce memory footprint
- Enable late materialization of graph state

### Index-Batching Strategy
**Single-GPU**:
1. Maintain sparse index of graph topology (not full adjacency)
2. During batch construction, dynamically build only required snapshots
3. Benefit: Only snapshots for current batch loaded in memory
4. Trade-off: Slight compute overhead (snapshot building) vs significant memory savings

### Distributed-Index-Batching Strategy
**Multi-GPU**:
1. Distribute temporal dimension across GPUs (different time periods per GPU)
2. Maintain local sparse indices
3. Synchronize only necessary ghost nodes between ranks
4. Minimize communication while maximizing memory parallelism

## Key Contributions
1. **Novel Batching Strategy**: First framework to apply dynamic snapshot construction to ST-GNN training
2. **Massive Memory Savings**: 89% peak memory reduction (e.g., 40GB → 4.4GB)
3. **Strong Scaling**: 11.78x speedup with 128 GPUs (standard DDP achieves ~10x, indicating improved efficiency)
4. **Realistic Scale**: First ST-GNN successfully trained on **complete PeMS dataset without partitioning**
   - Previous work: subset of PeMS or downsampled graphs
   - This work: Full temporal graph, all sensors
5. **Practical Framework**: Extension to PyTorch Geometric Temporal (widely used)

## Scientific Significance
### Problem Domain: Spatiotemporal Forecasting
ST-GNNs model:
- **Traffic flow** (LSTM on spatial graph)
- **Weather patterns** (precipitation, temperature across regions)
- **Power grids** (energy flow in distribution networks)
- **Pandemic spread** (infections across geographic network)

All require capturing:
1. **Spatial dependency**: How neighbors affect each location
2. **Temporal dependency**: How history affects future
3. **Periodic patterns**: Rush hour traffic, seasonal weather
4. **Non-local effects**: Events propagate across network

### Why Large-Scale Matters
- **PeMS dataset scale**: 1,000+ sensors × 25,000+ timesteps = 25M nodes in temporal graph
- **Realistic scale**: Small models (hundreds of hidden units) already saturate GPU memory
- **Practical value**: Traffic models used for real-time routing decisions (Waze, Google Maps scale needs this)

### Data-Driven Urban Computing
With PeMS-scale datasets, ST-GNNs can:
- Better predict congestion cascades
- Identify bottleneck sensors for traffic control
- Optimize signal timing across networks
- Plan infrastructure investments

## Innovation: Why Not Just Partition?
**Traditional approach**: Partition graph spatially or temporally
- Reduces per-GPU graph size
- Requires inter-GPU communication for boundary nodes
- Complex to implement correctly
- May miss long-range dependencies (temporal partitioning)

**PGT-I approach**: Keep full graph, compress representation
- All nodes available locally (no communication)
- Trade compute for bandwidth
- Simpler implementation (PyTorch Geometric compatible)
- Preserves full graph structure for modeling

## Limitations
- **Single Dataset**: Validation only on PeMS (traffic); generalization to other domains unclear
  - Weather ST-GNNs? Pandemic models? Different scaling characteristics?
- **Baseline Limitations**: Compared only to standard DDP
  - What about graph partitioning methods (Metis, ParMETIS)?
  - Other distributed ST-GNN frameworks?
- **Scalability Limit**: 128 GPUs tested; exascale behavior unknown
- **Heterogeneous Graphs**: Approach assumes homogeneous spatiotemporal structure
- **Static Topology**: PeMS sensor network doesn't change; dynamic graphs unclear
- **Memory Still Substantial**: 4.4GB still large for some edge devices

## Broader Implications
### Systems Challenge in ML
This work exemplifies an important ML systems problem:
- Algorithms designed assuming unlimited memory (full-batch training)
- Hardware reality: memory is expensive and limiting
- Solution: Architecture-aware algorithm design (sampling, partitioning, compression)

PGT-I contributes a new technique (dynamic snapshot construction) to this toolkit.

### Democratizing Large-Scale ML
By reducing memory 89%, models now trainable on:
- Smaller clusters (fewer GPUs)
- Cloud systems (smaller instance types = lower cost)
- Edge devices (potentially; 4.4GB still large)
