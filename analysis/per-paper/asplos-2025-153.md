# asplos-2025-153: CRUSH: A Credit-Based Approach for Functional Unit Sharing in Dynamically Scheduled HLS

**Venue:** ASPLOS  
**Confidence:** low (abstract-only)

## Problem
Dynamic HLS generates dataflow circuits with per-operation unit replication; resource sharing is unsafe due to potential deadlock when handshake-based flow control is combined with shared functional units.

## Motivation
Dynamic HLS circuits handle irregular control flow efficiently but waste area through replication; deadlock-free sharing would reduce area while preserving runtime flexibility.

## Method
CRUSH prevents deadlock by giving each shared functional unit a limited pool of 'credits' (vouchers that allow operations to use it). When an operation needs the unit, it grabs a credit first; when the operation finishes, the credit goes back to the pool. If no credits are available, backpressure signals propagate through the handshake network (the connections between circuit components) to pause upstream operations, preventing the hardware unit from being overloaded and stuck (deadlock). The system is implemented as a compiler transformation that automatically adds this credit tracking when synthesizing the hardware circuit.

## Key Novelty
A credit-based control system that lets hardware units be safely shared among multiple operations without deadlock, regardless of when those operations actually execute.

## Contributions
- Credit-based mechanism for deadlock-free functional unit sharing in dynamic HLS
- Compiler transformation pass integrating CRUSH into dynamic HLS flow
- Area reduction through functional unit sharing with correctness guarantees
- Formal analysis of deadlock prevention under credit protocol
