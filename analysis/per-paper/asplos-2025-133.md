# asplos-2025-133: CoServe: Efficient Collaboration-of-Experts (CoE) Model Inference with Limited Memory

**Venue:** ASPLOS  
**Confidence:** high (full text)

## Problem
CoE inference on memory-constrained edge devices (RTX 3080Ti, 12 GB GPU) requires serving 300+ expert models (60 GB total) that cannot fit in GPU memory. Expert swapping from SSD accounts for over 90% of inference latency; existing MoE-style LRU/FCFS management is inefficient for CoE's deterministic routing.

## Motivation
CoE achieves 99.9% accuracy (vs. 92% for a single model) for circuit board inspection and must run at the edge for privacy, but memory constraints make expert-switching the dominant cost.

## Method
CoServe exploits expert dependency from CoE's pre-assessable routing to drive three mechanisms: (1) dependency-aware request scheduling groups same-expert requests together and assigns to minimize total inference time across parallel CPU+GPU executor queues; (2) two-stage expert eviction first removes dependency-orphaned experts by memory footprint, then evicts by ascending offline-computed usage probability; (3) an offline profiler uses microbenchmarks and a CDF-based sliding decay window to find optimal memory allocation and executor count per device.

## Key Novelty
Exploiting CoE's deterministic routing (pre-assessable expert usage probabilities and dependency graphs) for dependency-aware scheduling and eviction -- impossible in MoE where routing is only known at runtime.

## Metrics
- 4.5x to 12x throughput over Samba-CoE (NUMA and UMA devices)
- Expert switching reduced by up to 93.87% (1060 to 65 switches in Task B2/NUMA)

## Hardware Target
GPU, CPU (heterogeneous NUMA and UMA edge devices)

## Baselines
Samba-CoE (LRU+FCFS), Samba-CoE FIFO, Samba-CoE Parallel

## Limitations
Evaluation uses only ResNet101/YOLOv5 circuit board inspection workloads; generalization to language-model CoE or dynamic routing distributions is not demonstrated.
