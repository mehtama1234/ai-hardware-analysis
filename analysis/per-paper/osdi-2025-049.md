# BlitzScale: Fast and Live Large Model Autoscaling with O(1) Host Caching

**Problem:** Model autoscaling faces a fundamental trade-off between scaling speed and storage/memory usage for parameter caching. The data plane is slow and blocking—scaled instances halt while parameters load—preventing frequent multi-host scaling.

**Method:** BlitzScale sends model parameters through the direct network between GPUs, which is typically underutilized, instead of slower storage paths. It maintains a constant-sized cache on each host that doesn't grow as models get larger, providing efficient memory usage. Rather than scaling entire computing instances at once (which must pause while parameters load), it scales individual model layers, allowing computational work to start on newly added GPUs before parameters fully finish loading. The system uses network broadcast sending (multicast) to efficiently deliver parameters to multiple instances without excessive caching overhead.

**Novelty:** BlitzScale eliminates autoscaling delays by loading parameters through the GPU-to-GPU network with a constant-sized cache, and scaling individual layers so computing instances never block waiting for parameters to arrive.
