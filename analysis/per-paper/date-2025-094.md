# RemapCom: Optimizing Compaction Performance of LSM Trees via Data Block Remapping in SSDs

**Venue**: DATE  
**Primary Theme**: Storage-aware LSM compaction  

## Problem
LSM-tree compaction in DRAM-SSD systems generates significant write amplification because unchanged data blocks are repeatedly read and written back to storage, degrading write performance and shortening SSD lifetime.

## Method
During compaction, the system identifies data blocks whose contents haven't changed. Rather than rewriting these blocks to a new location (which wastes SSD write cycles), it uses remapping—a technique that updates pointers to the data instead of moving the data itself. A lightweight tracking system monitors which individual key-value items within each block have been modified. The approach includes a strategy to keep unchanged blocks intact and prevent them from being split when adjacent blocks do change.

## Key Novelty
Unchanged data blocks are kept in place using remapping during compaction instead of being rewritten, reducing redundant SSD writes.

## Contributions
- Characterization of the UDB phenomenon in LSM compaction
- Lightweight state machine for tracking data block modification status
- UDB retention strategy preventing unnecessary block fragmentation
- Prototype achieving 53% write amplification reduction over state-of-the-art
