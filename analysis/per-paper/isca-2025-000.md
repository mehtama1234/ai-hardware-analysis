# ANVIL: An In-Storage Accelerator for Name-Value Data Stores

**Venue:** ISCA  
**Confidence:** low (abstract only)

## Problem
Large-scale name-value pair (NVP) lookups saturate both external and internal SSD bandwidth because every NVP must be sent to the host CPU to check for a name match. Existing NVP optimizations are limited to a single data store format, leaving the broad heterogeneity of NVP encodings unaddressed.

## Motivation
NVPs underpin millions of applications (databases, analytics, graph processing) and their lookup-intensive access pattern creates a fundamental I/O bottleneck when offloading to SSDs.

## Method
ANVIL puts the name-matching logic directly into the NAND flash chips of a regular SSD. Normally you'd stream all the key-value data to the host computer to check for name matches, but ANVIL filters inside the storage device instead, throwing away the entries that don't match before they cross the SSD-to-host connection. ANVIL supports different data organization methods (arrays, dictionaries, key-value stores, data mining formats) through one unified approach.

## Key Novelty
ANVIL accelerates name-value data stores by filtering inside the storage device's NAND flash chips instead of at the host, supporting multiple data organization formats.

## Contributions
- First end-to-end in-storage accelerator supporting multiple NVP data store formats
- Name-match filtering inside NAND flash chips to reduce SSD bandwidth consumption
- Speedups of 4.0x (database transactions), 25x (analytics), 14.6% (graph processing) over conventional SSD
