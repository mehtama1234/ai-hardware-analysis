# ANVIL: An In-Storage Accelerator for Name-Value Data Stores

**Venue:** ISCA  
**Confidence:** low (abstract only)

## Problem
Large-scale name-value pair (NVP) lookups saturate both external and internal SSD bandwidth because every NVP must be sent to the host CPU to check for a name match. Existing NVP optimizations are limited to a single data store format, leaving the broad heterogeneity of NVP encodings unaddressed.

## Motivation
NVPs underpin millions of applications (databases, analytics, graph processing) and their lookup-intensive access pattern creates a fundamental I/O bottleneck when offloading to SSDs.

## Method
ANVIL implements in-storage processing by pushing name-match logic directly into the NAND flash chips of a conventional SSD. Rather than streaming all key-value data to the host, ANVIL performs name-match filtering inside the storage device, discarding non-matching NVPs before they traverse the SSD-host interface. The system supports multiple NVP formats (arrays, dictionaries, key-value stores, data mining structures) through a unified near-storage computation model.

## Key Novelty
First end-to-end in-storage system accelerating a broad range of NVP formats by filtering non-matching names inside NAND flash chips, eliminating unnecessary host-bound I/O.

## Contributions
- First end-to-end in-storage accelerator supporting multiple NVP data store formats
- Name-match filtering inside NAND flash chips to reduce SSD bandwidth consumption
- Speedups of 4.0x (database transactions), 25x (analytics), 14.6% (graph processing) over conventional SSD

## Hardware Target

## Limitations
Speedups vary significantly across workload types (25x for analytics vs. modest 14.6% for graph processing), suggesting format-dependent efficiency.
