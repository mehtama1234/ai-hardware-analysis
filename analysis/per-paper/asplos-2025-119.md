# SYLQ-SV: Scaling Symbolic Execution of Hardware Designs with Query Caching

**Venue:** ASPLOS  
**Authors:** Kaki Ryan, Cynthia Sturton  
**Confidence:** low (abstract only)

## Problem
Symbolic execution of hardware designs (in SystemVerilog) suffers from path explosion, making full security and functional verification intractably expensive. Existing engines lack comprehensive SystemVerilog language support and do not exploit redundancy across SMT queries generated during path exploration.

## Motivation
Hardware security verification demands high-coverage path analysis, but symbolic execution runtimes remain prohibitive for real SoC-scale designs, limiting adoption in practical pre-silicon verification flows.

## Method
SylQ-SV tests hardware designs written in SystemVerilog by exploring multiple execution paths (called symbolic execution) to find bugs. During this exploration, it encounters mathematical questions that an SMT solver must answer; instead of solving each one from scratch, it remembers answers (caches them) and reuses them when encountering equivalent questions in different paths, saving computation. The tool fully supports SystemVerilog's features including SystemVerilog Assertions (SVA), enabling verification of complete real-world hardware designs.

## Key Novelty
The core idea is that hardware testing through multiple paths generates the same mathematical questions repeatedly, so caching solver answers avoids redundant work while maintaining full verification coverage.

## Contributions
- A dedicated SystemVerilog symbolic execution engine (SylQ-SV) with full SVA support
- SMT query caching mechanism that reuses results across symbolic paths
- Up to 17% runtime reduction over prior state-of-the-art symbolic execution tools
- Evaluation on OR1200, OpenTitan/Ibex, PULPissimo, and CVA6 SoC designs from HACK@DAC
