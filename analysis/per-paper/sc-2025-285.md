# Stackless vs. Stackful Coroutines: A Comparative Study for RDMA-based Asynchronous Many-Task (AMT) Runtimes

**Venue:** SC 2025  
**Authors:** Mia Reitz, Jonas Posner

## Problem & Motivation

Asynchronous Many-Task (AMT) runtimes enable efficient fine-grained parallelism on distributed systems by suspending tasks, capturing their state in continuations, and migrating them across nodes via RDMA. The efficiency of this process directly impacts application performance, but the trade-offs between stackful coroutines (with dedicated stacks) and stackless coroutines (C++20 language-level) remain poorly understood in distributed RDMA environments.

## Approach

Direct comparative implementation study creating two functionally equivalent AMT runtimes:

1. **Stackful Implementation:** Traditional approach with allocated stacks per coroutine.
2. **Stackless Implementation:** Modern C++20 stackless coroutines with compiler-managed state.

**Evaluation:**
- RDMA-based coordinated work-stealing scheduler
- Fine-grained recursive workload
- Metrics: Creation overhead, context switch latency, frame size, communication time impact

## Key Novelty

- **First Direct Comparison:** Systematic evaluation of coroutine types in distributed RDMA environment.
- **Comprehensive Overhead Analysis:** Quantifies all cost dimensions (creation, switching, memory, communication).

## Contributions

- Comparative analysis of stackful vs. stackless coroutines for AMT
- Overhead characterization across creation, switching, and memory
- Communication impact assessment for both approaches
- Practical guidelines for runtime designers

## Hardware Target

- CPU clusters with RDMA capabilities
- High-speed interconnected systems (InfiniBand, RoCE)
- Distributed memory architectures

## Workloads

- Fine-grained recursive asynchronous tasks
- Irregular data-dependent computations
- Work-stealing task scheduling patterns

## Key Results

- **Coroutine Creation:** Stackful 2.4x faster creation
- **Context Switching:** Stackless 3.5x faster context switches
- **Frame Size:** Stackless has significantly smaller frame sizes
- **Communication Time:** Network latency dominates; frame size reduction provides minimal communication benefit
- **Overall Performance:** Nearly identical end-to-end performance for small-state tasks

## Insights

- Both approaches are viable for AMT runtimes
- Creation overhead favors stackful coroutines
- Switching overhead favors stackless coroutines
- Frame size benefits of stackless not strongly reflected in communication time (latency-dominated)
- Choice depends on task state size and workload characteristics

## Limitations & Questions

- Single workload pattern (fine-grained recursive) evaluated
- Coarse-grained, data-parallel, or streaming workloads not assessed
- Scalability beyond experimental cluster size not demonstrated
- Real-world application performance (graph algorithms, sparse solvers) not evaluated
- Task state complexity impact on relative overhead not characterized
- Communication optimization opportunities not explored

## Classification

**Primary Theme:** Continuation Implementation Trade-offs in Distributed Runtimes  
**Technique Category:** Runtime Systems, Asynchronous Programming, Coroutines  
**Confidence:** Low (abstract only)

---

**Key Insight:** This comparative study reveals that both stackful and stackless coroutines are viable for distributed AMT runtimes, with complementary strengths (creation vs. switching overhead), and that network latency—not continuation overhead—dominates overall execution time, suggesting focus areas for future optimization.
