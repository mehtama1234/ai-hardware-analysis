# Plexus: Taming Billion-edge Graphs with 3D Parallel Full-graph GNN Training

**Venue:** SC 2025  
**Authors:** Aditya K. Ranjan, Siddharth Singh, Cunyang Wei, Abhinav Bhatele

## Problem & Motivation

Graph neural networks (GNNs) have emerged as powerful tools for learning on relational data, but training on billion-edge graphs presents a fundamental scalability challenge: the entire graph often exceeds GPU memory capacity. While mini-batch sampling enables some scaling, it compromises model quality. Distributed full-graph training suffers from severe communication overhead and load imbalance due to the irregular nature of real-world graphs.

## Approach

**Plexus** introduces a three-dimensional (3D) parallel training strategy:

1. **3D Parallelism:** Combines spatial (vertex/feature distribution) and temporal dimensions for full-graph training.
2. **Double Permutation Load Balancing:** Novel permutation scheme addressing irregular graph structure to minimize synchronization overhead.
3. **Automatic Configuration:** Performance model predicts optimal 3D parallel configuration for specific graphs and systems.

## Key Novelty

- **3D Parallelism:** Extends beyond traditional 2D spatial parallelism to exploit temporal dimension.
- **Irregular Structure Handling:** Double permutation specifically designed for real-world graph characteristics.
- **Automatic Tuning:** Eliminates manual configuration for optimal performance across different graphs.

## Contributions

- 3D parallel framework for full-graph GNN training at billion-edge scale
- Double permutation load balancing for irregular graphs
- Performance model enabling automatic 3D configuration selection
- Unprecedented scalability and speedups
- Validated on real-world graph datasets

## Hardware Target

- GPU clusters (NERSC Perlmutter, OLCF Frontier)
- Up to 2048 GPUs (Perlmutter)
- Up to 1024 GPUs (Frontier)
- Leadership-class HPC systems

## Workloads

- Full-graph GNN training
- Billion-edge real-world graphs
- Social networks, knowledge graphs, scientific graphs

## Results

- **Speedup:** 2.3-12.5x over prior state-of-the-art
- **Time-to-Solution:** 5.2-8.7x reduction on Perlmutter; 7.0-54.2x on Frontier
- **Scale:** Demonstrated on up to 2048 GPUs
- **Versatility:** Effective across six different graph datasets

## Limitations & Questions

- Specific graph characteristics (sparsity, diameter, clustering) not detailed
- Model quality comparison with sampling-based approaches not provided
- Memory requirements per GPU not specified
- Scalability to dynamic or streaming graph scenarios unclear
- Communication pattern analysis and bandwidth requirements missing
- Applicability to heterogeneous graphs or directed graphs not discussed
