# Rubick: Exploiting Job Reconfigurability for Deep Learning Cluster Scheduling

**Venue:** MLSYS 2025

## One-line Problem
DL cluster schedulers treat jobs as static black boxes, causing mismatches between execution plans and available resources that degrade performance and cluster utilization.

## Method
Rubick co-optimizes execution plan reconfiguration and multi-resource allocation jointly. A **performance model** with 7 fittable parameters captures GPU/CPU/bandwidth/strategy behaviors (DP/TP/PP/ZeRO/GC/GA) fitted from 7 profiling runs and updated online. **Resource sensitivity curves** show throughput vs allocation with best plan per configuration. A **scheduling algorithm** preferentially allocates to jobs with highest sensitivity slopes, shrinking least-sensitive jobs while guaranteeing SLOs via performance-based (not resource-based) guarantees.

## Novelty
First cluster scheduler treating execution plan reconfiguration as a first-class scheduling dimension, co-optimizing job plans and multi-resource allocations continuously for all running jobs.

## Key Metrics
- Average JCT reduction: **up to 3.2x** vs Sia, Synergy
- Makespan reduction: **up to 1.4x**
- Performance model error: avg 7.4%, max 10.4%
- Reconfiguration overhead: 78 seconds per event (1% total GPU hours)
