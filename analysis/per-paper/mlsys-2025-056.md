# Rubick: Exploiting Job Reconfigurability for Deep Learning Cluster Scheduling

**Venue:** MLSYS 2025

## One-line Problem
DL cluster schedulers treat jobs as static black boxes, causing mismatches between execution plans and available resources that degrade performance and cluster utilization.

## Method
Rubick learns how each training job's speed depends on the computational resources it receives and the strategy it uses. It builds a performance model from 7 trial profiling runs that predicts speed based on GPU, CPU, and bandwidth constraints across the compute phases (forward pass, backward pass, parameter updates) and their potential overlap, and updates this model continuously as jobs run. For each job, it calculates a sensitivity curve showing how throughput changes with different resource allocations, then uses these curves to decide which job should give up resources to which: it shrinks the job least sensitive to resource reduction to feed more resources to the job that benefits most, while guaranteeing each job meets its deadline.

## Novelty
First cluster scheduler treating execution plan reconfiguration as a first-class scheduling dimension, co-optimizing job plans and multi-resource allocations continuously for all running jobs.

## Key Metrics
- Average JCT reduction: **up to 3.2x** vs Sia, Synergy
- Makespan reduction: **up to 1.4x**
- Performance model error: avg 7.4%, max 10.4%
- Reconfiguration overhead: 78 seconds per event (1% total GPU hours)
