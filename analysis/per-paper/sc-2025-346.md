# Hardware-Software Co-Design of Iterative Filter-Update Numerical Methods Using Processing-In-Memory

**ID:** sc-2025-346  
**Venue:** SC 2025  
**Authors:** Eric Tang, Tianyun Zhang, William Bradford, Farzana Ahmed Siddique, James C. Hoe, Kevin Skadron, Franz Franchetti

## Problem & Motivation

**Data movement** is the dominant bottleneck in modern computing. Even techniques that reduce computation via pruning still require **reading entire datasets** to identify which elements to process.

Processing-In-Memory (PIM) can address this, but:
- Limited prior work on effective PIM programming models
- Unclear which algorithms benefit most
- Hardware requirements not well characterized

## Solution: Hardware-Software Co-Design for Filter-Update Methods

A co-designed framework targeting **iterative filter-update patterns**:

### Software: Domain-Specific Language (DSL)
- **Filter operation:** In-place, pointwise data pruning (load + filter → sparse dataset)
- **Update operation:** Store sparse updates back (selective stores)
- Simple enough for PIM hardware to support efficiently

### Hardware: PIM Architecture
- **Limited compute capacity** — only simple pointwise operations (arithmetic, comparisons)
- **High internal bandwidth** — between memory and compute units
- No complex instruction set required

### Case Study: Gradient Descent
Ill-conditioned convex optimization using filter-update:
1. **Filter load:** Select non-zero gradient coordinates
2. **Update compute:** Gradient descent step on sparse data
3. **Repeat:** Iterate until convergence

## Results

| Metric | Value |
|--------|-------|
| Data sparsification | 83% |
| Iteration overhead | 1.5x (convergence) |
| Data movement reduction | 3.9x net |

## Key Insight

**Filter-update is a universal pattern** in iterative methods (gradient descent, sparse matrix solvers, sparse deep learning). PIM is perfectly suited for this pattern because:
- Filtering happens **near memory** (low cost)
- Remaining computation is simple
- Data volume shrinks dramatically

## Implications

Demonstrates practical benefits of PIM for scientific and ML workloads; provides blueprint for future PIM hardware and programming models.
