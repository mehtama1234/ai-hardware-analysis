# asplos-2025-093 — Embracing Imbalance: Dynamic Load Shifting among Microservice Containers in Shared Clusters

**Venue:** ASPLOS  
**Confidence:** low (abstract only)  
**Primary Theme:** Imbalance-aware dynamic load shifting for microservice containers

## Problem
Containers within the same microservice deployed in large shared clusters experience temporal and spatial performance imbalance due to resource contention; standard load-balancing policies assume homogeneous container performance and respond with over-provisioning, wasting resources while still frequently violating SLAs.

## Motivation
Microservice deployments in shared clusters are dominated by performance imbalance between nominally identical containers, and uniform load balancing cannot exploit this imbalance, forcing operators to over-provision to meet SLAs at significant cost.

## Method
The system continuously measures response speed (latency and throughput) for each container in a microservice to detect performance imbalances—which occur because containers on the same shared hardware experience resource contention from other processes. Rather than trying to make all containers perform identically (which requires over-provisioning), it exploits these differences by sending more requests to fast containers and fewer to slow ones. This directs computational work to where it executes fastest, allowing the cluster to handle more total work with the same hardware without adding servers. The system integrates with existing load balancers and cluster schedulers to implement this intelligent request routing.

## Key Novelty
Instead of trying to make all containers perform equally, the system uses their performance differences to route requests more effectively.

## Contributions
- Characterization of temporal and spatial performance imbalance among same-microservice containers in production shared clusters
- Dynamic load shifting algorithm that exploits container-level performance heterogeneity for efficient request routing
- Reduction in resource wastage from over-provisioning while maintaining SLA compliance
- Integration with existing cluster schedulers without requiring changes to microservice code
