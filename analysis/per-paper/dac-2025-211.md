# SeIM: In-Memory Acceleration for Approximate Nearest Neighbor Search

**Venue:** DAC  
**Confidence:** low (abstract-only)

## Problem
ANNS bottlenecks on memory bandwidth (random access) and sorting (cross-unit dependencies), limiting throughput in CPU/GPU/ASIC systems critical for RAG-based LLM inference.

## Key Insight
ANNS operations have heterogeneous characteristics (parallel-memory-bound vs. compute-bound sorting); partitioning across memory hierarchy levels (bank/controller) reduces data movement.

## Method
The system places approximate nearest neighbor search operations at different levels of the memory hierarchy based on their data-access patterns. Vector loading and distance computation—which read large amounts of data—run directly at the memory bank level (the hardware storage where data is kept), while sorting runs at the memory controller level (the hardware that manages data access) with selective filtering to block unnecessary data transfers. Since computation happens where data already is, there's no need for costly back-and-forth movement to the CPU or GPU. The architecture requires only minimal modifications to existing DRAM.

## Contributions
- 22–268× throughput vs. CPU/GPU/ASIC
- 4–306× latency reduction
- 2–3081× power efficiency gain
- Adaptive filtering reduces merge overhead
