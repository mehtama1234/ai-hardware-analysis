# Integrating Distributed SQL Query Engines with Object-Based Computational Storage

**Venue:** SC 2025  
**Authors:** Junghyun Ryu, Soon Hwang, Junhyeok Park, Seonghoon Ahn, Jeoungahn Park, Jeongjin Lee, Jinna Yang, Soonyeal Yang

## Problem Statement
Current object storage systems (AWS S3, MinIO) expose only basic in-storage compute (WHERE-clause filtering). Complex SQL operators (aggregation, top-N) must execute at the compute layer, requiring scanning entire datasets and causing massive data movement over the network.

## Technical Approach
**Presto-OCS Connector:**
1. **Query Plan Analysis:** Analyzes Presto execution plans to identify pushdown opportunities
2. **Operator Offloading:** Identifies which operators can efficiently run in storage
3. **In-Storage Execution:** Complex operators (aggregation, top-N, joins) run natively in OCS
4. **Result Aggregation:** Partial results from storage combined at compute layer

**Supported Operations:**
- Complex aggregations (GROUP BY, SUM, COUNT, AVG)
- Top-N queries
- Basic joins
- Filtering and projection

## Evaluation
**Workloads:**
- Real-world HPC analytics queries
- TPC-H benchmark (standard SQL performance benchmark)

**Results:**
- **Speedup:** 4.07× vs. filter-only pushdown
- **Data Movement:** 99% reduction compared to full scans
- **With Compression:** 1.39× additional speedup over compressed filter-only pushdown

## Key Insight
Computational storage targets data movement, a major bottleneck in large-scale analytics. Advanced operator pushdown complements simpler filtering techniques and storage compression, providing multiplicative benefits.

## Hardware Requirements
- Object storage with computational capabilities (not commodity S3)
- Requires specialized storage appliances supporting pushdown APIs

## Limitations & Future Work
- OCS systems rare and expensive; broad adoption not yet practical
- Comparison with other in-storage execution strategies missing
- Scalability to petabyte-scale datasets not demonstrated
- Applicability to other SQL engines (Spark, Trino) not explored
- Cost analysis (compute in storage vs. network bandwidth) not provided
