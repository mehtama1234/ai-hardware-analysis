# HardHarvest: Hardware-Supported Core Harvesting for Microservices

**Venue:** ISCA 2025
**Confidence:** low (abstract-only)

## Problem
Software core harvesting—batch 'Harvest VMs' temporarily stealing idle cores from latency-critical 'Primary VMs'—incurs prohibitive overheads (hypervisor calls, TLB/cache flushes, context switches) that are tolerable for monolithic applications but unacceptable for sub-millisecond microservices.

## Motivation
Cloud servers running microservices suffer chronically low core utilization because VMs are sized for peak load; software harvesting is too slow to exploit the short idle windows between microservice requests.

## Method
HardHarvest moves core harvesting entirely into processor hardware. A hardware scheduler monitors incoming requests, detects idle cores in latency-critical applications (Primary VMs), and assigns them to batch jobs (Harvest VMs) without hypervisor calls—eliminating expensive software overhead. To prevent batch jobs from slowing down the main application, the system partitions memory caches—TLBs (fast caches for memory addresses) and data caches—between workloads using a smart replacement algorithm that keeps the main application's frequently-used data in cache while quickly freeing batch job data when needed. The scheduler continuously reclaims cores before the main application's latency increases.

## Key Novelty
HardHarvest solves the core-harvesting problem for microservices by implementing the entire operation—idle-core detection via request monitoring, cache/TLB partitioning with smart replacement, and preemption—in processor hardware instead of software.

## Contributions
1. First hardware architecture for core harvesting targeting sub-millisecond microservice SLOs
2. In-hardware request scheduling that transfers idle Primary VM cores to Harvest VM tasks without hypervisor intervention
3. TLB and cache partitioning with smart replacement policy to protect Primary VM state
4. 1.5x core utilization, 1.8x Harvest VM throughput, 6.0x Primary VM tail latency reduction vs. software core harvesting
