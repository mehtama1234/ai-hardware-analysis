# Bridging the Gap Between Binary and Source Based Package Management in Spack

**Venue:** SC
**ID:** sc-2025-120
**Confidence:** low

## Problem
Binary package managers limit configurability due to rigid ABI requirements, while source package managers are slow to compile. HPC systems need faster deployment with flexibility.

## Motivation
Spack is widely deployed in HPC but cannot mix binaries built separately, forcing full rebuilds when dependencies change.

## Method
Splicing extension to Spack that models binary compatibility and allows seamless mixing of source and binary distributions while maintaining dependency resolution flexibility.

## Key Novelty
Binary compatibility model for ABI-sensitive packages like MPI in HPC package managers

## Contributions
1. Binary compatibility model for HPC packages
2. Extension to Spack dependency resolution engine
3. Minimal installation-time overhead
