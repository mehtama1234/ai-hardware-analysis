# Bridging the Gap Between Binary and Source Based Package Management in Spack

**Venue:** SC
**ID:** sc-2025-120
**Confidence:** low

## Problem
Binary package managers limit configurability due to rigid ABI requirements, while source package managers are slow to compile. HPC systems need faster deployment with flexibility.

## Motivation
Spack is widely deployed in HPC but cannot mix binaries built separately, forcing full rebuilds when dependencies change.

## Method
Spack is an HPC package manager that normally forces you to choose between pre-compiled packages (fast but inflexible) or source-code compilation (flexible but slow). This extension adds a 'binary compatibility model'—rules that determine which pre-compiled packages can safely work together without conflicts. With this model, Spack can intelligently mix pre-compiled binaries and source-compiled packages in the same system, choosing which to use based on speed and flexibility needs. The system still tracks dependencies automatically, so it always knows what depends on what.

## Key Novelty
It creates a binary compatibility model—rules determining which pre-compiled packages (especially ABI-sensitive ones like MPI) can safely work together—letting HPC package managers mix fast pre-built binaries with flexible source compilations.

## Contributions
1. Binary compatibility model for HPC packages
2. Extension to Spack dependency resolution engine
3. Minimal installation-time overhead
