# asplos-2025-147: D-VSync: Decoupled Rendering and Displaying for Smartphone Graphics

**Venue:** ASPLOS  
**Confidence:** low (abstract-only)

## Problem
VSync-based rendering tightly couples the rendering pipeline to the display refresh cycle, causing frame drops when complex visual effects exceed the VSync interval on high-frame-rate smartphone displays.

## Motivation
Modern smartphones adopt 90-144 Hz displays with increasingly complex animations, overstressing the rigid synchronized rendering-display architecture.

## Method
D-VSync breaks the tight link between rendering and the display refresh cycle (VSync—the regular signal that tells the screen when it needs new images). Instead of forcing all rendering to finish within one VSync interval, the system lets rendering jobs run as long as needed and stores completed frames in a buffer. A predictive scheduling layer then matches each finished frame with the next available display refresh window, eliminating the forced frame drops that occur when rendering takes longer than one VSync period.

## Key Novelty
The core idea is to decouple rendering from the display refresh cycle using predictive frame scheduling, so rendering can finish asynchronously and get matched to the display's refresh windows rather than being dropped when it overshoots.

## Contributions
- D-VSync architecture decoupling rendering scheduler from display VSync cycle
- Asynchronous rendering with buffering layer for frame alignment
- Reduced frame drops and latency on high-frame-rate displays
- Implementation on Android/OpenHarmony rendering stacks
