# Transitive Array: An Efficient GEMM Accelerator with Result Reuse

**Venue:** ISCA 2025  
**Confidence:** low (abstract-only)

## Problem
GEMM in DNNs and LLMs incurs high computational cost, especially under resource constraints. Existing methods reduce precision but do not exploit reuse of intermediate partial results within GEMM.

## Motivation
Edge deployment of LLMs demands minimizing redundant multiplications in GEMM for low-power, high-throughput inference without accuracy degradation.

## Method
The approach reuses partial products (intermediate computation results from multiplying chunks of matrices) that were already calculated in earlier steps, rather than recomputing them. It tracks which results can be reused using directed acyclic graphs—visual dependency maps showing which calculations depend on others—then finds the best order to execute everything while respecting those dependencies and running operations in parallel. The Transitive Array accelerator implements this without dedicated multiplication hardware, instead spreading the work across multiple parallel lanes to maintain balanced throughput.

## Key Novelty
Transitive sparsity reuses intermediate GEMM results (partial computation fragments from matrix operations) by executing them according to a directed acyclic graph that specifies their dependency order, enabling a multiplication-free hardware accelerator for LLM inference.

## Contributions
1. Formalization of transitive sparsity as a GEMM result-reuse paradigm
2. DAG execution order strategy resolving dependency/parallelism constraints
3. Transitive Array: multiplication-free GEMM ASIC with load-balanced parallel lanes
4. ~7.46x / ~3.97x speedup and 2.31x / 1.65x energy reduction vs. Olive / BitVert on LLaMA

## Hardware Target
ASIC

## Key Metrics
- Speedup: 7.46x over Olive, 3.97x over BitVert
- Energy: 2.31x reduction over Olive, 1.65x over BitVert
- Accuracy: comparable to baselines on LLaMA models

## Baselines
Olive, BitVert

## Limitations
DAG construction overhead and scalability to very large weight matrices are not discussed.
