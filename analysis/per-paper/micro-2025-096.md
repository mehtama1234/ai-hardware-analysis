# micro-2025-096: MCBP: A Memory-Compute Efficient LLM Inference Accelerator Leveraging Bit-Slice-enabled Sparsity and Repetitiveness

**Venue:** MICRO 2025  
**Authors:** Huizheng Wang, Zichuan Wang, Zhiheng Yue, Yousheng Long, Taiquan Wei, Jianxun Yang, Yang Wang, Chao Li, Shaojun Wei, Yang Hu, Shouyi Yin  
**Confidence:** high (full text)

## Problem
LLM inference has three simultaneous bottlenecks: GEMM computation in prefill, weight loading during decoding (52.4% of short-prompt latency for LLaMA-7B on A100), and KV cache loading for long contexts. Existing Transformer accelerators address these independently at value granularity, missing bit-level optimization opportunities that are 10x larger.

## Motivation
Quantized weights exhibit bit-slice-level sparsity up to 10x higher than value-level sparsity, and bit-slice column repetitiveness enabling up to 5.1x computation reduction—properties invisible to value-level accelerators—motivate a unified bit-level design.

## Method
MCBP uses three bit-slice-granularity techniques:

**BRCR (BS-Repetitiveness-enabled Computation Reduction):** Decomposes k-bit weight matrix into k bit-slice matrices, groups m rows into a Group matrix, identifies repeated column vectors via CAM, computes a Merged Activation Vector (MAV) in H*(1-bs) additions, and reconstructs output via Enumeration matrix in m*2^(m-1) additions. Reduces computation vs. value-sparsity by up to 12.1x.

**BSTC (BS-Sparsity-enabled Two-State Coding):** Uses sign-magnitude format; high-order BS matrices (bits 3-7) exhibit >65% sparsity and are encoded as {0} for zeros or {1,m-bit data} for non-zeros at the same group granularity as BRCR, avoiding bit-reorder overhead. Low-order bits (1,2,8) are uncompressed.

**BGPP (Bit-grained Progressive Prediction):** Estimates attention scores MSB-to-LSB across rounds; a radius-scaled threshold (theta = max(A_hat) - alpha*radius) filters Keys after each round via early termination, reducing KV cache accesses by up to 50%.

Hardware: CAM-based BRCR unit, parallel BSTC encoder/decoder, clock-gated BGPP module, on-chip SRAM (384KB token, 768KB weight, 96KB temp), external HBM.

## Key Novelty
A unified bit-slice-granularity co-design simultaneously exploiting bit-level repetitiveness (CAM-based group matching), bit-level high-order plane sparsity (two-state coding), and progressive bit-by-bit KV filtering to jointly address all three LLM inference bottlenecks.

## Contributions
1. BRCR: up to 12.1x computation reduction vs. value-sparsity; 3.8x vs. naive bit-serial, using CAM-based grouped column matching
2. BSTC: bit-slice two-state coding exploiting sparsity 10.1x higher than value-level sparsity, eliminating bit-reorder overhead
3. BGPP: up to 50% KV cache access reduction via progressive early termination
4. End-to-end: 9.43x speedup and 31.1x energy efficiency vs. A100 GPU; 35x/5.2x/3.2x energy savings vs. Spatten/FACT/SOFA

## Hardware Target
ASIC (custom MCBP accelerator), GPU (A100 baseline comparison)

## Techniques
quantization, sparsity, memory-system, dataflow, near-data-processing

## Workloads
LLM-inference (LLaMA-7B, LLaMA-13B, OPT-1B3, Bloom-1B7, Qwen-7B), attention, transformer (26 benchmarks)

## Key Metrics
- Speedup: 9.43x vs. A100 GPU
- Energy efficiency: 22740 GOPS/W average; 31.1x vs. A100; 35x vs. Spatten; 5.2x vs. FACT; 3.2x vs. SOFA
- BRCR computation reduction: 5.1x group-wise vs. full-size merge (across 5 LLMs)
- BGPP KV cache reduction: up to 50%
- Bit sparsity: avg 10.1x higher than value sparsity in high-order bit planes

## Baselines
NVIDIA A100 GPU (TensorRT-LLM), Spatten, FACT, SOFA, Sanger, SpAtten, A3, ELSA, DTATrans

## Limitations
MCBP requires offline BSTC weight pre-compression; BGPP multi-round prediction latency must be overlapped with BRCR; optimal group size m requires per-model design-space exploration.
