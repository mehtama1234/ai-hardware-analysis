# Hardware/Software Runtime for GPSA Protection in RISC-V Embedded Cores

**Venue**: DATE  
**Primary Theme**: Runtime fault attack protection for RISC-V  

## Problem
Existing hardware countermeasures against fault attacks require compiler modifications and cannot protect indirect jumps; protecting unmodified binaries is not supported.

## Method
The system combines hardware and software to monitor an unmodified RISC-V program as it runs, continuously generating Generalized Path Signature Analysis (GPSA) signatures—fingerprints based on the execution path (the actual sequence of instructions being executed). These signatures check that the program's control flow (which instruction is executed next) remains correct and that the code itself hasn't been corrupted. If a fault attack tries to alter the program's path or code, the signature check catches it.

## Key Novelty
This is the first method to protect already-compiled RISC-V programs from fault attacks without compiler or binary modifications, including indirect jumps (jumps where the destination is calculated while the program runs).

## Contributions
- First fault attack protection for unmodified RISC-V binaries
- Support for indirect jumps unlike prior methods
- 3.35× average slowdown over unprotected implementation
- 1.86× area overhead for protection logic
