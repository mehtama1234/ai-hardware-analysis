# Integrating Prefetcher Selection with Dynamic Request Allocation Improves Prefetching Efficiency

**Venue:** HPCA  
**Confidence:** low (abstract-only)

## Problem
Hybrid hardware prefetchers sharing the same MSHRs and bandwidth resources create conflicts where competing prefetch requests from different algorithms negate each other's coverage, and existing prefetcher selection algorithms use inaccurate demand request allocation and coarse-grained selection criteria.

## Motivation
Commercial processors deploy multiple concurrent prefetching algorithms to cover diverse access patterns, but resource conflicts and poor coordination between prefetchers degrade overall effectiveness, especially for memory-intensive workloads.

## Method
Alecto intercepts each demand request before routing it to prefetchers. For each demand request, it evaluates fine-grained per-request suitability metrics (accuracy, coverage, timeliness) across prefetchers and routes the request only to the best-suited prefetcher(s). This prevents table pollution in temporal prefetchers and reduces resource contention while improving prefetcher table utilization.

## Key Novelty
Per-demand-request prefetcher selection that routes each request only to the most suitable prefetcher, simultaneously improving accuracy, coverage, and timeliness while drastically reducing prefetcher table energy by avoiding unnecessary training.

## Contributions
1. Identification that inaccurate demand request allocation and coarse-grained selection are the two key limitations of prior prefetcher selection approaches
2. Alecto algorithm performing fine-grained, per-demand-request prefetcher selection and allocation
3. 2.76% single-core and 7.56% eight-core IPC improvement over state-of-the-art RL-based Bandit selection
4. 48% reduction in prefetcher table access energy with less than 1 KB storage overhead
