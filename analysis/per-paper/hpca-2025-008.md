# DPUaudit: DPU-assisted Pull-based Architecture for Near-Zero Cost System Auditing
**Venue:** HPCA 2025 | **ID:** hpca-2025-008 | **Confidence:** low (abstract only)

## Problem
Existing hardware-based system auditing frameworks use push-based architectures that require a log sender on the monitored host, necessitating heavy software protection mechanisms that impose >10% runtime overhead, defeating the efficiency goal.

## Motivation
Data center security requires low-overhead system auditing for intrusion detection; push-based designs impose unacceptable performance costs on the monitored host.

## Method
DPUaudit switches from having the monitored computer push logs to having a DPU (Data Processing Unit, a specialized chip on the network card) pull system events directly from the computer's memory. Because the monitored computer no longer needs a log sender running on it, it doesn't need heavy software protections guarding that sender—eliminating the main source of slowdown. The DPU handles all log collection, processing, and verification itself, isolated on the network card away from the monitored system.

## Key Novelty
The key idea is reversing the audit data flow—from the monitored computer pushing logs to a DPU pulling them directly, which eliminates the log sender and its protection overhead, achieving 2.1% overhead compared to order-of-magnitude higher overhead in previous approaches.

## Contributions
1. Root-cause analysis: push-based log sender is the overhead bottleneck in hardware auditing
2. DPU-assisted pull-based architecture removing log sender from monitored host
3. Average 2.1% runtime overhead for 6 mainstream data center applications (vs >10x higher in prior work)
4. Maintained audit log integrity guarantees

## Metrics
- **Overhead:** Average 2.1% runtime slowdown (at least 10x less than existing approaches)
