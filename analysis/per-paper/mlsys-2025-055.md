# COMET: Fine-grained Computation-communication Overlapping for Mixture-of-Experts

**Venue:** MLSYS 2025

## One-line Problem
All-to-all communication in distributed MoE layers occupies up to 47% of execution time; existing coarse-grained overlapping methods cause compute inefficiency and sub-optimal latency hiding.

## Method
COMET combines two techniques. First, it analyzes shared memory buffers, breaks tensors (multi-dimensional arrays) into pieces along independent dimensions like the M-axis for matrix operations or N-axis for ranking, and reschedules computation to start as soon as local data is available. Second, it isolates communication and computation into separate groups of GPU cores (thread blocks) within a single merged kernel, then dynamically adjusts how many cores go to each task based on input size and parallelism strategy.

## Novelty
Fine-grained fused kernels resolving granularity mismatch between token-level communication and tile-level GEMM by shared-tensor decomposition and rescheduling, with adaptive SM allocation via NVSHMEM for GPU-initiated communication. Deployed in production on 10,000+ GPU clusters.

## Key Metrics
- Single MoE layer speedup: **1.96x** vs SOTA
- End-to-end speedup: **1.71x** on average (Mixtral, Qwen2, Phi3.5)
- Communication hidden: **86.5%** vs 68.6% (Tutel) and 29.2% (FasterMoE)
- End-to-end latency reduction: 34.1-44.4% vs baselines
