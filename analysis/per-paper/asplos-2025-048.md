# TNIC: A Trusted NIC Architecture

**Venue:** ASPLOS 2025  
**ID:** asplos-2025-048  
**Confidence:** low (abstract only)

## Problem
Distributed systems in untrusted cloud environments face Byzantine failures, but existing CPU-centric TEE approaches incur high overhead when enforcing network-level trust guarantees such as non-equivocation and transferable authentication.

## Motivation
Cloud multi-tenant workloads run on untrusted infrastructure; Byzantine fault-tolerant protocols are impractical at scale due to software-only TEE overhead.

## Method
TNIC places a tamper-proof security layer (a formally verified silicon root-of-trust) on the network card (SmartNIC hardware) instead of in the CPU. It uses hardware-accelerated cryptographic primitives running in network processing logic: transferable authentication (signed messages proving who sent them) and non-equivocation (monotonic counters preventing a sender from denying they sent something). Because security stays at the network card level, it works with any CPU. It provides APIs and patterns for Byzantine-fault-tolerant systems (where some components can fail or lie but the system still works), demonstrated by four working distributed systems.

## Key Novelty
Instead of relying on the CPU's security features (called a TEE), TNIC builds a tamper-proof security layer (formally verified silicon root-of-trust) directly on the network card (SmartNIC hardware) to provide network-level trust guarantees (transferable authentication and non-equivocation) that work with any CPU.

## Contributions
- TNIC: trusted NIC with formally verified root-of-trust providing transferable authentication and non-equivocation.
- CPU-agnostic unified security architecture with network-level isolation.
- APIs and protocol recipe for Byzantine fault-tolerant distributed systems.
- Up to 6x performance improvement over CPU-centric TEE systems.
