# hpca-2025-119: Criticality-Aware Instruction-Centric Bandwidth Partitioning for Data Center Applications

**Venue:** HPCA  
**Confidence:** low (abstract-only)

## Problem
Co-locating latency-critical (LC) and best-effort (BE) tasks on shared datacenter nodes causes memory bandwidth contention that results in priority inversion, where BE tasks monopolize bandwidth and cause LC tasks to violate quality-of-service (QoS) requirements.

## Motivation
Improving datacenter utilization through workload co-location is economically essential, but existing bandwidth partitioning schemes either fail to enforce LC QoS or waste bandwidth by over-protecting all LC memory accesses indiscriminately.

## Method
Pivot partitions memory bandwidth by prioritizing latency-critical tasks, but specifically targets only the load instructions that stall the CPU's execution pipeline—rather than all latency-critical accesses. It identifies these critical instructions through two-phase offline profiling: Phase 1 determines which memory loads miss the cache, and Phase 2 marks which of those cache misses actually halt the processor's instruction reordering. These marked loads receive priority at every stage of memory access—L1 and L2 caches (fast on-chip memory), L3 cache (larger on-chip memory), and the DRAM controller (main memory interface)—instead of only at a single bottleneck.

## Key Novelty
It specifically identifies load instructions that cause CPU pipeline stalls and prioritizes those throughout the entire memory path—L1, L2, L3 caches and DRAM controller—rather than equally protecting all latency-critical accesses at one point.

## Contributions
- Two-phase profile-guided technique to identify performance-critical loads (ROB-stalling) with minimal overhead
- Full memory path prioritization of critical LC loads across all cache levels and DRAM controller
- Up to 34.5% improvement in effective machine utilization vs. state-of-the-art approaches
- Up to 2.76x higher BE throughput while maintaining LC QoS guarantees
