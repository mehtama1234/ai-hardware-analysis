# Misam: Machine Learning Assisted Dataflow Selection in Accelerators for Sparse Matrix Multiplication

**Venue:** MICRO  
**Confidence:** low (abstract-only analysis)

## Problem
SpGEMM accelerators that support multiple dataflows (e.g., row-wise, column-wise, inner-product) face two critical problems: (1) no fast principled mechanism exists for selecting the optimal dataflow at runtime given input matrix sparsity patterns, and (2) providing hardware flexibility for multiple dataflows incurs area overhead and underutilization when one dataflow is locked in.

## Motivation
Real-world SpGEMM workloads exhibit highly diverse and dynamic sparsity patterns, so any single fixed dataflow leaves significant performance on the table, yet the cost of hardware reconfiguration must be carefully managed to yield net benefit.

## Method
Misam uses a lightweight machine learning classifier to predict the optimal dataflow—the computation strategy—for sparse matrices by analyzing sparsity characteristics like density and distribution patterns. Rather than building a single fixed accelerator, it runs on FPGAs, which are programmable chips that can be reconfigured, and selectively loads specialized hardware designs optimized for each sparsity regime. Before reconfiguring, the system checks whether the predicted performance gain justifies the overhead of loading the new design.

## Key Novelty
Misam's core idea is dynamic hardware specialization: machine learning predicts the best computation strategy for each sparse matrix, and FPGA partial reconfiguration loads specialized hardware for that strategy instead of simultaneously supporting all approaches.

## Contributions
- Lightweight decision tree that predicts optimal SpGEMM hardware configuration from matrix features without significant runtime overhead
- FPGA partial reconfiguration framework that swaps specialized SpGEMM bitstreams on demand, eliminating area overhead of multi-dataflow hardware
- Reconfiguration engine that performs cost-benefit analysis before initiating bitstream switching to avoid net-negative reconfiguration overhead
- Up to 10.76x speedup over fixed-dataflow baselines across diverse sparsity patterns
