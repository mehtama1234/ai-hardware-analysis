# asplos-2025-052 — Robustness Verification for Checking Crash Consistency of Non-volatile Memory

**Venue:** ASPLOS  
**Confidence:** low (abstract-only)

## Problem
Programs using non-volatile memory (NVM) must explicitly flush pending stores to guarantee persistence; developers routinely miss or mis-order these flushes. Existing crash-consistency checkers are testing-based and require user guidance, leaving the correctness of NVM programs unverified in the general case.

## Motivation
As NVM technologies (e.g., Intel Optane) are deployed in production systems, undetected crash-consistency bugs can silently corrupt persistent data structures, making a fully-automated, sound verification method urgently needed.

## Method
The paper introduces a robustness property for NVM crash consistency and proves that checking whether a post-crash NVM state is reachable from a given pre-crash execution reduces to validity of that execution under additional ordering constraints. A search-based algorithm enumerates all partial pre-crash executions and candidate NVM states, then dispatches each reachability query to an SMT solver via symbolic encoding of the program. The approach is integrated into the DPLL(T) framework to prune the search space, and is implemented in the prototype tool PMVerify.

## Key Novelty
Reduction of crash-consistency checking to SMT-based reachability under the NVM memory consistency model, enabling the first fully automated robustness verification without user-provided test inputs.

## Contributions
- Formal definition of robustness as a crash-consistency property for NVM programs.
- Algorithmic reduction of post-crash state reachability to memory-model-constrained execution validity, enabling SMT encoding.
- PMVerify prototype integrating the algorithm into DPLL(T) for efficient exploration.
- Experimental validation on PMDK benchmarks showing competitive bug detection vs. PSan.
