# LLMulator: Generalizable Cost Modeling for Dataflow Accelerators with Input-Adaptive Control Flow

**Venue:** MICRO 2025  
**Confidence:** High (analyzed from full text)

## Problem
Existing performance prediction methods for dataflow-based accelerators (TPUs, NPUs, FPGAs) fail to generalize across three dimensions: unseen applications with extreme loop scales (errors exceeding 40%), input-dependent control flows where branch probabilities shift at runtime (errors up to 60%), and diverse hardware architectures with varying memory delays and loop mapping primitives. No prior method unifies all three generalization axes.

## Motivation
Accurate, fast cost modeling is the critical bottleneck in design-space exploration for dataflow accelerators, and the growing complexity of hardware-software stacks (HLS, spatial mappings, dynamic operators) makes hand-crafted analytical models and static GNN approaches obsolete.

## Method
LLMulator fine-tunes a pre-trained language model (LLaMA-3.2-1B using LoRA, a parameter-efficient training method) to predict hardware performance through three techniques. First, instead of predicting performance as a single number, it predicts digit-by-digit, treating each digit as a discrete category rather than a continuous value—this works across any performance range and enables error correction via beam search (testing multiple digit sequences and keeping the best). Second, it continuously updates from live hardware simulations (Verilator), learning to adapt when loop sizes or branching patterns change during execution. Third, it builds training data by analyzing code structure (AST parsing), systematically varying loops, augmenting with an LLM, and using compiler tools (SiliconCompiler, OpenROAD) to show how code becomes hardware.

## Key Novelty
By treating performance numbers as digit-wise category predictions instead of single continuous values, LLMulator can generalize to any performance scale and combine this with online learning from hardware feedback to adapt to varying loop bounds and control flow.

## Contributions
- Progressive numeric modeling: digit-by-digit categorical output with beam search, reducing edge-value errors by 2.3%–13.6% over regression baselines.
- DPO-based Dynamic Prediction Calibration converges to 11.2% cycle error, a 9.7% improvement over static models.
- Progressive data augmentation covering AST generation, loop mutation, LLM self-augmentation, and hardware mapping parameters.
- 12.2% MAPE on ASIC design scenarios, 16.7%–7.8% error reduction vs GNNHLS and TLP.

## Limitations
Calibration via DPO requires repeated Verilator simulation runs per input, adding profiling overhead that may be prohibitive for very large dataflow programs; the method targets HLS-level modeling and does not address post-place-and-route variability.
