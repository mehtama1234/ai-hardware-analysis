# isca-2025-112 — GPUs All Grown-Up: Fully Device-Driven SpMV Using GPU Work Graphs

**Venue:** ISCA  
**Confidence:** low (abstract-only)

## Problem
Sparse matrix-vector multiplication (SpMV) on GPUs requires expensive host-side preprocessing to select per-row algorithms based on non-zero distribution, forcing costly CPU-GPU round-trips and limiting cache locality. This preprocessing adds latency that is particularly problematic for iterative solvers with repeated SpMV calls.

## Motivation
SpMV is a fundamental kernel in HPC and graph analytics, and its irregular sparsity patterns make static per-row algorithm selection at compile time impossible, yet existing GPU approaches pay high overhead for dynamic selection through host involvement.

## Method
The paper leverages GPU Work Graphs, a novel GPU programming model originally designed for graphics, to implement fully device-driven SpMV self-scheduling. Work Graphs enable fine-grained dataflow execution of individual workgroups using emerging GPU hardware and firmware support (AMD GPUs with rocSPARSE stack). Preprocessing is fused with per-row computation: as soon as preprocessing generates sufficient work metadata, workgroups of specialized per-row SpMV kernels are self-scheduled and dispatched on-device without host interaction. This interleaving improves L1/L2 cache locality and eliminates CPU-GPU synchronization entirely. The approach uses a fixed 25 MiB device-side supporting data structure independent of matrix size, contrasting with scaling structures in rocSPARSE LRB.

## Key Novelty
Applying GPU Work Graphs—a hardware/firmware-level on-device self-scheduling mechanism—to SpMV to fuse preprocessing and per-row computation on the GPU, eliminating host interaction and improving cache locality.

## Contributions
- First application of GPU Work Graphs to sparse linear algebra (SpMV), enabling fully device-driven preprocessing and execution.
- Novel Work Graphs SpMV kernels that self-schedule per-row algorithms based on dynamically determined non-zero structure.
- Up to 7.19x speedup (mean 3.35x) over rocSPARSE LRB for single SpMV across 59 sparse matrices.
- 75% reduction in code complexity and a fixed 25 MiB memory footprint independent of matrix size.

## Metrics
- **Speedup:** up to 7.19x (mean 3.35x, SD 1.89) over rocSPARSE LRB for single SpMV; beats rocSPARSE CSR-Adaptive for up to 92 consecutive SpMV calls
- **Other:** 75% reduction in code complexity; fixed 25 MiB data structure vs. matrix-size-scaling rocSPARSE LRB structures

## Limitations
