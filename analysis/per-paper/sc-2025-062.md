# Evaluating HPK for Running Cloud-Native Workloads on Slurm Clusters

**ID:** sc-2025-062 | **Venue:** SC

## Problem Statement
Integrating cloud-native and HPC workloads requires separate resources; leads to inefficient resource partitioning

## Motivation
Applications increasingly combine cloud-native and HPC processing steps; current separate platforms waste resources and complicate job management

## Method
HPK is a compatibility framework that allows cloud-native workloads (applications built to run in containers with orchestration, like Kubernetes) to execute on Slurm (a job scheduler for HPC clusters) without any code changes. Instead of needing separate physical clusters for the two workload types, HPK translates cloud-native requests into Slurm jobs, so both run on the same shared cluster infrastructure.

## Key Novelty
Instead of partitioning expensive computing resources into separate cloud and HPC clusters, you can run both workload types together on a single Slurm cluster.

## Contributions
- HPK framework for cloud-native workload support on HPC clusters
- Preservation of existing HPC job management and accounting
- No workload modification required
