# asplos-2025-148: Micro Blossom: Accelerated Minimum-Weight Perfect Matching Decoding for Quantum Error Correction

**Venue:** ASPLOS  
**Confidence:** high (full text)

## Problem
Exact MWPM decoders for QEC surface codes require sub-microsecond latency for superconducting qubit feedforward, but all prior exact CPU-based implementations achieve multi-microsecond latency. Approximate decoders sacrifice 1.7x-13.9x more logical errors at d=13.

## Motivation
Fault-tolerant T-gates require decoder feedforward within ~1 microsecond; each additional microsecond of latency multiplies effective logical error rate by (1+L/d), making decoding latency the critical path for practical fault-tolerant quantum computing.

## Method
The system pairs a CPU with an FPGA (a programmable logic chip) to run the blossom algorithm. The FPGA assigns a separate processor to each data point and connection in the problem graph, enabling massive parallelism. Processors maintain only local state and talk only to neighboring processors; conflicts are resolved entirely in hardware without CPU involvement, reducing CPU interactions from O(p*|V|+1) to O(p^2*|V|+1). The system processes measurement data incrementally as it arrives, achieving constant decoding speed regardless of data volume.

## Key Novelty
The first exact quantum error correction decoder to achieve sub-microsecond latency using the blossom algorithm on programmable hardware (an FPGA), where dedicated processors for each data point and edge resolve conflicts entirely in hardware.

## Contributions
- Sub-microsecond exact MWPM decoding: 0.8 us average at d=13, p=0.1% on Xilinx Versal VMK180 at 62 MHz
- Vertex- and edge-level parallelization of the blossom dual phase using local-only connectivity
- Hardware-resident isolated-conflict resolution eliminating O(p|V|) CPU interactions; average complexity O(p^2*d^2+1)
- Round-wise fusion for stream decoding; 8x lower latency than Sparse Blossom (best prior MWPM)

## Hardware Target

## Metrics
- Speedup: 8x lower average latency vs. Sparse Blossom (Apple M1 Max) at d=13, p=0.1%
- Latency: 0.8 us average; 17x improvement over Parity Blossom CPU baseline
- Worst-case complexity: O(d^9) vs. O(d^12) prior best

## Baselines
Parity Blossom (Apple M1 Max CPU), Sparse Blossom (Apple M1 Max CPU), Helios (approximate), Union-Find decoder

## Limitations
Prototype runs at moderate 62 MHz on FPGA; ASIC would enable higher frequencies and larger d for sub-microsecond latency, but no ASIC measurements are presented.
