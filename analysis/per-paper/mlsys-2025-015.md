# FlexAttention: A Programming Model for Generating Optimized Attention Kernels

**Venue:** MLSys 2025 | **ID:** mlsys-2025-015 | **Confidence:** high

## Problem
Every attention variant requires a bespoke hand-written CUDA/Triton kernel, creating an O(variants x hardware) maintenance burden and blocking rapid research iteration.

## Method
Instead of hand-writing separate kernels for each attention variant, users write two simple Python functions: one that modifies attention scores (like adding ALiBi bias) and one that specifies which token pairs should attend to each other. A BlockMask structure precomputes which blocks of computation can be skipped (called sparsity), enabling a sparse version of FlashAttention. PyTorch's compiler then converts these functions into a single optimized Triton kernel by combining them into one tiled operation—matrix multiply, softmax, matrix multiply—that skips any fully-masked blocks.

## Novelty
BlockMask + score_mod/mask_mod composable API that reduces any attention variant to a Triton template instantiation with near-FlashAttention-2 performance.

## Metrics
- 0.68-1.43x vs FlashAttention-2 for standard variants
- 5.49-8x vs PyTorch SDPA for unsupported variants
- 2.04x gpt-fast inference speedup; 2.4x torchtune training speedup
- <1% paged attention overhead vs 20-26% in vLLM
