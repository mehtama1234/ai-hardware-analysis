# XaaS Containers: Performance-Portable Representation With Source and IR Containers

**Venue:** SC 2025  
**Authors:** Copik, Alnuaimi, Kamatar, Hayot-Sasson, Madonna, Gamblin, Chard, Foster

## Problem
Containerization has become the default deployment method in both HPC and cloud, but containers force a fundamental trade-off: portability vs. hardware-specific performance. Early-stage compilation decisions are locked in at container build time, preventing adaptation to target system architectures.

## Approach
**XaaS (Acceleration as a Service)** proposes performance-portable containers by delaying optimization until deployment. The system stores applications in two forms:
1. **Source containers** – retain source code and build context
2. **IR containers** – preserve intermediate representations

At deployment on a target HPC system, the framework:
- Analyzes compilation pipeline specialization opportunities
- Uses **LLM-assisted method** to automatically discover specializations
- Rebuilds application binaries optimized for target architecture
- Maintains container abstraction layer

## Key Insight
Performance portability is achievable by deferring "early-stage compilation decisions" from container creation time to deployment time, enabling system-specialized binaries within containerized frameworks.

## Novelty
- Decoupling portability from performance via source/IR dualism
- LLM-based automatic specialization discovery (novel application of LLMs to compilation analysis)
- Deployment-time recompilation as a core containerization feature

## Hardware Targets
- HPC systems (multi-vendor architectures)
- GPU accelerators (vendor-specific optimization)
- Exascale-class clusters

## Metrics & Evaluation
- **Peak performance across diverse HPC systems** (primary metric)
- Specialization overhead (not quantified in abstract)
- No benchmark results provided

## Limitations
- No empirical performance numbers in abstract
- Scope of "specializations" and applicability across HPC software undefined
- Assumes practical feasibility of source/IR storage and deployment-time recompilation
