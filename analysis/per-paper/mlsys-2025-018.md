# SOLA: Optimizing SLO Attainment for Large Language Model Serving with State-Aware Scheduling

**Venue:** MLSys 2025 | **ID:** mlsys-2025-018 | **Confidence:** high

## Problem
LLM serving systems use fixed scheduling policies that cause latency distribution bias between TTFT and TPOT and high inter-request variance, resulting in poor SLO attainment (as low as 45.5%).

## Method
SOLA treats LLM request scheduling as a constrained optimization problem solved at each serving step, dynamically deciding which requests to serve, how many to bundle, and how many tokens to generate. Unlike systems with fixed priorities, SOLA continuously monitors actual performance—how long until the first response token arrives (TTFT) and how long between subsequent tokens (TPOT)—and picks the right strategy for each step: either minimize the longest gap between tokens while keeping first-token latency acceptable, or minimize the longest first-token latency while keeping between-token time acceptable. It executes this strategy through hierarchical prioritization (first among processing phases—prefill for input processing, decode for token generation—then among requests) using polynomial latency models that refine from real measurements, implemented in vLLM v0.4.2.

## Novelty
First serving system formalizing LLM scheduling as per-iteration constrained optimization with real-time SLO state awareness and dynamic strategy switching.

## Metrics
- SLO attainment improved from 45.5% to 99.4% (Llama3-70B, ShareGPT)
- 1.04-1.27x more requests served at 90% SLO attainment
- 0.40-0.45% scheduling overhead
