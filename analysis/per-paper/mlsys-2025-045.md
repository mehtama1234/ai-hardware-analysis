# Scaling Deep Learning Training with MPMD Pipeline Parallelism

**ID:** mlsys-2025-045 | **Venue:** MLSYS 2025

## Problem
GSPMD/SPMD-based pipeline parallelism in JAX can only encode GPipe-style schedules; it cannot express more efficient 1F1B or Interleaved 1F1B schedules, leaving ~20% throughput and significant activation memory savings unrealized.

## Method
JaxPP lets you mark where one processing stage ends and another begins with simple annotations; it automatically infers the data flow between stages from your model code. Unlike systems that force a single execution pattern, JaxPP supports flexible gradient accumulation schedules—like 1F1B (one forward pass, one backward pass) and Interleaved 1F1B—that use memory more efficiently and improve throughput. A central controller orchestrates execution by converting your model to a task graph, distributing tasks to processing units (SPMD actors, each managing one or more devices), determining data movement through topological ordering to avoid deadlocks, freeing memory buffers once they're no longer needed, and bundling all data transfers into single efficient messages.

## Key Novelty
JaxPP is the first system that lets JAX users define any pipeline schedule they want—like 1F1B or Interleaved 1F1B—using simple code annotations, without requiring model rewrites.

## Results
- **51.2%** faster than SPMD PP (GPipe) on GPT-3 175B (128 H100 GPUs)
- **1.16x** improvement over JAX FSDP
- **95.6%** of NeMo's hand-optimized throughput
- **98.33%** weak scaling efficiency from 64 to 1024 H100 GPUs
- Baselines: JAX SPMD PP, JAX FSDP, NeMo

## Hardware Target
NVIDIA H100 GPUs (DGX nodes), InfiniBand NDR400; multi-node clusters
