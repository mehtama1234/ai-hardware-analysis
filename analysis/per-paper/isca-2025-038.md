# isca-2025-038 — NUPEA: Optimizing Critical Loads on Spatial Dataflow Architectures via Non-Uniform Processing-Element Access

**Venue:** ISCA  
**Confidence:** low (abstract-only)

## Problem
On large spatial dataflow architectures (SDAs) where program instructions are distributed across a fabric of processing elements (PEs), some PEs are physically closer to memory than others, creating non-uniform data access latencies. Existing NUMA-style approaches place data near fixed compute units, which is complex and often ineffective when critical data is hard to identify statically.

## Motivation
Data movement is the dominant energy, performance, and scalability bottleneck in modern architectures, and SDAs provide a new opportunity to reduce it by placing critical load instructions near memory, which is easier for compilers to identify than the data those loads access.

## Method
On spatial dataflow architectures (systems where program instructions run on separate processing units, or PEs, distributed across a chip), different PEs sit at different distances from memory. The compiler identifies which load instructions (instructions that read data from memory) are critical using dependence analysis (tracing which instructions depend on others), then maps those loads to the PEs physically nearest to memory, reducing the distance data must travel. This is implemented on the Monaco SDA architecture (from Efficient Computer) with the effcc compiler, which exposes PE-to-memory distances to guide the compiler's placement decisions. This inverts NUMA systems: instead of moving data closer to fixed processors, NUPEA moves the data-reading instructions closer to memory.

## Key Novelty
NUPEA places load instructions near memory instead of moving data near processors—a simpler approach for compilers to analyze and optimize on spatial dataflow architectures.

## Contributions
1. Formalization of the NUPEA concept and contrast with NUMA-style data-centric approaches on SDAs
2. Architecture and compiler optimizations for NUPEA on the Monaco SDA and effcc compiler
3. 28% average speedup over a uniform-PE-access SDA across important kernels
4. 20% average speedup over a UPEA SDA augmented with NUMA

## Metrics
- **Speedup:** 28% avg over UPEA SDA; 20% avg over UPEA+NUMA SDA

## Baselines
- Uniform-PE-access (UPEA) SDA
- UPEA SDA with NUMA

## Hardware Target
ASIC (Monaco SDA)
