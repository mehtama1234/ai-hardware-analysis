# asplos-2025-175: Squeezing Operator Performance Potential for the Ascend Architecture

**Venue:** ASPLOS  
**Confidence:** low (abstract-only)

## Problem
Huawei's Ascend DSA requires manual memory operation management, creating complex performance bottlenecks difficult to diagnose. Existing roofline models suffer from visualization complexity and inaccurate performance assessment when applied to Ascend's component-level architecture.

## Motivation
As Ascend and similar DSAs become critical AI infrastructure, the lack of effective profiling and optimization methodology prevents operators from reaching their theoretical peak performance.

## Method
A component-based roofline model abstracts individual hardware components (compute units, memory subsystems, data pipelines) to capture per-component performance ceilings and identify bottleneck components. Combined with a structured optimization process from practical Ascend case studies, it identifies common issues (memory bandwidth saturation, pipeline bubbles) and their targeted optimization strategies.

## Key Novelty
Component-based roofline model abstracting Ascend hardware into distinct components for precise bottleneck identification and operator-level optimization on DSAs requiring manual memory management.

## Contributions
- Component-based roofline model extending classical analysis to Ascend's multi-component DSA
- Structured operator optimization methodology from practical Ascend case studies
- Catalog of common Ascend performance issues and targeted optimization strategies
- 1.07x to 2.15x model speed improvements on real DNN workloads
