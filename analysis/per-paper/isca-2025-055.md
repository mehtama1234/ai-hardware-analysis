# DX100: Programmable Data Access Accelerator for Indirection
**ID:** isca-2025-055 | **Venue:** ISCA | **Confidence:** high (full text)

## Problem
Indirect memory accesses (A[B[i]] patterns) in scientific computing, graph analytics, and database workloads cause severe DRAM bandwidth underutilization because DRAM controllers have only a 32–128 request window to reorder commands, while the dependency chains of indirect loads limit the memory-level parallelism achievable by conventional cores. Prior prefetchers and fetcher units improve latency but do not reorder, coalesce, or interleave accesses for bandwidth efficiency.

## Motivation
Memory bandwidth is the dominant bottleneck for irregular data-intensive workloads—sparse linear algebra, graph algorithms, hash-join—and the growing gap between available DRAM bandwidth and bandwidth actually utilized (as low as 11% measured) represents a major opportunity; next-generation DoE supercomputers (ATS-5) explicitly prioritize overcoming the memory wall for such applications.

## Method
DX100 is a programmable accelerator that CPU cores can share to speed up indirect memory accesses (A[B[i]] patterns) and streaming data operations, with an 8-instruction instruction set supporting loads, stores, atomic read-modify-write operations, and loop control. Its core strategy is using a large hardware reordering buffer—the Row Table with 16K entries made from BCAM (binary content-addressable memory for fast lookups) and SRAM (fast storage memory)—that batches and reorganizes addresses to maximize DRAM row-buffer hits; a Word Table coalesces redundant accesses, and a Request Generator spreads them across DRAM channels and bank groups for parallel execution. Streaming data flows through the L3 cache, while indirect accesses bypass the cache and go directly into DRAM controllers, with a Coherency Agent maintaining cache consistency by monitoring directories. An MLIR-based compiler with Polygeist automatically identifies indirect accesses in C/C++, tiles loops, and generates DX100 code, covering over 99% of graph frontier operations in real benchmarks.

## Key Novelty
DX100's core innovation is a large hardware reordering table (the Row Table with 16K entries) that can see and rearrange 500 times more memory addresses than DRAM controllers' built-in buffers (which hold only 32 addresses), allowing it to achieve near-peak DRAM bandwidth use regardless of how scattered the memory accesses are.

## Contributions
- DX100 programmable data-access accelerator with 8-instruction ISA supporting indirect/streaming load, store, and RMW operations with conditional execution and multi-level indirection
- Indirect Access unit with Row Table (BCAM+SRAM), Word Table, and Request Generator achieving 3.9x average bandwidth utilization improvement via reordering, coalescing, and interleaving over a 16K-element tile
- MLIR-based compiler infrastructure using Polygeist that automatically identifies, hoists, and transforms indirect access patterns in legacy C/C++ code to DX100 instructions
- 2.6x geometric mean speedup over 4-core multicore baseline and 2.0x over state-of-the-art DMP indirect prefetcher across 12 benchmarks (NAS, GAP, Hash-Join, UME, Spatter)

## Metrics
- **Speedup:** 2.6x over 4-core multicore baseline; 2.0x over DMP indirect prefetcher (geometric mean, 12 benchmarks)
- **Energy/TOPS-W:** 3.6x core instruction reduction (energy proxy); 777 mW power at 28nm
- **Area:** 4.06 mm^2 at 28nm (~1.5 mm^2 at 14nm, 3.7% of 4-core processor area)
- **Other:** 3.9x average DRAM bandwidth utilization improvement; 2.7x row-buffer hit rate increase; 12.1x DRAM controller request buffer occupancy increase; 6.1x cache MPKI reduction

## Baselines
- 4-core Intel Skylake-like multicore (gem5)
- DMP state-of-the-art indirect prefetcher

## Limitations
DX100 requires alias-free indirect regions (no concurrent core writes to accelerated arrays) and does not support pointer-chasing with variable base addresses or workloads with too-small frontiers for bulk tile offloading.
