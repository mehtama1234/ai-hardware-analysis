# Deterministic Client: Enforcing Determinism on Untrusted Machine Code

**Problem:** Untrusted machine code exhibits non-deterministic behavior (timing variations, memory access patterns, scheduling dependencies) that complicates security verification and reproducibility. Enforcing determinism while maintaining performance is challenging without architectural support.

**Method:** The system intercepts untrusted machine code and takes strict control of three normally-variable aspects: when instructions execute (timing), the order memory accesses happen, and how tasks are scheduled. By fixing these values, the code runs in the exact same way every time—making it deterministic. This control happens on your computer (client-side) rather than requiring special hardware, so performance is maintained.

**Novelty:** The core idea is using controls on your computer to make untrusted code run in the exact same way every time, without needing special hardware or losing speed.
