# Software-Style Hardware Debugging: A Hardware Generation, Simulation and Debugging Framework

**Venue:** ICCAD  
**ID:** iccad-2025-121

## Problem
Hardware verification still relies on traditional RTL workflows, creating a bottleneck in design-verification iteration efficiency and limiting the use of modern debugging techniques.

## Motivation
Hardware design iteration cycles are slow compared to software; bringing software debugging paradigms to hardware can significantly accelerate development.

## Method
ComoPy framework lets you simulate and debug hardware designs using familiar software techniques. You can set breakpoints (pausing points to inspect code) and trace execution on hardware description language source lines, then hot-reload changes (recompile and reload without restarting) for quick debug-fix cycles. The framework lets you dynamically switch between fast low-level RTL simulation (register-transfer level, the detailed gate-by-gate logic) and higher-level HDL execution (hardware description language), letting you balance speed against visibility for each debugging task.

## Key Novelty
The core idea is bringing software debugging techniques (breakpoints, tracing, hot-reloading) to hardware design verification by executing the hardware description language natively in a programming language.

## Contributions
- Host language native simulation enabling breakpoints and tracing on HDL source lines
- Software-style hot-reloading for incremental debug-fix iterations
- Dynamic switching between RTL and HDL execution levels
