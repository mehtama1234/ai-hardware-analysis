# isca-2025-025 — Need for zkSpeed: Accelerating HyperPlonk for Zero-Knowledge Proofs

**Venue:** ISCA 2025  
**Confidence:** high (full text read)

## Problem
Generating zero-knowledge proofs using the HyperPlonk zkSNARK protocol is prohibitively slow on CPUs (minutes to hours), due to four heterogeneous proof phases requiring large-bitwidth (255–381 bit) modular arithmetic over polynomials of degree up to 2^24. Existing ZKP accelerators target simpler protocols (Groth16, Orion, Spartan) that either require per-application trusted setups or produce large proofs, leaving HyperPlonk unaccelerated.

## Motivation
HyperPlonk's universal trusted setup + small proof sizes (~5 KB) make it ideal for blockchain/verifiable ML, but its prover is dominated by bandwidth-intensive SumCheck and compute-intensive Multi-Scalar Multiplication (MSM) kernels requiring specialized hardware.

## Method
zkSpeed is a modular ASIC with eight dedicated units:
- **SumCheck unit**: unified PE handling ZeroCheck, PermCheck, and OpenCheck variants; parallel polynomial evaluation across boolean hypercube instances; 48.9% area savings via shared modular multipliers (94 vs. 184 modmuls per PE).
- **MSM unit**: Pippenger's algorithm with improved bucket aggregation (group-size 16, 92% latency reduction vs. SZKP); handles both Sparse and Dense MSMs from the same hardware.
- **Multifunction Tree Unit (MTU)**: hybrid DFS/BFS traversal for Build MLE, MLE Evaluate, Product MLE; eliminates full-level intermediate storage; >99% PE utilization for 2^20 workloads.
- **FracMLE unit**: constant-time Binary Extended Euclidean Algorithm (BEEA, 509-cycle latency) with Montgomery batching (batch size 64), multiplier tree reduces partial-product from O(b) to O(log2 b); one output per cycle.
- **MLE Combine unit**: resource-shared for sequential OpenCheck/MSM phases (41% area savings, 72 vs. 122 multipliers).
- **Global SRAM**: compressed MLE tables (10–11x via binary packing of sparse control MLEs); 4-channel shared bus; HBM interface.
- Static scheduling via HyperPlonk's data-oblivious stage structure.

## Key Novelty
Unified SumCheck PE handling all three HyperPlonk SumCheck variants with shared modular multipliers, combined with a novel hybrid DFS/BFS Multifunction Tree Unit and Montgomery-batched inversion pipeline that cover the complete HyperPlonk proving protocol in one ASIC.

## Contributions
1. Fully-pipelined unified SumCheck accelerator supporting all three HyperPlonk polynomial structures with 48.9% area reduction via multiplier sharing.
2. Novel modular inversion using constant-time BEEA + Montgomery batching (batch 64) + multiplier tree; one inverse output per cycle.
3. Hybrid DFS/BFS Multifunction Tree Unit eliminating full-level intermediate storage, saving 41.6% area vs. dedicated units.
4. Full-chip design-space exploration over thousands of configurations; 801x geomean speedup over AMD EPYC 7502 at iso-compute area (366mm2, 7nm, 2 TB/s HBM).

## Hardware Target
ASIC (7nm TSMC, synthesized via Catapult HLS + Design Compiler)

## Baselines
- AMD EPYC 7502 (32-core CPU, HyperPlonk reference implementation)
- NoCap (Spartan ZKP accelerator)
- SZKP (Groth16/MSM accelerator)

## Limitations
Evaluation uses synthetically generated mock circuits (no real HyperPlonk application compiler exists), limiting workload diversity; the design is ASIC-only and does not generalize to other ZKP protocols without re-synthesis.
