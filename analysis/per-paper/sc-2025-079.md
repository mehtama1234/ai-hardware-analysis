# FT-Transformer: Resilient and Reliable Transformer with End-to-End Fault Tolerant Attention

**Venue:** SC 2025  
**Authors:** Dai, Wu, Huang, Jian, Zhu, Hu, Chen

## Problem
Transformer inference on large-scale HPC systems experiences soft errors at exascale. Traditional operation-level fault tolerance introduces:
- Significant computational overhead
- Excessive memory overhead
- Poor protection efficiency
- Scalability limitations for large models

## Approach
**FT-Transformer** uses module-level unified protection rather than per-operation protection:

### Attention Module Protection
- Treat all attention operations (QK^T, softmax, output projection) as single kernel
- Apply **end-to-end fault tolerance** protecting entire module
- Enables multi-step computation protection with reduced redundancy

### Linear Module Protection
- Design **strided ABFT** (Algorithm-Based Fault Tolerance)
- Avoids inter-thread communication (reduces synchronization overhead)
- Maintains correctness with minimal computational cost

## Key Metrics

| Metric | Value |
|--------|-------|
| Speedup vs. operation-level FT | 7.56x |
| Average FT overhead | 13.9% |
| Coverage | Comprehensive (nonlinear + linear) |

## Technical Innovation
**Module vs. Operation Granularity:**
- Operation-level: Protect each QK^T, softmax, projection → multiple redundancy mechanisms
- Module-level (FT-Transformer): Single unified checker for attention kernel → reduced overhead

**ABFT Optimization:**
- Strided computation avoids barrier synchronization
- Reduces memory footprint vs. checkpointing approaches

## Hardware Targets
- Large-scale GPU clusters
- HPC inference systems
- Any platform supporting transformer workloads

## Algorithm Characteristics
- **Scope**: Inference only (not training)
- **Coverage**: Nonlinear operations (attention, softmax) + linear layers
- **Fault Model**: Soft errors in computation/memory
- **Overhead**: 13.9% average (acceptable for reliability)
