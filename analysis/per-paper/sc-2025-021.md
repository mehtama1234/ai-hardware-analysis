# Differential Testing for Sequential to Parallel Transformations

## Overview
Dynamic differential testing framework (Seq2ParDiff) validating sequential-to-parallel code transformations by comparing parallel and sequential execution.

## Problem & Motivation
- **Challenge**: Automated parallelization tools error-prone; static validation insufficient; errors cause data races, poor performance, rounding issues
- **Opportunity**: Dynamic differential testing comparing parallel behavior against sequential reference can detect subtle transformations bugs
- **Use Case**: Validating automated OpenMP parallelization transformations

## Architecture & Method
**Differential Testing**
- Execute sequential program with test inputs → reference outputs
- Execute parallel version with same inputs
- Compare execution (outputs, memory state, control flow)
- Detect divergences indicating transformation errors

**Test Coverage**
- Multiple benchmark suites
- Diverse input sets
- Comprehensive execution comparison

## Key Contributions
1. **Seq2ParDiff framework**: Dynamic differential testing for parallel validation
2. **20 new faults found** in first benchmark set
3. **Outperforms static techniques** in bug detection rate
4. **Identifies faults missed** by other tools
5. **Trade-off identification**: Less effective on certain data race types

## Validation Insights
- Dynamic execution comparison catches bugs static analysis misses
- Reveals gaps in existing validation tools
- Data race detection remains challenging (incomplete vs some competitors)

## Limitations
- Data race detection less complete than some existing tools
- Benchmark details sparse (sizes, transformation complexity)
- No testing overhead analysis (cost to deploy validation)
- Transformation representativeness unclear
- Abstract-only prevents detailed evaluation
