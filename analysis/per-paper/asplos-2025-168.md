# Hierarchical Prefetching: A Software-Hardware Instruction Prefetcher for Server Applications

**Venue:** ASPLOS  
**Confidence:** low (abstract-only)

## Problem
Server-side applications have large instruction working sets causing severe front-end bottlenecks even with FDIP, because record-and-replay prefetchers lose coverage and timeliness when actual control flow diverges from predicted sequences.

## Motivation
Instruction cache misses are a primary bottleneck in server workloads, and existing prefetchers fail when control flow variability causes mismatches between recorded and replayed sequences.

## Method
The system analyzes the server binary to identify larger functional code regions called Bundles (10s–100s of kilobytes) that tend to execute together. Hardware then uses a record-and-replay prefetcher that watches which Bundles are executed and replays that pattern, prefetching entire Bundles when their entry points are detected rather than individual cache lines. Bundle metadata lives mostly in main memory with under 2KB stored on-chip to save space. This approach tolerates control flow variability because prefetching entire functional regions works even when execution takes unexpected paths that would defeat line-by-line prediction.

## Key Novelty
The core idea is defining large functional code Bundles (10s–100s kilobytes) and prefetching them as complete units rather than individual cache lines, so that execution stays on track even when control flow diverges from predictions.

## Contributions
- Bundle abstraction: coarse-grained functionality blocks identified via software analysis
- Hierarchical prefetching microarchitecture combining software Bundle formation with hardware record-and-replay under 2KB on-chip storage
- 6.6% average IPC improvement over FDIP across 11 server workloads
- Improved miss coverage and timeliness over prior instruction prefetchers
