# PIM Is All You Need: A CXL-Enabled GPU-Free System for Large Language Model Inference

**Venue:** ASPLOS 2025  
**ID:** asplos-2025-051  
**Confidence:** high (full text)

## Problem
LLM inference is memory-bound (GEMV-dominated decoding with ~21% GPU compute utilization on Llama2-70B) while GPU/TPU systems are compute-optimized; large per-user KV-caches limit batch sizes, and standalone PIM architectures lack sufficient memory capacity/scalability for trillion-parameter LLMs.

## Motivation
Running Llama2-70B on 4x A100s costs ~$694K/day for ChatGPT-scale inference with <25% compute utilization, motivating memory-bandwidth-optimized alternatives as LLMs scale toward trillion parameters.

## Method
CENT uses a hierarchical processing-in-memory (PIM) and near-memory (PNM) architecture deployed across 32 GDDR6-PIM memory devices connected via CXL 3.0. Each PIM device contains 16 multiply-accumulate units (32 billion operations per second in BF16), handling over 99% of the arithmetic, plus PNM units with 32 accumulators, reduction trees, special hardware for exponential functions, and 8 CPU cores for operations like Softmax (attention probability calculation), RMSNorm (normalization), square roots, and RoPE (rotary embeddings). A custom instruction set with commands like MAC_ABK (for matrix operations) and BCAST_CXL (for broadcasting) orchestrates computation and data movement across the CXL network. Pipeline parallelism assigns each transformer layer to one device with multiple prompts flowing through in sequence, while tensor parallelism splits a transformer layer across all devices synchronized via CXL broadcast and gather, with a hybrid mode for balancing throughput and responsiveness.

## Key Novelty
CENT replaces GPUs with a hierarchical PIM-PNM system connected via CXL 3.0 with a novel broadcast primitive, leveraging GDDR6-PIM's 512 trillion bytes per second internal bandwidth to achieve 2.3x higher LLM inference throughput than 4x A100 GPUs at 2.9x lower energy and 5.2x better TCO.

## Contributions
- CENT: 32 CXL devices with hierarchical PIM-PNM architecture, 512 TB/s aggregate internal bandwidth, full transformer block support.
- Scalable CXL network with broadcast/multicast primitives via H-slot flit encoding, supporting up to 4,096 nodes.
- PP/TP/hybrid TP-PP LLM parallelism mapping with detailed per-operation assignment (GEMV to near-bank PIM; Softmax/RMSNorm/RoPE to PNM RISC-V/accelerators).
- 2.3x throughput, 2.9x energy efficiency, 5.2x tokens/dollar vs 4x A100 GPUs.

## Metrics
- speedup: 2.3x end-to-end throughput (throughput-critical); 4.6x latency reduction (batch=1); 3.3x decoding throughput at 32K context
- energy: 2.9x tokens/joule over 4x A100
- area: CXL controller 19.0 mm2 at 7nm
- TCO: 5.2x tokens per dollar; owned $0.73/hr vs GPU $1.76/hr; rental $1.05/hr vs $5.45/hr

## Baselines
4x NVIDIA A100 80GB with NVLink 3.0 running vLLM (batch=128)

## Limitations
CENT underperforms GPU by 2x in compute-intensive prefill stage; evaluation limited to Llama2 at up to 32K context; GDDR6-PIM memory density reduced to ~75% of standard GDDR6.
