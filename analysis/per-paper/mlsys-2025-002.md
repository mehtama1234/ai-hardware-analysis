# TileLink: Generating Efficient Compute-Communication Overlapping Kernels using Tile-Centric Primitives

**Problem:** Overlapping GPU compute with inter-GPU communication for distributed LLM execution requires expert CUDA/NVSHMEM code (~2000 lines); operator decomposition approaches leave significant performance on the table.

**Method:** Two-part compiler. Frontend exposes 9 tile-centric primitives (producer_tile_notify, consumer_tile_wait, peer_tile_notify, peer_tile_wait, tile_push_data, tile_pull_data, rank_copy_data, rank_notify, rank_wait) that decouple compute and communication. Backend maps these to PTX via Triton+NVSHMEM using three stages: shape mapping, rank mapping (affine transforms for static layouts, lookup tables for dynamic), and channel mapping to NVLink/InfiniBand lanes.

**Key novelty:** Tile-centric primitives decouple compute/communication design spaces; compiled to fused kernels with ~10x less code than expert CUDA.

**Metrics:**
- 1.17x to 20.76x speedup vs non-overlapping baseline
- Performance comparable to FLUX (handwritten expert library)
- ~200 Python lines vs ~2000 CUDA lines for equivalent functionality
