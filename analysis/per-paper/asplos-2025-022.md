# MoC-System: Efficient Fault Tolerance for Sparse Mixture-of-Experts Model Training

**Venue:** ASPLOS  
**Confidence:** low (abstract-only)  
**Primary Theme:** sparse-activation-aware fault tolerance for MoE LLM training

## Problem
Sparse MoE LLMs have parameter counts far exceeding dense models of equivalent compute, making checkpoint-based fault tolerance extremely expensive in terms of checkpoint size, write bandwidth, and recovery time for distributed training at >10k node scale.

## Motivation
Distributed training clusters beyond 10k nodes have high failure rates, making fault tolerance essential, but the large parameter footprint of MoE models creates checkpoint overhead disproportionate to actual training compute.

## Method
MoE models only activate (use) a subset of experts (specialized sub-networks) per token, so most expert parameters never get updated in a given training step. MoC-System exploits this sparsity by saving (checkpointing) only the experts that were actually activated and updated, completely skipping the dormant ones—drastically reducing checkpoint file sizes. To manage I/O overhead, the system overlaps checkpoint writes with forward and backward computation, and spreads checkpoint data across nodes by expert grouping (expert-parallel sharding) to minimize per-node storage.

## Key Novelty
Instead of saving all expert parameters, the system only saves the ones actually used in each training step, which dramatically shrinks checkpoint files and reduces I/O overhead while keeping the system able to recover from failures.

## Contributions
- Analysis of fault tolerance bottleneck specific to sparse MoE training at scale
- MoC-System: selective expert checkpointing based on sparse activation patterns
- Distributed checkpoint orchestration overlapping I/O with computation
- Maintained full fault recovery capability with reduced checkpoint overhead
