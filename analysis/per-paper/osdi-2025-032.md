# Enabling Efficient GPU Communication over Multiple NICs with FuseLink

**Problem:** Existing ML cluster systems with multiple NICs per server fail to fully utilize all NICs due to static GPU-NIC bindings, creating bottlenecks at hot-spot NICs when handling imbalanced communication patterns across LLM serving instances, expert-parallel training, and recommendation model training.

**Method:** When a network interface gets too busy, FuseLink uses the GPU as a relay point to forward traffic to a less busy interface through the high-speed connections inside the server. This balances the network load across all available connections instead of letting one interface become a bottleneck. The system integrates into NCCL (the standard communication library that machine learning frameworks use), so existing applications work without requiring any code changes.

**Novelty:** GPUs dynamically redirect network traffic to less busy connections instead of being permanently bound to a single interface.
