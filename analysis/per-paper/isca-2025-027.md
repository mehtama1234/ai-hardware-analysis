# isca-2025-027 — Zettafly: A Network Topology with Flexible Non-blocking Regions for Large-scale AI and HPC Systems

**Venue:** ISCA 2025  
**Confidence:** low (abstract only)

## Problem
Post-exascale/zettascale AI/HPC systems need interconnects that support both scalability and non-blocking communication for concurrent jobs, but existing topologies (fat-tree, dragonfly) cannot flexibly partition non-blocking sub-networks to match the small-to-medium job sizes that dominate production core-hour consumption.

## Motivation
Production data shows small/medium jobs consume most core-hours and generate traffic within a network subset; today's topologies cannot isolate these jobs into non-blocking regions, causing inter-job interference and poor utilization.

## Method
Zettafly is a two-layer network: the bottom layer has small non-blocking groups (regions where data packets flow freely without congestion), and the top layer connects them with global routers. The key structural principle is that any packet moving between groups passes through at most one global router, keeping network distances short. The groups are sized to match typical small-to-medium HPC jobs that dominate production systems, so jobs running within a group achieve non-blocking communication without bottlenecks. The paper develops adaptive routing algorithms (algorithms that adjust paths based on live network conditions) for this topology and evaluates it against fat-tree and dragonfly variants through simulation on HPC workloads with multiple concurrent jobs.

## Key Novelty
Zettafly separates control of non-blocking group size from overall network scale, so you can partition massive networks into smaller non-blocking sub-networks matched to typical HPC and AI job sizes while keeping network paths short and costs reasonable at zettascale.

## Contributions
1. Zettafly topology with NB groups + single global router hop between groups.
2. Adaptive routing algorithms for the two-layer structure.
3. Simulation showing cost-effectiveness under multi-task mixed traffic.
4. Incremental deployment and flexible configuration analysis for zettascale systems.
