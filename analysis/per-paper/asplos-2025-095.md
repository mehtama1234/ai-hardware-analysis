# asplos-2025-095: PhasePrint: Exposing Cloud FPGA Fingerprints by Inducing Timing Faults at Runtime

**Venue:** ASPLOS  
**Confidence:** low (abstract only)

## Problem
Cloud FPGA vendors prevent tenants from localizing (identifying) specific FPGA instances to thwart attacks exploiting data remanence and analog covert channels. This paper addresses how to fingerprint and locate individual FPGAs in a shared cloud environment despite vendor-imposed restrictions on low-level hardware information.

## Motivation
FPGA localization is a double-edged capability: it enables adversaries to mount targeted attacks but also lets defenders rotate workloads away from long-term-occupied FPGAs that may leak data through remanence.

## Method
PhasePrint deliberately creates timing glitches by stressing the FPGA — using ring oscillators (self-oscillating circuits whose speed reveals timing characteristics) or changing voltage and clock frequency. Each physical FPGA responds uniquely to this stress because of manufacturing variations in propagation delays (the time signals take to travel through the chip). The system collects these fault patterns to generate a unique fingerprint for each FPGA, enabling identification without needing privileged hardware access.

## Key Novelty
The breakthrough is using deliberately-induced timing faults to create unique fingerprints for each individual FPGA, bypassing cloud vendor restrictions on hardware identification.

## Contributions
- A methodology to fingerprint cloud FPGA instances by eliciting and measuring runtime timing-fault patterns caused by process variation.
- Demonstration that FPGA localization is feasible even under cloud vendor restrictions that hide low-level hardware information.
- Analysis of the dual-use security implications of FPGA fingerprinting for both attackers (targeting) and defenders (workload rotation).
