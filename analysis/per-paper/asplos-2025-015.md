# Necro-reaper: Pruning away Dead Memory Traffic in Warehouse-Scale Computers

**Venue:** ASPLOS  
**Confidence:** low (abstract-only)  
**Primary Theme:** software-hardware co-design to eliminate dead memory traffic in warehouse-scale computers

## Problem
A significant fraction of memory traffic in warehouse-scale computers (WSC) is unnecessary: it consists of writebacks of deallocated (dead) heap data and fetches of uninitialized data, neither of which carries useful information. Short-lived heap allocations larger than a cache line—common in WSC—exacerbate this problem.

## Motivation
Memory bandwidth is a critical and growing bottleneck in warehouse-scale computing, and eliminating provably dead traffic can improve throughput and IPC without changing application semantics.

## Method
Necro-reaper combines software and hardware. A compiler uses profiling data (measurements from running real code) to analyze how long each chunk of memory stays allocated, then inserts special CPU instructions at allocation sites. A customized memory allocator uses these instructions to signal the hardware when memory is deallocated. The hardware then skips unnecessary memory traffic for dead regions without needing its own logic to track which data is still in use.

## Key Novelty
Special CPU instructions allow the compiler and memory allocator to signal dead heap memory to the hardware, which then skips unnecessary writebacks and fetches without needing its own tracking.

## Contributions
- Identification and quantification of dead memory traffic as a major WSC bottleneck
- New ISA instructions enabling software-directed avoidance of dead memory traffic
- Profile-guided compiler pass that annotates heap allocation/deallocation sites
- WSC-scale evaluation across 10 workloads: 26% geomean memory traffic reduction, 6% geomean IPC gain
