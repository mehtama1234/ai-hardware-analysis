# No Rush in Executing Atomic Instructions
**Venue:** HPCA 2025 | **ID:** hpca-2025-010 | **Confidence:** high (full text)

## Problem
Modern x86 processors implement unfenced atomic RMW instructions, enabling eager execution as soon as operands are ready, but eager execution locks cachelines early which prolongs lock duration and harms threads competing for contended cachelines. Lazy execution minimizes lock time but exposes full memory access latency on non-contended accesses.

## Motivation
With fence-free atomics confirmed in modern x86 processors, the new question is *when* to issue the atomic: eager doubles performance on non-contended workloads (canneal, freqmine) while lazy nearly halves execution time on contended workloads (pc, sps); a static policy always loses half the benefit.

## Method
**Rush or Wait (RoW)** dynamically selects eager vs lazy atomic execution via a 64-entry 4-bit saturating-counter predictor indexed by XOR of 12 LSBs of the PC. Three contention detection mechanisms update the predictor: (1) **Execution Window (EW)** — marks atomic contended if external coherence request arrives while cacheline is locked; (2) **Ready Window (RW)** — extends tracking from when operands are ready by computing address eagerly and snooping the Atomic Queue (AQ) for matching external requests; (3) **Directory detection (RW+Dir)** — additionally marks atomics contended when the cacheline arrives from another core's private cache with latency >400 cycles (threshold chosen experimentally). Store-to-load forwarding from older regular stores overrides lazy prediction to preserve atomic locality. Total storage: 64 bytes.

## Key Novelty
The first analysis of the eager-vs-lazy execution trade-off for unfenced atomics, and a hardware contention predictor (RoW) that dynamically switches between the two modes based on predicted cacheline contention with only 64 bytes of state.

## Contributions
1. Experimental characterization on real x86 hardware confirming fence-free atomic RMW implementation in modern processors
2. Analysis of eager-vs-lazy trade-off: up to 2x performance differential in both directions depending on contention
3. Three-tier contention detection (EW, RW, RW+Dir) for comprehensive contention tracking across different execution scenarios
4. RoW: 9.2% average (up to 43%) execution time reduction vs always-eager with only 64 bytes storage overhead

## Metrics
- **Speedup:** 9.2% average, up to 43% vs eager atomic baseline (32-core Alder Lake model)
- **Area:** 64 bytes total state (256-bit predictor + 256-bit AQ augmentation)
- **Other:** RW+Dir Sat achieves 7.3% vs eager and 5.5% vs lazy

## Baselines
Eager atomic execution, lazy atomic execution, Free Atomics (prior fence-free implementation)

## Hardware Target
CPU (x86 multicore, modeled on Intel Alder Lake)

## Technique Categories
cache, coherence, scheduling

## Workloads
HPC (Splash-4, PARSEC 3.0, fine-grain synchronization benchmarks)

## Limitations
Evaluated on synchronization-intensive parallel benchmarks; predictor aliasing with 64 entries degrades performance when mixed contended/non-contended atomics share PC entries.
