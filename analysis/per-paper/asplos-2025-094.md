# asplos-2025-094 — Dilu: Enabling GPU Resourcing-on-Demand for Serverless DL Serving via Introspective Elasticity

**Venue:** ASPLOS  
**Confidence:** low (abstract only)  
**Primary Theme:** Two-dimensional GPU elasticity for serverless DL serving

## Problem
Serverless DL serving systems use coarse-grained static GPU allocation that produces 15-94% GPU fragmentation due to dynamic workload patterns; existing horizontal-only scaling cannot adapt GPU resource allocation fine-grainedly within a running DL function instance, degrading utilization and violating QoS.

## Motivation
Large language model serving on serverless GPU infrastructure is expensive and fragmentation-prone, and the inability to dynamically right-size GPU resources within a function (without full cold restart) prevents efficient multiplexing and SLA compliance.

## Method
Dilu introduces Introspective Elasticity (IE), a two-dimensional co-scaling mechanism combining vertical scaling (adjusting GPU resource allocation within a running DL task) and horizontal scaling (adding/removing instances). Dilu uses multi-factor profiling with efficient pruning search to characterize each DL function's GPU compute/memory sensitivity. A cross-layer scheduler applies resourcing-complementary principles to fill fragmented GPU capacity with compatible DL tasks. At runtime, an adaptive 2D co-scaling controller continuously monitors QoS signals and adjusts both per-instance GPU allocation and the number of instances to minimize fragmentation while meeting SLAs.

## Key Novelty
Introspective Elasticity (IE) enables live two-dimensional (vertical + horizontal) GPU resource adjustment for serverless DL functions without full restarts, eliminating the coarse-grained static allocation that creates GPU fragmentation.

## Contributions
- Introspective Elasticity (IE): two-dimensional GPU co-scaling (vertical + horizontal) for serverless DL tasks
- Multi-factor profiling with pruning search for efficient DL task resource sensitivity characterization
- Resourcing-complementary scheduling principle for filling GPU fragments with compatible DL tasks
- 10-46% GPU defragmentation, up to 1.8x inference throughput, and 11-71% QoS violation rate reduction vs SOTA
