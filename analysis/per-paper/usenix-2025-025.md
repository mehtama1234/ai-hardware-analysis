# Cuckoo for Clients: Disaggregated Cuckoo Hashing

**Problem:** Cuckoo hashing's complex collision resolution and rehashing logic, which typically require centralized state management, do not scale efficiently in disaggregated systems where hash table state is separated from query clients. Standard cuckoo hashing implementations incur excessive coordination overhead when distributed across network or architectural boundaries.

**Method:** The paper proposes a disaggregated cuckoo hashing design where hash table storage resides on a remote server or accelerator while clients perform lookups and insertions with reduced communication overhead. The scheme likely optimizes the cuckoo displacement mechanism through batching, client-side caching, or clever metadata management to minimize network round-trips during collision resolution while the server manages actual state.

**Novelty:** Adapting cuckoo hashing's displacement-based collision resolution to work efficiently in disaggregated systems while preserving its O(1) lookup guarantees and collision handling efficiency.
