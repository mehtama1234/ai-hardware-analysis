# Cuckoo for Clients: Disaggregated Cuckoo Hashing

**Problem:** Cuckoo hashing's complex collision resolution and rehashing logic, which typically require centralized state management, do not scale efficiently in disaggregated systems where hash table state is separated from query clients. Standard cuckoo hashing implementations incur excessive coordination overhead when distributed across network or architectural boundaries.

**Method:** Cuckoo hashing resolves collisions (when multiple keys hash to the same location) by displacing one key to an alternative slot—if that slot is occupied, the old item also moves elsewhere, cascading until all items find slots (like musical chairs where people keep moving to find seats). In disaggregated systems where the hash table sits on a remote server and clients query it over a network, each displacement step requires a server round-trip, creating bottlenecks. This paper reduces those round-trips by letting clients batch operations together, cache metadata locally, and perform more work locally before contacting the server.

**Novelty:** This work adapts cuckoo hashing for disaggregated systems by optimizing how collision resolution works across network boundaries, reducing server round-trips and coordination overhead while preserving the fast, guaranteed lookup times that make cuckoo hashing efficient.
