# Scalable and Asynchronous Differential Checkpointing for Intermittently Powered Devices

**Venue:** ICCAD  
**ID:** iccad-2025-089

## Problem
Intermittently powered devices relying on checkpoint-recovery face scalability challenges: hardware-based differential checkpointing costs increase proportionally with memory size, and synchronous checkpointing blocks the MCU during backups, causing unacceptable latency.

## Motivation
Batteryless energy harvesting systems require efficient checkpointing to survive frequent power failures, but current approaches don't scale to devices with increasing memory capacity or support non-blocking checkpoint operations.

## Method
FLASC saves a device's state (checkpointing) by splitting the work between hardware and software. Normally the hardware tracks which memory changed—expensive when memory is large—but FLASC uses lightweight software tracking instead, keeping hardware cheap and simple. The system saves in the background while the processor keeps working, with safeguards ensuring correctness and no slowdown.

## Key Novelty
FLASC splits checkpoint work between hardware and software to enable asynchronous saving—storing only memory changes without pausing—while avoiding proportional hardware cost growth as memory increases.

## Contributions
- Scalable memory modification tracking mechanism that avoids hardware cost proportional to memory size
- Support for safe asynchronous checkpoint execution enabling MCU progress during backups
- 9.4% faster execution compared to state-of-the-art while using only 49.1% hardware resources
- 6.9× better scalability with increasing data memory size addressing prior architectural limitations
