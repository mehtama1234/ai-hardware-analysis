# CIM-BLAS: Computing-in-Memory Accelerator for BLAS

**Venue:** DAC  
**Confidence:** low (abstract-only)

## Problem
BLAS operations are memory-bandwidth-bound in CPUs and GPUs; memory wall is the primary bottleneck.

## Key Insight
Computing-in-memory can alleviate memory bandwidth bottleneck for data-intensive linear algebra workloads.

## Method
The accelerator solves the data-movement bottleneck in matrix operations (BLAS) by performing calculations directly inside non-volatile memory (persistent storage) where the data lives, rather than shuttling data to the CPU or GPU. It contains a unified floating-point arithmetic unit that adapts to handle different precision levels, since BLAS operations vary widely in their numerical requirements. The internal data pathways (dataflows) reconfigure to match the operation type: for operations limited by memory speed, it executes calculations in-memory; for computation-limited operations, it exploits the high parallelism from having many arithmetic units close to the data.

## Contributions
- First CIM BLAS accelerator with high-precision FP pipeline
- Configurable dataflows for BLAS hierarchy
- Orders of magnitude gains for level-1/2 BLAS
- 2.6–24.1× energy efficiency for level-3; excellent scalability
