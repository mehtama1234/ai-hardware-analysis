# IRIS: Unleashing ISP-Software Cooperation to Optimize the Machine Vision Pipeline

**Venue:** HPCA  
**Confidence:** high (full text)

## Problem
Continuous Vision (CV) SoC pipelines capture entire scenes at uniform high resolution (e.g., 4K), wasting memory bandwidth and backend compute on low-information regions (sky, road) that do not require full-resolution processing, while the ISP discards intermediate computations (edge masks, motion vectors) that could guide resolution reduction.

## Motivation
Mobile CV systems for autonomous driving and AR/VR face strict latency and energy constraints; uniform full-resolution capture causes both the frontend (ISP, memory bus) and backend (CPU/GPU) to process unnecessary data, and the ISP already generates the information needed to identify low-salience regions but discards it.

## Method
IRIS adds three lightweight components to the image sensor's preprocessing stage (ISP) to reduce resolution for less-important image regions using existing computations. It calculates importance scores from edge information and motion vectors the ISP already extracts, groups the image into hierarchical blocks at three sizes (16×16, 32×32, and 64×64 pixels), and downsamples blocks that fall below a backend-provided importance threshold, reducing them from 32×32 or 64×64 to 16×16 pixels and recording each block's final resolution as metadata. The backend adapts: Vision Transformers use a Quadformer-style mixed-resolution tokenizer to handle variable-resolution blocks, and localization algorithms (ORB-SLAM3) process regions in order of importance until improvements diminish. The sensor pipeline never stalls during this processing.

## Key Novelty
The innovation is repurposing edge masks and motion vectors that the image sensor already extracts—data normally discarded—as a zero-extra-computation importance scorer that automatically reduces resolution on less-critical image regions before storage.

## Contributions
1. IRIS: ISP hardware augmentation (Saliency Scorer + Quad Unit + Downsampling Unit) that performs mixed-resolution imaging by repurposing ISP byproducts at negligible added cost
2. ISS saliency score combining edge density and motion magnitude, validated to correlate strongly with ORB feature density on KITTI
3. Iterative feature extraction algorithm for ORB-SLAM3 leveraging ISS ranking to skip low-saliency regions with diminishing-return stopping criterion
4. Localization (ORB-SLAM3/KITTI): 22.8% avg latency, 10.5% tail latency, 22.5% energy reduction; Classification (ViT/ImageNet): 37.5% avg latency, 9% tail latency, 41.5% energy reduction with <1% accuracy loss at threshold 0.3

## Metrics
- **Speedup:** Localization: 22.8% avg latency reduction, 10.5% tail latency reduction; Classification: 37.5% avg latency reduction, 9% tail latency reduction
- **Energy:** Localization: 22.5% reduction; Classification: 41.5% reduction
- **Area:** Synthesized at 14nm (Synopsys); reported as not stalling the ISP pipeline; headline area overhead not quoted
- **Accuracy:** ViT top-1 within 1% of baseline at ISS threshold 0.3; ORB-SLAM APE below 5mm at ISS=0.2, MFI=3%
- **Other:** ~70% image size reduction at threshold 0.5; 55% at threshold 0.3

## Baselines
- Baseline uniform-resolution ISP pipeline (no downsampling)
- Software-only saliency generation (VL-SO, ViT-SO) without ISP hardware augmentation

## Limitations
Software-only saliency generation hurts performance (4.7% latency increase for small ViTs) because the saliency computation overhead outweighs benefits, making IRIS dependent on ISP hardware augmentation that requires ISP vendor cooperation or redesign.
