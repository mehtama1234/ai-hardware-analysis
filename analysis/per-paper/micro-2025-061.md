# ShadowBinding: Realizing Effective Microarchitectures for In-Core Secure Speculation Schemes

**Venue:** MICRO  
**Confidence:** low (abstract-only)

## Problem
Secure speculation schemes that mitigate Spectre-class speculative side-channel attacks (STT and NDA) lack rigorous RTL-level microarchitectural implementations and realistic performance/cost analysis. Prior work significantly underestimates overhead; specifically, STT's rename-stage taint computation creates an expensive single-cycle dependency chain that degrades performance on wider out-of-order cores.

## Motivation
As speculative side-channel attacks remain an active threat, deployment of in-core secure speculation schemes requires honest microarchitectural cost analysis; overly optimistic estimates prevent accurate understanding of true performance penalties.

## Method
ShadowBinding builds hardware designs for two security schemes—Speculative Taint Tracking (STT, which marks data that might leak through speculation) and Non-Speculative Data Access (NDA)—implemented on a RISC-V processor called BOOM. For STT, it proposes a variant called STT-Issue that moves the tagging step from the rename stage (where the processor first decodes instructions) to the issue stage (where it decides to execute them), eliminating a bottleneck where each instruction waits for the previous one's tag to be computed. The team uses RTL synthesis and cycle-accurate simulation to measure the real performance cost, including both instruction-throughput loss (IPC) and clock-speed reduction.

## Key Novelty
STT-Issue moves the step of marking unsafe data from the rename stage to the issue stage, removing the bottleneck that slows down wide processors, and provides the first real-hardware measurement showing that the combined instruction-throughput and speed loss from in-core security schemes reaches 35% or more on fast processors.

## Contributions
1. First rigorous RTL microarchitectures for STT and NDA on a real RISC-V OOO core (BOOM)
2. Novel STT-Issue variant: moves taint computation to issue stage, improving IPC, timing, and area over STT-Rename
3. Combined IPC+timing loss quantified: 35%, 27%, 22% for STT-Rename, STT-Issue, NDA respectively
4. Challenge to prior consensus that Spectre can be solved at low cost by in-core schemes

## Hardware Target

## Metrics
- IPC overhead: ~20% for highest-performance core configuration
- Combined IPC+timing loss: 35% (STT-Rename), 27% (STT-Issue), 22% (NDA)

## Baselines
Insecure baseline BOOM RISC-V core; STT-Rename; NDA

## Limitations
Analysis is limited to an academic RISC-V core (BOOM); commercial high-performance core behavior is extrapolated but not directly measured.
