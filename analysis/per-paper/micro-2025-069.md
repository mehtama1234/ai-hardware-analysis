# micro-2025-069: RTGS: Real-Time 3D Gaussian Splatting SLAM via Multi-Level Redundancy Reduction

**Venue:** MICRO  
**Confidence:** high (full text read)

## Problem
3DGS-SLAM systems cannot achieve real-time throughput (>=30 FPS) on edge devices; best existing algorithms run at 0.78–14 FPS on NVIDIA ONX edge GPU. Rendering and backpropagation stages dominate runtime (>80%), with severe pixel workload imbalance and costly atomic gradient aggregation causing memory conflicts.

## Motivation
AR/VR, autonomous driving, and robotics require real-time 3DGS-SLAM on power-constrained edge devices, but the gap between current algorithm throughput and 30 FPS exceeds 20x, blocking deployment.

## Method
RTGS is an algorithm-hardware co-design plug-in to edge GPUs.

**Algorithm side:**
- Adaptive Gaussian pruning: progressively removes low-importance Gaussians using gradients already computed during backpropagation (zero extra cost for importance scoring); uses a mask-prune strategy with dynamically adjusted pruning interval K.
- Dynamic downsampling: reduces non-keyframe resolution from 1/16 to 1/4 of full resolution based on temporal distance to the nearest keyframe, reusing keyframe identification and alpha-computing pipeline stages.

**Hardware side (28nm, 500 MHz, 8.11W, 28.41 mm2 ASIC plug-in):**
- Workload Scheduling Unit (WSU): combines pixel-level pairwise scheduling (pairs heavy/light-workload pixels into the same 2D buffer) with subtile-level streaming across 16 Rendering Engines, exploiting inter-iteration workload similarity to reuse scheduling patterns with minimal overhead.
- Rendering & Backpropagation (R&B) Buffer: stores forward-pass intermediate values (accumulated transmittance T_P,k and per-Gaussian color contributions C_hat_P,k) to eliminate recomputation in backprop, reducing alpha-gradient latency from 20 cycles to 4 cycles.
- Gradient Merging Unit (GMU): Benes network rearranges gradients from multiple REs, then a bypass-extended reduction tree performs pipelined sparse aggregation from pixel-level to tile-level to Gaussian-level, replacing atomic-add GPU operations.

## Key Novelty
Exploiting inter-iteration workload stability in SLAM (Gaussians are fixed between tracking iterations) to amortize pixel-level pairwise scheduling overhead across iterations, enabling near-oracle load balance with negligible scheduling cost.

## Contributions
- Multi-level redundancy characterization: 14% of Gaussians drive 86% of gradient magnitude; non-keyframes have high inter-frame pixel similarity; per-iteration workload distributions are stable
- Adaptive Gaussian pruning reusing existing backpropagation gradients (zero overhead for importance scoring)
- Dynamic non-keyframe downsampling (1/16 to 1/4 full resolution) tied to keyframe distance
- RTGS ASIC plug-in: WSU (inter-iteration scheduling reuse) + R&B Buffer (forward-to-backward data reuse) + GMU (pipelined sparse gradient aggregation via Benes network)
- Up to 48.8x speedup and 82.5x energy efficiency over edge GPU; >=30 FPS achieved across 4 datasets and 3 3DGS-SLAM algorithms

## Hardware Target
GPU (NVIDIA ONX edge GPU, host), ASIC (RTGS plug-in at 28nm)

## Technique Category

## Workloads
Vision (3DGS-SLAM: rendering + backpropagation + SLAM tracking/mapping)

## Metrics
- Speedup: up to 48.8x over ONX edge GPU baseline
- Energy efficiency: up to 82.5x over edge GPU baseline
- Area: 28.41 mm2 at 28nm (2.40 mm2 scaled to 8nm)
- Power: 8.11W at 500 MHz, 28nm (3.76W at 8nm)
- Accuracy: ATE and PSNR within 10% variance vs. unmodified baselines
- Gradient merging latency: 68% reduction vs. atomic ops
- Alpha gradient compute: 20 cycles -> 4 cycles (5x)

## Baselines
NVIDIA ONX edge GPU, NVIDIA RTX 3090, GauSPU (12nm GPU plug-in), DISTWAR (GPU-level atomic gradient optimization), GS-SLAM, MonoGS, Photo-SLAM, SplaTAM, Taming 3DGS, LightGaussian, FlashGS

## Limitations
ASIC implemented at 28nm, older than the 8nm baseline edge GPU; scaled 8nm projections (2.40 mm2 / 3.76W) are not validated with tape-out.
