# hpca-2025-109: Palermo: Improving the Performance of Oblivious Memory using Protocol-Hardware Co-Design

**Venue:** HPCA  
**Confidence:** low (abstract-only)

## Problem
Oblivious RAM (ORAM) protocols impose severe performance penalties because classical ORAM enforces strict sequential dependencies between memory operations, leaving memory bandwidth severely underutilized. Prior prefetching and request-elimination approaches are fragile under low-locality workloads and create additional ORAM stash pressure overhead.

## Motivation
ORAM is essential for data-privacy guarantees in secure enclaves and trusted hardware, but its high overhead makes it impractical for real workloads without hardware acceleration that exploits parallelism.

## Method
Palermo redesigns the RingORAM protocol to allow overlapping of memory operations both within a single ORAM request and across multiple concurrent requests, without violating correctness or security invariants. A dedicated ORAM controller hardware implements this relaxed protocol by concurrently issuing memory requests while tracking and enforcing only the necessary inter-request dependencies to maintain a consistent ORAM tree view. The architecture manages stash and position-map structures in hardware to prevent stash overflow while enabling pipelined DRAM accesses.

## Key Novelty
A protocol-hardware co-design that removes artificial sequential constraints in classical ORAM, enabling concurrent multi-request memory access without breaking security or correctness guarantees.

## Contributions
- New ORAM protocol that legally overlaps memory operations within and across ORAM requests
- Hardware ORAM controller that enforces only necessary dependencies, maximizing memory bandwidth utilization
- 2.9x average speedup over RingORAM with negligible area overhead (<2% of 12th-gen Intel CPU after scaling)
- Demonstrated superiority over state-of-the-art PageORAM, PrORAM, and IR-ORAM
