# DROIDFUZZ: Proprietary Driver Fuzzing for Embedded Android Devices

**Venue:** DAC  
**Confidence:** low (abstract-only)

## Problem
Embedded Android device security requires testing vendor-specific HAL drivers, which are proprietary and out of reach for traditional kernel testing.

## Key Insight
Cross-layer fuzzing with relational payload generation and execution state feedback can probe HAL-kernel boundaries and discover driver vulnerabilities.

## Method
DroidFuzz finds security bugs in proprietary device drivers by testing them at the boundary between hardware drivers and the operating system. It first explores which driver interfaces exist on the device, then generates test inputs that are valid on both sides of this boundary. Rather than using random data, it watches how the code behaves during testing and uses that feedback to probe deeper into driver logic.

## Contributions
- DroidFuzz fuzzer for vendor driver testing
- HAL driver probing for interface identification
- Relational payload generation for cross-boundary inputs
- Cross-boundary execution state feedback
- 12 security-critical bugs found in 7 devices; all vendor-confirmed
