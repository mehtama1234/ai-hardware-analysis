# HyperHammer: Breaking Free from KVM-Enforced Isolation

**ID:** asplos-2025-027  
**Venue:** ASPLOS  
**Confidence:** low (abstract-only)  
**Primary Theme:** Rowhammer-based hypervisor escape from KVM guest VMs

## Problem
Existing Rowhammer attacks against virtualized cloud environments can compromise co-resident VMs but have not demonstrated the ability to attack the hypervisor itself, and a key primitive enabling such attacks has been disabled by hypervisor mitigations. This paper develops a new Rowhammer attack capable of breaking KVM-enforced isolation to compromise the hypervisor from a guest VM.

## Motivation
Cloud hypervisors enforce the security boundary between tenants; a successful hypervisor compromise via hardware memory vulnerabilities would undermine the fundamental trust model of multi-tenant cloud infrastructure.

## Method
HyperHammer exploits Rowhammer—a technique that flips bits in RAM by repeatedly accessing nearby memory cells—to bypass protections built into KVM (a virtualization system that isolates guest VMs from the hypervisor). The attack likely uses either hammering techniques that KVM didn't block, or exploits how a guest's virtual memory addresses map to physical hardware memory, especially through huge pages (large memory blocks). By inducing bit flips in the hypervisor's protected memory regions, the attack corrupts the hypervisor's code or data structures, allowing the guest VM to escape isolation and gain hypervisor-level control.

## Key Novelty
HyperHammer is the first Rowhammer attack (a technique that flips bits in RAM by repeatedly accessing nearby memory cells) to escape KVM guest isolation and directly compromise the hypervisor, overcoming defenses that had previously blocked such attacks.

## Contributions
- Novel Rowhammer attack methodology that targets the KVM hypervisor from a guest VM in a contemporary virtualized environment.
- Circumvention of existing KVM mitigations that had previously disabled the key primitive used by earlier attacks.
- Demonstration of cross-privilege-boundary bit-flip exploitation to achieve hypervisor compromise.
