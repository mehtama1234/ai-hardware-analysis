# DAGonStore: Reliable Data Management for Workflows on the Computing Continuum with DynoStore and DAGonStar

**Venue:** SC 2025  
**Authors:** Dante D. Sánchez-Gallegos, José Luis González Compeán, Jesús Carretero, Raffaele Montella

## Problem Statement
The computing continuum (edge-to-cloud-to-HPC continuum) decentralizes processing but creates data management challenges:
- Heterogeneous storage nodes with varying reliability
- Network partitions and node failures common in distributed systems
- Data consistency across wide-area systems difficult
- Location-transparent access required for portable workflows

## Technical Approach
**DAGonStore Architecture:**
1. **Reliability Layer:**
   - Erasure codes for fault tolerance without full replication
   - Automatic recovery from node failures and disconnections
   - Maintains data availability during partial system failures

2. **Load-Balancing:**
   - Utilization-aware load-balancing distributes data and traffic
   - Monitors storage node usage and capacity
   - Adapts placement to avoid overload

3. **Integration:**
   - Works with DAGonStar workflow engine
   - Integrates DynoStore wide-area storage layer
   - Location-transparent data access to workflows

## Workflow Support
- **Data Placement:** Automatic distribution across continuum
- **Failure Handling:** Transparent recovery from node failures
- **Consistency:** Ensures input/output data remain accessible
- **Performance:** Load-balancing maintains throughput under failures

## Evaluation Results
- Demonstrated fault-tolerant workflow execution across computing continuum
- Maintained data availability under node failures
- Minimal user intervention required for fault handling
- Scalable to multiple storage nodes and failure scenarios

## Key Benefits
- **Resilience:** Automatic recovery from failures
- **Transparency:** Workflows unaware of failure handling
- **Efficiency:** Erasure codes reduce replication overhead
- **Balance:** Load-balancing improves resource utilization

## Limitations & Future Work
- **Scale Evaluation:** Tested system size not specified; large-scale behavior unclear
- **Erasure Code Overhead:** Performance and storage overhead not quantified
- **Latency Sensitivity:** Suitability for latency-critical workloads unclear
- **Comparison:** No comparison with other fault-tolerance approaches (replication, checksums)
- **Cost Analysis:** Trade-offs between reliability and performance not detailed
