# AMuLeT: Automated Design-Time Testing of Secure Speculation Countermeasures

**Venue:** ASPLOS 2025  
**ID:** asplos-2025-047  
**Confidence:** low (abstract only)

## Problem
Multiple Spectre hardware countermeasures have been proposed and then found insecure, but no automated tool tests speculation security guarantees early in the design phase, forcing slow, manual, expert-dependent verification.

## Motivation
Spectre-class vulnerabilities persist because verifying speculation security is slow and manual, delaying detection of flaws and iteration on fixes.

## Method
AMuLeT automatically tests whether proposed defenses against Spectre attacks work during hardware design, before building physical chips. It generates small test programs (litmus tests) that deliberately trigger speculative execution—when a CPU predicts ahead and runs instructions it might need—and varies both the timing windows when this speculation happens and the different ways an attacker could observe the side effects. The tool runs these tests on a software simulator of the hardware to find which Spectre attack variants each defense fails to block, giving designers rapid feedback to improve their solutions.

## Key Novelty
The key idea is automatically creating and running security tests during hardware design to catch whether speculative-execution attack defenses work, so engineers can quickly iterate without manual security analysis.

## Contributions
- AMuLeT automated design-time testing tool for Spectre countermeasures.
- Litmus test generation methodology covering diverse speculation windows and covert channels.
- Demonstrated identification of known insecurities in published Spectre countermeasures.
