# Pretraining LLMs at Scale: Tuning Strategies and Performance Portability

**Venue:** SC 2025  
**Authors:** Pérez Diéguez, Batlle Casellas, Torres-Camps, Teague, Ros-Giralt

## Problem
Large-scale LLM pretraining performance is highly sensitive to configuration choices:
- **ZeRO stages** (0/1/2/3) – Trade-off memory vs. communication
- **Communication collectives** – AllReduce, ReduceScatter, AllGather optimizations
- **Batch size** – Affects utilization and communication frequency
- **Default settings** – Far from optimal for specific hardware/network configurations

Result: Performance varies by 50%+ between default and tuned configurations on same hardware.

## Approach
**Communication-Aware Tuning Methodology:**

1. **Profile communication patterns** – Analyze AllReduce, ReduceScatter overhead
2. **Characterize hardware** – Network bandwidth, GPU utilization, memory
3. **Optimize ZeRO stages** – Select based on communication cost analysis
4. **Select collectives** – Match to network topology (Ethernet, NVLink, InfiniBand)
5. **Tune batch size** – Balance utilization with communication frequency

### Performance Portability Metric
Adapts cross-platform efficiency metric:
- Measures performance consistency across different systems
- High portability = tuning strategies work on diverse hardware
- Enterprise goal: Same methodology works across multiple clusters

## Results
- **1.6x speedup** over default DeepSpeed configurations
- **Production validation** at enterprise scale
- **Enterprise deployment** successful with tuned parameters

## Six Key Insights

### Challenge Prevailing Assumptions
1. **ZeRO stages trade-offs** – Stage 3 (most communication) not always optimal
   - Communication overhead can exceed memory savings
   - Stage 2 often better for networks with high latency

2. **Default communication collectives** – DeepSpeed defaults suboptimal for many networks
   - AllReduce not always best; ReduceScatter + BroadCast sometimes faster
   - Topology-specific selection critical

3. **Batch size criticality** – Often underestimated factor
   - Small changes (e.g., 512→1024) can cause 20% variance
   - Interacts with gradient accumulation steps
