# asplos-2025-097: Helix: Serving Large Language Models over Heterogeneous GPUs and Network via Max-Flow

**Venue:** ASPLOS  
**Confidence:** low (abstract only)

## Problem
Serving LLMs across heterogeneous GPU clusters (differing GPU types, memory capacities, and interconnect speeds) is inefficient because existing systems cannot jointly optimize model placement and request scheduling to account for both GPU and network heterogeneity simultaneously.

## Motivation
Real-world ML infrastructure increasingly mixes GPU generations and interconnect bandwidths; existing homogeneity-assuming serving systems leave significant throughput and latency on the table.

## Method
Helix converts the challenge of splitting an LLM across different GPUs into a flow optimization problem, represented as a graph where each GPU is a node and edges are labeled with their capacity (compute throughput and network bandwidth). A mathematical optimization solver (Mixed Integer Linear Programming, which searches for the best solution among all possibilities) then solves two problems together: deciding which model layers go on which GPU and how to route token requests through the cluster, finding the best placement and scheduling as a single system rather than optimizing them one at a time.

## Key Novelty
Unlike approaches that solve model placement and request scheduling independently, Helix solves them jointly as a single max-flow optimization problem, exposing trade-offs between the two decisions that separate approaches would miss.

## Contributions
- A max-flow graph formulation capturing both GPU and network heterogeneity via directed weighted edges.
- A MILP algorithm that jointly solves model placement and request scheduling on heterogeneous clusters.
- Up to 3.3x throughput improvement and up to 66%/24% reduction in prompting/decoding latency over existing approaches on 24-42 GPU heterogeneous clusters.
- Open-source Helix system.
