# Can Short Hypervectors Drive Feature-Rich GNNs? Strengthening the Graph Representation of Hyperdimensional Computing for Memory-efficient GNNs
**Venue:** DAC

## Problem
Hyperdimensional computing (HDC) requires ultra-long hypervectors (tens of thousands of bits) to express rich features, creating a memory bottleneck that offsets HDC's computational efficiency.

## Motivation
GNN memory accesses are a key bottleneck in graph processing; reducing hypervector dimension from tens of thousands to hundreds of bits enables massive memory savings for brain-inspired computing.

## Method
CiliaGraph adapts hyperdimensional computing—a method that normally requires extremely long vectors (tens of thousands of bits)—to work with short vectors (hundreds of bits) by fixing three core problems: using better encoding to prevent features from distorting when squeezed into fewer bits, applying weighted aggregation (combining neighboring nodes' information with varying importance based on graph structure) to reduce structural bias, and adding expanded supervision to ensure important nodes aren't left unrepresented. The approach succeeds because these neural operations are error-tolerant, allowing the network to learn accurately despite the significant information loss from using far shorter vectors.

## Key Novelty
CiliaGraph is the first graph neural network using hyperdimensional computing that breaks the consensus that you need tens of thousands of bits per vector, proving that hundreds of bits suffice for feature-rich graph learning.

## Contributions
1. 100-1000x reduction in memory access via short hypervectors
2. 100-300x reduction in training latency while maintaining competitive accuracy
3. Three resolved HDC-GNN incompatibilities (feature distortion, structural bias, central-node vacancy)
