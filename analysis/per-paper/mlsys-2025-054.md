# The Hidden Bloat in Machine Learning Systems

**Venue:** MLSYS 2025

## One-line Problem
ML framework shared libraries (PyTorch, TensorFlow, JAX, MXNet) are heavily bloated with unused GPU and CPU code, wasting memory and degrading runtime performance due to hardware-architecture mismatches.

## Method
Negativa-ML hooks into CUDA's cuModuleGetFunction API—a checkpoint where GPU kernels load before execution—to detect which GPU functions actually run on each workload. It removes bloat at two levels: individual functions and entire cubin files (compiled GPU binaries). CPU code bloat is identified using standard call-graph analysis. The method was tested on 4 ML frameworks (PyTorch, TensorFlow, JAX, MXNet), 10 real workloads, and 300+ shared libraries.

## Novelty
First tool to identify and remove GPU code bloat from ML shared libraries, revealing GPU code as the primary bloat source and hardware-architecture mismatch (code compiled for many GPU architectures, only one used) as the root cause.

## Key Metrics
- GPU code size: **up to 75% reduction**
- CPU code size: **up to 72% reduction**
- Total file size: **up to 55% reduction**
- Peak CPU memory: **up to 74.6% reduction**; Peak GPU memory: **up to 69.6% reduction**
- Execution time: **up to 44.6% reduction**
