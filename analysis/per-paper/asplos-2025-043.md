# ElasticMiter: Formally Verified Dataflow Circuit Rewrites

**Venue:** ASPLOS 2025  
**ID:** asplos-2025-043  
**Confidence:** low (abstract only)

## Problem
Dataflow circuits from HLS compilers cannot be optimized via standard sequential equivalence verification because their latency-insensitive handshake semantics are incompatible with traditional equivalence notions, leaving no sound basis for automated simplification.

## Motivation
HLS-generated dataflow circuits are increasingly important for both async and sync designs, but without formally verified transformation passes, circuits cannot be safely simplified post-synthesis, wasting area and timing slack.

## Method
These circuits are 'latency-insensitive'—they work no matter how fast or slow data arrives—which means standard circuit verification fails. ElasticMiter creates a 'miter' circuit (a testing harness that runs both the original and simplified circuits with the same inputs and checks for output mismatches) that verifies each simplification works under all possible arrival timings. Before applying any simplification rule, the system proves it with this miter, guaranteeing the result still works. The approach handles HLS-specific features like elastic buffering (delay-absorbing queues), fork/join nodes (where data splits and recombines), and control tokens.

## Key Novelty
This is the first formally verified system for transforming HLS dataflow circuits by building a miter that accounts for latency-insensitive timing to prove each simplification is correct.

## Contributions
- Generic equivalence verification framework for latency-insensitive dataflow circuits via miter construction.
- Graph rewriting system for systematic dataflow circuit datapath simplification.
- Formal proofs that each rewrite pattern preserves latency-insensitive equivalence.
- Foundation for formally verified dataflow HLS compilers.
