# SC25 Paper Analysis: sc-2025-097

## Tackling the Challenges of Adding Pulse-level Support to a Heterogeneous HPCQC Software Stack: MQSS Pulse

### Summary
This paper addresses the challenge of integrating pulse-level quantum control into heterogeneous HPC-Quantum Computing systems. Using MQSS (Munich Quantum Software Stack) as a case study, it identifies four key integration challenges and proposes concrete solutions including a compiled pulse API, LLVM extensions, and portable exchange formats.

### Key Problem
- **Pulse Control Gap**: Current HPCQC systems don't support pulse-level access to quantum hardware
- **Low-Level Abstraction**: Quantum control requires ports, frames, and waveforms that need integration
- **Integration Complexity**: Multiple system layers need coordination (UI, compiler, runtime, backend)

### Technical Challenges & Solutions
1. **User-Interface Level**: Python overhead → Solution: Compiled C/C++ Pulse API
2. **Compiler Level (IR)**: No pulse abstractions → Solution: LLVM extension for pulse instructions
3. **Backend Interface**: Hardware constraints unclear → Solution: C-based interface for constraint queries
4. **Exchange Format**: No standard representation → Solution: Portable pulse sequence format

### Contributions
1. Systematic identification of pulse-level integration challenges
2. Compiled C/C++ pulse API for efficiency
3. LLVM extension for pulse instruction support
4. C-based backend interface for hardware-aware compilation
5. Portable pulse exchange format
6. End-to-end pulse-aware compilation framework
7. Architectural blueprint for future HPCQC systems

### Hardware & Workloads
- **Target Hardware**: Quantum processors in HPCQC systems
- **Workloads**: Hybrid quantum-classical applications with pulse-level control

### Key Abstractions
- **Ports**: Input/output channels
- **Frames**: Reference signals
- **Waveforms**: Pulse envelopes

### Applications
