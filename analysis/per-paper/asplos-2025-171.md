# asplos-2025-171: Tally: Non-Intrusive Performance Isolation for Concurrent Deep Learning Workloads

**Venue:** ASPLOS  
**Confidence:** low (abstract-only)

## Problem
GPU sharing for concurrent DL workloads suffers from high interference, causing up to 188.9% latency overhead on high-priority inference tasks. Existing mechanisms impose high integration costs, inadequate isolation, and limited compatibility.

## Motivation
GPU underutilization in production DL clusters causes prolonged job queues and increased costs, making efficient multi-tenant sharing critical.

## Method
Tally uses fine-grained thread-block-level GPU kernel scheduling. It intercepts kernel launches and dynamically schedules thread blocks across co-running workloads without application modification, controlling interference at thread-block granularity rather than at the kernel or process level.

## Key Novelty
Thread-block-level GPU kernel scheduling that enforces isolation between concurrent workloads without any application-side changes.

## Contributions
- Non-intrusive GPU sharing requiring no application or framework modification
- Fine-grained thread-block-level scheduling to mitigate co-execution interference
- Only 7.2% P99 latency overhead on inference vs. 188.9% for TGS
- >80% throughput retention relative to TGS
