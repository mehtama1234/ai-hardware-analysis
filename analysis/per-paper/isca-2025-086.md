# Finesse: An Agile Design Framework for Pairing-based Cryptography via Software/Hardware Co-Design

**ID:** isca-2025-086 | **Venue:** ISCA | **Confidence:** high (full text)

## Problem
PBC accelerators require frequent re-engineering as security demands grow and pairing curve parameters evolve (BN254 to BLS24-509 etc.), but existing designs are either highly customized (inflexible) or flexible but low-performance. No framework automates the algorithm-to-hardware translation across diverse pairing curves, and the interdependency among algorithm choices, finite-field operator variants, and hardware configurations makes DSE intractable manually.

## Motivation
Evolving cryptographic attacks force migration to larger bit-width pairing curves; pairing is already 2 orders of magnitude slower than standard signatures, making hardware acceleration critical and re-engineering costs prohibitive.

## Method
Finesse uses a three-layer design: an intermediate representation (shared notation) for math operations on finite and extension fields, a RISC-style instruction set that executes multiple instructions per cycle (VLIW extension), and a customizable hardware pipeline model. A specialized compiler optimizes data flow, schedules instructions using issue-slot affinity (aligning long arithmetic operations with short linear ones to prevent conflicts), allocates registers, and generates executable code. A cycle-accurate simulator measures real performance and feeds results back to both the compiler and the hardware design tools (EDA toolchain) for joint optimization. The hardware implements four core arithmetic operations (mmul, madd, mlin, minv) in a multi-core SIMT (single instruction executing on multiple cores with different data) architecture with shared instruction memory, on both 40nm ASIC and Virtex-7 FPGA.

## Key Novelty
The innovation is issue-slot affinity scheduling, which partitions the pipeline's instruction slots into periodic intervals and aligns long modular-multiplication operations with short linear operations to eliminate write-back conflicts, combined with a co-design feedback loop between the compiler and hardware synthesis tools (EDA) that jointly optimizes any pairing curve implementation.

## Contributions
1. Finesse agile framework spanning algorithm IR to hardware RTL for 7 curves across 3 families, with compilation in 8–53 seconds
2. Three-layer abstraction (IR, ISA, pipeline model) decoupling algorithm variants from hardware
3. Issue-slot affinity scheduling improving IPC from ~0.19 to ~0.87–0.97 across BN and BLS families
4. 34x throughput and 6.2x slice efficiency over FlexiPair; 3x throughput and 3.2x area efficiency over SOTA non-flexible ASIC

## Metrics
- Area: 1.77 mm2 (1-core 40nm), 8.00 mm2 (8-core 40nm)
- Area efficiency: 12.09 kops/mm2 (8-core, 40nm) vs 1.39 kops/mm2 prior ASIC (65nm equiv.)
- Throughput: 34x vs FlexiPair; 3x vs SOTA ASIC
- IPC: 0.19 → 0.87–0.97 after scheduling optimization
- Compile time: 8s (BN254) to 53s (BLS24-509)

## Baselines
FlexiPair (flexible FPGA framework), prior SOTA ASIC (65nm FDSOI, 250 MHz)

## Limitations
Design-space exploration currently relies on exhaustive search over operator variant combinations; this may not scale to more complex future curves with larger embedding degrees.
