# Comparing Distributed-Memory Programming Frameworks with Radix Sort

**Venue:** SC | **ID:** sc-2025-105

## Summary
Comparative empirical study of five distributed-memory parallel programming frameworks (Chapel, MPI, OpenSHMEM, Conveyors, Lamellar) using distributed radix sort as a communication-intensive benchmark.

## Problem & Motivation
Distributed-memory frameworks vary in capabilities for managing communication and synchronization overhead. Developers lack empirical data to guide framework selection across supercomputer architectures. The paper addresses this gap by implementing the same algorithm across five frameworks and measuring performance trade-offs.

## Key Findings
- **Chapel** outperforms on both code simplicity (113 SLOC) and performance (17B elements/sec on 128 HPE Cray nodes)
- Significant differences in productivity/performance trade-offs across frameworks
- Open-source reference implementations enable reproducibility and community optimization

## Hardware & Systems
- HPE Cray Supercomputing EX (128 nodes evaluated)
- Multi-node distributed-memory clusters
- Focus on supercomputer scalability

## Techniques
- Distributed radix sort implementation
- Communication-intensive algorithm benchmark
- Framework performance metrics (throughput, code size)

## Metrics
| Metric | Value |
|--------|-------|
| Peak throughput | 17B elements/second |
| Implementation size | 113 SLOC (Chapel) |
| Scale tested | 128 nodes |

## Contributions
1. Empirical comparison providing practical framework selection guidance
2. Demonstrated Chapel's superior code productivity (113 SLOC)
3. Open-source implementations for continued optimization
4. Quantified scalability differences across frameworks

## Limitations
- Single algorithm (radix sort) may not represent all communication patterns
- Generalizability to computation-bound or latency-critical workloads unclear
- Limited to HPE Cray systems in evaluation
