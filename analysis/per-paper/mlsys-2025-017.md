# Dynamic Input Pruning for Efficient LLM Inference on Mobile Devices

**Venue:** MLSys 2025 | **ID:** mlsys-2025-017 | **Confidence:** high

## Problem
SwiGLU MLP layers on mobile devices fully load all weight matrices from DRAM per token, causing excessive energy and low throughput on bandwidth-constrained hardware.

## Method
Dynamic Input Pruning (DIP) saves DRAM bandwidth by selecting only the K largest input values entering the MLP layer—a process called top-K selection based on input magnitude (the size of the numbers)—and ignoring the rest, which means you don't need to load weight columns for inputs you're skipping. Instead of using a separate predictor network to decide what to keep, DIP simply looks at input magnitudes directly. A cache-aware variant called DIP-CA goes further: it uses a gamma multiplier (gamma=0.2) to prefer keeping weight columns that are already in the device's fast cache, reducing how often the device needs to fetch data from DRAM. Testing on Apple A18 processors (60 GB/s DRAM, 1 GB/s Flash) with Phi-3-Medium and LLaMA models showed the approach works, and LoRA fine-tuning can recover any accuracy lost.

## Novelty
Predictor-free input-magnitude-based dynamic pruning of all three SwiGLU MLP matrices, with a cache-aware variant that maximizes DRAM reduction by coordinating selection with hardware memory hierarchy.

## Metrics
- 46% DRAM reduction on Phi-3-Medium
- 40% throughput increase on Apple A18 simulation
- <0.1 perplexity increase at optimal sparsity
