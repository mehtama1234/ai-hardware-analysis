# Redesigning GROMACS Halo Exchange: Improving Strong Scaling with GPU-initiated NVSHMEM

**Venue:** SC 2025  
**Authors:** Doijade, Alekseenko, Brown, Gray, Páll

## Problem
GROMACS molecular dynamics simulations struggle with strong scaling (fixed problem size, increasing nodes) on heterogeneous GPU systems:

1. **Latency-sensitive workload** – Peak iteration rates in sub-millisecond regime (~0.5-1.0 ms)
2. **MPI CPU-centric bottleneck** – GPU must wait for CPU to coordinate MPI communication
3. **Halo-exchange overhead** – Domain decomposition ghost zone exchange becomes critical bottleneck
4. **GPU underutilization** – GPU idle during CPU-initiated MPI waits

Traditional pipeline: GPU compute → GPU wait for CPU MPI coordination → CPU MPI → GPU wait for halo data

## Approach
**GPU-Initiated NVSHMEM Halo Exchange:**

### Architecture Change
GPU-resident kernel directly communicates instead of CPU middleman:
```
GPU Kernel: pack halo data + NVSHMEM remote write
         (overlapped via async copy engine)
vs.
MPI model: GPU→CPU (PCIe), CPU MPI_Isend, CPU MPI_Irecv, GPU waits
```

### Technical Components

1. **Kernel Fusion** – Single GPU kernel:
   - Compacts halo data (pack step)
   - Initiates NVSHMEM writes to neighbors
   - Continues computing while data in flight

2. **Asynchronous Copy Engine** – NVLink feature:
   - Copies data asynchronously
   - CPU not involved in transfer
   - Overlaps with GPU computation

3. **Fine-Grained Overlap** – Computation during communication:
   - Forward communication phases
   - Backward computation phases
   - Minimize communication-free zones

## Performance Results

### Speedups (Strong Scaling)

| Scenario | Speedup |
|----------|---------|
| Intra-node (NVLink) | 1.5x |
| Multi-node (NVLink) | 2x |
| Multi-node (NVLink + InfiniBand) | 1.3x |

### Interpretation
- **Largest gains on NVLink** (2x multi-node) – GPU-GPU direct is bottleneck
- **Smaller gains with IB inter-connect** (1.3x) – network bandwidth becomes limiting
- **Intra-node (1.5x)** – NVLink latency reduction primary benefit

## Hardware Target
- **NVIDIA GPUs** (A100 or H100 implied)
- **NVLink** intra-node communication
- **InfiniBand** inter-node communication
- Exascale-scale cluster (implied multi-node experiments)

## Key Insight
**CPU-mediated communication is fundamental bottleneck** for latency-sensitive workloads:
- Removing CPU from critical path → 2x speedup possible
- Demonstrates benefit of GPU autonomy over CPU coordination

## Limitations

### Scope Constraints
- **GROMACS-specific** – Unclear if technique generalizes to other MD codes (NAMD, AMBER, LAMMPS)
- **Halo-exchange-specific** – Works for structured communication patterns; less clear for irregular codes

### Evaluation Gaps
- Problem size/scale not specified
- Specific HPC system not named
- Pure NVLink vs. mixed NVLink+IB comparison limited
- MPI library optimizations (MPICH vs. OpenMPI) not explored

### Hardware Assumptions
- Assumes NVLink bandwidth sufficient (not all GPU types have NVLink)
- Assumes NVSHMEM library available and optimized on target system
- Assumes symmetric network connectivity

## Technical Challenges Addressed
1. **Data packing** – GPU kernel must efficiently pack halo data (coalesced memory access)
2. **Overlap coordination** – Ensure computation doesn't touch halo data being written
3. **Multi-node topology** – NVSHMEM routing across network interfaces
4. **Error recovery** – One-sided semantics require careful error handling

## Related Concepts
- One-sided communication (NVSHMEM)
- Molecular dynamics strong scaling

## Significance for SC Community
**Challenges "GPU + MPI" paradigm:**
- GPU-initiated communication outperforms CPU-mediated for latency-sensitive workloads
- Implies paradigm shift: GPU as autonomous agent, not CPU's accelerator
- Could inspire redesigns of other latency-sensitive algorithms

## Generalization
Likely applicable to:
- Finite-element methods (FEM) with structured connectivity
- Lattice Boltzmann methods
- Other stencil-based codes with predictable halo exchange
- NOT applicable to irregular/unstructured communication patterns
