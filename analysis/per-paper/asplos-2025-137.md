# asplos-2025-137: RTL Verification for Secure Speculation Using Contract Shadow Logic

**Venue:** ASPLOS  
**Confidence:** low (abstract-only)

## Problem
Out-of-order processors face speculative execution attacks, and proposed hardware mitigations lack formal, RTL-level security proofs, leaving unknown vulnerabilities as new attacks continue to emerge.

## Motivation
Formal and rigorous evaluation of processor hardware designs against speculative execution attacks is urgently needed to break the cycle of ad-hoc mitigations and newly discovered exploits.

## Method
Contract Shadow Logic adds a verification layer (called shadow logic) to a processor's hardware design (RTL). This layer encodes contracts—rules defining what information the processor can leak when it speculatively executes ahead (runs instructions before confirming they're needed). The shadow logic tracks information flow through speculative execution, and automated verification tools (model checking or equivalence checking) verify that no possible execution violates the contracts. The result is a formal proof that the hardware is secure against speculative execution side-channel attacks.

## Key Novelty
By embedding verification logic (shadow logic) that tracks information leakage directly in processor hardware code (RTL), you can mathematically prove the design is secure against speculative execution attacks.
