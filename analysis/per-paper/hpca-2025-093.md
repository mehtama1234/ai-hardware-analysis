# hpca-2025-093 — OASIS: Object-Aware Page Management for Multi-GPU Systems

**Venue:** HPCA  
**Confidence:** low (abstract-only)

## Problem
Unified Virtual Memory (UVM) in multi-GPU systems applies a single, application-object-agnostic page placement and migration policy to all data, failing to account for the fact that different data objects and different execution phases of the same object benefit from different page management strategies.

## Motivation
As multi-GPU systems scale to handle larger deep learning workloads, UVM's one-size-fits-all page management causes unnecessary migrations, missed duplication opportunities, and suboptimal data locality, leaving significant performance on the table.

## Method
OASIS dynamically identifies application object access patterns at runtime by monitoring page-access counters and tracking object-level access behaviors across execution phases. Based on the detected patterns, it proactively assigns one of several page management policies—on-touch migration, access-counter-based migration, or duplication—to each object on a per-phase basis. The policy decision logic runs in software/hardware coordination and uses lightweight profiling to adapt to phase changes without manual programmer annotation.

## Key Novelty
Runtime object-aware, phase-adaptive page management that automatically selects among migration and duplication policies per data object in multi-GPU UVM systems.

## Contributions
- Characterization of object-level page access behavior variation across application objects and execution phases in multi-GPU workloads
- OASIS: a dynamic runtime system for object-granularity, phase-adaptive page management policy selection
- 64% improvement over on-touch migration, 35% over access-counter migration, 42% over duplication
- 12% improvement over state-of-the-art GRIT with significantly lower design complexity
