# UGPU: Dynamically Constructing Unbalanced GPUs for Enhanced Resource Efficiency

**Venue:** ISCA  
**Confidence:** low (abstract-only)

## Problem
Physical GPUs maintain a fixed, balanced ratio of compute and memory resources, which is inefficient when co-executing workloads have heterogeneous compute-to-memory demands. Partitioning a GPU into unbalanced slices requires accurate performance prediction under variable resource allocations and causes heavy data migration overhead when memory resources are redistributed.

## Motivation
Cloud GPUs serving multiple concurrent tenants waste resources because no single balanced configuration is optimal for the diverse compute-memory ratios of simultaneously running applications.

## Method
UGPU dynamically carves a single physical GPU into unbalanced GPU slices—each with a tailored compute-SM count and HBM capacity—using a demand-aware resource partitioning algorithm that avoids complex analytical performance models. To handle memory redistribution without incurring the latency of traditional page migration, it introduces PageMove, which exploits the fact that all HBM memory channels share physical TSV connections within the DRAM stack, enabling parallel page migration between bank groups. PageMove pairs a customized memory address mapping with a Parallel Page Migration Mode (PPMM) and updated virtual memory management to move pages across memory dies at high throughput concurrently.

## Key Novelty
PageMove exploits pre-existing intra-stack TSV connectivity and simultaneous multi-bank-group transfers in HBM to execute parallel page migration between memory dies, eliminating the dominant overhead of dynamic GPU slice reconfiguration.

## Contributions
- First study of dynamically constructing unbalanced GPU slices from a single physical GPU for multi-tenant cloud workloads.
- Demand-aware resource partitioning algorithm that adaptively sizes compute and memory slices without a performance model.
- PageMove: a lightweight HBM architecture extension enabling parallel page migration across bank groups via TSV connections.
- Custom memory address mapping and PPMM protocol integrated with virtual memory management to support live slice reconfiguration.
