# isca-2025-076 — In-Storage Acceleration of Retrieval Augmented Generation as a Service

**Venue:** ISCA  
**Confidence:** low (abstract only)

## Problem
When RAG knowledge bases move to persistent NVMe storage, the Search & Retrieval phase (embedding model inference + similarity search + high-latency storage accesses) becomes the dominant end-to-end latency contributor, erasing the cost benefits of using persistent storage.

## Motivation
Growing knowledge bases make DRAM-only RAG economically impractical; in-storage compute is required to avoid retrieval bottlenecks from degrading LLM generation service quality.

## Method
A metamorphic in-storage accelerator is embedded inside NVMe storage devices. It is programmable to handle diverse RAG retrieval algorithms, dynamic data structures (HNSW, IVF), and varying compute patterns without host CPU involvement. The accelerator also runs smaller language models for query embedding generation in-storage, while final LLM generation executes on DGX A100 systems.

## Key Novelty
A metamorphic (reconfigurable) in-storage accelerator that executes both query embedding inference and similarity search entirely within the storage device, eliminating round-trips to host memory.

## Contributions
1. Empirical identification of Search & Retrieval as the dominant RAG latency bottleneck with persistent storage
2. Metamorphic in-storage accelerator supporting diverse RAG algorithms and dynamic data structures
3. In-storage execution of smaller language models for query embedding
4. Up to 4.3x throughput improvement over Xeon + NVMe; 1.5x over A100 + DRAM

## Hardware Target
ASIC, SoC

## Technique Category

## Workloads

## Metrics
- Speedup: 4.3x vs. Xeon CPU + NVMe; 1.5x vs. A100 GPU + DRAM

## Baselines
Xeon CPUs with NVMe storage, A100 GPUs with DRAM

## Limitations
In-storage execution limited to smaller embedding models; large LLM generation still requires external GPU.
