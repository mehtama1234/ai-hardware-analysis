# hpca-2025-018 — NVMePass: A Lightweight, High-performance and Scalable NVMe Virtualization Architecture with I/O Queues Passthrough

**Venue:** HPCA  
**Confidence:** low (abstract-only)

## Problem
Existing NVMe virtualization approaches either degrade performance (Virtio software path) or require dedicated hardware with limited VM scalability (VFIO/SR-IOV). No solution achieves near-native I/O performance, zero CPU overhead, and high VM count scalability simultaneously.

## Motivation
Cloud storage workloads require low-latency NVMe at scale; performance-CPU overhead trade-offs in existing virtualization constrain VM consolidation without SLA degradation.

## Method
NVMePass allows virtual machines to communicate directly with NVMe storage devices, bypassing the hypervisor (the software layer that normally mediates all access). Each VM is assigned exclusive I/O queues (communication channels with the storage) and storage space (logical block address ranges) that cannot overlap. A new hardware component called an NVMe Resource Domain (NRD), built into the storage controller itself, acts as a security guard for storage access—it checks every request and blocks any VM from accessing storage assigned to another VM. Because the hypervisor no longer needs to inspect every storage operation, the system achieves near-native performance without the slowdown that comes from software mediation.

## Key Novelty
The key innovation is a hardware component (NVMe Resource Domain) embedded in the storage controller that enforces VM isolation and enables full I/O queue passthrough without any hypervisor involvement in the storage data path.

## Contributions
- NVMePass architecture: NVMe I/O queue passthrough with zero hypervisor data-path involvement.
- NVMe Resource Domain (NRD) hardware primitive for device-level VM isolation.
- DMA/interrupt remapping eliminating virtualization overhead without SR-IOV hardware.
- 100.1-100.5% IOPS of VFIO; 40% lower latency vs. SPDK-Vhost at 150 VMs; 68% throughput improvement at 100 VMs.
