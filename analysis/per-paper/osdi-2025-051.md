# NanoFlow: Towards Optimal Large Language Model Serving Throughput

**Problem:** Existing LLM serving engines achieve poor compute utilization because heterogeneous operations (compute, memory, networking) execute sequentially within devices. Despite assumptions that LLM serving is memory-bound, it is actually compute-bound for most workloads.

**Method:** NanoFlow improves GPU utilization by running multiple copies of the same operations on a single GPU at the same time—by splitting the input into smaller nano-batches. This works because while one batch is computing, the GPU can simultaneously fetch data for the next batch and transmit the previous result over the network, so compute, memory transfer, and networking overlap instead of happening one after another. The system automatically figures out how many nano-batches to create, their size, the order to process them, and how to split the GPU's resources among them, all while managing interference between concurrent operations to minimize total execution time.

**Novelty:** Nano-batches enable intra-device parallelism (concurrent operations on one GPU) by overlapping compute, memory transfer, and networking instead of sequential execution.
