# isca-2025-074 — OptiPIM: Optimizing Processing-in-Memory Acceleration Using Integer Linear Programming

**Venue:** ISCA  
**Confidence:** low (abstract only)

## Problem
Efficient PIM acceleration requires careful software-hardware mapping (algorithm-to-PIM operation and data layout), but existing accelerators use manual heuristics or exhaustive search, producing under-optimized performance and/or long search times.

## Motivation
PIM accelerators' advantage — exploiting internal memory bandwidth — is only realized with good mappings; automated, provably optimal mapping generation is the missing piece.

## Method
OptiPIM formulates PIM mapping as an Integer Linear Programming (ILP) problem. A PIM-friendly mapping representation with accurate cost modeling concisely covers the full design space, making the ILP tractable. The framework is implemented as a compiler pass in MLIR, consuming PyTorch workloads and emitting optimized mappings for PIM targets. Optimal mappings are produced within 4 minutes.

## Key Novelty
Formulation of the PIM mapping problem as an ILP within MLIR, enabling provably optimal mapping generation for data-intensive ML workloads in practical time.

## Contributions
1. PIM-friendly mapping representation with cost model for concise ILP formulation
2. ILP-based optimizer generating optimal mappings within 4 minutes
3. MLIR integration for PyTorch workload support on PIM accelerators
4. At least 1.9x speedup over heuristic mappings on state-of-the-art PIM accelerators

## Hardware Target
PIM (processing-in-memory)

## Technique Category
compiler, scheduling, near-data-processing

## Workloads
CNN, transformer, LLM-inference

## Metrics
- Speedup: at least 1.9x over heuristic mappings
- Optimization time: within 4 minutes

## Baselines
Manually tuned heuristics on state-of-the-art PIM accelerators

## Limitations
ILP tractability may degrade for very large design spaces; generalization beyond ML workloads not fully demonstrated.
