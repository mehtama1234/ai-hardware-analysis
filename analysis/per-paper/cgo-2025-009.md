# MTE4JNI: A Memory Tagging Method to Protect Java Heap Memory from Illicit Native Code Access

**Venue:** CGO 2025 | **Confidence:** Low (abstract-only)

## Problem & Motivation
Java Native Interface (JNI) allows native code to directly access Java heap via raw pointers, bypassing Java's safety guarantees. Android-wide adoption makes mobile security critical.

## Technical Approach
Leverages ARM Memory Tagging Extension (MTE) to tag Java heap objects. Runtime enforcement monitors native JNI code access, comparing pointer tags against object tags to prevent unauthorized dereferences.

## Key Novelty
This is the first method using ARM's Memory Tagging Extension to protect Java heap from unauthorized access via JNI (the interface that lets native code access Java).

## Key Results
- 11× overhead reduction vs. guarded copy (single-threaded)
- 27× reduction (multi-threaded)
- Superior memory safety protection with practical overhead

## Hardware & Techniques
- **Target:** CPU (ARM MTE)
- **Techniques:** Memory tagging, security, JNI enforcement
