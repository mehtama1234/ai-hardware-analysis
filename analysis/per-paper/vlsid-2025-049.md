# hbcLock: Encrypted RF Communication Utilizing Body-Coupled Keys for the Internet of Bodies

**ID**: vlsid-2025-049 | **Venue**: VLSID | **Confidence**: low (abstract only)

## Problem Statement
Wearable devices continuously transmitting sensitive health data (ECG, vital signs) via RF technologies (BLE, Wi-Fi) face eavesdropping risks from nearby adversaries. Traditional key management schemes are impractical for implanted or body-worn bioelectronics.

## Motivation
Internet of Bodies (IoB) applications require both cryptographic security and practical key establishment methods. Leveraging the human body as an implicit authentication channel could enable secure wearable communication without cumbersome key infrastructure.

## Method
- **Approach**: Hybrid RF + body-coupled communication system
- **Process**:
  1. Wearable encrypts biodata (e.g., ECG) using local key
  2. Transmits encrypted data over RF (BLE)
  3. Simultaneously transfers unencrypted encryption key through body tissue
  4. Receiver captures key via body contact, decrypts RF-received data
- **Prototype**: Custom wearable + receiver hardware, 1-lead ECG use case

## Key Results
- **Signal Integrity**: 100% match achieved between decrypted ECG and original
- **Integration**: Successful parallel operation of RF encryption + body key transfer
- **Characterization**: Preliminary human body channel measurements for feasibility

## Novelty & Contributions
1. **First practical hybrid system** combining RF encryption with human-body-channel key establishment
2. **Proof-of-concept implementation** demonstrating end-to-end system functionality
3. **Body-channel characterization** providing baseline for human tissue key transfer
4. **Zero-configuration security** eliminating pre-shared key infrastructure

## Limitations
- **Minimal bio-signal scope**: Demonstration limited to 1-lead ECG; multi-channel scalability unknown
- **Channel characterization incomplete**: Body channel attenuation, variability, and long-term reliability only preliminary
- **Limited threat model**: Assumes proximity-based contact; distant RF eavesdropping and spoofing not addressed
- **No formal security analysis**: No penetration testing, side-channel analysis, or formal security proofs
- **Implementation details sparse**: Power consumption, form factor, latency not discussed
- **Single subject**: Preliminary experiments likely on limited number of subjects
