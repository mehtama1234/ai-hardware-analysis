# Marching Page Walks: Batching and Concurrent Page Table Walks for Enhancing GPU Throughput

**Venue:** HPCA  
**Confidence:** low (abstract-only)

## Problem
GPU page table walkers handle only a single walk request at a time, creating severe queuing latency when thousands of concurrent threads simultaneously demand address translation across wide virtual address ranges.

## Motivation
Virtual memory support is critical for GPU programmability, but the mismatch between single-request-per-walker hardware and massively parallel GPU thread address translation demands causes a major performance bottleneck.

## Method
Marching Page Walks scans the queue of pending address translation requests to find groups that can share the same page table lookups—for example, when different threads need to translate nearby addresses that map through the same page table entry (the lookup table mapping virtual to physical memory). It bunches these compatible requests and sends multiple lookup instructions to memory at once instead of one at a time. This batching works because GPU workloads tend to access memory in clusters, with many threads working on nearby addresses simultaneously.

## Key Novelty
Marching Page Walks lets a single page table walker send multiple address translation requests concurrently by batching requests that share page table lookups, cutting queue waiting times without needing extra hardware.

## Contributions
1. Identification of walker queuing latency as the dominant bottleneck in GPU address translation
2. MPW design that scans and groups pending walk requests sharing page table memory accesses
3. Concurrent multi-request issuance per walker mechanism
4. 86.7% reduction in page walk queuing latency and 55.6% average GPU performance improvement

## Limitations
