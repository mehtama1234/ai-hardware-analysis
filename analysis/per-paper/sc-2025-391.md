# Towards a user-centric HPC-QC environment

**Venue:** SC
**ID:** sc-2025-391
**Confidence:** low

## Problem

Hybrid HPC-QPU systems lack robust execution environment for hybrid quantum-classical programs; integration challenges in scheduling, portability, and reproducibility.

## Motivation

Portable runtime environment needed for hybrid quantum-classical program development in HPC with QPU integration.

## Method

They designed a software intermediary (middleware) that improves hybrid HPC-quantum systems by adding a second scheduling stage after the main HPC scheduler. This second stage uses QRMI—a manufacturer-independent standard interface—to optimize when and how quantum processors (QPUs) run their tasks. The system includes monitoring and observability tools to show what's happening and help developers diagnose issues.

## Key Novelty

A second scheduling layer using vendor-neutral standards (QRMI) to optimize quantum processor use in hybrid HPC systems.

## Contributions

1. Portable runtime for hybrid quantum-classical HPC programs
2. Second-layer QPU scheduling mechanism
3. Multi-SDK management via QRMI
4. Monitoring and observability infrastructure
5. Hybrid system architecture
