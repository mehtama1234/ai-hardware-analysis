# PCcheck: Persistent Concurrent Checkpointing for ML

**Venue:** ASPLOS  
**Authors:** Foteini Strati, Michal Friedman, Ana Klimovic  
**Confidence:** low (abstract only)

## Problem
Checkpointing large ML training runs to persistent storage introduces high overhead when done at high frequency, yet infrequent checkpointing leads to long recovery times after failures — a growing problem as training scale increases and cheap spot VMs dramatically raise failure rates.

## Motivation
As ML training jobs scale to thousands of GPUs over weeks and increasingly use preemptible spot VMs, the probability and cost of failures rises sharply, requiring checkpointing solutions that are simultaneously low-overhead and high-frequency.

## Method
PCcheck saves neural network models to durable storage while training continues, by overlapping the storage I/O with GPU computation so neither blocks the other. It uses copy-on-write snapshots (capturing only what changes in model state) and pipelined multi-stage I/O (sending data to storage in stages). The system tracks consistency across concurrent training steps to guarantee each checkpoint is valid and recoverable.

## Key Novelty
PCcheck overlaps checkpoint storage with training compute using copy-on-write snapshots and pipelined I/O, enabling frequent durable checkpoints without slowing training.

## Contributions
- PCcheck: a persistent concurrent checkpointing system for large-scale ML training
- Copy-on-write model state snapshots enabling overlap of checkpoint I/O with training computation
- Pipelined multi-stage I/O reducing checkpoint-induced training pauses
- Support for high-frequency checkpointing with low overhead on spot VMs and large GPU clusters
