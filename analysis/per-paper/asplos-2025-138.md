# asplos-2025-138: pulse: Accelerating Distributed Pointer-Traversals on Disaggregated Memory

**Venue:** ASPLOS  
**Confidence:** low (abstract-only)

## Problem
CPU-side caches in disaggregated memory architectures cannot amortize network latency for pointer-chasing workloads over linked data structures, because each traversal step depends on the preceding result, making prefetching and caching ineffective.

## Motivation
Disaggregated memory is increasingly deployed for rack-scale resource pooling, but pointer-intensive operations suffer from serial network round-trips that caching cannot hide.

## Method
In disaggregated memory systems (where CPU and memory servers are separated by network), following a chain of pointers normally requires the CPU to send many individual requests to memory—and each request must wait for the previous answer before asking the next question, creating network delays. pulse eliminates this by placing processing elements directly on the memory servers; these local engines can follow the pointer chains in place, fetching each next address immediately without network round-trips. The framework supports different types of linked structures (linked lists, trees, graphs) and can distribute work across multiple memory servers so multiple traversals run in parallel, improving speed, power efficiency, and throughput.

## Key Novelty
Rather than having the CPU repeatedly request the next pointer over the network, pulse runs the traversal directly on the memory servers, eliminating network delays for each step.
