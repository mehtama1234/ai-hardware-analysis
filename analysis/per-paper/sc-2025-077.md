# Story of Two GPUs: Characterizing the Resilience of Hopper H100 and Ampere A100 GPUs

**Venue:** SC 2025  
**Authors:** Cui, Patke, Nguyen, Ranjan, Chen, Cao, Bauer, Bode

## Problem
Exascale AI systems mix GPU generations (A100, H100). Resilience differences between generations directly impact system availability and job completion rates, but large-scale empirical data is scarce.

## Dataset & Methodology
**Delta Supercomputer Study:**
- 1,056 total GPUs (A100 + H100 mix)
- 2.5 years operational data
- 11.7 million GPU hours of error tracking
- Error types: memory, hardware component failures
- Analysis: MTBE (Mean Time Between Errors), recovery effectiveness, failure modes

## Key Findings

### Memory Resilience
- **H100 memory 3.2x worse MTBE** than A100 per-GPU
- H100's increased memory capacity (80 GB vs. 40 GB) exacerbates error exposure
- Recovery mechanisms insufficient to handle increased memory footprint

### Hardware Resilience
- **H100 hardware resilience improved** over A100 for critical components
- Apparent tension: memory errors up, hardware resilience down – distinct failure domains

### Application Impact
- **GPU errors → job failures** due to lack of robust recovery at application level
- No transparent error detection/recovery framework in production workloads

### Scaling Projection
- **5% GPU overprovisioning required** for larger-scale systems
- Implies 1-in-20 nodes held as spare capacity to maintain availability

## Architecture Comparison

| Aspect | A100 | H100 |
|--------|------|------|
| Memory capacity | 40-80 GB | 80 GB |
| Memory MTBE | Baseline | 3.2x worse |
| Hardware resilience | Baseline | Better |
| Recovery mechanisms | Limited | Insufficient |

## Implications
1. H100 adoption requires addressing memory resilience gap
2. Application-level fault tolerance mechanisms critical at exascale
3. System-level redundancy (5% overprovisioning) necessary trade-off

## Limitations
- Delta-specific population; other GPU clusters may show different patterns
- No analysis of memory error types (SEC/DED, correctable vs. uncorrectable)
- Workload characteristics not disclosed
- No proposed solutions for recovery mechanism improvement

## Related Concepts
- GPU reliability engineering
- Exascale system availability
- Fault tolerance for AI accelerators
- Memory error characterization
