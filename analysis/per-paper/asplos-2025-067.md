# CIPHERMATCH: Accelerating Homomorphic Encryption-Based String Matching via Memory-Efficient Data Packing and In-Flash Processing

**Venue:** ASPLOS 2025  
**Confidence:** low (abstract-only)

## Problem
HE-based exact string matching incurs prohibitive computational latency from expensive HE operations (multiplication, rotation) and severe data movement from large ciphertext footprints.

## Motivation
Privacy-sensitive cloud applications (DNA read mapping, biometric matching, web search) require secure string matching on encrypted data, but HE costs make real-time deployment infeasible.

## Method
Homomorphic encryption lets you compute on encrypted data without decrypting it, but it's slow because multiplication and rotation operations cost a lot of computation, and the encrypted data takes up lots of memory and uses lots of bandwidth. CIPHERMATCH tackles this three ways: it packs encrypted data more efficiently to use less memory, redesigns the string matching algorithm to use cheaper addition operations instead of expensive multiplication and rotation, and moves computation close to flash storage to avoid repeatedly transferring encrypted data between storage and main memory.

## Key Novelty
The core idea is combining algorithm redesign to eliminate expensive multiplication with in-flash processing (computing near flash storage to avoid moving data between storage and main memory).

## Contributions
- Optimized software data packing reducing HE ciphertext footprint
- Algorithm reformulation removing expensive HE multiply/rotate operations
- In-flash processing (IFP) hardware architecture for near-storage HE computation
