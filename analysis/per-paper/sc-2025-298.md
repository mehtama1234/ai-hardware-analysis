# PerfAnalyzer: Revealing Performance Trends using Version Oriented Visual Analysis of Scientific Software

**Venue:** SC 2025  
**Authors:** Sayef Azad Sakin, James P. Ahrens

## Problem Statement
Scientific software undergoes continuous development with performance implications. Isolating performance regressions requires correlating changes in code, configurations, and parameters across many versions—a tedious and error-prone manual process. Current tools lack integrated version-to-performance tracking.

## Technical Approach
**PerfAnalyzer Dashboard:**
1. **Automated Collection:** Gathers computational parameters from each Git commit and execution
2. **Parameter Tracking:**
   - Input/output parameters (problem size, data files, etc.)
   - Software configuration (compiler flags, algorithm settings)
   - Hardware configuration (CPU, GPU, memory, node count)
   - Performance metrics (runtime, throughput, power)
3. **Version Integration:** Links measurements to specific Git commits
4. **Visual Analysis:** Interactive dashboard revealing performance trends

**Key Features:**
- Automatic parameter correlation with Git history
- Multi-run averaging for robustness
- Version-to-version diff highlighting
- Outlier and regression detection

## Evaluation: CloverLeaf Mini-Application
**Case Study Setup:**
- Tracked performance across multiple CloverLeaf versions
- Collected parameters on diverse computing environments
- Correlated code changes with performance outcomes

**Findings:**
- Successfully identified performance-changing commits
- Revealed parameter changes explaining performance differences
- Highlighted issues invisible in isolated measurements

## Benefits
- **Rapid Root Cause Analysis:** Link performance changes to specific commits
- **Parameter Correlation:** Identify configuration factors affecting performance
- **Reproducibility:** Document computational environment and parameters
- **Regression Detection:** Automated discovery of performance degradations

## Limitations & Future Work
- **Limited Scope:** Single mini-application evaluation; full-application scalability unclear
- **Overhead:** Automated parameter collection and tracking cost not quantified
- **Anomaly Detection:** Automated regression detection and alerting not discussed
- **Multi-Repository:** Handling dependencies across multiple Git repos not addressed
- **Scalability:** Performance with 1000s of versions or parameters not evaluated
