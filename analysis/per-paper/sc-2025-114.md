# From Edge to HPC: Investigating Cross-Facility Data Streaming Architectures

**Venue:** SC | **ID:** sc-2025-114

## Summary
Comparative evaluation of three cross-facility data streaming architectures (Direct, Proxied, Managed Service) on production HPC infrastructure, characterizing performance trade-offs for scientific workflows.

## Problem & Motivation
Scientific computing increasingly requires real-time data ingestion from edge sources and collaboration across computing facilities. Architectural choices for streaming data integration significantly impact throughput, latency, and scalability, but systematic guidance is lacking.

## Key Findings
- **Direct Streaming (DTS):** Minimal hops → highest throughput, lowest latency
- **Managed Service Streaming (MSS):** Greater deployment feasibility/scalability but significant overhead
- **Proxied Streaming (PRS):** Middle ground with scalability matching DTS performance in most cases
- Tradeoffs: simplicity vs. performance vs. multi-user scalability

## Hardware & Systems
- **Platform:** OLCF Advanced Computing Ecosystem (ACE)
- **Infrastructure:** Oak Ridge Leadership Computing Facility
- **Deployment:** Production-grade HPC datacenter infrastructure
- **Framework:** DS2HPC architectural framework + SciStream toolkit

## Techniques
- **Direct Streaming:** Point-to-point data paths (minimal intermediaries)
- **Proxied Streaming:** Intermediate proxy layer for buffering/routing
- **Managed Service Streaming:** Full message queue infrastructure
- **Workflow evaluation:** Work sharing, feedback patterns, broadcast/gather

## Metrics
| Metric | Approach |
|--------|----------|
| Throughput | DTS > PRS > MSS |
| Latency (round-trip) | DTS < PRS < MSS |
| Overhead | MSS >> PRS ≈ DTS |
| Deployment feasibility | MSS > PRS > DTS |
| Scalability | MSS ≈ PRS > DTS |

## Contributions
1. First systematic comparison of cross-facility streaming architectures on production HPC
2. DS2HPC framework and SciStream toolkit for streaming integration
3. Empirical performance characterization across workload patterns
4. Architectural guidance for facility-specific streaming design
5. Production deployment validation on OLCF ACE

## Limitations
- Evaluation limited to synthetic workloads
- Production workflows may exhibit different patterns
- Specific to OLCF ACE infrastructure characteristics
- Generalization to other facilities and configurations unclear
- Limited guidance on architecture selection beyond benchmark results
