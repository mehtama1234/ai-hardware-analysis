# Concord: Rethinking Distributed Coherence for Software Caches in Serverless Environments

**Venue:** HPCA  
**Confidence:** low (abstract-only)

## Problem
Serverless functions incur high latency from frequent global storage accesses; existing node-local caching schemes either restrict each data item to a single cache node (causing frequent remote reads) or allow multi-node replication but impose heavy coherence overhead, neither being optimal for serverless access patterns characterized by frequent reads, strong temporal locality, and few concurrent writers.

## Motivation
Global storage access is a dominant performance bottleneck in serverless computing, and serverless workloads' unique access patterns (read-heavy, temporally local, small data items, few concurrent nodes per application) are not well-served by existing single-node or naive multi-replica caching strategies.

## Method
Concord implements a directory-based distributed software cache coherence protocol inspired by hardware cache coherence, adapted for serverless environments. It allows multiple replicas of the same data item across nodes and satisfies reads locally from any replica. The protocol minimizes coherence traffic, reduces contention points, handles node failures and frequent coherence domain changes. Two additional capabilities are unlocked: transactional storage accesses and transparent data-aware function placement.

## Key Novelty
A directory-based hardware-cache-coherence-inspired software coherence protocol tailored to serverless access patterns, enabling multi-node read replication with efficient invalidation while supporting transactional storage and data-aware placement.

## Contributions
1. Concord: distributed software cache coherence system for serverless with directory-based multi-replica protocol
2. Coherence protocol resilient to node failures and frequent coherence domain changes from serverless churn
3. Transactional storage accesses unlocked as a new capability in serverless environments
4. 2.4x execution speedup and 1.7x throughput improvement on 16-node cluster vs. state-of-the-art, using only 4.8% of application memory
