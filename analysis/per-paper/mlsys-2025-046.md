# AI Metropolis: Scaling Large Language Model-based Multi-Agent Simulation with Out-of-order Execution

**ID:** mlsys-2025-046 | **Venue:** MLSYS 2025

## Problem
LLM-powered multi-agent simulations use global step-wise synchronization that creates false dependencies between spatially distant agents with no real interaction, limiting concurrency to ~1.94 avg concurrent queries out of 25 agents (95% of time is LLM inference).

## Method
AI Metropolis uses out-of-order execution instead of waiting for all agents to finish each step before proceeding. It tracks which agents actually depend on which others by calculating whether they're close enough to interact: agent A is blocked by agent B only if their spatial distance is within interaction reach given the time difference and maximum possible speed (using the formula: radius_p + |StepA - StepB - 1| * max_vel). Agents within interaction range at the same time step are grouped into clusters, which a controller dispatches to parallel workers via a priority queue ordered by step number (earlier steps run first). Workers update the dependency graph in parallel using Redis, an in-memory database with transactional safety, with critical controller logic written in C++ for low latency.

## Key Novelty
Spatial-temporal dependency tracking enables out-of-order execution for multi-agent simulation, eliminating false blocking between distant agents while preserving true causality.

## Results
- **1.3x-4.15x** speedup over parallel-sync global synchronization baseline
- Approaches oracle performance at 500 agents (97% of oracle on 8 GPUs)
- Evaluated: Llama-3 8B (L4 GPUs), Llama-3 70B (A100 GPUs), Mixtral 8x7B
- Baselines: single-thread, parallel-sync, oracle

## Hardware Target
NVIDIA L4 GPUs, NVIDIA A100 GPUs; LLM inference via SGLang
