# Composing Distributed Computations Through Task and Kernel Fusion

**Venue:** ASPLOS  
**Confidence:** low (abstract-only)

## Problem
Distributed task-based programs composed from multiple libraries incur significant overhead from redundant data movement and kernel launch costs when tasks from different libraries execute separately, yet existing runtimes cannot see across library boundaries to fuse these tasks.

## Motivation
High-level Python programs built from composing task-based libraries leave cross-library optimization opportunities unexploited, causing them to underperform explicitly parallel MPI programs.

## Method
Diffuse creates a common language—called an intermediate representation or IR—that describes computation tasks from different libraries in the same format, enabling cross-library analysis. At runtime, when task graphs become available, a JIT compiler (just-in-time compiler running during execution) identifies compatible tasks and combines them into single merged tasks, then further fuses the GPU kernels (the programs that run on graphics processors) within those merged tasks. This approach works with computations from cuPyNumeric and Legate Sparse without requiring any changes to application code.

## Key Novelty
Diffuse uses a shared representation of distributed computations to automatically combine tasks and GPU kernels across different libraries at runtime, allowing high-level Python programs to match or exceed MPI performance.

## Contributions
- Diffuse IR: a general intermediate representation for distributed task-based computations
- Dynamic task fusion pass identifying and merging compatible distributed tasks across library boundaries
- JIT kernel fusion within fused tasks, reducing GPU kernel launch overhead and improving data locality
- 1.86x average (up to 10.7x) speedup on up to 128 GPUs
