# On Improving the HLS Compatibility of Large C/C++ Code Regions

**Problem:** HLS tools impose restrictions on supported C/C++ language features, limiting the size and variety of code regions that can be offloaded to hardware accelerators in heterogeneous CPU-FPGA applications. Non-synthesizable constructs such as dynamic memory allocation and unsupported language features prevent larger code regions from compilation.

**Method:** The tool automatically rewrites code to work around limitations of hardware compilers. It flattens structs and arrays (simplifying nested data structures) because hardware compilers can't handle complex data layouts. It moves dynamic memory allocations to the CPU and replaces them with static, compile-time-determined sizes, since hardware needs to know memory requirements before compilation. It also asynchronously executes host-side functions like printf() separately, because hardware can't perform these operations.

**Novelty:** A coordinated set of automatic code transformations that overcome C/C++ language feature restrictions, allowing larger code regions to run on hardware accelerators.
