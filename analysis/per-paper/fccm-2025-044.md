# On Improving the HLS Compatibility of Large C/C++ Code Regions

**Problem:** HLS tools impose restrictions on supported C/C++ language features, limiting the size and variety of code regions that can be offloaded to hardware accelerators in heterogeneous CPU-FPGA applications. Non-synthesizable constructs such as dynamic memory allocation and unsupported language features prevent larger code regions from compilation.

**Method:** The paper proposes automated code transformations to circumvent HLS restrictions: struct and array flattening to simplify data structures, moving dynamic memory allocations outside synthesizable regions, converting dynamic allocations to static allocations determined at compile time, and asynchronously executing host-side functions such as printf() to eliminate unsynthesizable operations.

**Novelty:** Systematic set of code transformation techniques that automatically improve HLS compatibility by addressing fundamental C/C++ language feature restrictions limiting synthesizable region size.
