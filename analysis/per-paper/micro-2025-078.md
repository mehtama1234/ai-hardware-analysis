# micro-2025-078: Accurate Leakage Speculation for Quantum Error Correction

**Venue:** MICRO 2025  
**Authors:** Chaithanya Naik Mude, Swamit Tannu  
**Confidence:** high (full text)

## Problem
Physical qubits can leak into higher energy states (|2>, |3>, etc.), corrupting syndrome measurements and spreading errors to neighboring qubits. Detecting leakage on data qubits is especially hard because they are never directly measured during QEC cycles.

## Motivation
Existing heuristic leakage detectors (e.g., eraser) have high false-positive rates (flagging 11/16 syndrome patterns as leakage), triggering unnecessary LRCs that add gate errors and lengthen QEC cycles, while the approach does not generalize beyond surface codes.

## Method
GLADIATOR frames leakage detection as a graph labeling problem. Offline, it builds a code-aware error-propagation graph: nodes are syndrome patterns, weighted directed edges encode transition probabilities under leakage vs. non-leakage errors calibrated from device data. Nodes where cumulative leakage-edge weight (W_L) exceeds non-leakage weight (W_NL) by a threshold are labeled as leakage patterns and compiled into a lookup table. Online, a parity-adjacency generator extracts a 5-bit syndrome pattern per data qubit each cycle; a combinational sequence checker (<=10 LUTs/data qubit) classifies it in <1 ns. GLADIATOR-D adds a two-round sliding window for additional accuracy. The approach is code-agnostic (surface, color, qLDPC codes).

## Key Novelty
A probabilistic graph-labeling framework distinguishing leakage-induced syndrome patterns from Pauli-error patterns via calibrated transition probabilities, implementable with <=10 LUTs per data qubit (17x-63x less than eraser).

## Contributions
1. GLADIATOR: code-aware offline graph construction + online lookup table for cross-code leakage speculation
2. Up to 3x fewer unnecessary LRCs (2x average), 1.73x less leakage population growth vs. eraser
3. <0.1% FPGA LUTs at code distance 25; 17x-63x FPGA reduction vs. eraser
4. Structured staggered open-loop LRC scheduling as a competitive baseline for closed-loop methods

## Hardware Target
FPGA (Kintex UltraScale+ evaluated)

## Techniques
reliability, scheduling

## Workloads
Quantum fault-tolerant computing (surface code, color code, qLDPC)

## Key Metrics
- Speedup: 1.7x-3.9x QEC cycle speedup over always-LRC
- Accuracy: 16% reduction in logical error rate; 1.91x lower false-positive rate vs. eraser
- Area: <=10 LUTs per data qubit; <0.1% total LUTs at d=25
- False positive reduction: 3.11x fewer combined FP+FN vs. eraser

## Baselines
eraser, eraser+m, Always-LRC, Staggered Always-LRC, MLR-only, DQLR

## Limitations
GLADIATOR's graphical model must be rebuilt per QEC code and re-calibrated when device noise drifts; GLADIATOR-D adds latency that may constrain real-time QEC controller timing.
