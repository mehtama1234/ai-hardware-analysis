# Deploying Lightweight Input-Aware Selective Instruction Duplication in HPC Applications

**Venue:** SC
**Paper ID:** sc-2025-002
**Confidence:** low

## Problem Statement
Silent data corruptions (SDCs) from transient hardware faults in HPC; input-dependent SDC propagation not captured by existing SID methods that use only default inputs

## Motivation
Modern HPC applications vulnerable to transient faults; existing selective instruction duplication (SID) approaches have poor SDC coverage on non-default inputs

## Method
The Protego framework first explores different inputs to find that distinct groups of inputs require different patterns of instruction duplication—the practice of running certain instructions twice to detect transient hardware faults (temporary glitches). At runtime, it rapidly extracts features from the input data to classify which group the current input belongs to. Based on this classification, it selectively enables the appropriate instruction duplication strategy for that input group, adapting which instructions are protected without needing to re-profile the entire application.

## Key Novelty
Selective instruction duplication (running certain instructions twice to catch transient hardware faults) should adapt which instructions to protect based on analyzing runtime input data, rather than using a fixed protection strategy determined in advance.
