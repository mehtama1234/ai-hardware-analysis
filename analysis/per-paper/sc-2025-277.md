# Preserving CUDA Syntax for SYCL Portability: A Thin C++ Abstraction without Kernel Migration

**Venue:** SC 2025  
**Authors:** Esteban Miguel Rangel, Humza Qureshi

## Problem & Motivation

GPU hardware landscape fragmentation (NVIDIA CUDA dominance vs. emerging Intel/AMD alternatives) forces scientific applications into a dilemma: maintain a single optimized CUDA backend with vendor lock-in, or invest massive effort in multi-backend support with code duplication and maintenance burden. Current solutions require either full source translation or acceptance of sub-optimal portable code.

## Approach

A thin C++ abstraction layer that:

1. **Preserves CUDA Syntax:** Maintains original kernel syntax and launch patterns unchanged.
2. **Mechanical Conversion:** Functorization process mechanically adapts CUDA to SYCL without full translation.
3. **Single-Source Compilation:** Enables compilation through both CUDA and SYCL toolchains from identical source.
4. **Optimization Preservation:** Retains architecture-specific optimizations in each backend.

## Key Novelty

- **Syntax Preservation:** No rewriting of kernel logic; preserves developer intent and optimizations.
- **No Code Duplication:** Single kernel source compiles to both CUDA and SYCL.
- **Mechanical Process:** Functorization is systematic and reproducible, not requiring AI or complex translation.

## Contributions

- Unified kernel abstraction maintaining CUDA syntax
- Mechanical functorization approach for backend adaptation
- Single-source CUDA/SYCL compilation strategy
- Elimination of multi-backend code duplication
- Production case study on CRK-HACC (N-body cosmology)

## Case Study

**CRK-HACC:** Production N-body cosmology code
- Baseline: Native CUDA implementation
- Target: SYCL portable version
- Platforms: Polaris (NVIDIA H100s) and Aurora (Intel GPUs)
- Metric: Kernel execution time parity

## Results

- Competitive performance for SYCL relative to native CUDA
- Preserves code clarity and readability
- Reduces maintenance overhead vs. separate backends
