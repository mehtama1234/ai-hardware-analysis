# EDM: An Ultra-Low Latency Ethernet Fabric for Memory Disaggregation

**Venue:** ASPLOS  
**Authors:** Weigao Su, Vishal Shrivastav  
**Confidence:** low (abstract only)

## Problem
Achieving low remote memory access latency over Ethernet for memory disaggregation remains unsolved; existing protocols (TCP/IP, RDMA/RoCEv2) are implemented atop the Ethernet MAC layer and incur fundamental MAC-layer latency and bandwidth overheads that are particularly severe for small memory messages.

## Motivation
Memory disaggregation requires near-local-memory latency for remote accesses, but current Ethernet protocol stacks impose multi-microsecond latencies that make disaggregated memory impractical for latency-sensitive workloads.

## Method
EDM moves the entire remote memory access protocol into the Ethernet PHY layer (the physical signaling layer), completely bypassing the MAC layer (which normally processes packets) to avoid the delays that layer introduces. At each network switch, EDM implements a centralized scheduler inspired by the Parallel Iterative Matching algorithm that dynamically creates reserved bandwidth channels—called virtual circuits—between compute nodes and memory nodes. These reserved channels eliminate queuing delays and the overhead of Layer 2 packet processing by the switch. An FPGA testbed demonstrates approximately 300 nanoseconds of latency for accessing remote memory when the network is unloaded.

## Key Novelty
Move the entire remote memory access protocol stack into the Ethernet PHY layer (bypassing the MAC layer) and implement a Parallel Iterative Matching-based scheduler at switches to create dedicated bandwidth channels (virtual circuits) that eliminate queuing.

## Contributions
- EDM: a remote memory access protocol stack implemented entirely within the Ethernet PHY layer, bypassing the MAC
- Centralized PIM-inspired in-network PHY scheduler creating virtual circuits to eliminate queuing and L2 processing delays
- FPGA testbed demonstrating ~300 ns unloaded remote memory access latency (order of magnitude lower than RoCEv2)
- Network simulation showing latency remains within 1.3x unloaded latency even at high network loads

- Latency: ~300 ns unloaded vs. RoCEv2 (order of magnitude lower); comparable to CXL

## Baselines
RoCEv2, TCP/IP, CXL (PCIe-based)

## Limitations
Centralized scheduler may face scalability challenges at very large network sizes; PHY-level implementation complexity and hardware cost not discussed.
