# HEC: Equivalence Verification Checking for Code Transformation via Equality Saturation

**Problem:** Current tools cannot provide holistic verification of source-to-source code transformations (control flow and datapath transformations) used in compiler optimization and High-Level Synthesis, leaving the correctness of these transformations unvalidated.

**Method:** HEC verifies that code transformations (like those in compiler optimizations) produce results identical to the original code. It works by building e-graphs (data structures that compactly represent all mathematically equivalent forms of code) and integrating them with MLIR (a compiler framework that represents code in intermediate form). The system applies two verification strategies—dynamic rewriting tests actual transformations, while static rewriting verifies they're mathematically equivalent—to check loop unrolling (repeating loop bodies to reduce overhead), tiling (dividing loops into smaller blocks), and fusion (merging separate loops). On standard PolyBenchC benchmarks, it validated transformations across over 100,000 lines of code in 40 minutes.

**Novelty:** HEC verifies code transformations by combining e-graphs (data structures for tracking equivalent code) with MLIR (a compiler framework) and using both dynamic execution testing and static mathematical verification.
