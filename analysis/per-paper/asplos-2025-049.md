# Past-Future Scheduler for LLM Serving under SLA Guarantees

**Venue:** ASPLOS 2025  
**ID:** asplos-2025-049  
**Confidence:** high (full text)

## Problem
LLM serving frameworks using continuous batching suffer from either overestimation of memory consumption (conservative schedulers) or underestimation leading to harmful request evictions (aggressive schedulers), because neither accurately accounts for the dynamic memory release profile of concurrently running requests across future decoding steps.

## Motivation
As LLM inference scales to thousands of GPUs serving tens of millions of requests per day under strict SLA constraints (TTFT, TPOT, MTPOT), maximizing goodput requires precise KV-cache memory estimation that adapts to varying input-output length distributions across chatbot, code, and reasoning workloads.

## Method
Two components: (1) **Output length distribution prediction** samples predicted output lengths from the empirical distribution of the last ~1,000 finished requests (sliding window), updating each running request's predicted remaining length at each step using the conditional distribution P(l > l_current). (2) **Future required memory estimation** sorts running requests by estimated remaining length, computes memory occupancy at each future completion event, and determines peak future memory as max(M_t+1, M_t+2, ...) across all future completion times. A queued request is admitted only if adding it keeps peak future memory below hardware capacity. Implemented in LightLLM with <1% scheduling overhead via GPU-parallel computation.

## Key Novelty
Output length distributions are stable within adjacent time windows — this observation enables a parameter-free, model-agnostic historical-distribution sampling approach to precisely estimate peak future KV-cache memory demand, eliminating both conservative underutilization and aggressive eviction.

## Contributions
- Discovery that LLM request output length distributions are stable within adjacent time windows, validated on six real-world trace datasets (BurstGPT, Mooncake, in-house).
- Past-Future scheduler: two-component algorithm for future peak memory estimation via historical distribution sampling and per-completion-event memory accounting.
- LightLLM: production-deployed LLM serving framework on thousands of GPUs.
- 2-3x higher goodput over vLLM/TGI/DeepSpeed-MII under heavy load on Llama2-7B/13B/70B.

## Metrics
- goodput: 2-3x over aggressive/conservative schedulers under heavy load
- memory utilization: ~93-94% vs theoretical optimum 95-98%, vs conservative ~58-72%
- eviction rate: ~3-7% vs 93% for aggressive (watermark=99%)
- multimodal: 50-60% throughput improvement on LLaVA and Qwen-VL

## Baselines
vLLM (aggressive), TGI (conservative), DeepSpeed-MII/FastGen (conservative), TensorRT-LLM (conservative)

## Limitations
Relies on distribution stationarity within adjacent time windows; may degrade if output length distributions shift abruptly; warm-up period needed at startup.
