# Mojo: MLIR-based Performance-Portable HPC Science Kernels on GPUs for the Python Ecosystem

**Venue:** SC | **ID:** sc-2025-117

## Summary
Mojo language evaluation for scientific GPU computing, leveraging MLIR for compile-time performance portability across NVIDIA H100 and AMD MI300A with Python-like syntax.

## Problem & Motivation
Scientific Python users face a productivity-performance trade-off: Python is productive but CuPy/Numba sacrifice performance; CUDA/HIP provide performance but require language switching and single-vendor targeting. Mojo aims to bridge this gap with Python integration and compile-time portability.

## Key Findings
- **Memory-bound kernels:** Mojo performance competitive with CUDA
- **Atomic operations:** Performance gaps on AMD MI300A
- **Fast-math compute kernels:** Gaps on both NVIDIA and AMD platforms
- **Learning curve:** Still fairly low-level despite Python integration
- **Fragmentation:** MLIR approach shows promise for ecosystem convergence

## Hardware & Systems
- **GPUs evaluated:** NVIDIA H100, AMD MI300A
- **Architectures:** Different memory hierarchies and compute capabilities
- **Target:** Multi-GPU scientific computing systems

## Techniques
- **MLIR compiler infrastructure:** Multi-Level Intermediate Representation for portability
- **CUDA-like syntax:** Familiar programming model for GPU experts
- **Python integration:** Seamless integration with Python ecosystem
- **Compile-time code generation:** Performance portability without runtime overhead

## Evaluated Kernels
| Kernel | Category | Result |
|--------|----------|--------|
| 7-point stencil | Memory-bound | Competitive |
| BabelStream | Memory-bound | Competitive |
| miniBUDE | Compute-bound | Gaps identified |
| Hartree-Fock | Compute-bound + atomics | Gaps identified |

## Contributions
1. First comprehensive scientific GPU evaluation of Mojo language
2. Demonstrated MLIR viability for performance-portable GPU code
3. Identified remaining gaps (atomics, fast-math optimization)
4. Showed path toward fragmented Python GPU ecosystem convergence
5. Practical assessment for scientific computing adoption

## Limitations
- Limited kernel evaluation set (4 workloads)
- Performance gaps on AMD MI300A suggest platform-specific issues
- Fast-math gaps on both platforms indicate incomplete optimization
- Learning curve remains high despite Python integration
- Maturity concerns based on identified gaps
- No comparison with other portability approaches (OpenMP, SYCL, etc.)
