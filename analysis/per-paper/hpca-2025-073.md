# SPARK: Sparsity Aware, Low Area, Energy-Efficient, Near-memory Architecture for Accelerating Linear Programming Problems

**Venue:** HPCA  
**Confidence:** low (abstract-only)

## Problem
Integer Linear Programming (ILP) and Linear Programming (LP) solvers run for tens of hours on large parallel computers because their sparse, branch-intensive algorithms are poorly matched to CPUs and GPUs. GPUs suffer from thread divergence on ILP branching and require frequent host interactions, while CPU solvers like Gurobi cannot meet real-time decision thresholds (seconds to minutes).

## Motivation
Real-life optimization problems (network routing, traffic scheduling, map routing) require decisions in seconds, but state-of-the-art solvers on CPUs and GPUs take hours, making ILP impractical for time-critical applications.

## Method
SPARK reconfigures the existing L1 cache in a CPU to act as a near-cache compute accelerator with ~1.4% area overhead. It integrates sparsity detection and sparsity-aware compute units near the cache to skip insignificant multiplications in sparse matrix operations, and exploits reuse patterns inherent to ILP algorithms (e.g., simplex pivots, branch-and-bound traversal) through a reuse-aware datapath. The architecture is reconfigurable to handle both sparse and dense ILPs and LPs without separate hardware.

## Key Novelty
Near-L1-cache reconfiguration that enables sparsity-aware, reuse-aware computation for ILP/LP directly within the CPU pipeline at minimal area cost (~1.4% of a CPU).

## Contributions
1. Near-cache ILP/LP accelerator that reconfigures existing L1 cache with minimal hardware overhead (~1.4% of CPU area)
2. Sparsity detection and sparsity-aware compute eliminating redundant operations and data movement in sparse ILP workloads
3. Reuse-aware architecture exploiting computational patterns of ILP solver algorithms
4. 15x/20x speedup and 152x/740x energy improvement over AMD Zen3 CPU and NVIDIA Tesla V100 GPU on MIPLIB 2017 benchmarks

## Metrics
- **Speedup:** 15x over Zen3 CPU, 20x over V100 GPU (sparse ILP); 7-17x over CPU, 103-250x over GPU (sparse LP)
- **Energy:** 152x improvement over Zen3 CPU, 740x over V100 GPU (sparse ILP)
- **Area:** ~1.4% of a CPU die

## Baselines
- AMD Zen3 CPU (Gurobi)
- NVIDIA Tesla V100 GPU

## Limitations
Evaluation focuses on MIPLIB 2017 benchmarks; applicability to ILP problem classes beyond mixed-integer programming is not discussed.
