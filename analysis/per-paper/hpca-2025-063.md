# Make LLM Inference Affordable to Everyone: Augmenting GPU Memory with NDP-DIMM

**Venue:** HPCA  
**Confidence:** low (abstract-only)

## Problem
Deploying large LLMs (e.g., LLaMA2-70B) on consumer-grade GPUs with limited VRAM is impractical; offloading model weights to host DRAM or NVMe storage creates severe bandwidth bottlenecks on the PCIe interconnect, resulting in very low inference throughput.

## Motivation
As LLM-assisted services proliferate, democratizing LLM inference on budget consumer hardware (rather than expensive server-grade HBM-equipped GPUs) is a pressing need.

## Method
The system recognizes that LLM neurons (the basic units) aren't equally important—some get used much more than others depending on the input. It keeps the frequently-used 20% of neurons that handle 80% of the work on the consumer GPU for speed, and offloads the rarely-used 80% of neurons that only handle 20% of work to processing units embedded in DRAM chips, so computation happens right at the data instead of moving weights across the slow PCIe link. A lightweight predictor watches each input to identify which neurons will be active, and a scheduler balances work across multiple DRAM modules while the GPU and DRAM chips compute in parallel.

## Key Novelty
It recognizes that LLMs use some weights much more than others, and stores the rarely-used weights in processing units built into DRAM chips rather than shuttling all weights across the slow PCIe connection, so computation happens right where the data lives.

## Contributions
- Hot/cold neuron classification leveraging ~80/20 activation sparsity split in LLMs
- Heterogeneous GPU + NDP-DIMM execution strategy with a lightweight real-time neuron predictor
- Window-based online load-balancing scheduler across NDP-DIMM modules
- 75.24x average speedup over state-of-the-art offloading inference systems; LLaMA2-70B at 13.75 tokens/s on consumer hardware
