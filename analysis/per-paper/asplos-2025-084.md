# asplos-2025-084 — Concurrency-Informed Orchestration for Serverless Functions

**Venue:** ASPLOS  
**Confidence:** low (abstract only)  
**Primary Theme:** Concurrency-aware serverless container orchestration

## Problem
Serverless FaaS platforms suffer excessive cold starts because existing container keep-alive policies ignore concurrent invocations: they fail to reason about whether reusing a busy container (delayed warm start) or cold-starting a new container is preferable, and they make imbalanced eviction decisions that prematurely evict soon-to-be-reused containers.

## Motivation
Concurrent function invocations are pervasive in production FaaS workloads, yet state-of-the-art keep-alive policies treat each invocation independently, causing unnecessary cold starts and latency inflation.

## Method
CIDRE is an algorithm that decides when to keep containers running versus start new ones, by tracking detailed information about each container—whether it's currently handling tasks and when it will free up—combined with signals about how many tasks are arriving at once. When a new task arrives, it predicts whether waiting for a busy container to finish (a 'warm start' that reuses the existing container) is faster than starting a completely new container from scratch (a 'cold start'). For deciding which containers to shut down, it combines how recently each was used with predictions of whether it will be needed soon, which prevents the mistake of deleting containers that new tasks will immediately require. The algorithm was tested on two production serverless workload traces.

## Key Novelty
CIDRE is the first serverless keep-alive policy to explicitly track concurrency state (how many tasks each container is handling) and use it to make both warm-vs-cold-start decisions and balanced shutdown choices simultaneously.

## Contributions
- Identification of two new concurrency-driven challenges in FaaS keep-alive: delayed warm start tradeoff and imbalanced eviction
- CIDRE algorithm combining fine-grained container and coarse-grained concurrency information for orchestration
- Up to 75.1% reduction in cold start ratio and 39.3% reduction in average invocation overhead
