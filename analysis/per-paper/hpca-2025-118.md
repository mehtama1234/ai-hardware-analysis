# hpca-2025-118: NearFetch: Saving Inter-Module Bandwidth in Many-Chip-Module GPUs

**Venue:** HPCA  
**Confidence:** low (abstract-only)

## Problem
In many-chip-module (MCM) GPUs, inter-module bandwidth is physically constrained by organic substrate or silicon interposer manufacturing limits, and fetching data from remote modules causes bandwidth contention that reduces effective achieved bandwidth, degrading GPU performance on high-sharing workloads.

## Motivation
As single-die GPU scaling approaches lithographic limits, multi-chip-module designs are necessary but introduce a new class of inter-module bandwidth bottleneck that is orthogonal to traditional memory latency—GPUs are uniquely bandwidth-sensitive due to their high thread-level parallelism.

## Method
NearFetch intercepts memory requests as they travel through intermediate GPU modules and checks if any of these modules already store the requested data locally. If one does, the data is forwarded from that nearby module instead of fetching it from the distant main memory partition, saving the extra hops. To support this interception, NearFetch uses a topology-aware Miss Status Handling Register (MSHR) coalescing scheme—a tracking mechanism that records which memory addresses exist in which modules so forwarding decisions can be made intelligently. The system introduces a metric called Inter-Module Bandwidth per Access (IBPA) to measure how much bandwidth is wasted when data travels multiple hops across modules.

## Key Novelty
NearFetch intercepts memory requests traveling through intermediate GPU modules and forwards data from whichever module along the path already has it, reducing the number of hops needed without restructuring the GPU's physical design.

## Contributions
- IBPA (Inter-Module Bandwidth per Access) metric for quantifying multi-hop bandwidth waste in MCM GPUs
- Data forwarding scheme enabling shorter-path data supply from intermediate routing modules
- Topology-aware MSHR coalescing for tracking forwarding candidates across cache misses
- 42.6% IBPA reduction and 52.2% average (up to 98.1%) performance improvement for high-sharing workloads

## Limitations
Benefits are concentrated on high-sharing workloads; low-sharing workloads show minimal improvement, limiting general applicability.
