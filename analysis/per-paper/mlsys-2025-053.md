# Graph Learning at Scale: Characterizing and Optimizing Pre-Propagation GNNs

**Venue:** MLSYS 2025

## One-line Problem
Pre-propagation GNNs spend 88-91% of training time on data loading due to expanded input sizes (K(R+1)x larger), making data I/O the dominant bottleneck rather than compute.

## Method
To reduce data loading bottlenecks, the approach optimizes how data moves from storage to the GPU. It uses chunk reshuffling—organizing data in larger blocks instead of individual rows—which lets the GPU prepare its own training batches. It overlaps reading from storage with GPU computation by prefetching the next batch while the current one processes, and uses GPU Direct Storage (GDS) to connect the GPU directly to fast storage for very large graphs. Additionally, it adjusts the training process using mini-batch gradient descent and chunk-based sampling strategies to handle the expanded input sizes.

## Novelty
First to characterize data loading (not compute) as PP-GNN's primary bottleneck, and chunk reshuffling that enables GPU-side batch assembly from coarser I/O without fine-grained per-row access.

## Key Metrics
- **15x** average training throughput improvement over PP-GNN baselines
- **Up to 100x** speedup versus sampling-based GNNs on large graph benchmarks
- Comparable accuracy to graph-sampling methods
