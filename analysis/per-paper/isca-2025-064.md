# isca-2025-064 — Single-Address-Space FaaS with Jord

**Venue:** ISCA  
**Confidence:** low (abstract only)

## Problem
FaaS systems incur millisecond-level overheads from isolating functions in separate address spaces (containers or microVMs), preventing microsecond-scale SLOs required by microservice workloads; the address-space isolation forces costly context switches and cross-function data copies.

## Motivation
FaaS was designed for microsecond-level event-driven execution, but all modern implementations impose container/VM overhead that pushes latency to milliseconds, limiting usefulness for latency-sensitive microservices.

## Method
Jord co-locates functions in a single address space using hardware/software co-design for user-level in-process memory isolation, extending virtual memory capabilities. Memory isolation is enforced at nanosecond granularity without kernel involvement, enabling zero-copy cross-function communication and scalable user-level function dispatch that avoids OS context switches.

## Key Novelty
Jord revives the function-as-a-function FaaS semantic by enabling user-level in-process memory isolation at nanosecond granularity within a single address space, eliminating container/microVM overhead that causes millisecond latencies.

## Contributions
1. A single-address-space FaaS architecture with user-level in-process memory isolation at nanosecond granularity.
2. Zero-copy cross-function communication through shared address space with hardware-enforced isolation.
3. Meets microsecond-level SLOs while performing within 16% of an idealized insecure baseline.
4. Over 2x higher throughput compared to enhanced state-of-the-art FaaS systems.
