# Leveraging control-flow similarity to reduce branch predictor cold effects in microservices

**Venue:** ISCA  
**Confidence:** low (abstract only)

## Problem
Microservices suffer from severe branch mispredictions due to cold branch predictor state when cores are shared across interleaved service invocations or power-gated between requests. This cold-start effect degrades tail latency under strict SLA constraints.

## Motivation
Microservice architectures dominate modern datacenters, and their fine-grained execution with frequent core switching causes predictor state eviction, making branch mispredictions a primary performance bottleneck that existing warm-predictor-focused designs cannot address.

## Method
The system proposes Similarity-based Branch Prediction (SBP), which combines traditional branch predictors (which guess the next instruction based on history or compiler hints) with a new component called CHESS that records the actual control flow (sequence of executed code) from previous requests. When the traditional predictor is cold (lacking recent state due to context switches between services), CHESS identifies similar past requests and replays their execution paths to predict which branches will be taken, without waiting for the predictor to re-learn from scratch. This approach requires only 18.1 KB of additional memory to store reference execution traces from prior requests.

## Key Novelty
CHESS exploits the similarity of control-flow patterns across requests in microservices—rather than trying to preserve the branch predictor's state across service invocations, it stores execution traces from similar past requests and replays them to predict branches for new requests.

## Contributions
- Quantitative analysis confirming high control-flow similarity across microservice requests
- SBP hybrid predictor combining history-based, static-hint, and similarity-based prediction
- CHESS achieving 94% branch MPKI reduction over cold fetch predictor; 78% over state-of-the-art
- Performance within 95% of warm baseline using 18.1 KB additional storage
