# DynamoLLM: Designing LLM Inference Clusters for Performance and Energy Efficiency

**Venue:** HPCA  
**Confidence:** high (full text)

## Problem
LLM inference clusters running on GPU-dense infrastructure consume excessive energy and incur high operational carbon emissions because existing systems provision resources for peak load at maximum GPU frequency and tensor parallelism, ignoring the strong heterogeneity in request types (input/output length variation) and diurnal load fluctuations that create large energy-saving opportunities.

## Motivation
LLM inference workloads are rapidly becoming a dominant share of datacenter power consumption, and a single static cluster configuration cannot simultaneously serve the energy needs of short/low-compute and long/high-compute requests, leaving 35-53% energy savings on the table while meeting latency SLOs.

## Method
The system has three management layers that dynamically adjust three key settings to save energy: how many servers run, how the model splits across GPUs (tensor parallelism), and GPU speed. Requests are directed to separate server pools based on their input/output token requirements, with a BERT-based prediction model determining the right pool for each request. When reconfiguring, the system minimizes switching overhead by: pre-warming machines from saved snapshots, moving model weights efficiently over fast GPU-to-GPU connections (NVLink) using a matching algorithm, and keeping the GPU control tool (nvidia-smi) ready in memory for instant speed adjustments.

## Key Novelty
The system adjusts server count, model-to-GPU distribution, and GPU speed for each request type, while minimizing reconfiguration overhead by efficiently moving model weights over NVLink and reusing pre-warmed machine snapshots.

## Contributions
1. Characterization of LLM inference energy-performance heterogeneity across request lengths, system load, model size, and SLO requirements using Azure production traces
2. DynamoLLM: hierarchical cluster/pool/instance controller framework with MILP-based energy optimization under SLO constraints
3. Reconfiguration overhead reduction techniques: bipartite-graph-matching NVLink weight re-sharding, proactive VM snapshot pre-warming, in-memory nvidia-smi frequency tuning
4. 53% energy savings, 38% carbon reduction, 61% cost reduction at service level while meeting latency SLOs on production traces

## Metrics
- **Energy:** 53% energy saving, 38% carbon reduction vs. static SinglePool baseline
- **Other:** 61% cost reduction; individual knob savings: ScaleInst 4.1%, ScaleShard 7%, ScaleFreq 19%, DynamoLLM 35% in cluster experiment

## Baselines
- SinglePool (TP8, max frequency, static)
- MultiPool (per-type pools, no scaling)
- ScaleInst (scale instances only)
- ScaleShard (scale parallelism only)
- ScaleFreq (scale frequency only)

## Limitations
Evaluation assumes all GPUs are NVIDIA H100 (homogeneous hardware); heterogeneous GPU cluster scenarios and multi-tenant LLM co-location are not addressed.
