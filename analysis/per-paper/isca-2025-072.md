# isca-2025-072 — HeterRAG: Heterogeneous Processing-in-Memory Acceleration for Retrieval-augmented Generation

**Venue:** ISCA  
**Confidence:** low (abstract only)

## Problem
RAG systems face two distinct memory bottlenecks: retrieval suffers from random/irregular access patterns causing low bandwidth utilization, and generation is bandwidth-limited by frequent GEMV over large LLM weights. HBM-based PIM alone is both too expensive and capacity-insufficient to hold large-scale knowledge bases.

## Motivation
Enterprise RAG adoption is accelerating, but each stage has fundamentally different memory requirements; no single PIM technology adequately addresses both capacity (retrieval) and bandwidth (generation) demands.

## Method
HeterRAG uses two different types of processing-in-memory—hardware that does computation directly on the storage itself—to solve two different problems: DIMM-based PIM (affordable, large-capacity standard memory) stores knowledge bases and accelerates the scattered memory access patterns during document retrieval, while HBM-based PIM (specialized high-speed memory) handles the matrix-vector multiplications (GEMV operations) that LLMs repeatedly do during text generation. The system sends each retrieval or generation task to whichever PIM type handles that kind of memory access best, managing the data flow between them.

## Key Novelty
HeterRAG is the first system to combine two types of processing-in-memory (DIMM-based and HBM-based) to simultaneously solve the knowledge-base size problem in retrieval and the data-movement speed problem in LLM generation for RAG.

## Contributions
1. Characterization of distinct memory bottlenecks in RAG retrieval vs. generation stages
2. Heterogeneous PIM architecture combining DIMM-based and HBM-based PIM
3. Stage-to-PIM-domain mapping strategy for end-to-end RAG acceleration
4. System demonstrating capacity + bandwidth coverage beyond HBM-only PIM
