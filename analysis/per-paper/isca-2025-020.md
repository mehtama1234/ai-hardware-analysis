# REIS: A High-Performance and Energy-Efficient Retrieval System with In-Storage Processing

**Venue:** ISCA  
**Confidence:** low (abstract-only analysis)

## Problem
The retrieval stage of RAG is a bottleneck because ANNS on large embedding databases causes massive host-to-storage data movement; existing ISP approaches use storage-agnostic algorithms, skip data-fetch acceleration, and require heavy SSD hardware modifications.

## Motivation
LLMs have static knowledge cutoffs and retraining is expensive; RAG is the practical solution, but its retrieval stage can dominate end-to-end inference latency at scale, making storage-side acceleration critical.

## Method
REIS moves the similarity-search computation (called Approximate Nearest Neighbor Search, or ANNS) directly inside the storage device, cutting out the massive data transfer between the computer and storage that normally slows down retrieval. Rather than forcing a generic search algorithm onto the storage hardware, REIS designs the algorithm specifically to match how NAND flash controllers (the chips inside SSDs) naturally work in parallel. To speed up retrieval further, REIS overlaps the vector search with fetching the actual data, so the storage device can work on both tasks at the same time rather than one after another. This design avoids the need for major modifications to the SSD hardware.

## Key Novelty
REIS designs the similarity-search algorithm (ANNS) specifically to match the flash storage controller's internal design, which accelerates both vector search and data retrieval without major hardware modifications.

## Contributions
1. ISP-optimized ANNS algorithm tailored to flash controller internal bandwidth and parallelism
2. Acceleration of post-ANNS data retrieval step (absent in prior ISP works)
3. Near-storage design requiring minimal hardware modification to existing SSDs
4. High-performance, energy-efficient retrieval enabling faster RAG pipelines
