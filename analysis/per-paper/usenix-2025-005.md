# Resource Multiplexing in Tuning and Serving Large Language Models

**Problem:** LLM training (tuning) and inference (serving) have conflicting resource requirements and cannot efficiently share GPU resources simultaneously. Current systems either dedicate hardware to one workload or suffer significant performance degradation when sharing.

**Method:** Implements dynamic resource multiplexing that allows GPU memory, compute, and bandwidth to be time-shared or spatially partitioned between training and serving workloads. Uses scheduling policies to prioritize based on latency and throughput requirements. Likely employs kernel-level isolation or virtualization to prevent interference between workloads while maintaining efficient resource utilization across both phases.

**Novelty:** Practical system for concurrent LLM tuning and serving on shared hardware with dynamic resource arbitration between conflicting performance goals.
