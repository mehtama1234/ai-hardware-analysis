# Resource Multiplexing in Tuning and Serving Large Language Models

**Problem:** LLM training (tuning) and inference (serving) have conflicting resource requirements and cannot efficiently share GPU resources simultaneously. Current systems either dedicate hardware to one workload or suffer significant performance degradation when sharing.

**Method:** This system lets training and serving share a single GPU by dynamically dividing its resources—memory, computing power, and bandwidth—either by taking turns (time-sharing) or reserving separate regions (spatial partitioning). A scheduler continuously decides how to allocate resources based on each task's priority: how quickly the serving needs to respond (latency) and how fast training should progress (throughput). Kernel-level isolation (controls built into the operating system) or virtualization (creating isolated execution spaces) keeps the tasks from interfering with each other despite sharing hardware.

**Novelty:** A single GPU can run both training and serving at the same time through dynamic arbitration of resources—constantly deciding which task gets access based on their different performance needs.
