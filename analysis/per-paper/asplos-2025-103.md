# asplos-2025-103: Segue & ColorGuard: Optimizing SFI Performance and Scalability on Modern Architectures

**Venue:** ASPLOS  
**Confidence:** low (abstract only)

## Problem
Software-based fault isolation (SFI) for WebAssembly (Wasm) incurs significant performance overhead from memory-access instrumentation and limits the number of Wasm instances that can run concurrently in a single address space due to address-space partitioning constraints.

## Motivation
Wasm sandboxing is critical for safe, high-performance web and server-side execution, but its instrumentation overhead and scalability limits are barriers to broad deployment in latency-sensitive and high-concurrency applications.

## Method
Segue encodes each Wasm sandbox's memory bounds into x86-64 segment registers (the FS/GS base registers), which the CPU checks automatically on every memory access—eliminating the runtime's need to insert explicit boundary-checking code into Wasm programs. This removes 44.7% of Wasm overhead on SPEC CPU 2006 benchmarks and cuts Firefox's font-rendering sandbox cost by 75%. ColorGuard uses memory protection keys (a CPU-level memory tagging feature), assigning each Wasm instance a unique tag so they can safely coexist in the same address space; this enables up to 15 times more concurrent instances without separate memory partitions.

## Key Novelty
Offloading WebAssembly sandbox enforcement from software instrumentation to hardware—using x86-64 segment registers for bounds and memory protection keys for instance isolation.

## Contributions
- Segue: eliminates up to 44.7% of Wasm SFI overhead on SPEC CPU 2006; 75% overhead reduction in Firefox font rendering.
- ColorGuard: up to 15x more concurrent Wasm instances per address space via memory tagging.
- Integration and evaluation in three production Wasm toolchains: Wasm2c, WAMR, and Wasmtime.
