# asplos-2025-089 — lambda-trim: Optimizing Function Initialization in Serverless Applications With Cost-driven Debloating

**Venue:** ASPLOS  
**Confidence:** low (abstract only)  
**Primary Theme:** Cost-driven Python debloating for serverless function initialization

## Problem
In serverless FaaS platforms, Function Initialization (package import, module loading) accounts for more than 50% of the monetary cost of cold starts in real-world ML applications, yet existing optimization efforts focus on the container/VM startup phase rather than the Python initialization phase.

## Motivation
Serverless ML applications pay substantial billed cost for loading unused Python modules during cold starts, and this initialization overhead is the user's responsibility under current pricing models, making it a critical but neglected optimization target.

## Method
Lambda-trim works in three automated stages. First, a static analyzer traces through the code to identify which modules (pre-written code packages) the function actually needs—the dependency graph. Second, it profiles the code using serverless billing costs (measuring both memory usage and execution time—the two things you pay for in serverless computing) to assess each module's time and money impact. Third, it removes unnecessary code and unused modules while keeping the functionality intact; the cleaned-up function then runs directly on serverless platforms with no further changes needed.

## Key Novelty
The innovation is profiling code with awareness of both memory and execution time—serverless's two billing dimensions—to prioritize what gets removed during initialization, the loading phase.

## Contributions
- Identification and quantification of Function Initialization as the dominant cold-start cost component in ML serverless workloads
- Static analyzer for serverless Python module dependency graphs
- Serverless-pricing-aware profiler that accounts for both latency and memory billing dimensions
- Automated debloater producing deployable applications with reduced cold-start latency and cost
