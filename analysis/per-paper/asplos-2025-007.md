# asplos-2025-007: AnyKey: A Key-Value SSD for All Workload Types

**Venue:** ASPLOS  
**Confidence:** low (abstract-only)

## Problem
Existing KV-SSD designs are optimized only for workloads where values are much larger than keys; when key sizes are relatively large, expanded key metadata causes significantly degraded performance with unbounded metadata growth.

## Motivation
Large-scale KV store applications increasingly target KV-SSDs for cost-effective and scalable storage, but a hidden assumption of small-key workloads limits existing designs to one workload type, creating a deployment gap for real-world diverse workloads.

## Method
The system redesigns how a key-value storage device (KV-SSD) manages its index. Instead of storing each full key directly in the index—which becomes huge if keys are large—AnyKey stores only a small, fixed-size reference to each key, such as a hash or compact descriptor, while keeping the full key data elsewhere. This keeps the index lean no matter how big the keys grow, preventing the performance collapse that normally happens when key sizes balloon.

## Key Novelty
Instead of storing full keys in the index, store only small fixed-size references—this keeps the index size constant regardless of how large the actual keys are.

## Contributions
- First evaluation of KV-SSD designs under large-key workloads, exposing significant performance degradation.
- AnyKey's metadata-bounded key management architecture preventing metadata bloat under varying key sizes.
- Broad evaluation across diverse real-world workloads demonstrating consistent performance over existing KV-SSD designs.
