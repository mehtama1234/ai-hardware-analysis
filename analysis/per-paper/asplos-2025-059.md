# asplos-2025-059 — Exo 2: Growing a Scheduling Language

**Venue:** ASPLOS  
**Confidence:** low (abstract-only)

## Problem
User-schedulable languages (USLs) fix a single design point for what programmers control and what is automated, but no universal control/automation split exists even in narrow domains, causing USLs to be inextensible when new hardware targets or optimization strategies emerge.

## Motivation
High-performance kernel authors for different hardware targets need different scheduling operations, and forcing them to use a fixed built-in set either over-constrains or under-automates their workflow, increasing scheduling code volume and effort.

## Method
Exo 2 enables users to define new scheduling operations externally to the compiler by composing a set of trusted fine-grained primitives (actions for modifying code, inspection for querying code structure, and references for pointing to code locations). The key mechanism is Cursors, a new abstraction that unifies code references across actions, inspections, and scheduling library composition, allowing safe user-defined scheduling transformations. Users build scheduling libraries that amortize transformation effort across related kernels without modifying the compiler internals.

## Key Novelty
The Cursor abstraction that enables users to write fully externalized, composable scheduling libraries safe from compiler internals, allowing the scheduling language to grow without core modifications.

## Contributions
- Exo 2 architecture for externally extensible user-schedulable languages via composable trusted primitives.
- Cursor abstraction unifying code actions, inspection, and references to support user-defined scheduling operations.
- Scheduling libraries demonstrated across 80+ high-performance kernels reducing scheduling code by an order of magnitude.
- Performance competitive with state-of-the-art implementations on three different hardware platforms.
