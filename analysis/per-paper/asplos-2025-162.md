# Debugger Toolchain Validation via Cross-Level Debugging

**Venue:** ASPLOS  
**Confidence:** low (abstract-only)

## Problem
Existing debugger toolchain validation compares traces from optimized vs. unoptimized executables, but compiler optimizations make such traces incomparable and leave bugs undetected when the unoptimized binary itself contains toolchain errors.

## Motivation
Bugs in production debugger toolchains (GDB, LLDB) can systematically mislead developers, yet comprehensive testing has been absent due to the lack of sound test oracles.

## Method
Cross-Level Debugging (CLD) compares execution traces from debugging the same executable at source-level and instruction-level within the same debugger. Three invariant relations are formalized—reachability preservation, order preservation, and value consistency—that must hold between the two trace levels regardless of optimization. The Devil framework implements these as test oracles, generates test programs, runs both debugging levels, and flags violations as toolchain bugs.

## Key Novelty
Using source-level versus instruction-level debugging of the same executable as a built-in oracle, enabling detection of toolchain bugs without comparing across different executables.

## Contributions
- Cross-Level Debugging (CLD): comparing source-level and instruction-level debug traces of the same executable
- Formalization of three semantic invariant relations as test oracles
- Devil framework for automated debugger toolchain validation
