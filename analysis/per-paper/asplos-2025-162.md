# Debugger Toolchain Validation via Cross-Level Debugging

**Venue:** ASPLOS  
**Confidence:** low (abstract-only)

## Problem
Existing debugger toolchain validation compares traces from optimized vs. unoptimized executables, but compiler optimizations make such traces incomparable and leave bugs undetected when the unoptimized binary itself contains toolchain errors.

## Motivation
Bugs in production debugger toolchains (GDB, LLDB) can systematically mislead developers, yet comprehensive testing has been absent due to the lack of sound test oracles.

## Method
Cross-Level Debugging compares two debugging views of the same program: source-level debugging (showing the code you wrote) and instruction-level debugging (showing what the CPU actually executes). It checks that three things must be true between them: the program must visit the same code locations in both views, must visit them in the same order, and variables must have the same values at each location. A tool called Devil automates this by generating test programs, running them through both debug views, and flagging any violations as bugs in the debugger toolchain.

## Key Novelty
It detects debugger bugs by comparing source-level and instruction-level debugging views of the same executable, which catches errors other methods miss in unoptimized binaries.

## Contributions
- Cross-Level Debugging (CLD): comparing source-level and instruction-level debug traces of the same executable
- Formalization of three semantic invariant relations as test oracles
- Devil framework for automated debugger toolchain validation
- 27 new bug reports in GDB and LLDB; 18 confirmed, 12 fixed
