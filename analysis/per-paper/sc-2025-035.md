# sc-2025-035: OpenSHMEM MLIR: A Dialect for Compile-Time Optimization of One-Sided Communications

## Summary
Introduces an OpenSHMEM dialect for MLIR that preserves one-sided communication semantics as first-class IR constructs, enabling compiler-level optimizations that would be impossible to recover from low-level LLVM IR.

## Problem
- Communication is increasingly a performance bottleneck in HPC
- Mainstream compilers (LLVM) lower OpenSHMEM to opaque runtime calls
- High-level semantics (one-sided patterns, PGAS model) are lost during lowering
- Compiler cannot apply communication-specific optimizations

## Method
The researchers built a new module for MLIR (a compiler's intermediate representation—the format compilers use internally before generating machine code) that treats OpenSHMEM communications (direct messages between processors) as visible language features instead of hiding them in opaque function calls. This allows the compiler's optimization algorithms to see and understand the communication patterns. They integrated it with existing LLVM optimizations and demonstrated four specific improvements: tracking which processor initiates each communication (PE recording), combining multiple atomic operations into fewer ones, switching code from waiting-for-completion mode (blocking) to continuing-without-waiting mode (non-blocking), and bundling multiple messages into larger batches.

## Key Innovations
1. **First OpenSHMEM MLIR dialect**: Preserves PGAS semantics in IR
2. **Communication-aware IR**: First-class representation of communication intent
3. **Compiler integration**: Works with existing optimization infrastructure
4. **Semantic-preserving transformations**: Correctness guaranteed by design

## Hardware Targets
- Generic HPC systems with OpenSHMEM support
- Any system supporting one-sided communication

## Demonstrated Optimizations
1. **PE recording**: Track number of processing elements
2. **Atomic fusion**: Combine compatible atomic operations
3. **Blocking-to-non-blocking**: Convert blocking calls to non-blocking when safe
4. **Message aggregation**: Combine small messages
