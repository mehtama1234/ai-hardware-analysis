# asplos-2025-083 — Practical Federated Recommendation Model Learning Using ORAM with Controlled Privacy

**Venue:** ASPLOS  
**Confidence:** low (abstract only)  
**Primary Theme:** ORAM-backed federated learning for recommendation models

## Problem
Federated learning (FL) for recommendation models is impractical because the large embedding tables require each user to access a tiny fraction of table entries, and hiding those access patterns via ORAM incurs prohibitive latency and SSD wear. Existing ORAM-based approaches have latency and SSD lifetime overheads that make them undeployable at scale.

## Motivation
Recommendation models hold commercially sensitive embedding tables that cannot be centralized, but FL is blocked by the massive table sizes and the need to obliviously access them, making privacy-preserving training practically infeasible today.

## Method
FEDORA places the large ORAM structure on SSDs rather than DRAM, using SSD-friendly access optimizations to reduce write amplification and wear. It introduces epsilon-FDP (Federated Differential Privacy), a formal framework that trades off ORAM privacy strength against performance by allowing a controlled, quantified privacy budget, reducing the number of ORAM operations required. The system also supports modern FL operation modes (e.g., asynchronous and partial participation) so it integrates with production FL pipelines.

## Key Novelty
Epsilon-FDP is a new formal privacy notion that explicitly balances ORAM obliviousness against performance cost, enabling practical SSD-backed ORAM for federated recommendation training.

## Contributions
- epsilon-FDP: a formal privacy-performance tradeoff framework for ORAM in federated settings
- SSD-backed ORAM placement with SSD-friendly access pattern optimizations
- Support for modern FL operation modes (asynchronous, partial participation)
- Up to 24x latency reduction and over 1000x SSD lifetime improvement over ORAM baseline

## Limitations
