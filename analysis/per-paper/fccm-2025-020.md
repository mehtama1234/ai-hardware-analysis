# Efficiency, Expressivity, and Extensibility in a Close-to-Metal NPU Programming Interface

**Problem:** NPU programming toolkits present a fundamental tradeoff: low-level toolkits require substantial developer effort while high-level toolkits abstract away critical optimization features. Developers cannot simultaneously achieve ease-of-programming and fine-grained control over accelerator optimizations.

**Method:** They updated IRON—a toolkit for programming neural processing units (NPUs, specialized AI hardware you control directly)—by making its programming constructs modular and customizable. Programmers can now plug in custom tools to control how code maps to hardware regions (placement) and how data moves between them (data transformation). They evaluated it three ways: efficiency (measured by code reduction and code-complexity metrics), expressivity (support for all existing IRON features and patterns), and extensibility (whether placement and data-movement tools can be customized).

**Novelty:** The core idea is a customizable programming interface for neural processors with modular tools that let programmers control optimization details—how code maps to hardware (placement) and how data moves (transformation)—while making code 26% shorter.
