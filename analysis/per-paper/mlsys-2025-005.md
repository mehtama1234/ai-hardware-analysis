# Supply-Chain Attacks in Machine Learning Frameworks

**Problem:** ML frameworks have ~20x more dependencies than comparable non-ML packages, but existing supply-chain defenses only detect OS-level threats (system calls, network traffic), leaving ML-specific attacks undetected.

**Method:** The paper exploits Python's shared global variables to demonstrate supply-chain attacks on machine learning systems. A malicious package can rewrite PyTorch or TorchVision settings (interpolation modes, softmax functions, model forward methods) at import time, or use Python's inspect module and a low-level C API to modify function variables, enabling three attack types: backdoor injection via model hijacking, pipeline breaking via interpolation swaps, and model weight theft via steganography. The authors measure security awareness using GPT-3.5 (97.8% recall) then GPT-4 (78.9% precision, 0.85 Cohen's kappa) to analyze 549,635 GitHub issues/PRs from the 50 largest ML repositories, compared against the 50 largest Linux repositories.

**Key novelty:** First systematic ML-specific supply-chain attack class exploiting Python's shared memory; comprehensive GitHub security awareness study at scale using LLMs.

**Metrics:**
- Analysis pipeline: 97.8% recall, 78.9% precision, 0.85 Cohen's kappa
- 549,635 issues/PRs analyzed across Top-50 ML repos
- ML community security awareness statistically similar to Linux community (despite higher risk)
