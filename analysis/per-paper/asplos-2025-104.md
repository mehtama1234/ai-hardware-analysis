# asplos-2025-104: Protecting Cryptographic Code Against Spectre-RSB: (and, in Fact, All Known Spectre Variants)

**Venue:** ASPLOS  
**Confidence:** low (abstract only)

## Problem
Constant-time cryptographic code is designed to prevent timing-based secret leakage, but Spectre attacks — especially Spectre-RSB (Return Stack Buffer) — can violate constant-time guarantees by leaking secrets during speculative execution, and prior defenses cover only Spectre-v1 while leaving other Spectre variants unaddressed.

## Motivation
Post-quantum and classical cryptographic primitives deployed in production (e.g., Kyber) are vulnerable to the full Spectre attack surface, and a comprehensive, formally verified defense is needed to make cryptographic software provably secure against all known Spectre variants.

## Method
The approach combines a new value-dependent information-flow type system with a compiler transformation. The type system tracks whether values depend on secrets and may flow to speculative leak channels under any known Spectre variant. The compiler transformation rewrites low-level code by inserting fences, reordering, and masking as needed. Both the type-system soundness and compiler-transformation correctness are machine-proved in Coq, then implemented in the Jasmin high-assurance cryptography framework.

## Key Novelty
A Coq-verified value-dependent information-flow type system and matching compiler transformation that jointly protect against all known Spectre variants (including Spectre-RSB) with below 5-7% overhead for complex primitives.

## Contributions
- A value-dependent information-flow type system ensuring no secrets leak under speculative execution across all known Spectre variants.
- A compiler transformation for Jasmin that enforces type-system guarantees on generated low-level code.
- Coq proofs of type-system soundness and compiler-transformation correctness.
- Below 2% overhead for most cryptographic primitives; 5-7% for Kyber post-quantum KEM.
