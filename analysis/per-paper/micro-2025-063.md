# MX+: Pushing the Limits of Microscaling Formats for Efficient Large Language Model Serving

**Venue:** MICRO  
**Confidence:** high (full text)

## Problem
The 4-bit Microscaling (MXFP4) format suffers severe accuracy degradation when applied to LLM activation tensors because activation outlier values (Block Max, BM) are encoded with only 1 mantissa bit, causing large quantization errors that also corrupt the entire 32-element block via the shared exponent scale. This makes MXFP4 impractical for production LLM inference despite its potential bandwidth and compute savings.

## Motivation
LLM inference is memory-bandwidth-bound, making 4-bit quantization critical for cost-effective serving, yet MXFP4 fails on activation quantization due to outliers—blocking industry adoption of the lowest-bit MX tier.

## Method
MX+ repurposes the private exponent field of the Block Max (BM) element within each MX block as additional mantissa bits. The BM's exponent is always set to the representable maximum by the MX definition, so those bits are free to store mantissa precision instead. For MXFP4+, BM goes from E2M1 to effective E0M3 (3 mantissa bits vs 1). An extra 8-bit field per 32-element block stores the BM index (5 bits index, 3 reserved). For software GPU integration, MX+ decomposes BM into high/low halves (BMH, BML), both representable as standard E2M1 FP4, enabling a dense MMA plus one additional sparse MMA for BMH. For hardware integration into Blackwell-class Tensor Cores, dedicated BM Detector, Forward and Swap Units (FSUs), and a BM Compute Unit (BCU) are added outside the dot-product engine, computing BM-related products in parallel—adding only 0.020mm2 at 28nm.

## Key Novelty
Repurposing the BM element's own exponent field as extended mantissa within the MX block encoding—requiring no change to block structure, shared scale, or NBM elements—precisely represents the outlier without additional storage cost or software framework modification.

## Contributions
1. MX+ format: non-intrusive BM outlier precision extension (E0M3 vs E2M1 for MXFP4+), 0.25 bits/element overhead
2. Software integration via CUTLASS+vLLM on RTX 5090; up to +42.15% accuracy vs MXFP4, ≤1.13x slowdown
3. Hardware Tensor Core integration (BM Detector + FSU + BCU, 28nm, 0.020mm2) at 0.38% throughput overhead
4. Systematic comparative analysis showing MX consistently outperforms MSFP and SMX at equivalent bit widths

## Metrics
- Accuracy: up to +42.15% task accuracy (Llama-3.1-8B, MXFP4+ vs MXFP4)
- Perplexity: WikiText-2 from 27.69 (MXFP4) to ~9.5 (MXFP4+) for Llama-3.1-8B
- Hardware slowdown: 0.38% vs MXFP4 with HW integration
- Software slowdown: up to 1.13x (A-MXFP4+) at long decode
- Area: 0.020mm2 at 28nm per Tensor Core

## Baselines
MXFP4, MXFP6 (E2M3), MXFP8 (E4M3), MSFP variants, SMX variants, A8W4, BF16

## Limitations
Evaluation is limited to post-training quantization (direct-cast); QAT results are only shown for smaller vision/CNN models; not validated on MoE or very long-context LLMs.
