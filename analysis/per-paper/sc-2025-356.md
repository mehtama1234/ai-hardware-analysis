# Seeking Cost-Optimal Infrastructure Size for Distributed Filesystems: A Ceph Case Study

**Paper ID:** sc-2025-356
**Venue:** SC
**Confidence:** low

## Problem Statement
Predicting distributed filesystem I/O performance based solely on hardware configuration is not straightforward

## Motivation
Cost-effective DFS design requires understanding how hardware choices (cores, RAM, bandwidth) affect actual performance

## Method
They tested Ceph, a distributed storage system, by systematically changing how much CPU, memory, and disk bandwidth it could access. Using Linux hotplug (which dynamically enables or disables CPU cores) and Cgroups (which constrains how many resources a process can use), they created different hardware configurations. They then measured I/O performance—how fast the system could read and write data—under each configuration.

## Key Novelty
Adding more CPU, memory, or disk bandwidth to a distributed filesystem doesn't speed up I/O performance proportionally; the relationship is non-linear and depends on which resource is increased.

## Contributions
- Method for assessing hardware configuration impact on DFS
- Evidence that resource reduction doesn't yield proportional performance loss
- Cost-effective Ceph design guidelines
