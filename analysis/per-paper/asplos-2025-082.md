# COMET: Towards Practical W4A4KV4 LLMs Serving

**Venue:** ASPLOS 2025  
**Confidence:** low (abstract-only)

## Problem
Standard activation quantization to 4-bit causes unacceptable accuracy loss, making W4A4 impractical despite INT4 tensor core availability on modern GPUs, and leaving KV cache memory bandwidth largely unaddressed by existing W8A8 or W4-only methods.

## Motivation
LLM inference is bottlenecked by GPU memory bandwidth and capacity; W4A4KV4 would halve memory traffic vs W8A8, but requires solving the activation outlier accuracy problem to be deployable.

## Method
COMET makes practical 4-bit quantization (storing weights and intermediate calculations as 4-bit integers instead of higher precision) by identifying extreme activation values and keeping those at 8-bit precision instead—most values compress to 4-bit without losing accuracy. The GPU kernel efficiently handles this mixed 4-bit/8-bit data by placing elements close together in memory to speed up dequantization (converting back to regular precision for computation), overlapping data loading with calculation to reduce idle time, and balancing work across streaming multiprocessors (the GPU's parallel processing units). This enables large models like LLaMA-3-70B to run efficiently on a single A100-80G GPU with 4-bit key-value caches.

## Key Novelty
COMET achieves practical 4-bit weight and activation (W4A4) quantization by keeping extreme activation values at 8-bit while compressing others to 4-bit, combined with a GPU kernel that co-locates mixed 4-bit/8-bit data and balances work across processors to fully utilize INT4 tensor cores.

## Contributions
- FMPQ: fine-grained mixed-precision algorithm compressing most activations to INT4 with negligible accuracy loss
- Optimized W4Ax kernel with mixed-precision layout, software pipelining, and fast dequantization
- Fine-grained SM scheduling for load balance across streaming multiprocessors
- COMET framework: first practical W4A4KV4 LLM serving; 2.88x kernel speedup vs cuBLAS, 2.02x throughput vs TensorRT-LLM
