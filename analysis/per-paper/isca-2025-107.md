# MoPAC: Efficiently Mitigating Rowhammer with Probabilistic Activation Counting

**ID:** isca-2025-107
**Venue:** ISCA
**Confidence:** low (abstract-only)

## Problem
DDR5 JEDEC's Per-Row Activation Counters (PRAC) introduce extended DRAM timing parameters that cause 10% average performance overhead for all applications — even benign ones — because counter updates are performed on every activation regardless of actual attack likelihood.

## Motivation
As PRAC moves toward commercial adoption in DDR5, its blanket per-activation overhead represents a significant tax on normal workloads that must be reduced without compromising Rowhammer security guarantees.

## Method
MoPAC reduces counter-update frequency by performing PRAC updates probabilistically rather than on every row activation. To maintain security, the mitigation threshold is adjusted downward by the inverse of the sampling probability to ensure aggressors are still caught before exceeding the Rowhammer threshold. MoPAC-C (memory-controller side) uses two precharge command variants: a normal-latency precharge that skips counter updates and a higher-latency precharge that performs counter updates, with the controller probabilistically selecting which to issue. MoPAC-D (in-DRAM) probabilistically selects activations for counter updates within the DRAM chip and uses ALERT or REF timing to absorb the counter-update latency.

## Key Novelty
Probabilistic PRAC counter updates with threshold compensation, enabling a hardware-transparent reduction in DDR5 timing overhead while preserving formal Rowhammer security guarantees.

## Contributions
1. MoPAC-C: memory-controller-side probabilistic precharge selection achieving 1.7% average slowdown at threshold 500, vs. 10% for PRAC.
2. MoPAC-D: fully in-DRAM probabilistic activation sampling achieving 0.7% average slowdown at threshold 500.
3. Formal security argument showing threshold adjustment correctly compensates for probabilistic undercounting.
4. Demonstration that MoPAC removes a major commercial adoption barrier for PRAC in DDR5.

## Limitations
Probabilistic undercounting could be exploited by adversaries who craft attack patterns that exploit the sampling gap; the security argument assumes statistical independence of activations.
