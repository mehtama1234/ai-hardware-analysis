# Fault Escaping: Improving Robustness of DPU Enhanced Platform with Mutual Assisted VM Recovery

**Venue:** ASPLOS  
**Confidence:** low (abstract-only)

## Problem
Cloud servers using DPUs to offload virtualization split VM state across the DPU SoC and the host, so a failure in either component crashes the entire machine with no fault-tolerant mechanism designed for this split-hypervisor architecture.

## Motivation
DPU-based offloading has increased cloud server failure rates because splitting hypervisor functions across two processing units doubles the failure surface, requiring a fundamental rethink of VM fault tolerance.

## Method
Fault escaping treats the split hypervisors on the DPU SoC and the host as redundant peers. Hybrid synchronization keeps the full VM state accessible on either side with kilobyte-scale overhead by differentiating hot and cold VM state. When one side fails, VMs migrate their verified state to the surviving peer and resume execution there rather than attempting in-place recovery of the failed component.

## Key Novelty
Treating DPU and host hypervisors as redundant peers enabling VMs to escape a failing component, rather than waiting for in-place recovery.

## Contributions
- Fault-escaping scheme enabling VM migration from a failing DPU or host to the surviving peer
- Hybrid synchronization protocol maintaining full VM state on both sides with kilobyte-scale overhead
- VM state verification ensuring only consistent, uncorrupted state is migrated
- Improved cloud server robustness without dedicated fault-recovery hardware

## Hardware Target

## Techniques

## Metrics
- Other: kilobytes of synchronization overhead; VM recovery latency improvement

## Baselines
Traditional monolithic hypervisor fault tolerance, DPU-based platforms without fault escaping

## Limitations
Recovery requires the surviving peer to have sufficient resources; contention under simultaneous failures not discussed.
