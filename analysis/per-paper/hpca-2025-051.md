# Let-Me-In: (Still) Employing In-pointer Bounds Metadata for Fine-grained GPU Memory Safety

**Venue:** HPCA  
**Confidence:** low (abstract-only)

## Problem
GPU programs written in C/C++ inherit memory safety vulnerabilities such as out-of-bounds accesses. The heterogeneous GPU memory hierarchy (heap, local memory, thousands of concurrent threads) makes it difficult to enforce fine-grained bounds checking with low overhead.

## Motivation
As GPUs are deployed in safety-critical systems (autonomous driving, medical diagnostics), memory corruption bugs pose serious reliability and security risks, and existing GPU memory safety schemes impose prohibitive metadata storage or performance costs.

## Method
LMI aligns GPU memory allocations to powers-of-two boundaries and performs static analysis at compile time to identify and mark pointer arithmetic instructions. Bounds metadata is encoded into the unused upper bits of 64-bit GPU virtual address pointers, eliminating separate metadata memory structures. Hardware bounds-checking logic validates each memory access against the in-pointer metadata before issuing the request.

## Key Novelty
Storing per-object bounds metadata entirely within the unused upper bits of GPU pointers, made feasible by power-of-two allocation alignment and static pointer-arithmetic tagging.

## Contributions
1. Fine-grained GPU memory safety mechanism (LMI) covering heap and local memory with negligible hardware overhead
2. Power-of-two allocation alignment strategy that enables in-pointer metadata encoding on GPUs
3. Static analysis pass that identifies and marks pointer arithmetic instructions
4. Evaluation demonstrating near-zero performance and hardware cost overhead
