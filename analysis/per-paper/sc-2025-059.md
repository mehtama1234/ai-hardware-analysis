# To Stream or Not to Stream: Towards A Quantitative Model for Remote HPC Processing Decisions

**ID:** sc-2025-059  
**Venue:** SC  
**Confidence:** high

## Problem
Scientific instruments generate data exceeding local compute; file-based remote HPC processing impractical for time-sensitive analysis

## Motivation
Real-time streaming frameworks promise latency reduction but lack principled feasibility assessment

## Method
The framework builds a decision tool called the Streaming Speed Score that figures out whether to send data directly to a remote computer (streaming) or save it to files first. It does this by measuring four things: how fast data arrives (data rate), how well it travels across the network (transfer efficiency), how quickly the remote computer can handle it (processing power), and how much time gets lost reading and writing files (I/O overhead). By comparing these measurements, the model tells you which approach—streaming the data live or storing it as files—will finish your analysis faster.

## Key Novelty
The innovation is a mathematical model (Tpct) that determines when streaming outperforms the file-based approach by considering data rate, network transfer efficiency, and processing power.

## Contributions
1. Develops Streaming Speed Score framework
2. Models total processing completion time (Tpct)
3. Validates on LCLS-II, APS, FRIB, LHC use cases
4. Shows 97% latency reduction under high data rates
