# Precise exceptions in relaxed architectures

**Venue:** ISCA 2025
**Confidence:** low (abstract-only)

## Problem
The 60-year-old definition of precise exceptions assumes a sequential programmer's model and is fundamentally inadequate for modern relaxed-memory architectures like Arm-A; no formal specification exists for what exception precision means under relaxed concurrency.

## Motivation
As architectures expose programmer-visible relaxed memory behavior, the hardware-software contract at exception entry and exit is ambiguous, threatening correctness of systems software relying on exception semantics.

## Method
The authors built a formal mathematical model (an axiomatic model) that defines how exceptions behave in Arm-A processors when memory operations don't always execute in the order they're written. They identified three critical cases the model must handle: what happens at exception boundaries when memory is relaxed, external hardware aborts, and software-generated interrupts. To validate the model, they built a toolchain and a library of litmus tests—small test programs that show exactly which processor behaviors are allowed and which are forbidden. The model extends existing Arm-A specifications by adding formal rules for how exceptions enter and exit.

## Key Novelty
This is the first formal definition of what exception precision means in Arm-A, a processor with relaxed memory, answering a decades-old question in computer architecture.

## Contributions
1. Formal axiomatic model for precise exceptions in Arm-A's relaxed-memory setting
2. Identification and characterization of cross-boundary relaxed behavior, external aborts, and software-generated interrupts
3. Tooling for executing and checking the axiomatic model
4. Library of litmus tests covering exception precision behaviors
