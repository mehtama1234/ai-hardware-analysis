# GSplit: Scaling Graph Neural Network Training on Large Graphs via Probabilistic Splitting

**ID:** mlsys-2025-035 | **Venue:** MLSYS 2025 | **Confidence:** high

## Problem
Data-parallel GNN mini-batch training causes massive redundant feature loading (up to 2.5x) and computation because the same graph vertices appear in multiple GPU micro-batches.

## Method
GSplit pre-computes an optimal GPU assignment for graph vertices during an offline phase by sampling graph patterns to estimate which vertices and edges are used together frequently, then using METIS (a graph partitioning algorithm that minimizes edges crossing between groups) to assign vertices to GPUs accordingly. At training time, each sampled mini-batch is instantly partitioned by looking up each vertex's pre-assigned GPU in a table—a constant-time operation that replaces expensive per-batch optimization. During each GNN layer, GPUs exchange only the features that cross their boundaries, eliminating the redundant loading that occurs when the same vertices appear in multiple GPU batches.

## Key Novelty
The core idea is pre-computing a global GPU assignment from sampled graph patterns using METIS, reducing per-batch graph partitioning from an NP-hard optimization problem to a constant-time lookup while provably minimizing inter-GPU communication.

## Metrics
- **Speedup:** Up to 4.4x over DGL (2.5x avg), 4.1x over P3 (2.4x avg), 1.9x over Quiver (1.4x avg)
- **Hardware:** AWS EC2 p3.8xlarge, 4x NVIDIA V100

## Baselines
DGL, Quiver, P3 (push-pull parallelism), Edge (naive split)
