# isca-2025-028 — MagiCache: A Virtual In-Cache Computing Engine

**Venue:** ISCA 2025  
**Confidence:** low (abstract only)

## Problem
Array-level in-cache computing architectures commit entire SRAM arrays to compute roles, leaving most computing lines idle at runtime and causing severe on-chip capacity loss. Bursty memory accesses in data-parallel applications also incur high in-cache data movement latency.

## Motivation
Data-parallel workloads need in-cache computation to eliminate cache-to-processor data movement, but current coarse-grained array-level designs waste capacity because only a few rows per array are active at any time.

## Method
MagiCache uses cacheline-level in-cache computing: each SRAM array can dynamically designate individual rows as computing lines or cachelines with negligible overhead. A **virtual engine** monitors runtime computation and storage needs, performing dynamic row allocation (cacheline-level space management). An **instruction chaining** technique allows asynchronous execution of computing arrays, overlapping bursty memory access latency via pipelined, out-of-order scheduling.

## Key Novelty
Cacheline-granularity dynamic allocation of SRAM rows between compute and cache roles via a virtual engine, eliminating fixed capacity loss of array-level in-cache designs and hiding access latency via instruction chaining.

## Contributions
1. Cacheline-level in-cache architecture with per-row dynamic assignment (compute vs. cache).
2. Virtual engine for runtime space management based on observed compute/storage demand.
3. Instruction chaining for asynchronous computing array execution to overlap memory latency.
4. 1.19–1.61x speedup over state-of-the-art in-cache computing with only 6.5 KB extra storage.
