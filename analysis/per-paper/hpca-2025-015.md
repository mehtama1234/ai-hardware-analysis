# hpca-2025-015 — Chronus: Understanding and Securing the Cutting-Edge Industry Solutions to DRAM Read Disturbance

**Venue:** HPCA  
**Confidence:** low (abstract-only)

## Problem
DDR5 PRAC RowHammer mitigation places counter increment on the critical DRAM access path and is vulnerable to the "wave attack," forcing overly conservative refresh thresholds and prohibitive performance overhead for future DRAM generations.

## Motivation
DRAM cell shrinkage increases RowHammer vulnerability each generation; PRAC is the first in-DRAM standard mitigation but had no rigorous security/performance analysis and its overheads grow with future node scaling.

## Method
Chronus separates activation counters from data arrays so counter updates run concurrently with data accesses (no critical-path latency). It dynamically controls the number of preventive refreshes per back-off signal to neutralize wave attacks. Only in-DRAM die modifications required; open-sourced.

## Key Novelty
Decoupling activation counters from data storage enables concurrent updates without access latency penalty, while dynamic refresh count control defeats wave attacks.

## Contributions
- First rigorous security, performance, energy, and cost analysis of DDR5 PRAC.
- Identification of PRAC's two weaknesses: critical-path counter latency and wave-attack vulnerability.
- Chronus concurrent counter mechanism eliminating PRAC latency overhead.
- Dynamic preventive refresh count control defeating wave attacks; near-zero overhead for modern DRAM.
