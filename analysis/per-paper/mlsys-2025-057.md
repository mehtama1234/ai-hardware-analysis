# Radius: Range-based Gradient Sparsity for Large Foundation Model Pre-training

**Venue:** MLSYS 2025

## One-line Problem
Top-k gradient sparsification for data-parallel LLM training is incompatible with AdamW and requires expensive allgather whose cost grows linearly with worker count.

## Method
Radius observes that the most important gradients (top-k, the largest ones) stabilize after 15-20% of training, so it computes which ones matter once and reuses that selection for 200 steps rather than recomputing every step. Since all workers compute this same selection from combined gradient data independently, they only need to send the values of selected gradients using standard combining (allreduce) without exchanging index information, avoiding the expensive allgather step. Before computing selections, Radius applies AdamW's optimizer adjustments so that selections reflect genuine model changes. It accumulates non-selected gradients and periodically adds them back to prevent permanent information loss.

## Novelty
Leverages temporal index stability to replace allgather (O(n) scaling) with dense allreduce on sparse subset, making gradient sparsification scalable and AdamW-compatible for the first time.

## Key Metrics
- Per-step time reduction: **21%** at 40% sparsity on GPT-2.0B (64 A100)
- Overall pre-training speedup: **19%** at 40% sparsity
- Communication reduction: **89.7%** at d=0.4
- Scaling efficiency at 128 GPUs: **42.5%** vs 32.8% (dense baseline)
- Downstream task performance: preserved on GLUE/SuperGLUE/LAMBADA
