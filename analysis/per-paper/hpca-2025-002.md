# LEGO: Spatial Accelerator Generation and Optimization for Tensor Applications
**Venue:** HPCA 2025 | **ID:** hpca-2025-002 | **Confidence:** high (full text)

## Problem
Existing spatial accelerator design frameworks either rely on a small set of hand-written RTL/HLS templates (limiting design space coverage) or cannot automatically generate synthesizable RTL. Existing polyhedral and STT representations entangle control flow with dataflow, causing 2x-2.6x area/power overhead in control logic.

## Motivation
Foundation models and multimodal generative AI require a single accelerator to efficiently handle diverse tensor kernels (GEMM, convolution, attention) with different optimal dataflows, yet no existing framework can automatically explore and generate RTL for arbitrary dataflow combinations.

## Method
LEGO represents hardware using mathematical transformation rules (affine transformations, which convert time and space coordinates into computation instructions) that keep computation logic, data paths, and memory completely separate. It solves linear equations to find which processing units should connect to maximize data reuse, uses a tree algorithm (Minimum Spanning Tree via the Chu-Liu/Edmonds algorithm) to remove unnecessary connections, and applies breadth-first search to plan wiring across combined computation flows (fused dataflows) while organizing memory into banks that avoid access conflicts. Finally, it converts the high-level design (Architecture Description Graph) into a detailed specification (Detailed Architecture Graph), applies mathematical optimization (linear programming) to minimize temporary storage hardware and eliminate unused logic, and outputs synthesizable hardware code.

## Key Novelty
The core innovation is a unified approach based on affine transformations that completely separates control logic from data flow, enabling automatic generation of working hardware code (synthesizable RTL) for any combination of spatial dataflows without hand-written templates, while reducing control overhead by 2 to 6.5 times compared to prior polyhedral and state-transition-table (STT) approaches.

## Contributions
1. Relation-centric affine representation separating control flow from dataflow, eliminating division/modulo and enabling shared control-signal propagation (6.5x flip-flop, 5.0x LUT savings vs AutoSA)
2. Frontend: integer-linear-equation interconnection analysis, MST-based minimal connection selection, BFS-based heuristic for multi-dataflow fusion with conflict-free memory banking
3. Backend: primitive-level DAG with LP-based delay matching and pin-rewiring; 28-35% area savings over naive RTL
4. 3.2x speedup, 2.4x energy efficiency over Gemmini; single architecture serves diverse foundation model kernels

## Metrics
- **Speedup:** 3.2x over Gemmini
- **Energy:** 2.4x energy efficiency over Gemmini
- **Area:** 35% savings from backend optimization; 2.0x area savings vs TensorLib
- **Other:** 6.5x flip-flop savings vs AutoSA; 5.0x LUT savings vs AutoSA
