# FACIL: Flexible DRAM Address Mapping for SoC-PIM Cooperative On-device LLM Inference

**Venue:** HPCA  
**Confidence:** low (abstract-only)

## Problem
On-device LLM inference requires the same model weights to be accessed by both DRAM-based PIM units (for GEMV in the memory-bound decode phase) and SoC processors (for GEMM in the compute-bound prefill phase), but PIM-operable tensor layouts require different DRAM bank mappings from those preferred by SoC processors, creating costly re-layout overheads when switching between the two.

## Motivation
Edge devices have limited memory capacity, so PIM must function as both a compute unit and a conventional memory device; enabling re-layout-free cooperative inference between SoC and PIM is essential to minimize time-to-first-token on resource-constrained edge hardware.

## Method
FACIL introduces a flexible DRAM address mapping scheme in the memory controller that assigns different DRAM address mappings to the page offset bits of each huge page. A user-level library determines the appropriate mapping for each tensor, allowing LLM weights to be placed in DRAM banks that are simultaneously PIM-operable and contiguously addressable by the SoC processor. This dual-mapping eliminates the need to copy or re-layout tensor data when switching between PIM-executed GEMV and SoC-executed GEMM operations.

## Key Novelty
Per-huge-page configurable DRAM address mapping in the memory controller that allows the same physical tensor to be accessed coherently by both PIM hardware and SoC processors without data re-layout.

## Contributions
1. FACIL: flexible DRAM address mapping that enables simultaneous PIM-operable and SoC-contiguous tensor placement
2. Memory controller extension assigning different DRAM address mappings to page offset bits per huge page
3. User-level library for determining and managing appropriate DRAM address mappings at tensor granularity
4. 2.37x and 2.63x time-to-first-token reduction for short conversation and code autocompletion tasks over SoC-PIM baseline

## Limitations
The approach is evaluated on edge LLM scenarios with LPDDR-interfaced PIM; applicability to server-class PIM systems with different DRAM packaging is not discussed.
