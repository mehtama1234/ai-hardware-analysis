# asplos-2025-172: Be CIM or Be Memory: A Dual-mode-aware DNN Compiler for CIM Accelerators

**Venue:** ASPLOS  
**Confidence:** low (abstract-only)

## Problem
CIM accelerators can switch dynamically between compute and memory modes, but existing DNN compilers ignore this capability and statically assign resources, leaving performance untapped especially for LLMs with variable per-layer memory/compute demands.

## Motivation
Emerging LLMs have highly variable memory and compute requirements across layers; exploiting CIM mode-switching is crucial to fully utilize CIM accelerators for real-world DNNs.

## Method
CMSwitch tells the compiler about a hardware capability it previously ignored: CIM accelerators can switch between compute mode (performing calculations) and memory mode (storing or accessing data). The compiler uses optimization techniques—dynamic programming (trying different solutions systematically) and mixed-integer programming (math for finding the best outcome when some variables must be whole numbers)—to determine where to split the network and how much hardware resources to allocate to compute versus memory modes. The result is packaged in a form that works across different CIM hardware targets.

## Key Novelty
It's the first compiler to jointly optimize compute and memory mode resource allocation using dynamic programming and mixed-integer programming, adapting resources dynamically to each neural network layer's requirements.

## Contributions
- Novel hardware abstraction attribute exposing CIM mode-switching to compiler optimization
- Compilation pass combining dynamic programming and MIP for optimal mode/resource allocation
- Tailored meta-operator for generalized hardware-agnostic CIM compilation output
- 1.31x average speedup over SOTA CIM compilers across diverse DNN workloads including LLMs
