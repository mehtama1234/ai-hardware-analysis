# WIC: Hiding Producer-Consumer Synchronization Delays with Warp-Level Interrupt-based GPU Communications

**Problem:** GPU kernels suffer high synchronization overhead when producers must wait for consumers through traditional barriers and polling-based synchronization. Producer-consumer communication patterns incur latency stalls that reduce GPU utilization and throughput.

**Method:** In typical GPU programs, producers and consumers pause at synchronization barriers until everyone reaches the same point—wasting time waiting. WIC uses interrupt signals directed at thread groups (called warps) so producers can notify consumers asynchronously, without waiting for confirmation. Instead of repeatedly checking (polling) or pausing to synchronize, consumers continue other work until an interrupt wakes them when data arrives. This decouples their timing, hiding synchronization delays so they don't reduce overall GPU throughput.

**Novelty:** Interrupt signals to thread groups let producers notify waiting consumers automatically, eliminating the need for synchronized pause-point barriers.
