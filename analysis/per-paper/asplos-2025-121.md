# Dynamic Partial Deadlock Detection and Recovery via Garbage Collection

**Venue:** ASPLOS  
**Authors:** Georgian-Vlad Saioc, I-Ting Angelina Lee, Anders Moller, Milind Chabbi  
**Confidence:** low (abstract only)

## Problem
Concurrent message-passing programs in Go are susceptible to partial deadlocks where goroutines block indefinitely on channels, causing severe memory leaks in long-running systems. Existing techniques cannot both detect and automatically recover from these partial deadlocks at runtime.

## Motivation
Go's lightweight concurrency model makes partial deadlocks common in production systems, and memory leaks from blocked goroutines degrade availability, as evidenced by 252 deadlocks detected in 24 hours in a real Uber service.

## Method
GOLF extends Go's garbage collector marking phase to soundly approximate goroutine liveness: a goroutine is considered live only if its channel references are reachable from the GC root set. During GC marking, goroutines blocked on channels with no live senders are flagged as deadlocked. Detected deadlocked goroutines are then automatically cancelled or cleaned up to free memory and restore system progress, integrating directly into the existing GC pause.

## Key Novelty
Using the garbage collector's reachability marking phase as a sound liveness approximation for goroutines, enabling automatic partial deadlock detection and recovery without separate runtime monitors.

## Contributions
- A novel technique to detect partial deadlocks by approximating liveness through GC reachability
- GOLF: an implementation integrated into the Go runtime GC that detects and recovers from partial deadlocks
- Detection of 94% of microbenchmark partial deadlocks and 50% in a large industrial codebase
- Production deployment at Uber detecting 252 partial deadlocks over 24 hours
