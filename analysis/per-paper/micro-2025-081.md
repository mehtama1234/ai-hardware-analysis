# micro-2025-081: Delegato: Locality-Aware Atomic Memory Operations on Chiplets

**Venue:** MICRO 2025  
**Authors:** Victor Soria Pardos, Adria Armejach, Tiago Muck, Dario Suarez Gracia, Jose A. Joao, Miquel Moreto  
**Confidence:** high (full text)

## Problem
Chiplet-based architectures impose high, non-uniform memory access latencies across chiplet boundaries, severely degrading performance of atomic memory operations (AMOs) for synchronization. Existing near AMOs cause cache-line ping-pong across chiplets; centralized AMOs incur coherence misses and ALU area at the directory.

## Motivation
Chiplet integration is now the primary scaling path for large core-count processors (e.g., NVIDIA Grace with NVLink at 50 ns cross-chiplet latency), making conventional AMO strategies significantly less efficient than in monolithic designs.

## Method
Two new coherence transactions are introduced in AMBA 5 CHI: (1) Delegated AMOs forward the RMW via a new SnpAMO message to the current cache-line owner, executing locally without cache-line transfer; (2) Migrating AMOs transfer ownership to the requester via AtomicLoad (exposing the primitive to the directory). Five static directory AMO policies (All-Central, All-Migrate, Present-Central, Pinned-Owner, Unowned-Central) and a Chiplet-Aware policy select the best transaction based on cache state and chiplet location. Delegato is a reuse-tracing mechanism: the L2 sets a one-bit reuse_bit in every SnpAMO response, feeding a directory Predictor Table that transitions between Pinned-Owner, Present-Central, and Chiplet-Aware states. Evaluated in gem5 23.1 (AMBA 5 CHI, 32 OoO cores in dual 16-core chiplets, HeteroGarnet NoC).

## Key Novelty
Delegated and Migrating AMO coherence transactions letting the directory execute AMOs at the cache-line owner without invalidation or transfer, plus a one-bit reuse tracing mechanism (Delegato) transporting private-cache locality information to the directory predictor.

## Contributions
1. Two new far AMO coherence transactions (Delegated and Migrating) within AMBA 5 CHI; Migrating requires no directory ALU
2. Five static policies and a Chiplet-Aware policy exploiting requester/owner chiplet location
3. Delegato: reuse-tracing piggybacking on SnpAMO responses for a directory-level predictor
4. 1.13x speedup over DynAMO and 1.07x over All-Centralized, on 20+ benchmarks in gem5

## Hardware Target
chiplet, CPU

## Techniques
coherence, interconnect, memory-system

## Workloads
graph-analytics (BC, BFS, SSSP), HPC (LULESH, Barnes-Hut, FMM), lock-free data structures

## Key Metrics
- Speedup: 1.07x over centralized AMOs; 1.13x over DynAMO
- Area: atomic ALU extension 2894 um2 at TSMC 7nm (0.11% of Neoverse V1 tile)
- Critical path: Delegated AMOs reduce inter-chiplet messages from 4 to 2 in worst case

## Baselines
Near AMOs, Centralized AMOs (All-Central), DynAMO predictor, NVIDIA Grace single/dual-chiplet configurations

## Limitations
Delegate transactions limited to single-owner scenarios (multi-sharer case deferred); performance gains are modest (1.07x-1.13x geomean) reflecting the narrow AMO optimization window.
