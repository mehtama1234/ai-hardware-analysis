# CXLfork: Fast Remote Fork over CXL Fabrics

**Venue:** ASPLOS  
**Confidence:** low (abstract-only)  
**Primary Theme:** CXL-enabled zero-copy remote process cloning for serverless scale-out

## Problem
Remote process cloning across cluster nodes incurs high serialization and copying overhead, creating large cold-start latency for serverless functions and other scale-out workloads. Traditional fork() semantics do not map efficiently to distributed shared memory environments like CXL-attached memory.

## Motivation
CXL interconnects enable globally-shared memory pools across nodes, and exploiting this for process cloning can eliminate cold-start bottlenecks in serverless computing without the overhead of network-based state transfer.

## Method
CXLfork implements a remote fork interface that uses CXL-attached shared memory to achieve near-zero-serialization, zero-copy process cloning across nodes. It stores process state in globally-shared CXL memory for cluster-wide deduplication, so cloning a process on a remote node avoids transferring state over the network. Fine-grained tiering between local DRAM and CXL memory is supported. CXL-porter builds on top as an efficient horizontal autoscaler for serverless functions.

## Key Novelty
Using CXL-attached globally-shared memory for cluster-wide process-state deduplication to achieve near-local-fork latency for remote process cloning.

## Contributions
- CXLfork: a remote fork interface achieving close to zero-serialization, zero-copy process cloning over CXL fabrics
- Cluster-wide process-state deduplication using CXL shared memory
- Fine-grained state tiering between local DRAM and CXL memory
- CXL-porter: an efficient horizontal autoscaler for serverless functions built on CXLfork
