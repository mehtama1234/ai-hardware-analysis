# Enhancing CGRA Efficiency Through Aligned Compute and Communication Provisioning

**Venue:** ASPLOS 2025  
**Confidence:** high (full text)

## Problem
CGRAs overprovision communication resources: each PE is paired with a full crossbar router designed for peak congestion, consuming 44% of power/area (routers 15% + communication config 29%) while average utilization is low. Individual-node execution also inflates configuration memory overhead.

## Motivation
Edge devices need domain-agnostic, high-performance, energy-efficient accelerators. Existing CGRAs waste 43% power and 46% area on over-provisioned communication without proportional throughput benefit.

## Method
Plaid introduces a hierarchical execution paradigm based on three-node structural motifs — the exhaustive set of three-node DFG subgraph patterns (fan-in, fan-out, unicast). The Plaid Collective Unit (PCU) groups three ALUs around a single lightweight local router handling all intra-motif data dependencies internally; a global router connects PCUs for inter-motif communication. The Plaid compiler (Morpher toolchain + simulated annealing modulo scheduling) identifies motifs in DFGs using an iterative greedy-then-randomized algorithm, generates a hierarchical DFG, and maps onto PCU arrays using flexible schedule templates. Synthesized in Verilog RTL at 22nm FDSOI, 100MHz; a 2x2 PCU array matches a 4x4 spatio-temporal CGRA in functional unit count.

## Key Novelty
Three-node DFG motifs (mathematically proven exhaustive building blocks) enable a Plaid Collective Unit that handles intra-motif communication with a single local router, eliminating per-PE over-provisioned crossbars and aligning compute/communication provisioning.

## Contributions
- Identification of compute/communication misalignment as the core CGRA efficiency bottleneck
- Three-node structural motif abstraction as exhaustive DFG building blocks
- Plaid CGRA: hierarchical two-level NoC (local intra-PCU + global inter-PCU)
- End-to-end Plaid compiler with motif identification + hierarchical modulo-scheduling mapper

## Hardware Target

## Workloads
CNN, vision (TinyML), HPC (PolyBench linear algebra, image processing)

## Metrics
- Performance: 1.4x over spatial CGRA; matches spatio-temporal CGRA
- Power: 43% reduction vs spatio-temporal CGRA
- Energy: 42% reduction vs spatio-temporal; 27.7% vs spatial
- Area: 46% savings vs spatio-temporal; 48% vs spatial
- vs domain-optimized CGRA: 1.22x energy efficiency, 1.25x area efficiency
- CGRA fabric: 33,366 um2 at 22nm

## Baselines
- Spatio-temporal CGRA (4x4 PE, 22nm, ADRES/HyCUBE style)
- Spatial CGRA (SNAFU/Riptide style, 22nm)
- Domain-optimized spatio-temporal CGRA (ML-specialized, REVAMP style)

## Limitations
Performance degrades on kernels with very complex or long-distance dependencies that fall outside three-node motifs, requiring fallback to global routing.
