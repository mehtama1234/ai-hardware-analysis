# Towards Optimal Rack-scale μs-level CPU Scheduling through In-Network Workload Shaping

**Problem:** Prior rack-scale CPU scheduling systems suffer from inaccurate network load balancing and complex sub-optimal scheduling because they lack application awareness. This results in poor tail latency and throughput for microsecond-level services.

**Method:** Pallas uses information about each request's CPU needs to sort them at network switches into groups (shards) with similar computational demands. By routing these CPU-similar requests to appropriate servers using a simple rule (CPU affinity), the system avoids complex optimization and keeps load balanced. Each server then schedules incoming requests with full knowledge of what's coming, making better decisions than scheduling blindly.

**Novelty:** Sorting requests by CPU demand at the network level rather than at individual servers, which enables simpler and more efficient rack-scale scheduling.
