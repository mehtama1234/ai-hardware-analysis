# asplos-2025-008: PipeLLM: Fast and Confidential Large Language Model Services with Speculative Pipelined Encryption

**Venue:** ASPLOS  
**Confidence:** low (abstract-only)

## Problem
Confidential GPU computing (e.g., NVIDIA H100 TEE) protects outsourced LLM inference through data encryption, but synchronous encryption imposes up to 52.8% throughput reduction for OPT-30B and 88.2% for OPT-66B, making confidential LLM serving commercially impractical.

## Motivation
Outsourced LLM inference increasingly requires strong confidentiality guarantees via TEE-enabled GPUs, but the encryption overhead makes confidential LLM serving commercially unviable without a mechanism to hide encryption latency.

## Method
PipeLLM encrypts data while the GPU computes, rather than waiting for one to finish before starting the other—similar to how modern CPUs run multiple instructions at the same time. The challenge is that the encryption system doesn't know what data to encrypt until the GPU actually requests it. PipeLLM solves this by predicting what will need encrypting next, based on patterns in how AI models typically serve requests—like token generation and KV-cache access (a buffer storing prior tokens)—and encrypting it before the GPU asks. When a prediction is wrong, a lightweight mechanism recovers without any errors.

## Key Novelty
PipeLLM uses speculative prediction of what needs encrypting—based on LLM serving patterns—to overlap encryption with GPU computation, nearly eliminating encryption latency.

## Contributions
- Characterization showing up to 88.2% throughput drop from synchronous encryption in H100-class confidential GPU LLM serving.
- Speculative pipelined encryption predicting encryption targets from LLM serving patterns.
- Efficient pipeline relinquishing mechanism for handling mispredictions with low overhead.
- Demonstrated <19.6% throughput overhead vs. non-confidential baselines (vLLM, PEFT, FlexGen) across 13B-175B LLMs.
