# asplos-2025-064 — Accelerating LLM Serving for Multi-turn Dialogues with Efficient Resource Management

**Venue:** ASPLOS  
**Confidence:** low (abstract-only)

## Problem
Current LLM serving frameworks recompute attention keys and values for all prior turns on each new query in a multi-turn dialogue, incurring substantial redundant compute overhead. Additionally, the long accumulated prompt lengths from multi-turn context cause head-of-line blocking under FCFS scheduling, underutilizing GPU resources.

## Motivation
Multi-turn chat interactions are the dominant LLM serving pattern, but serving frameworks optimized for single-request throughput suffer disproportionate latency and GPU underutilization as conversation length grows.

## Method
The paper introduces efficient resource management for multi-turn LLM serving by preserving KV-cache state across turns to eliminate recomputation of prior-turn attention keys and values. A new scheduling policy replaces FCFS with a length-aware or priority-based scheduler that avoids head-of-line blocking by reordering or preempting long-prompt requests. KV-cache memory is managed dynamically to balance cache retention across concurrent multi-turn sessions, trading off memory capacity against recompute cost.

## Key Novelty
Cross-turn KV-cache retention combined with a head-of-line blocking-aware scheduler specifically designed for the multi-turn dialogue serving regime.

## Contributions
- Characterization of multi-turn dialogue as a distinct LLM serving workload with unique KV-cache and scheduling challenges.
- Cross-turn KV-cache management to eliminate redundant attention recomputation across dialogue turns.
- Scheduling policy that mitigates head-of-line blocking for long accumulated prompts in multi-turn settings.
- GPU resource utilization improvements demonstrated on multi-turn chat benchmarks.
