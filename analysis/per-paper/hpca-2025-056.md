# Adyna: Accelerating Dynamic Neural Networks with Adaptive Scheduling

**Venue:** HPCA  
**Confidence:** low (abstract-only)

## Problem
Dynamic neural networks (DynNNs) conditionally skip computation based on input difficulty, but current GPUs and specialized accelerators lack dataflow and architecture support to realize theoretical efficiency gains because dynamic execution patterns defeat static resource allocation.

## Motivation
DynNNs offer a promising way to reduce average inference cost by matching computation to per-sample difficulty, but without hardware-aware scheduling these savings are not realized on real silicon.

## Method
Adyna solves the problem of dynamic neural networks (networks that conditionally skip computation when inputs are easy) by precompiling multiple specialized kernels (hardware-optimized computation versions), each designed for a different workload size. At runtime, instead of using a generic kernel or compiling on demand, the system observes what the actual workload looks like and selects the precompiled version best suited for it. An intelligent algorithm decides which kernel versions to prepare upfront, balancing coverage of different workload sizes against the limited on-chip memory available on the accelerator. This ensures the hardware always runs code optimized for the specific input at hand, unlocking efficiency gains that dynamic networks promise but hardware traditionally cannot deliver.

## Key Novelty
The core insight is precompiling a small set of specialized kernels (each optimized for a specific workload size) and dynamically selecting which one to execute based on observed input characteristics, so hardware resources are always well-utilized regardless of how much computation the input actually requires.

## Contributions
1. Unified representation capturing diverse DynNN architectures for general hardware design
2. Dynamism-aware dataflow scheduler that selects kernels based on runtime dynamic-size distributions
3. Kernel sampling algorithm to choose optimal precompiled kernel sets for on-chip storage
4. 1.70x/1.57x average speedup over multi-tile/multi-tenant accelerators (up to 2.32x/2.01x)

## Limitations
Precompiling multiple kernels increases compilation time and on-chip memory pressure; the sampling algorithm's effectiveness depends on the dynamic-size distribution being predictable.
