# QServe: W4A8KV4 Quantization and System Co-design for Efficient LLM Serving

**Problem:** INT4 quantization delivers memory savings but existing dequantization approaches incur 20-90% runtime overhead on CUDA cores, erasing gains at large cloud-serving batch sizes.

**Method:** QoQ (4-8-4) algorithm: (1) Progressive group quantization uses INT8 per-channel then INT4 per-group with a protective range [-119, 119] ensuring INT4 values scale safely within INT8 for Tensor Core GEMM. (2) SmoothAttention applies per-channel scale to Keys, absorbed into preceding linear weights using RoPE commutativity, enabling 4-bit KV without accuracy loss. (3) Compute-aware weight reordering stores weights in GEMM computation order enabling 128-bit/thread memory transactions. Fast dequantization uses subtraction-before-multiplication and 4-way vadd4 register parallelism. KV4 attention uses bit-trick ops to cut dequantization from 5 to 2 ops/element.

**Key novelty:** Protective-range progressive quantization for safe W4A8 Tensor Core use; SmoothAttention with RoPE-commutativity-aware Key scale absorption.

**Metrics:**
- 1.2x Llama-3-8B throughput on A100 vs TensorRT-LLM
- 1.4x Llama-3-8B throughput on L40S vs TensorRT-LLM
- 2.4x Qwen1.5-72B throughput on A100 vs TensorRT-LLM
- 3.5x Qwen1.5-72B throughput on L40S vs TensorRT-LLM
- L40S QServe exceeds A100 TensorRT-LLM throughput
