# QServe: W4A8KV4 Quantization and System Co-design for Efficient LLM Serving

**Problem:** INT4 quantization delivers memory savings but existing dequantization approaches incur 20-90% runtime overhead on CUDA cores, erasing gains at large cloud-serving batch sizes.

**Method:** QServe makes INT4-quantized weights efficient by keeping dequantization on Tensor Cores (specialized multipliers) rather than general-purpose CUDA cores. Progressive group quantization uses a protective range of [-119, 119] to ensure INT4 values remain safe when scaled back to INT8 for Tensor Core multiply-accumulate without overflow; SmoothAttention suppresses outliers in Key tensors by applying per-channel scales that absorb into preceding layer weights (exploiting RoPE's mathematical commutativity), enabling 4-bit Key/Value quantization without accuracy loss. Compute-aware weight reordering stores weights in their actual GEMM access order for efficient 128-bit/thread memory fetches, while fast dequantization via vadd4 instructions (processing 4 weights per instruction) reduces per-element operations from 5 to 2 in attention decoding.

**Key novelty:** Protective-range progressive quantization for safe W4A8 Tensor Core use; SmoothAttention with RoPE-commutativity-aware Key scale absorption.

**Metrics:**
- 1.2x Llama-3-8B throughput on A100 vs TensorRT-LLM
- 1.4x Llama-3-8B throughput on L40S vs TensorRT-LLM
- 2.4x Qwen1.5-72B throughput on A100 vs TensorRT-LLM
- 3.5x Qwen1.5-72B throughput on L40S vs TensorRT-LLM
- L40S QServe exceeds A100 TensorRT-LLM throughput
