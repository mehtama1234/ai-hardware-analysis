# isca-2025-075 — Dynamic Load Balancer in Intel Xeon Scalable Processor: Performance Analyses, Enhancements, and Guidelines

**Venue:** ISCA  
**Confidence:** low (abstract only)

## Problem
Increasing inter-host network speeds cause bursty, unevenly distributed traffic across CPU cores, creating queuing delays and latency variance. The Intel DLB on-chip accelerator improves over software load balancers but still consumes substantial host CPU cycles preparing work descriptors for received packets.

## Motivation
Network throughput growth outpaces CPU load-balancing capacity; eliminating the host CPU from the descriptor enqueue hot path removes the last significant overhead in hardware-assisted load balancing.

## Method
The researchers tested Intel's DLB (Dynamic Load Balancer, hardware built into processors to distribute work across cores) against software alternatives using focused performance tests. They then designed AccDirect, which uses a direct hardware-to-hardware communication channel (called PCIe P2P) between the network interface card and the DLB, bypassing the CPU entirely. The network card can now directly send work assignments to the DLB's queues using P2P DMA (direct memory access between devices, without CPU involvement), removing the CPU overhead that normally happens when preparing and enqueuing these assignments. By cutting the CPU out of this frequently-executed operation (the 'hot path'), they eliminated a major bottleneck.

## Key Novelty
AccDirect eliminates host CPU involvement in load balancing by using a direct hardware-to-hardware connection (PCIe P2P) between the network interface card and the processor's built-in load balancer, reducing system-wide CPU power consumption by 10% while maintaining equivalent throughput.

## Contributions
1. Microbenchmark suite comparing Intel DLB vs. software load balancers
2. Identification of host CPU descriptor preparation as the dominant remaining DLB overhead
3. AccDirect PCIe P2P architecture bypassing CPU in load-balancing hot path
4. Comprehensive DLB configuration guidelines across its large QoS feature space
