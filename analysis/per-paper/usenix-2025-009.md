# Opening Up Kernel-Bypass TCP Stacks

**Problem:** Kernel-bypass TCP stacks with different design choices for throughput and latency have never been systematically compared across representative workloads, making it difficult to understand performance trade-offs when handling both bulk data transfers over multi-hundred gigabit Ethernet and small request-response messages requiring low latency.

**Method:** The researchers compared six different TCP network stacks—both kernel-bypass versions (which skip the operating system for faster data sending) and traditional in-kernel ones—by running them on representative workloads: bulk data transfers over multi-hundred gigabit Ethernet and small request-response messages. They measured throughput (how much data flows per second) and latency (response time) to understand which design choices work best for each workload type.

**Novelty:** This is the first systematic comparison of kernel-bypass TCP stacks across representative workloads, showing that no single design excels at both bulk data transfers and low-latency request handling.
