# Towards an Automated Workflow for Floating-Point Analysis of GPU Kernels

**Venue:** SC 2025  
**Authors:** Esteban Miguel Rangel, S. John Pennycook

## Problem & Motivation

GPU kernels used in scientific computing require rigorous floating-point accuracy evaluation to ensure scientific validity, but current analysis methods are manual, labor-intensive, and inflexible. No standardized approach exists to systematically evaluate accuracy across different precision modes (FP16, TF32, BF16, IEEE) and compiler optimizations.

## Approach

An automated floating-point analysis workflow that:

1. **Records GPU Kernel Execution:** Uses Intercept Layer for OpenCL to capture GPU kernel execution.
2. **CPU Replay:** Replays recorded kernels on CPU runtimes (PoCL) without source modification.
3. **Precision Evaluation:** Analyzes floating-point error using Verificarlo across multiple precision modes.
4. **Compiler Effect Analysis:** Evaluates impact of compiler optimizations (-ffast-math) using stochastic arithmetic (MCA/PRISM).

## Key Novelty

- **No Source Modification:** Extracts and analyzes kernels without rewriting application code.
- **Diverse Precision Support:** Evaluates IEEE and reduced-precision modes systematically.
- **Open Tools Integration:** Builds on standardized, open-source tools and standards (OpenCL, SYCL).

## Contributions

- Automated floating-point error analysis workflow for GPU kernels
- GPU-to-CPU replay mechanism enabling CPU-based analysis
- Support for IEEE and reduced-precision modes (FP16, TF32, BF16)
- Integration of stochastic arithmetic for compiler optimization effects
- Reusable methodology leveraging open tools

## Hardware Target

- GPU systems (SYCL-compatible)
- CPU analysis platforms
- Cosmology and scientific simulation systems

## Workloads

- GPU kernel floating-point error quantification
- HACC cosmology simulation (force kernel case study)
- Scientific simulations with mixed-precision requirements

## Case Study

Analysis of the force kernel from HACC (large-scale cosmology code) exploring:
- IEEE-compliant precision
- Reduced-precision modes (FP16, TF32, BF16)
- Compiler optimization effects via -ffast-math

## Limitations & Questions

- Early work; workflow maturity and readiness level unclear
- Single case study limits generalization to diverse kernels
- CPU replay performance overhead not quantified
- Scalability to production-scale kernels and large applications undemonstrated
- Integration path for production workflows not defined
- Applicability to proprietary architectures (NVIDIA, AMD) not discussed
