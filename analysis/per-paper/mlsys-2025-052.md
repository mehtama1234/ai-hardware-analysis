# Balancing Pipeline Parallelism with Vocabulary Parallelism

**Venue:** MLSYS 2025

## One-line Problem
Vocabulary (embedding + output projection) layers concentrated on one pipeline stage cause compute and memory imbalance that worsens pipeline bubbles and memory bottlenecks.

## Method
Vocabulary Parallelism distributes embedding and output layers (which handle vocabulary processing—the complete set of tokens the model can work with) evenly across pipeline devices instead of concentrating them on one device. The method reduces communication overhead between devices, measured in all-reduce barriers (device synchronization points), through two strategies: Algorithm 1 cuts these from 3 to 2, and Algorithm 2 reduces to 1 by computing softmax outputs online (incrementally rather than storing intermediate values) and using pre-computed gradients. This integrates with existing pipeline scheduling methods like 1F1B and V-Half.

## Novelty
Online softmax optimization eliminating 2 of 3 communication barriers in vocabulary layer passes, enabling vocabulary computation to be pipelined across all devices with only a small constant activation memory overhead.

## Key Metrics
- Throughput improvement: **5% to 51%** over naive approaches
- Communication barriers: **3 → 1** (Algorithm 2)
- Perfect compute + memory balance when combined with V-Half schedule
