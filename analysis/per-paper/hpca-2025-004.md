# Efficient Memory Side-Channel Protection for Embedding Generation in Machine Learning
**Venue:** HPCA 2025 | **ID:** hpca-2025-004 | **Confidence:** low (abstract only)

## Problem
Embedding table lookups in ML models (DLRMs, LLMs) leak sensitive input features through memory access patterns, making them vulnerable to side-channel attacks; protecting these accesses with conventional ORAM incurs prohibitive overhead due to the massive size of embedding tables.

## Motivation
Privacy-preserving ML inference requires hiding memory access patterns to embedding tables, but embedding tables can be hundreds of gigabytes, making ORAM's O(log N) overhead per access impractical.

## Method
The paper evaluates three defenses against side-channel attacks (information leaking through memory access patterns): linear scan (reading every row of the embedding table—a lookup table for neural network parameters—to hide which row is actually used), ORAM (a technique that encrypts and reshuffles memory accesses to obscure patterns, but is expensive for huge tables), and Deep Hash Embedding (DHE), which computes the embedding through a neural network fed the index directly, eliminating the memory access signature. A hybrid scheme combines DHE for large tables (where computation cost is spread across many lookups) and linear scan for small tables, chosen per table based on measured performance tradeoffs.

## Key Novelty
The core innovation is replacing embedding table lookups with Deep Hash Embedding (DHE)—a neural network that computes embeddings from indices instead of fetching them from memory—which defends against side-channel attacks by eliminating the telltale memory access pattern rather than merely hiding it, yielding 4x speedup over optimized ORAM and 1116x memory footprint reduction.

## Contributions
1. Systematic comparison of linear scan, ORAM, and DHE for embedding side-channel protection
2. Demonstration that DHE eliminates memory access patterns and reduces memory footprint by up to 1116x
3. Hybrid DHE+linear-scan scheme: 4x speedup over ORAM (DLRM), 3.08x end-to-end speedup
4. Extension to LLMs: 1.32x prefill and 1.07x decoding speedup over ORAM for GPT-2

## Metrics
- **Speedup:** 4x large DLRM tables vs ORAM; 3.08x end-to-end vs optimized ORAM; 1.32x GPT-2 prefill, 1.07x decoding
- **Memory:** up to 1116x footprint reduction
