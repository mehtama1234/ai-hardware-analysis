# FLStore: Efficient Federated Learning Storage for non-training workloads

**Problem:** FL non-training workloads (scheduling, personalization, clustering) suffer from high latency and cost due to remote cloud object-store or in-memory cache bottlenecks for large metadata volumes.

**Method:** FLStore builds a cache that sits between applications and data storage, placing computation right next to the cached data to avoid latency. A hash-table-based Cache Engine spreads data across cache nodes and sends requests to whichever node holds the needed data using locality-aware key hashing (a method that keeps related data together). A Request Tracker watches how each client accesses data over time to spot frequently-used data ('hot data'). The system uses four caching policies, each designed for a different type of federated learning workload: P1 stores each client's model updates by round, P2 caches the aggregated (combined) models, P3 saves derived information like gradients and loss values across rounds, and P4 pre-loads data it predicts will be requested next.

**Key novelty:** Unified compute+data serverless cache with a systematic four-policy taxonomy derived from FL workload access analysis.

**Metrics:**
- 71% avg latency reduction vs cloud object-store aggregator (99.7% peak)
- 92.45% cost reduction vs object-store aggregator (98.8% peak)
- 64.6% avg latency reduction vs in-memory cache aggregator
- 98.83% cost reduction vs in-memory cache aggregator
