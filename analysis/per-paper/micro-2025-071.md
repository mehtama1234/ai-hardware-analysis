# micro-2025-071: Efficient Security Support for CXL Memory through Adaptive Incremental Offloaded (Re-)Encryption

**Venue:** MICRO  
**Confidence:** low (abstract-only)

## Problem
CXL memory expansion adopted in cloud TEE environments (Intel SGX/TDX, AMD SEV) requires XTS encryption for data confidentiality via CXL IDE, but XTS encryption's per-page sequential latency causes significant performance overhead on memory-intensive workloads. Dynamically switching encryption modes and re-encrypting pages adds further overhead.

## Motivation
CXL memory is increasingly deployed in cloud computing to expand DRAM bandwidth and capacity, but integrating it with TEE-protected enclaves creates a security overhead bottleneck that limits adoption in latency-sensitive workloads.

## Method
AIORE speeds up encrypted access to CXL memory expansion devices by using two different encryption methods depending on how often data is accessed. Frequently accessed pages (hot pages) use CTR encryption, which is fast and can run in parallel, while rarely accessed pages (cold pages) use XTS encryption, which is required by the CXL IDE security standard. When a page's usage pattern changes, AIORE re-encrypts only that single page, doing the work using compute resources inside the CXL memory device itself so the re-encryption happens in parallel with regular memory traffic. This approach is tested using gem5 full-system simulation across diverse workloads.

## Key Novelty
The key advance is offloading incremental page re-encryption to the CXL memory device's own compute, enabling dynamic switching between CTR and XTS encryption modes based on access frequency.

## Contributions
- Adaptive per-page encryption policy dynamically selecting CTR vs. XTS based on access frequency
- Incremental re-encryption limiting scope to changed pages rather than full memory regions
- Re-encryption offloaded to CXL memory node compute to hide latency
- Security overhead reduced 62.8% on average; residual overhead within 3.7% vs. insecure baseline
