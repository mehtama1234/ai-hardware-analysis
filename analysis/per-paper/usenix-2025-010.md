# On-Demand Container Partitioning for Distributed ML

**Problem:** Distributed ML training workloads have dynamic resource requirements that static container configurations cannot adapt to, leading to underutilization and prolonged training times.

**Method:** The system watches how much CPU, memory, and network bandwidth each container actually uses during training. When one container needs more resources while another has spare capacity, it automatically shifts resources between them without pausing the job. These adjustments happen continuously based on what the workload demands at each moment.

**Novelty:** The system automatically shifts CPU, memory, and network resources between containers while training is running, adjusting in real-time to match what each container actually needs rather than using pre-set allocations.
