# Lincoln: Real-Time 50~100B LLM Inference on Consumer Devices with LPDDR-Interfaced, Compute-Enabled Flash Memory

**Venue:** HPCA  
**Confidence:** low (abstract-only)

## Problem
Consumer devices cannot run large 50-100B LLM models in real time because: (1) Flash storage has insufficient internal read bandwidth for per-iteration weight loading, and (2) the conventional Flash interface (NVMe/UFS) offers far lower transmission bandwidth to the NPU than DRAM interfaces, making both the prefill and decode phases severely bandwidth-limited.

## Motivation
Privacy and cost concerns drive demand for on-device LLM inference, but current approaches are limited to small, lower-quality models because the weight-loading bottleneck from Flash memory makes large-model inference far too slow for real-time use.

## Method
Lincoln uses a two-phase strategy matched to how large language models work. During the prefill phase (the initial stage, which is compute-heavy), it connects Flash storage to the NPU using LPDDR, which is the same fast interface normally used for RAM, so weights move much faster than standard Flash connections while keeping costs down. During the decode phase (the output stage, which needs lots of memory access), it embeds computing directly on Flash storage using hybrid bonding (a 3D connection technology), so matrix-vector calculations happen at the storage itself and avoid slow data transmission, while speculative decoding predicts future tokens to reduce latency. Flash's internal speed is also improved using tighter array designs that reduce read time and enable more parallel data paths, all built on 3D hybrid bonding already present in consumer Flash chips.

## Key Novelty
The core idea is to split the LLM workload by phase: use LPDDR's high speed to stream weights from Flash during prefill, and embed compute directly on Flash storage using hybrid bonding (3D connection technology) during decode to handle memory-intensive operations without transmission delays.

## Contributions
1. Device-level Flash bandwidth improvement via enhanced array shrinking and 3D hybrid bonding for more parallel Flash planes
2. LPDDR-interfaced Flash for prefill phase: repurposing the high-speed DRAM interface for Flash weight transmission to NPU
3. Near-Flash computing via hybrid bonding for decode phase: GEMV execution on Flash dies to eliminate transmission bottleneck
4. Integration with speculative decoding; up to 13.23x prefill and 254.1x generation speedup over conventional SSD-based systems
