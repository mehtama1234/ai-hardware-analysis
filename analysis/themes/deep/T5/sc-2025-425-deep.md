# KDRSolvers: Scalable, Flexible, Task-Oriented Krylov Solvers

**Venue:** SC · **Subtheme:** Flexible Sparse Solver Data Partitioning via Task Runtimes

## What It Does

KDRSolvers decouples sparse matrix storage format from Krylov solver algorithm implementation, enabling flexible data partitioning strategies without code refactoring. The core abstraction is dependent partitioning: the library represents sparse matrices using an abstract dependent partitioning that maps between three partitioning layers—domain (nonzero positions), range (output values), and entries (row/column indices). Universal co-partitioning operators automatically propagate partitioning decisions from matrices to vectors; the framework ensures that matrix partitions and vector partitions align without manual coordination.

For example, if a user changes from row-block partitioning to 2D graph partitioning, the matrix partitioning adapts, and co-partitioning operators automatically adjust vector partitions—no algorithmic code changes required. Multi-operator systems handle non-contiguous data ingestion (e.g., if different rows come from different file formats or compression schemes).

The implementation targets the Legion task-based runtime, which schedules sparse matrix-vector multiply operations across heterogeneous systems (multi-GPU clusters, CPU nodes) while respecting dependencies.

## The Key Result

On up to 1,024 NVIDIA GPUs, KDRSolvers achieves 9.6% reduction in iteration time versus PETSc/Trilinos baseline. Performance is competitive with established sparse solver frameworks while offering automatic partitioning propagation.

## Why This Approach

Traditional sparse solver frameworks (PETSc, Trilinos) require manual data partitioning: users specify how matrix rows are distributed, then manually ensure vector partitions match. Changing partitioning strategy (e.g., from 1D row-block to 2D graph partitioning for load balancing on heterogeneous systems) requires extensive code refactoring to align matrix and vector operations. This limits exploration of partitioning strategies for optimal performance on new hardware.

KDRSolvers solves this by abstracting the partitioning as a dependent structure: the framework automatically derives vector partitioning from matrix partitioning via co-partitioning operators. Users specify the matrix partitioning once, and all operations (matrix-vector multiply, preconditioner application, dot products) automatically partition vectors correctly. This enables rapid prototyping of new partitioning strategies without rewriting solver code.

Task-based runtime (Legion) further helps by scheduling operations automatically across GPUs, hiding heterogeneity from the solver algorithm.

## What It Leaves Open

- Speedup modest (9.6%); Legion runtime overhead not isolated or quantified separately, making it unclear whether speedup comes from better partitioning or just overhead reduction from abstraction.
- Scalability beyond 1,024 GPUs not tested; modern large-scale systems (10,000+ GPU datacenters) may expose additional scaling challenges not addressed.
- Limited evaluation on diverse problem types; focus on standard SPD/general linear systems, but performance on ill-conditioned problems, saddle point systems, or nonlinear (Newton-Krylov) problems unknown.
- Dependent partitioning abstraction adds memory overhead for metadata; this overhead not quantified, particularly for systems with millions of nonzeros.
- Comparison limited to PETSc/Trilinos; modern alternatives (Ginkgo, MFEM with task-based backends) not evaluated.
