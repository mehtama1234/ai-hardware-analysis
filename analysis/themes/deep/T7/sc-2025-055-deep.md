# Dynamic Factor Graphs for Attack Preemption

**Venue:** SC · **Subtheme:** HPC Security Monitoring and Proactive Threat Detection

## What It Does

This work deploys a factor-graph-based dynamic security model at the NCSA Blue Waters supercomputer—a petascale HPC facility—to perform real-time anomaly detection and attack preemption. Factor graphs are probabilistic graphical models where nodes represent random variables (e.g., network flow characteristics, login patterns, process behavior) and edges encode dependencies (e.g., a suspicious login increases the probability of subsequent data exfiltration). The system ingests live network traffic (via Zeek IDS) and host-based signals (process creation, file access) to continuously update marginal probabilities on the graph: nodes representing attack indicators (ransomware activity, unauthorized privilege escalation) are driven by observed evidence, and nodes representing system state are updated dynamically.

The key challenge in HPC is that defensive signals are extremely noisy: legitimate HPC jobs exhibit unusual I/O patterns (many processes accessing the same file, rapid process spawning) that superficially resemble attacks. Factor graphs handle this via probabilistic reasoning: rather than binary alert/no-alert decisions, the graph computes posterior probabilities for attack hypotheses, allowing operators to focus on high-confidence threats. The system is coupled with visualization tools that show the factor graph state and highlight which signals contributed most to an attack probability estimate, enabling human operators to understand why the system flagged a threat and make context-aware decisions.

## The Key Result

The system characterizes 228+ security incidents from archived NCSA Blue Waters logs. In a pilot deployment, the factor-graph system detected a known ransomware family (infection attempt on compute nodes) with sufficient precision to improve the production Zeek IDS policies used operationally. The visualization tools provided operators with actionable insights into attack patterns. While the paper does not report quantitative metrics (e.g., false-positive rate, detection latency, time-to-remediation), it demonstrates feasibility of factor-graph-based detection in a production petascale environment.

## Why This Approach

Supercomputing systems are high-value targets for cyberattacks: national laboratories, universities, and industry run security-sensitive workloads (climate modeling, nuclear simulations, pharmaceutical research) on HPC resources. Traditional alert-based intrusion detection (Zeek IDS, Snort) generates thousands of daily alerts; most are false positives, overwhelming security operators. Manual triage of alerts is infeasible at scale. Factor graphs provide a probabilistic framework for combining noisy signals—network traffic (many anomalies are normal for HPC), host behavior (rapid process spawning is normal for parallel jobs), and context (which users, which systems)—to compute attack probabilities. This is fundamentally different from rule-based detection (if X and Y then alert), which is brittle in complex environments. The factor graph approach is also interpretable: operators can inspect the graph to understand why a particular threat probability is high, enabling them to make informed decisions and tune the model over time.

## What It Leaves Open

- Evaluation is limited to a single ransomware family detection; the paper does not report generalized detection rates for diverse attack types (data exfiltration, privilege escalation, botnet activity, supply-chain compromises).
- No quantitative metrics for false-positive rate, false-negative rate, or detection latency are reported; unclear whether the system meets operational SLAs for rapid response.
- Factor graph structure and variable dependencies are not detailed; it is unclear whether the model captures HPC-specific correlations (e.g., job scheduling patterns, inter-node communication topologies) or generalizes only to non-HPC environments.
- Scalability to exascale systems (Frontier, Aurora, FUGAKU) with 10x more nodes and 10x higher traffic volume is not discussed.
- No comparison against other anomaly detection methods (isolation forests, autoencoders, rule-based Zeek policies) to establish whether factor graphs provide unique advantages over alternatives.
- Privacy implications of continuous network/host monitoring are not discussed; storage and retention policies for attack logs are not specified.
