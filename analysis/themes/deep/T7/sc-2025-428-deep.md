# Secure In-Storage Execution of VTK Workloads on Modern Parallel NFS Data Servers

**Venue:** SC · **Subtheme:** Data-Movement Reduction via In-Storage Processing

## What It Does

This work offloads scientific visualization workloads (specifically VTK—Visualization Toolkit pipelines) from compute clients to pNFS (Parallel NFS) data servers, reducing data movement across the network. The architecture uses pNFS protocols to execute VTK filter operations (read, resample, threshold, clip) in-silo on storage servers where the data already resides. The client submits high-level VTK commands (e.g., "load dataset X, apply filter Y, return geometry only") to the storage server via a FUSE (Filesystem in Userspace) interface, which translates VTK requests into local file system operations on the storage server's NFS exports. The storage server executes the VTK pipeline locally, performs data reduction (e.g., thresholding drops 90% of grid points), and returns only the reduced result (geometry and scalar fields) to the client, avoiding terabyte-scale data transfers across network.

Critically, the system preserves security: user credentials and permission checks are passed through the pNFS client location awareness mechanism, and the FUSE interface enforces standard file-system access controls. The implementation leverages Linux kernel enhancements for efficient local pNFS access (avoiding unnecessary network roundtrips) and maintains backward compatibility with standard NFS clients.

## The Key Result

On two large-scale scientific datasets, in-storage VTK execution achieves 6.1× end-to-end speedup (total time from filter initiation to result delivery) and 7.1× improvement in data loading time compared to client-side VTK processing. The speedup comes from two sources: (1) eliminating terabyte-scale network transfers (7.1× directly), and (2) overlapping network communication with computation. Despite the significant data-movement reduction, the paper does not report metrics for per-operation latency, intermediate memory usage, or scalability to many concurrent clients.

## Why This Approach

Scientific visualization is a critical bottleneck in data-intensive computing: climate simulations generate petabytes of data annually; analyzing even 1% requires filtering/reduction at the source. Moving terabytes across high-latency WAN or even LAN is prohibitively slow. In-silo compute (pushing computation to data, not pulling data to compute) is a well-established principle in data-center design, but has not been widely applied to scientific visualization. pNFS infrastructure already exists in HPC facilities (NERSC, OLCF, LLNL); repurposing it for in-storage VTK execution is cost-effective. The FUSE abstraction allows userspace VTK code to run on storage servers without kernel modifications, accelerating deployment. Alternative approaches (serverless compute on object storage, Spark on HDFS) introduce new dependencies and infrastructure; in-storage pNFS execution is closer to the existing HPC stack.

## What It Leaves Open

- Evaluation limited to two datasets; unclear how performance scales to more complex/higher-dimensional datasets or non-VTK workloads (ParaView, VisIt, custom visualization code).
- Only tested on pNFS; applicability to other parallel storage systems (Lustre, GPFS, Ceph) is not discussed.
- Requires Linux kernel enhancements for efficient pNFS local access; deployability on older HPC systems or non-Linux storage servers is unclear.
- Scalability to many concurrent clients not evaluated; contention for CPU/memory on storage servers may degrade performance if multiple visualization jobs run simultaneously.
- No comparison against alternative data-reduction approaches (client-side sampling, server-side decimation, hierarchical data formats like HDF5 with partial I/O).
- Security model assumes trusted storage infrastructure; untrusted storage servers, encryption at rest, or encrypted data processing are not addressed.
