# Implications of Full-System Modeling for Superconducting Architectures

**Venue:** SC · **Subtheme:** Post-CMOS Interconnect & Memory Bottlenecks

## What It Does

Superconducting electronics offer tantalizing advantages: 100x higher clock frequency (100 GHz vs 1-5 GHz CMOS), zero power dissipation in the superconductive state. But do these speedups translate to realistic workloads? This paper constructs the first full-system simulation of a superconducting CPU in gem5, combining superconducting cores (100 GHz RISC-V) with cryogenic semiconductor cores (4 GHz, for memory controllers and I/O), multilevel caches, and the SRNoC superconducting interconnect (superconductive routers). The key finding: superconducting speedups are highly dependent on data width and memory pressure. For compute-intensive workloads (low memory traffic, arithmetic-heavy), superconducting cores achieve up to 24x speedup because the high clock frequency is not stalled by memory access. But for memory-intensive workloads, speedup drops to just 1.2x because: (1) superconducting cores stall on cache misses waiting for room-temperature DRAM (cryogenic DRAM doesn't exist yet); (2) SRNoC interconnect performance is extremely data-width dependent. When sending wide data (64-bit words), SRNoC becomes 1246x slower than its narrow-data design point because superconducting routers use flux-quanta to encode information (each flux quantum ≈ 2e⁻¹⁵ Weber), making wide-data transmission require exponentially more routers. The paper identifies 800 GB/s cache bandwidth as a critical design requirement to feed superconducting cores without stalling; conventional CMOS cache hierarchies cannot sustain this.

Data flow: Superconducting core at 100 GHz issues load → hits L1 cache (4 cycles) → misses L2 → must fetch from room-temperature DRAM (100+ ns = 10,000+ cycles) → core stalls almost entirely. Meanwhile, SRNoC trying to send 256-bit wide data (normal for AI workloads) must split across 128 flux-quantum lanes, serializing transmission → effectively nullifies superconducting latency advantage.

## The Key Result

On SPEC CPU2006 and compute-intensive benchmarks, superconducting cores achieve up to 24× speedup versus conventional CMOS. On memory-intensive workloads, speedup drops to 1.2× due to DRAM bottleneck. SRNoC interconnect demonstrates 35-73× energy efficiency advantage for narrow data paths (1-2 bits) but suffers 1246× performance degradation for wide data (64+ bits). Cache bandwidth requirement: 800 GB/s, far exceeding conventional hierarchies.

## Why This Approach

As Moore's Law slows (process scaling stalling below 3nm, power density becoming unsustainable), the semiconductor industry explores alternatives: superconducting logic, optical interconnect, in-memory computing. Superconducting electronics are compelling in isolation — zero dissipation, high frequency — but the architectural implications are unexplored. Do superconducting CPUs make sense for general-purpose computing, or only for accelerators? Full-system simulation is essential to answer this because speedups compound (or don't) across the memory hierarchy. A 100x core speedup is pointless if DRAM latency is unchanged; the system speedup is determined by Amdahl's law: speedup = 1 / (memory stall fraction + compute time / 100). This paper demonstrates that conventional CMOS memory hierarchies and interconnects severely constrain superconducting benefits. The alternative — waiting for superconducting DRAM, designing superconducting memory controllers (not feasible in liquid helium), or entirely abandoning DRAM — is not practical in the near term.

## What It Leaves Open

- Superconducting DRAM technology is not addressed; assumes room-temperature DRAM will forever remain the bottleneck, limiting applicability to specialized domains.
- SRNoC interconnect design decisions (flux quantum encoding, wide-data multicast) are presented as fixed; no exploration of alternative encodings (e.g., polarization, frequency modulation) that might scale better with data width.
- Cryogenic semiconductor cores (4 GHz) are assumed necessary for memory controllers, but their design and memory-barrier integration is not detailed; unclear if they become a secondary bottleneck.
- Workload evaluation limited to SPEC CPU2006 and generic compute-intensive benchmarks; no specialized workloads (cryptography, quantum simulation, signal processing) where superconducting properties might excel.
- Area, yield, and cost of superconducting-CMOS heterogeneous integration not modeled; gem5 assumes perfect fabrication.
- Power consumption breakdown not provided; though superconducting cores dissipate zero power in steady state, cooling overhead (dilution refrigerators for liquid helium) and cryogenic interconnect power are not quantified.
