# Automatic Generation of Mappings for Distributed Fourier Operations

**Venue:** SC · **Subtheme:** Communication Optimization for Scientific Computing

## What It Does

In distributed scientific computing, multi-dimensional Fourier transforms (used in fluid dynamics, weather simulation, quantum chemistry) are frequently fused with linear algebra operations (matrix multiply, solve). Traditional libraries like heFFTe (distributed FFT) and COSMA (distributed matmul) provide independent optimizations: heFFTe arranges MPI ranks in a process grid to minimize all-to-all transpose communication during the FFT; COSMA separately optimizes matmul. But they don't coordinate between operations. For example, if an FFT produces output in a [16×16] rank grid while matmul expects [8×32], an implicit reshape/transpose must occur, incurring 50% additional communication. This paper proposes automatic mapping generation: given a sequence of Fourier and linear algebra operations (e.g., FFT → A*x → inverse FFT), the system formulates a constraint satisfaction problem (CSP) in Z3 SMT solver to jointly optimize grid shape, Fourier decomposition strategy, and data layout across all operations. The key mechanism is **non-linear iterative formulation**: instead of fixing grid shapes per operation (standard library behavior), the optimizer searches across compatible grid shapes (e.g., 16×16, 8×32, 4×64 all equivalent for 256 ranks) and selects the path that minimizes cross-operation communication. For example: FFT produces [16×16] grid → optimizer recognizes that transposing to [8×32] costs 32 all-to-all messages but saving matmul setup via [8×32] avoids 64 messages → net savings 32 messages → selects [8×32]. The Z3 solver encodes Fourier dimension constraints (FFT dimensions must be powers of 2), linear algebra constraints (compatible matrix dimensions), and communication costs as weighted predicates, then outputs an execution plan specifying rank assignments per operation and global memory layout.

Data flow: Input array X [256×256] distributed 16×16 across ranks → FFT decomposes as 16 independent 1D FFTs per rank, then local transposition, then 16 more per-rank FFTs → intermediate [16×16] grid → cost minimizer chooses whether to reshape to [8×32] before matmul or absorb reshape into FFT itself → execute selected plan → output.

## The Key Result

On coupled Fourier-linear algebra workloads, automatic mapping generation achieves 2-31× speedup compared to using heFFTe and COSMA together (standard practice). The wide speedup range (2-31x) reflects different workload compositions: workloads with many FFTs and few matmuls show larger gains (more communication saved through FFT optimization), while balanced workloads show moderate gains.

## Why This Approach

Scientific computing codes frequently interleave spectral methods (FFTs) with direct solvers or iterative methods (matrix operations). Each operation has its own optimal process grid for minimal communication: FFT prefers slab or pencil decompositions (Nx × Ny or Nx × 1); matmul prefers square 2D grids (sqrt(P) × sqrt(P)) for load balance. Switching between grids incurs expensive transpose-redistribute operations. Manually scheduling these transitions requires deep domain expertise (few researchers can optimize coupled Fourier-matmul workflows). The alternative — rigid library interfaces that force users to adapt algorithms — limits algorithmic innovation. Automatic mapping via SMT solving provides a general mechanism: express constraints (FFT can't use non-power-of-2 dimensions, matmul needs compatible shapes) and communication costs (transpose = O(P) messages), and let the solver find the globally optimal path. This is tractable because the constraint space, while large, has structure exploitable by modern SMT solvers (Z3 uses incremental SAT solving and theory-specific reasoning for arithmetic). The paper's key insight is that Fourier operations' communication patterns are "rigid" (fixed by algorithm) but "flexible" in grid shape (multiple equivalent grids for same computation), creating degrees of freedom that matmul scheduling can exploit.

## What It Leaves Open

- Specific benchmarks, workload mixes, and cluster topologies not detailed in abstract; claims of 2-31× speedup range widely depending on problem structure.
- Scalability beyond 256-512 ranks and how SMT solver time grows with problem size (nonlinear solver can have exponential worst-case runtime); no analysis of solver time vs. execution time.
- Heterogeneous interconnects (hierarchical bandwidth, non-uniform MPI latency) not modeled; assumes uniform bandwidth, which is unrealistic for high-dimensional torus topologies or slow inter-node links.
- Integration with fault tolerance and dynamic load balancing (if ranks have variable compute speed due to congestion, can the solver adapt in-flight) is unexplored.
- Does not address out-of-core or GPU-accelerated FFTs; assumes CPU-only distributed memory computation.
- Error feedback and numerical stability of grid reshaping not discussed; assumes stable transform across grid shapes (true mathematically, but floating-point precision may degrade under certain reshape sequences).
