# Make Updates Faster: A Fast Multi-Stripe Updates Framework in Erasure-Coded Storage Clusters

**Venue:** SC · **Subtheme:** Optimized Update Strategies for Erasure-Coded Distributed Storage

## What It Does

Erasure coding (e.g., Reed-Solomon) reduces storage redundancy in data centers (e.g., 10 data blocks + 4 parity blocks for 40% overhead vs. 3x replication for 200% overhead), but updates are expensive: modifying a data block requires reading all d data blocks, computing new parity, and writing back modified blocks plus new parities—a read-modify-write (RMW) cycle that generates d times more network traffic than the payload. The framework optimizes updates via three mechanisms: (1) Locality-aware update merging coalesces multiple update requests targeting the same stripe into a single RMW cycle, reducing network round trips. (2) Collector and tree selection abstracts the network topology: the framework models update propagation as building a tree rooted at the stripe (all blocks involved in one RMW), selects nodes greedily to minimize load imbalance and message hops. (3) Dynamic stripe scheduling adapts the order in which pending updates are issued to exploit time-varying network bandwidth: if a link becomes congested, the scheduler postpones updates that would bottleneck on that link, prioritizing updates that use available capacity.

Data flow: update requests arrive at a coordinator, are coalesced by stripe (locality-aware merging), then scheduled dynamically. For each scheduled update, the framework selects a collector (an intermediary node that gathers all d data blocks and computes parities) and a tree structure (how to route blocks to the collector and parities back to storage nodes), balancing per-node load and hop count. The system maintains estimates of link bandwidth and adapts scheduling to saturate available capacity.

## The Key Result

In deployment on Alibaba's erasure-coded storage infrastructure (ECS), the framework achieves 16.15% to 88.71% improvement in update throughput compared to baseline approaches. Improvements are highest on workloads with clustered updates (high spatial locality within update bursts), and benefits vary by network conditions (heterogeneous bandwidth). On some microbenchmarks, the framework saturates available network bandwidth, indicating near-optimal performance; on production traces, real-world benefits depend on workload update patterns and network topology.

## Why This Approach

Erasure-coded storage is ubiquitous in cloud data centers because it drastically reduces redundancy overhead, but updates remain a bottleneck. Naive update strategies (process updates sequentially, rebuild all parities for each update) waste network bandwidth and cause long latency tails. Prior optimization work focuses on single aspects: some exploit locality (coalesce updates) but don't adapt to network conditions; others optimize scheduling but don't minimize collector load. The key insight is that these three optimization dimensions are interdependent: locality-aware merging reduces traffic per update, but if the collector is heavily loaded, benefits disappear; scheduling adapts to current network state, but without locality awareness, each update still generates high traffic. The framework's three-part design addresses all three simultaneously. The approach is chosen over post-update verification (checksums) or other reliability mechanisms because update latency/throughput directly impacts data center SLAs; reliability (correctness of parity computation) is assumed to be handled by the erasure codec itself.

## What It Leaves Open

- **Evaluation limited to Alibaba ECS environment**: the framework's performance on other erasure-coded systems (Google Colossus, Microsoft Azure Storage) or with different erasure codes (EVENODD, LRC, qLDPC-inspired codes) is unknown; generalization is unclear.
- **Dynamic scheduling overhead not detailed**: the framework requires real-time estimation of link bandwidth, network topology awareness, and online scheduling decisions; CPU overhead on the coordinator and latency added by scheduling delays are not quantified.
- **Assumes specific workload patterns**: benefits are highest on bursty, clustered updates (e.g., log-structured writes from a single application); for fine-grain, random updates (e.g., multi-tenant key-value stores), locality exploitation provides little benefit, and the framework's overhead may outweigh gains.
- **Network model simplification**: the framework abstracts network as tree structures; real data center networks are complex (fat-tree, Clos) with adaptive routing and congestion control; interaction with TCP/QUIC congestion handling is not addressed.
- **Real-world trace analysis limited**: evaluation uses Alibaba production traces, but specifics of workload distribution, update frequencies, and failure rates are not disclosed; reproducibility is limited.
