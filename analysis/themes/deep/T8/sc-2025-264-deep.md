# Reproducible Performance Evaluation of OpenMP and SYCL Workloads under Noise Injection

**Venue:** SC · **Subtheme:** Systematic Noise Resilience Characterization for Parallel Programming Models

## What It Does

Modern HPC systems experience system noise: OS jitter (interrupts, context switches), shared cache interference, NUMA effects (non-uniform memory access latencies when threads migrate across sockets). This noise causes performance variability that makes reproducible benchmarking difficult and hides the true performance characteristics of parallel programs. The paper implements a noise injection framework that captures real system traces (OS activity, cache contention patterns, NUMA events) and replays them as controlled perturbations during benchmark execution. The approach profiles a real parallel workload running under normal conditions to record noise events (e.g., "core 3 experienced 500 clock cycles of cache miss delay at time T"), then re-runs the workload under synthetic, controlled noise conditions where the same events fire at predictable times. This decouples workload performance from uncontrolled environmental variation.

The evaluation compares OpenMP and SYCL (two competing parallel programming models for HPC) on benchmarks (N-body simulation, Babelstream, MiniFE mini-app) under three conditions: (1) default execution (no noise control), (2) default + noise injection (synthetic noise replayed), (3) default + mitigation strategies (thread pinning to cores, isolating a housekeeping core to absorb OS activity, toggling SMT). Data flows from real execution traces → synthetic noise events → controlled benchmark runs, enabling systematic characterization of how each programming model responds to noise.

## The Key Result

The framework demonstrates that SYCL exhibits greater noise resilience than OpenMP across the tested workloads: under moderate noise injection, SYCL performance degrades less than OpenMP. Specific findings vary by platform and workload: thread pinning is effective on some workloads but not others; housekeeping core isolation reduces variability but adds latency; SMT toggling shows platform-specific trade-offs. The key result is methodological: the noise injection framework enables reproducible, noise-controlled comparison that cannot be achieved via traditional benchmarking (which averages over uncontrolled noise).

## Why This Approach

Parallel programming model benchmarks traditionally run many trials and average the results, hoping to smooth out noise. However, this masks performance variability and prevents reproducible comparisons across systems: the same program may see 5% variability on one platform and 15% on another, making it impossible to fairly compare OpenMP vs. SYCL without controlling for environmental factors. Noise injection solves this by making the environment reproducible: both OpenMP and SYCL see identical noise patterns, so differences in performance degradation directly reflect model robustness, not luck. The approach is chosen over simulation (which is slow and approximate) and over noise suppression (thread pinning, which is often impractical in shared HPC facilities); instead, controlled injection provides the best of both: real program execution with known perturbations. Tracing real noise and replaying it ensures that the injected noise is realistic and captures actual HPC system behavior rather than synthetic patterns.

## What It Leaves Open

- **Evaluation limited to two processor platforms**: specific architecture details (cache hierarchy, NUMA topology, SMT configuration) are not named, making it hard to predict results on other systems. Generalization to ARM-based or GPU-accelerated HPC systems is unexplored.
- **Workload set is small**: N-body, Babelstream, MiniFE are standard benchmarks but may not represent all parallel patterns; domain-specific workloads (stencil codes, sparse linear algebra) and fine-grain synchronization-heavy codes are not tested.
- **Mitigation strategy effectiveness is platform and workload dependent**: the paper shows this variation but does not provide a model or heuristic to predict which mitigation works best on a new platform without extensive benchmarking.
- **Overhead of noise injection not quantified**: recording and replaying noise events adds instrumentation cost; the paper does not measure profiling overhead or the fidelity of replayed noise vs. real noise.
- **OpenMP vs. SYCL comparison may reflect compiler/library quality, not model design**: SYCL resilience could stem from better compiler optimizations or runtime scheduling, not from the language/API design itself; this is not disentangled.
