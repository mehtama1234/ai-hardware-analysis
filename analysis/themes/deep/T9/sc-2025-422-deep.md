# Advancing Quantum Many-Body GW Calculations on Exascale Supercomputing Platforms

**Venue:** SC · **Subtheme:** Exascale Quantum Chemistry

## What It Does

This work advances the GW method (Green's function-based electronic structure) for quantum chemistry on exascale supercomputers. The bottleneck in GW is the frequency-dependent dielectric function ε(ω): computing it requires iterating over frequency grids (typically 100–1000 points) and for each frequency, solving large linear systems (N³ cubic scaling in system size N). The paper optimizes GW by: (1) GPU kernel fusion combining matrix multiply + inverse operations, reducing memory traffic by 2x, (2) performance portability abstractions (OpenACC, Kokkos) enabling the same code on NVIDIA MI250X (Frontier) and Intel Xe (Aurora), and (3) overlapping compute and communication via asynchronous MPI + GPU streams.

Data path: molecular geometry → Kohn-Sham DFT (orbital preprocessing) → frequency grid iteration → GPU dielectric compute (fused kernels) → MPI allreduce across ranks → next frequency.

## The Key Result

Exascale GW implementation achieves 59.45% of peak performance on Frontier (AMD MI250X, 1.1 exaflops) and 48.2% on Aurora (Intel Xe), compared to 15–20% for naive implementations. For a 2048-atom nanostructure GW calculation, execution time: 1.2 hours on 9,408 nodes, linear scaling to full system. Compared to prior GW codes (Berkeleygw 2.1), achieves 3.2x speedup at same accuracy.

## Why This Approach

GW calculations are memory-bandwidth bound: each frequency point requires 10–100 GB data movement for matrix operations. Naive implementations serialize frequency iterations, loading/unloading data repeatedly; fusion (computing multiple frequencies before writeback) amortizes load cost. Performance portability is critical because exascale systems are heterogeneous (MI250X, Xe, future ARM/RISC-V); vendor-specific optimizations don't generalize. OpenACC and Kokkos enable single-source code targeting multiple backends.

## What It Leaves Open

- Accuracy vs. speed: frequency grid adaptivity (coarsening where dielectric is smooth) not fully exploited; potential 2–3x further speedup unclear
- Scaling to ultra-large systems (10k+ atoms): communication overhead for allreduce grows O(log P); network saturation analysis missing
- Integration with other quantum chemistry methods (BSE, Bethe-Salpeter) requires custom kernel tuning; generalizability unclear
- Power consumption at exascale not characterized; 9,408 GPU nodes consume 20+ MW, limiting production use
- Post-processing (band structure, optical spectra) not accelerated; most production workflows need additional analysis
