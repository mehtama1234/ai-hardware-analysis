# Augmenting Simulated Noisy Quantum Data Collection by Orders of Magnitude Using Pre-Trajectory Sampling with Batched Execution

**Venue:** SC · **Subtheme:** Quantum Simulation Acceleration

## What It Does

This work optimizes classical simulation of noisy quantum systems using trajectory-based methods. Simulating a noisy n-qubit system exactly requires tracking a 2ⁿ × 2ⁿ density matrix; even with sparsity, n=20 requires gigabytes of memory. Trajectory methods approximate by sampling Monte Carlo trajectories (each representing one possible noise realization) and averaging results. The paper introduces "Pre-Trajectory Sampling"—a scheduling strategy that: (1) tailors which error types to sample based on application goals (e.g., prioritize T1 decay over dephasing if T1 is longer), (2) reuses samples across multiple trajectories to reduce memory (amortization), and (3) adaptively increases sample density in regions of high gradient (importance sampling).

Data path: quantum circuit → identify error types → pre-sample trajectories (with importance weighting) → execute each trajectory → aggregate results.

## The Key Result

Pre-Trajectory Sampling reduces GPU memory usage by 3–8x compared to uniform sampling on 20–30 qubit systems, while maintaining <5% error accuracy loss. For a 30-qubit noisy circuit simulation, achieves 50+ GPU-hours of compute in 2 GPU-hours real time via trajectory batching. Compared to exact density matrix methods, 10x speedup at comparable accuracy.

## Why This Approach

Exact quantum simulation (density matrix) becomes infeasible beyond n~15 qubits; trajectory methods scale to n=30–40 but require massive Monte Carlo sample counts (10⁶+). Pre-Trajectory Sampling exploits structure in the noise model: depolarizing errors dominate over Rabi oscillations, T1 decay matters more than T2 dephasing. By prioritizing high-impact error types, the method reduces required samples by 5–10x. Importance weighting (concentrating samples on high-variance trajectories) further reduces variance without increasing sample count.

## What It Leaves Open

- Error type prioritization heuristic: manual tuning per circuit; automatic priority learning not proposed
- Scaling to 50+ qubits: trajectory batching and GPU memory scaling unclear; hybrid CPU-GPU strategies not explored
- Real-time noise characterization: assumes noise models known offline; adaptive re-characterization as hardware degrades not addressed
- Generalization to other noise models (correlated error, time-dependent noise) unclear; method assumes Markovian errors
- Comparison against tensor network simulators (qiskit-aer, Cirq) missing; unclear if pre-trajectory outperforms other classical simulators
