# One Number. Nine Responses. 2,090 Papers.

## The Central Constraint

There is a number that governs almost every paper in this corpus. It is not a model size, a chip generation, or a benchmark score. It is a ratio: operations per byte.

Call it **arithmetic intensity**. When a processor executes a computation, it does two things: it moves data from memory to the arithmetic units, and it performs arithmetic on that data. Intensity measures how much arithmetic you get per byte you move. A matrix multiply between large, reused matrices can achieve thousands of operations per byte. An operation that reads every number once and uses it once — streaming without reuse — falls to a ratio of one or below.

Intensity matters because the two resources — compute and memory bandwidth — improve on completely different trajectories. The arithmetic units on modern chips get faster every generation; on-chip SRAM improves in concert. But the bandwidth between the chip and its off-chip memory (DRAM, HBM) grows far more slowly, because it is limited by the number and speed of physical wires leaving the chip, and wires do not scale like transistors. An H100 GPU can perform 1,979 trillion 16-bit floating-point operations per second. Its HBM delivers 3.35 trillion bytes per second. To feed one operation per byte moved, the chip would need only 3.35 TFLOPS — it would be busy 0.17% of the time. To actually use the chip at 100%, a workload must perform around 590 operations per byte of memory traffic. Below that threshold, any additional arithmetic capacity is wasted; the machine starves, and the expensive silicon idles.

Now consider what running a large language model actually requires during inference. Generating a single word — not a batch of words, a single token — requires reading every one of the model's parameters exactly once and multiplying each by the current state of the sentence. A 70-billion-parameter model at half-precision is 140 gigabytes of weights, and the arithmetic per byte of weight is almost exactly one multiply-accumulate: an intensity around one operation per byte. That is 590 times below the threshold at which the H100 is compute-bound. The most powerful AI chip available spends more than 99% of its arithmetic capacity idle, waiting for the next number to arrive from memory. The memory system is the bottleneck, not the arithmetic.

The KV cache makes this worse. To attend to past context, the model stores a key vector and a value vector for every token it has processed. With 32 layers and 32 heads on a 70B model at half-precision, a single conversation at 32,000 tokens accumulates 64 gigabytes of KV cache — larger than the HBM on most individual GPUs. That cache is re-read in full for every token generated. Beyond 2,048 tokens of context, reading the KV cache consumes more than half of total inference time. And context lengths are growing: papers in this corpus study systems at 128,000, 512,000, and one million tokens.

The gap between what the hardware can do and what the workload demands is not a small inefficiency to be engineered away. It is a structural tension between the trajectory of computation and the trajectory of data movement. This is the wall. Every one of the 2,090 papers in this corpus is, at some level, an attack on it.

## The Nine Responses

The nine research themes in this corpus are not nine different problems. They are nine different angles of attack on the same problem, each operating at a different layer of the stack.

**Attention (T1)** confronts the KV-cache directly. The 207 papers in this theme attack the cache from every direction: compress it (TurboAttention quantizes keys and values to 2–4 bits, reaching 1.7× speedup; DeepSeek-V3's multi-head latent attention cuts the per-token footprint from 516KB to 70KB — a 7.4× reduction); evict it selectively (ClusterKV groups tokens into semantic clusters and recalls only what is needed, holding a 2K budget for a 32K context at 2× lower latency); skip reading most of it (SampleAttention achieves a 5.29× TTFT reduction at 1M tokens by attending only to the fraction of past tokens that carry the dominant attention mass); or fuse the read so data never crosses the slow memory boundary twice (LeanAttention proves the softmax rescaling operator is associative, enabling decode to run at near-100% GPU occupancy). The most radical answer is to move the arithmetic to where the data already lives — near-data attention inside SSDs (InstAttention, 11.1× throughput) or hybrid-bonded compute stacked on memory (H2EAL, 5.2–48.2× speedup). Speculative decoding (Smurfs, SpecASR, LP-Spec) amortizes one expensive KV-cache read across multiple generated tokens by proposing several candidates and verifying them in a single parallel pass.

**Quantization (T2)** attacks the denominator directly: if each number requires fewer bits, fewer bytes must be moved per operation, and intensity rises. Halving the bit-width doubles the effective intensity. The 134 papers here push this as far as physics allows. At the aggressive end, Slim-Llama runs a billion-parameter model at 1-bit and ternary precision for 9 picojoules per parameter and 4.69 milliwatts total — two orders of magnitude below what a GPU spends moving a full-precision weight. QServe co-designs W4A8KV4 (4-bit weights, 8-bit activations, 4-bit KV cache) so tightly that a cheaper L40S GPU outperforms an A100 running FP16. The systematic finding is that most of a network's dynamic range is consumed by a handful of outlier values; the research is overwhelmingly about managing those outliers — isolating them (COMET's mixed-precision activations), transforming them away (DuoQ), or redesigning the number format so the same bits span a range better matched to the distribution (microscaling formats, MX+, BitMoD's per-group types).

**Memory architecture (T3)** accepts that data movement is expensive and asks: what if the computation happened at the data? The 325 papers in this theme are structured around one physical insight. Inside an HBM stack, the internal bandwidth — across sense amplifiers between banks — runs hundreds of times faster than the external pins can export. Processing-in-memory (CENT, McPAL, AttenPIM) exploits this by placing small arithmetic units adjacent to the banks, so a KV-cache read and the dot product against it happen at the same location, at much higher effective bandwidth. CENT, the most extreme result, builds a GPU-free serving system from 32 CXL-attached PIM devices, reaching 2.3× the throughput of four A100s at 2.9× lower energy. The memory is also being redesigned at the device level: resistive crossbars (RRAM, PCM, MRAM), where a matrix-vector multiply is executed in one analog step by Ohm's law, achieve 60–188 TOPS/W in silicon prototypes — one to two orders of magnitude beyond what a digital GPU can deliver on the same operation.

**Interconnect (T4)** scales the memory-bandwidth problem from one chip to thousands. Training a large model requires all-reducing gradients across every participating GPU after every step. On 400Gb/s InfiniBand, moving 200GB of gradients for a 100B-parameter model takes roughly 8 seconds; a compute step may take one second. The chip spends 89% of the training step waiting for its neighbors. The 161 papers in this theme attack the ratio from every direction: overlap computation with communication so the hardware never idles (Overlap-based methods like ZeRO++); compress the gradient before it travels (AGC, PowerSGD); replace copper with silicon photonics to cut energy and reach (three papers at ISSCC 2025 measure photonic links at 2.3–4.0 pJ/bit, versus 10–20 pJ/bit for copper SerDes at the same speed); and redesign the topology so traffic takes shorter paths (fat-tree, dragonfly, torus each optimal for different traffic patterns). Within a single node, NVLink delivers 900 GB/s versus PCIe's 64 GB/s — the interconnect tier dominates latency budget for any inter-GPU synchronization.

**Sparsity (T5)** attacks the numerator: if most computations produce zero or near-zero output, skip them, and effective intensity rises. The 107 papers in this theme confront a fundamental hardware mismatch. A GPU's arithmetic units process data in lockstep: a 128-wide vector unit runs all 128 lanes even when 120 of them are multiplying by zero. Unstructured sparsity produces no speedup because the hardware has no way to not execute a lane. Three strategies escape this: force zeros into shapes the hardware can detect and skip (NVIDIA's 2:4 format, where exactly 2 of every 4 weights are nonzero, exploits tensor-core hardware that skips the zero pair and runs at 2× dense throughput); build custom processors that tolerate irregular skipping (bit-serial or bitmap-driven units that process only surviving nonzeros); or make the sparsity dynamic and semantic (mixture-of-experts, where each token is routed to only 2 of 64 expert sublayers, processes 3% of weights per token while retaining the full model's capacity). The last of these is now mainstream — DeepSeek-MoE, Mixtral, and every frontier open model uses MoE — and the hardware consequences (routing overhead, irregular expert load, expert parallelism across GPUs) are active research.

**Compilers (T6)** close the gap between mathematical description and physical execution. A 4096×4096 FP16 matrix multiply should take 0.44 milliseconds on an A100; naive code takes 10–50 milliseconds. The gap is not arithmetic — every floating-point operation still executes — but scheduling. Whether a 4KB tile of data is in a register, shared memory, L2 cache, or HBM makes the difference between the operation feeding at 19 TB/s (register bandwidth) or 3.35 TB/s (HBM bandwidth) or 600 GB/s (PCIe). The compiler's job is to tile, fuse, reorder, and schedule operations so data lives in the fastest memory when it is needed, and to automate this search over the thousands of legal schedules. MLIR preserves domain structure across compilation levels so optimizations at one level compose with optimizations at another. Auto-tuners (TVM, Triton) search the space of schedules and tile sizes, measuring rather than modeling the hardware. Equality saturation (DialEgg, CGO 2025) holds all equivalent program forms simultaneously and extracts the cheapest, finding transformations that directional rewrites would miss. For EDA — compiling hardware designs rather than programs — LLMs now write Verilog directly (RL-optimized at ICCAD 2025), generating structured chip designs that survive formal verification at rates that previously required expert engineers.

**Security (T7)** reveals that the memory bandwidth problem has a hostile cousin. Every time a processor touches memory, it leaves a trace — in power draw, in cache timing, in electromagnetic radiation — that can leak secrets to an adversary. Cache timing attacks exploit the 4-cycle versus 200-cycle gap between a hit and a miss, a gap that exists precisely because caches are the hardware's response to the memory bandwidth wall. Trusted execution environments (Intel SGX, ARM TrustZone) address this with isolation, but isolation requires memory encryption, and memory encryption adds indirection: every memory access passes through an integrity check tree, adding latency and bandwidth overhead. The 141 papers in this theme live at an uncomfortable intersection: the solutions to the memory wall (larger caches, near-memory processing, compute-in-memory) all create new attack surfaces, because they change which physical resource leaks information about what is being computed.

**Reliability (T8)** addresses the fact that at scale, hardware does not work. A 3nm transistor gate is ten silicon atoms wide; manufacturing variation shifts its threshold by 20% from device to device. Cosmic rays flip DRAM bits at a rate of one error per 4GB per month at sea level. A cluster of 100,000 GPUs experiences hardware faults multiple times per hour. The 150 papers in this theme build systems that function despite this: ECC catches single-bit errors in DRAM; checkpointing allows training runs to survive node failures; formal verification (now accelerated by LLMs at ICCAD and DAC 2025) proves correctness before fabrication; and automatic test pattern generation finds the manufacturing defects that escaped inspection. The reliability problem intensifies at exactly the scale and precision that efficiency techniques demand — a 4-bit quantized weight that flips one bit changes value by 12.5%, not the 0.003% a 32-bit weight would change.

**Specialized domains (T9)** abandon the premise of general-purpose silicon entirely for computations where the mismatch is too severe to patch. Fully homomorphic encryption — computing on data that remains encrypted — runs four to five orders of magnitude slower than plaintext on a CPU; a BERT inference takes 17 hours. A dedicated chip (BTS at ISCA 2025) cuts that to practical ranges. Zero-knowledge proofs are dominated by field arithmetic; zkSpeed (ISCA 2025), at 366mm², beats a server CPU by 801×. Quantum computing requires classical control electronics fast enough to respond to qubit measurements in microseconds, before the qubit decoheres — a problem MICRO and DAC papers attack with room-temperature FPGA controllers and optimal gate compilers. Photonic chips, where matrix operations propagate at the speed of light, bypass the charge-movement bottleneck entirely; ISSCC 2025 silicon photonics macros measure 2.3 pJ/bit. These are not niche concerns: ML-for-EDA (using machine learning to automate chip design) and EDA-for-ML (designing better chips for machine learning) are now the largest single cluster in the 281-paper ICCAD corpus, and they are co-evolving in a feedback loop — better EDA tools produce better chips that produce better ML models that produce better EDA tools.

## The Tensions

The nine themes do not fit together without friction. Each response to the memory-bandwidth wall creates new constraints for the others.

Quantization reduces bytes per weight but shatters the regularity of computation. A 4-bit weight and an 8-bit activation cannot be multiplied on a standard tensor core; the hardware must either dequantize (paying to expand) or be custom-built for the non-standard format. The result is an arms race between number-format innovation and compiler/hardware support, visible in the DAC 2025 Pareto study that swept 35,000 format configurations to find that the best formats required microarchitecture changes, and MX+ (MICRO 2025) which discovered that even within an adopted format, one poorly-encoded element per block corrupted the whole group.

Security countermeasures consume bandwidth. Memory encryption requires an integrity tree — a Merkle tree over the encrypted memory, verified on every access — adding latency and bandwidth that directly worsen the intensity ratio. Near-memory processing architectures, which help the memory wall, also move computation to a location the trusted execution environment's perimeter may not cover. A GPU secure enclave (Telekine, ASPLOS 2025) must encrypt everything leaving the GPU; at the bandwidths these systems operate, that overhead is not theoretical.

Sparsity and memory regularity conflict. A sparse KV-cache eviction strategy that retains only 10% of tokens makes memory access irregular — the surviving tokens are scattered across the cache — and DRAM is designed for sequential access, not scatter-gather. The engineering cost of re-regularizing that access can exceed the bandwidth saved.

The prefill/decode split, identified as the organizing principle of LLM serving (WindServe, Hybe, Seesaw in the T1 essay), creates a new problem at the seam. Disaggregating prefill onto GPU clusters and decode onto PIM devices requires streaming partially-computed KV tensors between them, and the bandwidth cost of that transfer can erase the efficiency gain that motivated the split.

## What This Field Is Betting On

The bets of 2025 are visible in where the papers cluster and what assumptions they share.

The dominant bet for inference is a specific stack: **4-bit weights, 8-bit activations, 4-bit KV cache, heterogeneous prefill/decode, with a compiler that handles non-standard formats without dequantization**. QServe's W4A8KV4, COMET's W4A4KV4, and the dozen papers building LUT-based accelerators to bypass dequantization entirely all share this target. The LUT approach (LUT Tensor Core, FIGLUT, VQ-LLM) is a bet that replacing the multiply by a pre-computed table lookup — turning an arithmetic problem into a memory lookup — is the right response when the problem was memory-bound all along.

The dominant bet for training is **data-and-tensor parallelism with gradient compression and topology-matched collectives**, running on clusters connected by optical inter-node links. The papers at SC 2025 and ISCA 2025 training ORBIT-2 on 65,536 GPUs, and the InfiniBand/optical photonics papers at ISSCC and Hot Chips, share the assumption that the training cluster will continue to grow faster than copper links can scale, making photonics a transition from optional to necessary within the decade.

The underinvested area, visible only in the gaps between papers, is the **edge and mobile inference stack**. The papers here are smaller in count and more fragmented: Slim-Llama (4.69 mW), TinyML on FPGA, a handful of LPDDR-attached near-Flash designs (Lincoln). The compute ecosystem assumes data-center GPUs; the tools, compilers, and hardware abstractions for running frontier models on a device are far less developed. This is where the T9 photonic and neuromorphic bets look most promising long-term, but the manufacturing maturity is not there yet.

The field is collectively betting that the transformer attention mechanism, or a close hybrid of it, will remain the dominant architecture for long enough to justify the hardware investments being made. DeepSeek-V3's latent attention and the Attention+SSM hybrids (Mamba, Jamba) are hedge positions: reducing but not eliminating the quadratic KV cache, changing the exponent without replacing it. Whether a different mechanism — fully linear, fully recurrent, or something not yet named — displaces the cache problem entirely is the architectural question that would, if resolved, strand large portions of this corpus.

## The Open Problem

Here is the one question whose answer would simultaneously change the trajectory of six of the nine themes:

**How do you guarantee, not just expect, that a compressed and sparse attention computation produces output that is indistinguishable from full-precision dense attention on a specific worst-case input?**

Today's KV-cache compression methods (ClusterKV, TurboAttention, MILLION) show good *average* accuracy on benchmark suites. But as the MLSys 2025 paper "Rethinking Key-Value Cache Compression" showed, the benefit of compression *vanishes or goes negative* once PagedAttention and FlashAttention are already in the serving stack, and some individual samples degraded badly even when the average looked fine. The industry makes deployment decisions based on average accuracy. Worst-case guarantees — the kind that would let a hospital system or a financial institution trust a quantized model — do not exist.

Answering this question would require a theory of how rounding error propagates through a multi-head attention layer under adversarial input, combined with hardware that can dynamically detect when a specific input is at risk and selectively increase precision. It would let the quantization, attention, and compiler research streams converge on a shared contract: a compression scheme is valid if and only if it satisfies this guarantee on the system's actual input distribution, not on a benchmark someone curated in 2023. Until that theory exists, the industry will keep shipping compressed models that work on average and hoping the tail does not bite.
