# Punica: Multi-Tenant LoRA Serving

**Problem:** Serving multiple LoRA-fine-tuned model variants for different tenants requires inefficient memory and compute resources, as each tenant's adapted weights cannot easily share a single base model inference path without serialization overhead.

**Method:** Punica multiplexes requests from different LoRA adapters into shared batches, uses a hierarchical memory layout to keep LoRA weights in high-bandwidth memory, and applies dynamic scheduling to batch incompatible LoRA requests while maintaining throughput.

**Novelty:** Efficient batching and scheduling mechanism that enables high-throughput multi-tenant LoRA serving by sharing base model computation across tenants with different adapter weights.
