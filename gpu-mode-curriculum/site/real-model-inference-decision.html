GPU systems workbench

Real-model inference: from correctness to serving evidence

Counterbalanced real GPT-2/T4 HTTP runs preserve outputs and establish a batching benefit; optimized paged attention does not consistently beat equally batched native attention.

Reference and correctness

The workload uses revision-pinned pretrained GPT-2 and its tokenizer. Greedy library generation is the reference. Cached decoding supplies positions derived from the attention mask so left padding cannot shift a request's positions. Every timed candidate must preserve the reference token IDs, including when prompts share a batch.

For 31 one-token decode steps, 12 attention layers and four requests, the wrapper performs 31 × 12 × 4 = 1,488 per-request mask scans. The observed nonzero calls and stream synchronizations support a host/device coordination bottleneck in this wrapper. This does not imply that paged attention inherently requires those synchronizations.

The bounded default uses batches of up to four, a 5 ms window, a queue limit of 32 and 16 output tokens. Cancel by posting the request ID to /cancel. Custom paging remains an experimental option.

Learning path

  1. FlashAttention lecture: connect the attention reference to the paged-attention correctness harness.
  2. Profiling CUDA kernels: explain why launch and synchronization overhead can outweigh arithmetic improvements.
  3. Kernel benchmarking tales: compare equal workloads and retain losing candidates.
  4. Disaggregated LLM inference: connect kernel measurements to queues, TTFT and completion tails.

Related paper: Past-Future Scheduler for LLM Serving under SLA Guarantees. Use its corpus record to extend the exercise from bounded request batching to memory-aware serving; this experiment does not reproduce that paper.

Decision and remaining work

Bounded HTTP batching improvement established. General backend superiority and production capacity remain unproven.

Run the selected native microbatch endpoint, or extend the measured workload with longer generations and sustained arrivals before generalizing the result.

  • Each mode has four 16-request rounds per session; round p95 remains a small-sample tail statistic.
  • Repeated HTTP mode order is counterbalanced; earlier direct profiles used fixed-order blocks and separate instrumented captures.
  • Custom direct-generation and HTTP protocols use different prompts/token counts; do not compare their absolute latencies.
  • Cancellation stops token delivery at boundaries; mixed-batch GPU slots persist until batch completion.
  • Profiler category totals in the initial raw report include overlapping event types; use individual operator counts and raw traces, not summed GPU categories.
  • No production language-quality, multi-GPU, portability, or analog hardware acceptance.
