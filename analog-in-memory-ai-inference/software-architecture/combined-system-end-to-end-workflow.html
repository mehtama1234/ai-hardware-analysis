The Underlying Argument

Why The Model Comes First

The model graph is the object being changed. Before the chip matters, the system has to know which operations are repeated weighted sums, which operations choose between close answers, and which operations carry control meaning. Analog hardware is only a candidate for the parts where physical error can be bounded without changing the useful answer.

Why Placement Is A Contract

Moving an operator to analog creates a contract: the input must be converted into a physical signal, the stored weights must represent the intended numbers, the output must be converted back, and digital logic must know where to resume if the analog result is unsafe. A placement record is incomplete unless it names converter boundaries, expected error sources, sensitivity, and fallback.

Why Analog Error Is Not One Number

The analog tile is a chain of physical choices. DAC bits, row voltage drop, device conductance, column current, ADC bits, saturation, drift, and calibration each change the final code. The useful evidence is not merely that an error occurred. The useful evidence says which part of the chain caused the error and whether the selected operating point keeps it inside budget.

Why Digital Control Is Central

The digital scheduler and governor decide when analog work is allowed. They turn model sensitivity, residual error, tile health, cumulative error, and service pressure into hardware decisions: allow, delay, reroute, throttle, or fall back. This is the point where a research idea becomes a rule that can be checked in RTL.

Why EDA Evidence Matters

Software simulation can show that a rule is reasonable. RTL can show that the rule can be represented as logic. Synthesis can show that the logic lowers into gates. OpenLane can show that one selected digital block can be placed and routed under recorded constraints. These are separate claims. The workbench should keep them separate so the user can see exactly what has been proven.

First-Principles Workflow

1. Start With The Model

The object is not the chip yet. The object is the model graph: layers, operators, weights, activations, choices, and outputs. The first question is which parts of the graph are repeated weighted sums and which parts are decisions that should stay digital.

Existing pages: customer workload intake, frontend workbench, architecture.md.

Current connection: the backend now derives a hardware_placement package artifact from ONNX graph analysis. It names analog candidates, digital-only regions, converter boundaries, model sensitivity classes, fallback points, and governor fields. The artifact is available through the package API and is also saved as hardware-placement.json in the exported package archive.

2. Place Work Across Analog And Digital

Analog compute is useful for repeated multiplication with stored weights. It is weak at control, branching, normalization, softmax decisions, updates, and brittle output choices. Placement is the act of drawing that boundary.

Existing pages: compiler plan, simulation as compiler, hybrid benchmarking pipeline.

Current connection: the first mini placement pass emits analog candidates, digital-only operators, converter boundaries, fallback points, and governor fields. The hardware lab now imports that artifact into backend-hardware-placement-governor-input.csv, appends those rows to the model-impact governor requests, and checks them through the Verilog governor trace.

3. Measure The Analog Chain

An analog tile is not an abstract matrix multiply. It is a chain of voltage, conductance, current, wire drop, noise, drift, ADC decision, and digital correction. The output is only useful if the residual error is named and bounded.

Existing pages: AIHWKIT plan, simulator calibration, toolkit results.

Working lab: analog_nonideality_stack.py and its generated measurement reports.

Current connection: the hardware-lab exporter wraps the analog residual and model-sensitivity records as backend-compatible evidence. The backend imports them through the hardware-lab evidence endpoint and uses them in claim readiness.

4. Ask Whether The Error Matters

A numeric error is not equally important everywhere. A small error in a hidden projection may be tolerable. The same error near attention selection, logits, or a control action may change the chosen result.

Existing pages: proof ladder, robot learning implications.

Working lab: measured_tile_transformer_impact.py produces fixed-projection, stressed-projection, attention, and logits cases.

Current connection: the hardware-lab exporter attaches model-sensitivity evidence to the backend package, and claim readiness uses that evidence for the narrow analog accuracy claim.

5. Let Digital Logic Refuse Bad Analog Work

The digital controller is the referee. It receives residual, sensitivity, cumulative error, tile health, and service pressure. It allows analog only when the operation can afford the physical error.

Existing pages: analog vs digital validation, timing budget.

Working lab: Verilog governor, scheduler, generated test cases, and RTL checkers.

Current connection: backend-derived placement rows are appended to model-impact governor requests and checked through the Verilog model-impact governor. The integrated scheduler/governor trace also passes locally, but it is not yet fully driven by the backend placement rows.

6. Prove The Controller Can Become Hardware

A runtime rule is not enough. The controller has to synthesize, meet timing, and route under physical constraints. This is where policy becomes gates and geometry.

Existing pages: tapeout risk, memory technology decision.

Working lab: Yosys synthesis reports and OpenLane scheduler/governor results.

Current connection: local OpenLane-derived power/thermal context is now imported as needs-review evidence. This strengthens the implementation story without turning it into measured hardware power or signoff.

7. Show The Answer Without Overclaiming

The frontend should not say the chip is ready because one simulation passed. It should say which claims are measured, simulated, RTL-verified, synthesized, routed, estimated, or blocked.

Existing pages: evidence matrix, company roadmap.

Current connection: the frontend has a Hardware Lab Evidence panel and an Import Hardware Lab action. It shows supported placement and accuracy claims, needs-review latency and energy claims, and blocked production readiness.

The current hardware-lab batch imported into package pkg-e931662a01293df2 with six accepted records and zero rejects. The endpoint refreshes prior local hardware-lab records instead of piling up duplicate current evidence.

Placement Mini-Pass

Turn ONNX operators into analog candidates, digital-only regions, converter boundaries, and scheduler/governor inputs.

AIHWKIT Adapter

Use AIHWKIT as an external simulator when installed. Skip cleanly when missing. A real run must satisfy the adapter output contract before it can strengthen a claim.

Crossbar Risk Adapter

Allowed Claim After Connection

Allowed: this is a working prototype flow for deciding where analog in-memory inference may be safe. It can import a model, analyze fit, attach hardware-lab evidence, run digital-control checks, and show which claims are supported or blocked.

Not allowed yet: this is not proof of a production analog foundation-model chip. It still lacks calibrated silicon, full external AIHWKIT/CrossSim agreement, real analog macro layout, board traces, measured power, reliability data, and signoff tapeout evidence.
