How we build the transformer-to-chip proof

This is the executable work order behind the conceptual chapters. It converts the conference lessons into artifacts and tests that connect the transformer model, hybrid compiler, analog converter, digital control, runtime fallback, and final task result.

The build sequence

workload contract → operator inventory → movement ledger → analog eligibility → compiler schedule → converter profile → calibration/governor → reliability sweep → token comparison → evidence package

Each stage consumes the output of the previous stage. We do not begin by claiming a full LLM runs on analog hardware. We begin with a small transformer fixture and make every boundary explicit.

First implementation target: deep-transformer-mlp-stack.onnx. It is small enough to make the execution package reproducible while still containing repeated transformer-style fixed-weight matrix work, digital nonlinearities, residuals, SRAM boundaries, calibration, and fallback.

Phase 1 — freeze the workload

Create workload_contract.json. It is the experiment’s identity card, not a presentation detail.

{
  "model": "deep-transformer-mlp-stack.onnx",
  "model_hash": "sha256:...",
  "phase": "prefill",
  "batch_size": 1,
  "sequence_length": 16,
  "quality_metric": "relative_output_residual",
  "latency_metric": "time_per_token",
  "energy_metric": "joules_per_token",
  "fallback": "digital",
  "hardware_profile_id": "sky130_converter_candidate_v1"
}

Then create a second contract for decode. Keep prefill and decode separate because their reuse, KV-cache, movement, and latency behavior are different.

Phase gate

We cannot compare hybrid and digital until model weights, inputs, tokenization, shapes, phase, quality metric, and denominator are frozen.

The current fixture produces 36 operators, including 12 MatMul candidates, with 36 movement rows and 36 schedule events. The result is explicitly estimated planning evidence; it is not yet token-level decode or physical hardware evidence.

Run its regression check with:

.venv/bin/python ../scripts/check_transformer_execution_contract.py

Phase 3 — calculate the movement ledger

For every tensor edge, calculate the complete cost of representing and moving the value.

Ledger fieldWhat to calculate
StorageWeight and activation bytes, SRAM bank, conductance capacity, and residency.
ConversionsDAC/ADC count, resolution, serial/parallel behavior, and conversion time.
AccumulationPartial sums, bit slices, digital accumulator width, overflow and saturation.
SynchronizationBarriers between analog array, converter, SRAM, and digital logic.
StateKV-cache reads/writes, calibration state, and tile health state.
RecoveryExtra traffic and work when a tile falls back to digital.

Required output: movement_ledger.json. It must allow a complete token cost to be reconstructed without hiding conversion or cache work.

Reject rule: an analog MAC speedup is not a system speedup if movement, conversion, calibration, or fallback erases it.

Phase 4 — run the analog eligibility pass

The compiler applies explicit gates rather than intuition.

eligible = fixed_weight_matmul
    and precision_supported
    and sensitivity_passes
    and movement_benefit_positive
    and converter_range_legal
    and calibration_profile_valid

Each result is explainable:

{
  "operator": "dense1.matmul",
  "placement": "analog",
  "reason": "all_eligibility_gates_passed"
}

Or:

{
  "operator": "attention.softmax",
  "placement": "digital",
  "reason": "dynamic_nonlinear_operation"
}

Required output: analog_eligibility.json. The first failed gate is preserved, because rejection reasons become future design work.

Phase 5 — import the physical converter profile

The EDA repo produces physical evidence. The software workbench imports it through a versioned hardware profile.

{
  "converter_id": "sky130_sar_candidate_v1",
  "resolution_bits": 4,
  "legal_input_range": [0.1, 1.6],
  "minimum_code_spacing_mv": 83.5,
  "monotonic": true,
  "pvt_status": "needs_review",
  "mismatch_status": "open",
  "calibration_profile": "nominal_only",
  "analog_placement_allowed": false
}

The last field is decisive. If the converter is not physically accepted for the required operating envelope, the compiler may still run software experiments, but it must select digital fallback for physical claims.

Physical gate enforcement command

The current EDA gate can be imported directly:

cd software-architecture
backend/.venv/bin/python scripts/build_transformer_execution_contract.py \
  --model samples/deep-transformer-mlp-stack.onnx \
  --physical-gate ../../analog-digital-chip-design-eda/evidence/aimc-simulator-adapters/analog-converter-physical-cell-gate.json \
  --enforce-physical-gate \
  --output /tmp/deep-transformer-physical-gated

The current result is physical_cells_present_waiting_for_extracted_artifacts. Because analog_allowed_for_physical_claim is false, all 12 matrix candidates are emitted as digital_fallback. This is the correct conservative behavior until the EDA gate is upgraded.

Phase 6 — implement calibration and the runtime governor

A calibration profile records what was measured, where it is valid, how it corrects values, and when it expires.

Runtime conditionDecisionTrace to save
Calibration valid and residual within budgetUse analog.Tile, profile, residual, temperature, timestamp.
Profile stale but recalibration availableRecalibrate and retry.Calibration duration and energy.
Range, timeout, or health failureDigital fallback.First failure and fallback cost.
Repeated failureQuarantine tile.Fault count and re-enable policy.

Required outputs: calibration_profile.json and runtime_governor_trace.json. Fallback is not a hidden success; it is part of latency, energy, and reliability.

Phase 7 — run reliability sweeps

Run the same workload over process/mismatch seeds, supply corners, temperatures, noise, settling time, converter timing, and stale calibration. Collect distributions instead of one favorable run.

for mismatch_seed in seeds:
  for voltage in voltage_corners:
    for temperature in temperature_corners:
      for calibration_age in calibration_ages:
        run_hybrid_token_case()
        record(residual, token_agreement, fallback, latency, energy)

Required output: reliability_results.json containing median, 95th percentile, worst case, failure count, and fallback rate. Reliability asks whether the system stays inside its operating envelope, not whether one nominal run passes.

Phase 8 — run three comparable executions

ExecutionPurpose
All-digital baselineReference logits, tokens, latency, and energy denominator.
Idealized hybridSeparates mapping and model sensitivity from physical converter limitations.
Physically constrained hybridIncludes converter profile, calibration, movement, governor, and fallback.

The first executable version now runs the MLP fixture through ONNX ReferenceEvaluator twice. It perturbs only declared analog MatMul weights with a seeded relative-error model, computes relative L2 error, RMSE, cosine similarity, and argmax agreement, and writes hybrid_output_comparison.json. The physical-gated run applies no analog perturbation and must reproduce the digital output exactly because all candidates have fallen back.

backend/.venv/bin/python scripts/run_transformer_output_comparison.py \
  --model samples/deep-transformer-mlp-stack.onnx \
  --output /tmp/deep-transformer-output-comparison \
  --target-profile robotics \
  --error-scale 0.001

Compare the same weights, prompts, shapes, phases, quality metric, thermal condition, and compilation budget. This is still a software stress experiment, not measured converter data or token-level LLM evidence.

Phase 9 — execute the decode slice

The attention fixture now has a six-token decode runner. At each token it computes Q/K/V, appends K and V to digital cache state, reads all prior cache entries, applies digital score/Softmax/value mixing, and applies the output projection. The artifact records cache movement rather than hiding it.

backend/.venv/bin/python scripts/run_transformer_decode_comparison.py \
  --model samples/attention-block.onnx \
  --sequence-length 6 \
  --output /tmp/attention-decode-comparison \
  --error-scale 0.001

The current six-token run moves 960 bytes reading prior K/V state and 384 bytes writing new K/V state. The unconstrained synthetic hybrid replay has mean relative error 0.001594, maximum relative error 0.001737, and output-channel agreement 100%. These are fixture results, not tokenizer-level LLM results.

Phase 9b — token decision gate

The tiny causal-LM fixture now adds integer token IDs, a vocabulary projection, autoregressive generation, teacher-forced next-token agreement, free-running sequence agreement, and an oracle check that explicit cached decode matches the ONNX full-prefill graph. This closes the semantic gap between vector-output parity and token-level behavior while keeping the claim explicitly limited to the toy vocabulary.

backend/.venv/bin/python samples/make-tiny-causal-lm-onnx.py
backend/.venv/bin/python scripts/run_tiny_causal_lm_decode.py \
  --model samples/tiny-causal-lm.onnx \
  --prompt 1,2 \
  --generated-steps 4 \
  --output /tmp/tiny-causal-lm-decode \
  --error-scale 0.001

Phase 10 — sweep reliability before making a claim

One passing error sample is not reliability. The tiny causal-LM runner now sweeps synthetic projection error scales and random seeds while preserving teacher-forced agreement, free-running sequence agreement, and the ONNX prefill oracle result for every case.

backend/.venv/bin/python scripts/run_tiny_causal_lm_reliability_sweep.py \
  --model samples/tiny-causal-lm.onnx \
  --error-scales 0,0.001,0.003,0.005,0.01 \
  --seeds 7,11,19,23 \
  --output /tmp/tiny-causal-lm-reliability

The checked-in five-scale/four-seed run accepted 17/20 cases. All generated token sequences agreed, but three cases at 1% synthetic error exceeded the 1% relative residual limit. This is the first explicit quality boundary in the loop; the system must recalibrate or fall back instead of hiding those failures.

This is a software sensitivity distribution. It becomes a physical reliability result only when the error scale is replaced by measured per-tile distributions indexed by voltage, temperature, age, mismatch, noise, and calibration state.

Phase 11 — import calibrated simulator evidence safely

The sibling EDA repository contains a CrossSim calibrated attention profile for the same attention-block.onnx and the same four static projection candidates. The importer verifies that identity, checks weight names and shapes, checks residual limits, and preserves the simulator-only claim boundary.

backend/.venv/bin/python scripts/import_attention_calibration_profile.py \
  --model samples/attention-block.onnx \
  --profile ../../analog-digital-chip-design-eda/evidence/aimc-simulator-adapters/crosssim-calibrated-attention-block-analog-error-simulation.json \
  --output /tmp/attention-calibration-import

This is the correct bridge: calibrated simulator data can constrain the matching attention workload, but it cannot be silently reused for the tiny causal model or treated as measured silicon.

The matching attention decode runner can now consume the accepted profile and apply only its declared held-out residual vectors to Q/K/V/O. The six-token replay measured maximum relative error 1.33e-07 with 100% output-channel agreement. This is calibrated simulator replay, not calibrated silicon.

backend/.venv/bin/python scripts/run_transformer_decode_comparison.py \
  --model samples/attention-block.onnx \
  --calibration-profile-json ../../analog-digital-chip-design-eda/evidence/aimc-simulator-adapters/crosssim-calibrated-attention-block-analog-error-simulation.json \
  --error-scale 0 \
  --output /tmp/attention-decode-calibrated

Phase 12 — benchmark the same token denominator

The correctness loop now has a cost denominator. The benchmark replays the same six-token trace through digital and hybrid reference implementations, counts fixed projection MACs, dynamic attention MACs, converter values, K/V-cache bytes, and reports Python wall time separately from the modeled energy estimate.

backend/.venv/bin/python scripts/benchmark_tiny_causal_lm.py \
  --model samples/tiny-causal-lm.onnx \
  --output /tmp/tiny-causal-lm-benchmark

With the documented default assumptions, the six-token trace moves 1344 K/V-cache bytes and estimates a 2.20x digital-over-hybrid energy ratio. The Python reference timing is not accelerator latency; the energy coefficients must be replaced by measured tile, converter, SRAM, RTL, or board data.

One-command vertical-slice run

The individual stages are now composed into one reproducible package builder:

backend/.venv/bin/python scripts/run_transformer_vertical_slice.py \
  --output /tmp/transformer-vertical-slice

The run emits 21 hash-linked artifacts when the calibrated EDA profile is present, including MLP and attention contracts, token decode, reliability distribution, calibrated attention replay, cost benchmark, physical-gate audit, claim report, and manifest. The manifest was independently rehashed with zero mismatches. Its claim report is the authoritative boundary: it refuses measured hardware performance and production readiness until those evidence levels exist.

The physical-gate audit currently reports all four named converter cells present, but these two extracted artifacts are still missing: evidence/aimc-simulator-adapters/candidate-post-layout/models/converter_layout_area_record.json and evidence/aimc-simulator-adapters/candidate-post-layout/rerun/converter-post-layout-break-even-rerun.json. A separate Magic starter-layout measurement records 4/4 cells and a 237.6 µm² macro bounding box, but it remains explicitly non-signoff. Starter payloads are deliberately not promoted to extracted evidence.

Repository ownership

The bridge is a versioned hardware profile and evidence schema. The two repositories should not duplicate physical truth or silently promote one evidence level into another.

Definition of done for the first sprint

  1. MLP workload contract is frozen.
  2. Every operator has a placement and reason.
  3. Movement ledger reconstructs complete cost.
  4. Converter profile can reject physical analog placement.
  5. Fallback-aware schedule runs.
  6. Hybrid output is compared with digital output.
  7. At least one reliability sweep is recorded.
  8. All artifacts are hash-linked and claim-labeled.

Allowed claim

The project has a reproducible, movement-aware, fallback-aware transformer-to-chip evaluation loop, including a toy token-level decode and a guarded matching-fixture calibration import.

Refused claim

This sprint cannot claim measured LLM silicon performance, production readiness, universal analog superiority, or board energy unless those separate evidence gates are completed.

Next handoff

The next implementation gate is a real small causal language model with a production tokenizer, followed by measured per-token latency and energy on a common digital baseline. In parallel, replace the synthetic error sweep with per-tile calibration indexed by voltage, temperature, mismatch, noise, drift, and fallback state.
