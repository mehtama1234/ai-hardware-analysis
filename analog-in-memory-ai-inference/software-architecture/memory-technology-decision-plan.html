Memory Technology Decision Plan

This page defines how to choose and justify the memory element for the analog IMC product.

Question: is this chip a fixed-weight inference engine, a low-update accelerator, an adapter-update system, or a real adaptive platform?

Rule:

Do not claim adaptive Physical AI until write speed, write energy, endurance, retention, recalibration, rollback, and post-update accuracy are measured or credibly bounded.

Plain-Language Vocabulary

The memory element is the physical place where the chip stores model weights. A model weight is a learned number inside the neural network.

Writing a weight means changing what is stored in memory. Reading a weight means using that stored value during inference.

Endurance means how many times the memory can be rewritten before it wears out. Retention means how long it remembers the value. Drift means the stored value slowly changes.

RRAM, PCM, MRAM, FeRAM, and SRAM are different memory families. They trade off density, write speed, endurance, drift, analog precision, cost, and manufacturability.

Output Classes

  • Fixed-weight ready: weights are written once or rarely; strongest early analog fit.
  • Periodic-update candidate: updates happen occasionally with acceptable cost and recalibration.
  • Adapter-update candidate: large analog base is stable while small digital/SRAM adapter layers change.
  • Adaptive blocked: workload needs frequent full-weight updates that memory cannot support safely yet.

How The Memory Decision Happens Practically

  1. Start with the workload update need: never changes, occasional update, small adapter update, or frequent learning.
  2. List candidate memory types and their measured or expected behavior.
  3. Check whether each memory can store the needed weight precision.
  4. Check whether writing weights costs too much time or energy.
  5. Check whether repeated writes wear out the memory.
  6. Check whether drift forces frequent recalibration.
  7. Choose the safest claim: fixed-weight ready, periodic-update candidate, adapter-update candidate, or adaptive blocked.

Common Mistakes This Page Prevents

  • Choosing a memory because one paper reported high endurance without checking analog weight accuracy.
  • Confusing binary storage endurance with multi-level analog weight endurance.
  • Ignoring write energy and recalibration time.
  • Claiming frequent learning before measuring post-update accuracy.
  • Picking memory technology before choosing the first workload wedge.

Detailed Walkthrough

The memory decision should start from the workload, not from the most exciting device paper. A memory can look excellent in isolation but still be wrong for the product if it cannot support the model size, update behavior, accuracy, foundry path, or temperature range.

Before The Decision

Collect the workload's update need. A fixed industrial detector and a robot that learns continuously are very different products. The same memory technology may be acceptable for one and blocked for the other.

During The Decision

Score each memory option against the same questions: can it store enough weights, can it represent enough levels, can it be rewritten when needed, how much energy does writing cost, how much does it drift, and can it be manufactured on the target process?

After The Decision

The result should be a claim boundary. It may say "fixed-weight ready" or "adapter-update candidate." It should not say "adaptive Physical AI ready" unless full update evidence exists.

What The User Should Conclude

The memory page should end with one of four practical conclusions:

  • Fixed-weight path: safest if the model rarely changes.
  • Rare-update path: possible if write cost and recalibration are acceptable.
  • Adapter-update path: strong compromise when the base model can stay analog and small parts can update digitally.
  • Adaptive blocked: frequent full-weight updates are not proven yet.
