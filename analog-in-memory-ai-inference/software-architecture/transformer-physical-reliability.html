chapter 04 · physical reality and reliability

Make physics a mapping input

The physical chip is not the final implementation of an abstract schedule. Its range, timing, parasitics, thermal state, mismatch, noise, and calibration behavior determine which schedules are legal in the first place.

The hidden object: a valid operating envelope

A model mapping is valid only inside an operating envelope. That envelope is a set of conditions under which the physical signal remains observable, convertible, and useful to the model.

input range → array signal → settling/parasitics → comparator margin → ADC code → calibration → digital value → model residual

If any step violates its range or timing assumption, the compiler must change placement or choose fallback. Physical reality flows backward from circuit limits to compiler decisions and model eligibility.

Calibration is a measurement policy

Calibration cannot recover information the converter never observed. A table may correct a repeatable transfer shape, but it does not automatically correct unmeasured codes, input-dependent settling, temperature drift, random noise, comparator polarity, layout coupling, or conditions outside the profile.

Calibration must be tied to the model error budget: state where residual is measured, which operator consumes it, and whether that operator’s output sensitivity passes.

Thermal and packaging consequences

Analog arrays, ADCs, SRAM, interconnect, and fallback logic dissipate power in different places and times. A design efficient at array level may create a converter, memory, or package hotspot.

Connect thermal state to the schedule: prefill may create sustained parallel activity, while decode may create bursty converter/cache activity. The target is whether temperature changes calibration, deadline, or output quality.

Reliability and fallback are performance

When analog is disabled, the token still has to complete. Digital fallback consumes time, bandwidth, and energy. Report fallback frequency, cause, recovery latency, extra SRAM traffic, quality, quarantine, and re-enable policy. A system that is correct only because it silently chooses digital is a digital baseline with optional analog attempts; that can be useful, but the accounting must say so.

Physical work order

  1. Close converter legal range and monotonicity.
  2. Attach the converter profile to the compiler target.
  3. Run PVT, mismatch, noise, and timing sweeps.
  4. Update eligibility using those distributions.
  5. Run extracted layout variants where possible.
  6. Propagate thermal and calibration conditions into token scheduling.
  7. Measure digital fallback cost and correctness.

Allowed claim

This chapter can claim that physical converter and reliability measurements should constrain transformer mapping, calibration, scheduling, and fallback.

Refused claim

It cannot claim converter acceptance from partial codes, nominal calibration, ideal simulation, or clean layout alone. It cannot claim production reliability without silicon and operating-condition evidence.
