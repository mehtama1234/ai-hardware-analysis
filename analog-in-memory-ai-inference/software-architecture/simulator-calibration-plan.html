Simulator Calibration Plan

This page defines how the analog simulator moves from guessed assumptions to measured chip behavior.

Question: when can simulator evidence become strong enough to guide customer and silicon decisions?

Rule:

Uncalibrated simulation is a hypothesis. Calibrated simulation is evidence, but still not the same as final production proof.

Plain-Language Vocabulary

A simulator is a software copy of how we think the chip behaves. It lets us test ideas before hardware is ready or before a customer has a board.

Calibration means adjusting the simulator so it matches real measurements. If real hardware behaves differently from the simulator, the simulator must be corrected.

A chip profile is the named set of assumptions used by the simulator. It should record noise, drift, converter precision, temperature behavior, and other physical limits.

ADC means analog-to-digital converter, and DAC means digital-to-analog converter. Converter behavior matters because the analog chip must still communicate with digital software and control logic.

A calibrated simulator does not prove everything. It means the simulator is tied to evidence instead of pure guesswork.

Calibration Loop

  1. Run a benchmark in the simulator with a named chip profile.
  2. Run the closest matching test on device, circuit model, board, or lab setup.
  3. Compare output error, accuracy, latency, power, drift, and temperature behavior.
  4. Fit simulator parameters to measured behavior.
  5. Version the updated profile.
  6. Re-run benchmarks and update claim readiness.

How Calibration Happens Practically

  1. Choose one benchmark and run it in the simulator.
  2. Record every assumption: precision, noise, drift, temperature, converter behavior, tile mismatch, and write error.
  3. Run the closest matching physical test available: device test, circuit extraction, board run, thermal run, or lab measurement.
  4. Compare simulator output against measured output.
  5. Change the simulator profile only when there is evidence for the change.
  6. Version the new profile so old reports remain traceable.
  7. Re-run claims that depended on the old profile.

Common Mistakes This Page Prevents

  • Treating guessed simulator settings as facts.
  • Updating the simulator without recording why.
  • Keeping old claims after new measurements contradict them.
  • Calibrating only accuracy while ignoring power, timing, and temperature.
  • Using one chip profile for every workload and environment.

Detailed Walkthrough

Calibration is how the simulator earns trust. At the beginning, the simulator is a controlled guess. It may use values from papers, vendor data, or rough circuit estimates. That is fine for early design, but it must be labeled as assumption-based evidence.

Before Calibration

Pick one simulator profile and freeze it for a run. The profile should say exactly what it assumes: precision, read noise, write error, drift, IR drop, ADC/DAC behavior, temperature, and tile mismatch. If the assumptions are not recorded, the result cannot be reviewed later.

During Calibration

Run the closest matching physical test. Early on this may be a device measurement or circuit simulation. Later it should be board data or silicon data. Compare not only final accuracy, but also output distributions, timing, power, thermal behavior, and how errors change over time.

After Calibration

If measurement disagrees with simulation, update the chip profile and rerun affected benchmarks. Old reports should remain archived, but their claim strength should be downgraded if the assumptions are no longer valid.

Evidence Levels

Source-backedNumbers come from papers, vendor docs, or known references.Reasonable planning assumption, not chip proof.
Circuit-backedNumbers come from circuit simulation or extracted models.Stronger hardware design evidence, still not board proof.
Board-backedNumbers come from a running board or prototype setup.Measured claim for that setup.
Silicon-backedNumbers come from measured chip behavior.Measured chip behavior under stated conditions.
Production-backedNumbers come from qualified production runs.Production claim for the qualified configuration.

What The User Should Conclude

The calibration page should tell the reader how much to trust each simulation. A simulator result with guessed numbers is useful for learning what might break. A simulator result calibrated against board and silicon behavior is useful for planning customer deployment. Neither should be confused with broad production proof.
