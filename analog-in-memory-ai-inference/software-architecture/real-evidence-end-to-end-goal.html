Real Evidence End-To-End Goal

Build the next version of the analog AI workbench so it connects real tools and real measurements into the same proof path. The system should say what is proven, what needs review, and what remains blocked.

The Path

AI model
  -> workload requirements
  -> analog/digital split

  -> digital control logic

The rule is simple: do not claim more than the evidence proves.

First-Principles Frame

Analog in-memory compute is useful only if the whole system wins. The analog core may reduce multiply and memory-movement cost, but that gain can disappear through ADC cost, DAC cost, analog error, drift, calibration, fallback execution, thermal limits, host overhead, or task accuracy loss.

So the workbench must not ask only whether a layer can run on analog. It must ask whether the workload finishes correctly, fast enough, and with less energy after every analog, digital, converter, memory, calibration, and fallback cost is counted.

Seamless Page-Flow Goal

The HTML and markdown pages are part of the system, not side notes. They should read as one review path. A reader should be able to start at Connected System Map, move through Master Review Path, Combined Workflow, this goal, Current Proof Ledger, the Workbench, and the hardware-lab evidence pages without guessing how one page connects to the next.

Question Every Page Must AnswerReason
What object is this page about?The reader needs to know whether the page is about a model graph, analog tile, digital controller, EDA artifact, backend package, board run, power trace, or claim.
What constraint matters?Analog error, converter cost, timing, power, thermal behavior, unsupported operators, routing, and measurement provenance are different problems.
What design move does the system make?The page must say what changes: split the graph, simulate the tile, generate RTL, run synthesis, import evidence, or block a claim.
What evidence exists now?The reader should see whether the proof is local simulation, calibrated simulation, RTL check, Yosys synthesis, OpenLane package readiness, routed OpenLane exploratory result, measured board runtime, or measured power.
What claim is allowed?The page should state the strongest safe sentence the current evidence supports.
What stronger claim is refused?The page should block measured silicon, measured energy, signoff, reliability, or production language when those proofs are missing.
What receives the next handoff?The next artifact or page should be named so the workflow is not left implicit.

The writing standard is: plain first-principles explanation, concrete artifact, proof level, allowed claim, refused claim, and next work.

The model is split.
Analog handles the parts where physical error is tolerable.
Digital logic controls exact decisions, routing, fallback, and interfaces.
The lab checks analog error, RTL behavior, synthesis, OpenLane readiness, and routed OpenLane exploratory results for selected digital controllers.
The backend imports the evidence and blocks claims stronger than the proof.
Measured board runtime and measured power remain separate gates.

The page set is not done if local simulation looks like measured board evidence, OpenLane readiness or routed exploratory evidence looks like full-chip signoff, analog simulator evidence looks like calibrated silicon, or the reader cannot tell what to do next after finishing a page.
