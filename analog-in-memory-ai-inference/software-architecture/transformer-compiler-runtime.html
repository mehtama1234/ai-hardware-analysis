Compile the hybrid execution

A hybrid chip is not programmed by labeling layers analog or digital. It needs a target-specific schedule that makes tensor movement, bit slicing, conversion, calibration, accumulation, synchronization, and fallback executable.

The hidden object: a legal execution schedule

The model graph expresses dependencies, but hardware needs a time-ordered plan. A schedule must answer where every tensor resides, when it moves, how it is converted, who owns accumulation, and what happens when a physical condition fails.

operator graph → placement → tile assignment → precision/slices → array launch → ADC → digital accumulation → SRAM → nonlinear/residual work → governor

The compiler’s output is not only an optimization. It is the executable interpretation of the physical constraints.

Example schedule

load activation → quantize → DAC slice 0 → array matmul → ADC → DAC slice 1 → array matmul → ADC → digital recombine → bias → activation → SRAM residual → governor check → fallback if required

Every event needs a cost and a correctness owner. If the schedule cannot name those, it is a diagram rather than a compiler result.

Bit slicing and accumulation

An analog array computes a bounded physical sum, not an arbitrary high-precision signed integer product. Logical precision may require positive/negative paths, conductance slices, activation slices, separate sign handling, multiple ADC reads, digital recombination, accumulation, overflow, and saturation checks.

The compiler must calculate how many array launches and conversions precision creates. A four-bit physical slice does not mean the complete matrix operation costs one four-bit event.

Practical warning: bit slicing can turn nominal array throughput into a conversion-bound schedule. Expose this before performance claims.

Runtime governor

The runtime protects the model from physical uncertainty. It evaluates calibration identity and age, temperature and supply, tile health, residuals, timeout, input saturation, and task sensitivity.

ConditionActionEvidence
Profile valid, residual below thresholdAllow analog.Governor trace and accepted analog result.
Profile stale, recalibration availablePause, recalibrate, retry.Calibration event and cost.
Range or health violationUse digital fallback.Fallback reason and end-to-end cost.
Repeated failuresQuarantine tile or disable analog.Fault counter and recovery policy.

Checker-driven search

A candidate is not better because it has lower predicted MAC cost. It must survive shape/dependency checks, precision and overflow, movement/conversion accounting, analog sensitivity, physical range/timing, RTL legality, and held-out model comparison. Keep rejected candidates and reasons so the search becomes evidence rather than a winner-only story.

Immediate implementation

  1. Replace the review-only compiler handoff with a versioned target profile.
  2. Make MLP and attention fixtures consume the same schedule schema.
  3. Add event costs for conversions, SRAM, calibration, and fallback.
  4. Generate token schedules for prefill and decode separately.
  5. Replay the schedule against the digital baseline and analog-error model.
  6. Emit a claim-ready evidence bundle with conditions.
