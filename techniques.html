00 · The one organizing fact

The chip is fast. The bus is slow. Almost everything follows from this.

A modern AI chip can do a trillion multiplications per second. Main memory can deliver maybe one-hundredth of that in data to multiply. The chip spends most of its time waiting — idle, starving at the loading dock. Every technique on this page is a different way to shrink that gap.

compute: ~1000 TOPS memory bandwidth: ~1 TB/s utilization when memory-bound: —

What you're seeing

Each square is a compute unit. Bright teal = working. Dim amber = idle, waiting for data. One packet arrives from memory at a time. That's the ratio — 1 packet feeding 12 units means 11 are always waiting.

Why it matters

AI inference is almost always "memory-bandwidth limited," not "compute limited." Throwing more arithmetic at the problem doesn't help. You need to move data less, or move it shorter distances, or make it smaller.

01 · MOVE LESS · T2 — smaller numbers 113 papers

Same computation, fewer bits — four times the throughput

Every number in a neural network lives in memory as a sequence of bits. Float32 uses 32 bits — fine grained but bulky. INT8 uses 8 bits — four times as many values fit in the same memory transfer. You lose precision; you gain speed and capacity. The question is how much precision the model can afford to lose.

precision: — max rounding error: — values per memory transfer: —

Mechanism

Map the full float range onto a smaller integer range. Every real value rounds to the nearest step. Fewer bits = wider steps = more error, but also 2×–8× more values fit in each memory transfer — and many chips do 4 INT8 multiplications in the same cycle as 1 FP32.

Why it matters

The KV cache (theme T1) can consume hundreds of GB of DRAM during inference. Halving the bit width halves the cache size and doubles the serving throughput. INT4 is now production standard at most major labs.

corpus → T2 spans ISCA, MICRO, HPCA, MLSys, ASPLOS. INT4 is the modal choice in 2025 papers; FP8 appears in training; INT2 is emerging for weight-only compression.
02 · MOVE LESS · T1 — attention 195 papers

Generating each word means reading every prior word's stored notes

A language model writes one word at a time. To do it, it re-reads summaries of every prior word — summaries it computed and cached the first time through (the "KV cache"). That cache grows with each word. By token 1000, generating one word means hauling 1000 pages of notes across the memory bus. Longer context = slower per-token generation.

context: — tokens data read per new token: — decoding is: memory-bandwidth limited

Mechanism

Each new token generated requires reading the K and V vectors for every prior token in the sequence. As context grows from N to 2N, the data movement per token doubles. Serving a 128K-token context window means every single generated word reads 128,000 cached summaries from DRAM.

Why it matters

The memory bandwidth bottleneck (diagram 00) bites hardest here. Papers attack it by quantizing the KV cache, evicting cold entries, sharing prefixes across users, or tiling the attention computation so intermediate data stays in fast on-chip SRAM (FlashAttention).

corpus → 47% of T1 papers name the KV cache as the primary bottleneck. ASPLOS, HPCA, and MLSys 2025 each have 10+ papers on KV cache management alone.
03 · SHORTEN THE TRIP · T3 — memory wall 290 papers

Stop hauling data — move the math to where it already lives

The bus between memory and processor is where energy goes to die. Every byte that crosses it costs power and time. The radical answer: don't cross it at all. Put the computation units inside the memory itself. Multiply-accumulate happens at the storage cell. Zero bus traversal. Zero bus energy.

bus traversal: ~100 pJ / operation in-memory MAC: ~1 pJ / operation energy ratio: ~100×

Mechanism

Processing-in-Memory (PIM) embeds simple compute logic — adders, multipliers, activation functions — inside or immediately adjacent to DRAM arrays. A matrix-vector product runs without moving data to the CPU/GPU at all. Analog variants use the physics of resistive memory to compute dot products electrically.

Why it matters

AI inference is 60–80% data movement energy, not arithmetic. PIM attacks that majority cost. The tradeoff: less programming flexibility, lower precision, and harder to debug than a GPU — so papers spend significant effort on correctness guarantees and quantization strategies.

corpus → 27 ISCA 2025 papers focus on PIM/near-data processing. RRAM-based analog PIM appears repeatedly; hybrid digital-analog architectures dominate the advanced designs.
04 · MOVE LESS · T5 — sparsity 96 papers

Most of the weight matrix is zero — so skip it

A trained neural network's weight matrix is mostly near-zero values that contribute almost nothing to the output. If you identify them and skip the computation entirely, you get the same answer with a fraction of the work. The catch: zeros are scattered unpredictably, and skipping irregular patterns is hard to parallelize on a GPU.

sparsity: — computed: — skipped: —

Mechanism

During or after training, weights below a threshold are zeroed out. At inference, a sparse compute unit checks each weight before multiplying: if zero, skip and move on. Structured sparsity (pruning whole channels or blocks) maps better to hardware; unstructured sparsity is higher accuracy but irregular to execute.

Why it matters

At 90% sparsity you do 10× less arithmetic and move 10× less data — if the hardware can exploit it. Nvidia's Ampere A100 supports 2:4 structured sparsity natively (2 non-zeros per 4 weights) for exactly 2× speedup. Papers push to higher ratios with accuracy recovery techniques.

corpus → T5 spans ISCA, MICRO, HPCA. Structured sparsity (block, N:M) is now dominant over unstructured. Activation sparsity (sparse attention) is a rising 2025 theme.
05 · MOVE IT RELIABLY · T4 — interconnect 139 papers

Training across hundreds of chips means getting them all to agree — over a wire

During training, every GPU computes a gradient update on its own data slice. Before the next step, everyone needs the sum of all gradients — the "collective." A ring-allreduce does this by passing shards around a ring of GPUs, accumulating as they go. The bottleneck is the link between any two adjacent GPUs. Bandwidth there limits training throughput everywhere.

phase: — passes: — link bandwidth: the ceiling

Mechanism

Ring-allreduce in two phases: reduce-scatter (each GPU sends its shard clockwise, accumulates what arrives — after N-1 passes each GPU has one fully-summed shard) then all-gather (broadcast the fully-summed slices back around). Total data sent: 2×(N-1)/N × message size. For large N that approaches 2 messages regardless of cluster size.

Why it matters

Training a frontier model requires thousands of GPUs communicating constantly. If the interconnect can't keep up, GPUs idle waiting for gradient updates — the same compute-starvation problem from diagram 00, now between chips rather than between compute and memory. NVLink, InfiniBand, and custom topologies (Torus, Dragonfly) exist entirely to raise this ceiling.

corpus → T4 is the dominant theme at SC 2025 (74 papers). Novel topologies (Zettafly, MeshSlice 2D-tensor) and traffic-shaping (NetCrafter) are the main 2025 contributions.
06 · SHORTEN THE TRIP · T6 — compilers 140 papers

Four operators → one kernel: the intermediate tensors never leave the chip

When a compiler runs a neural network on a chip, it can execute each operator (Conv, ReLU, Norm, Add) as a separate kernel — each one writing its output to DRAM and the next reading it back. Or it can fuse them into a single kernel that keeps intermediate results in the chip's fast on-chip SRAM and only touches DRAM once. Same math. Radically less data movement.

unfused: — DRAM roundtrips fused: 1 roundtrip effective speedup: ~3–4×

Mechanism

The compiler's job is to find chains of operators where all intermediate tensors fit in SRAM simultaneously, then merge them into one GPU kernel. The merged kernel reads its input once from DRAM, streams through all operations in registers/SRAM, writes output once. DRAM roundtrips collapse from N to 1.

Why it matters

DRAM bandwidth is the bottleneck (diagram 00). Fusion directly reduces the number of times data crosses the DRAM ↔ compute bus — which is the expensive operation. Modern ML compilers (XLA, TVM, Triton, MLIR) spend most of their optimization budget here. A 3–10× speedup from fusion alone is common on transformer workloads.

corpus → T6 at ASPLOS, MLSys, DAC, CGO. Operator fusion + memory layout co-optimization is cited as the primary lever in 60%+ of T6 papers. MLIR-based passes are now the standard IR for this.
07 · The map

All nine themes, one constraint — each theme is an attack on a different part of the wall

The six mechanisms above are not independent ideas. They're all attacks on the same wall from different angles. Place them on the system and the pattern is clear: some reduce how much data you move (T2, T5); some shorten how far it travels (T3, T6); some manage the chip-to-chip channel (T4); some add correctness and trust guarantees around the whole thing (T7, T8); some redesign the compute end entirely (T1, T9).

The through-line: every advance in 2025 buys fewer bytes moved, or shorter distances traveled, or stronger guarantees on what arrives. Arithmetic got cheap a decade ago. The field now optimizes the wire, not the math.

Themes that reduce data

T2 quantization — smaller numbers, fewer bits per transfer.
T5 sparsity — zeros skipped, never fetched.
T1 attention — KV cache compressed, prefixed, paged, tiled.

Themes that shorten the trip

T3 memory wall — compute embedded in DRAM, data barely moves.
T6 compilers — intermediate tensors stay in SRAM via fusion.
T9 specialized — custom datapaths eliminate general-purpose overhead.

Themes that protect the channel

T4 interconnect — topology, routing, and bandwidth between chips.
T7 security — data in transit and at rest, adversarial and fault-driven.
T8 reliability — correctness under lower power margins and faults.

What's still open

LLM inference at scale has no clean solution yet — 31 ISCA papers alone grapple with this. The KV cache memory crisis is a thousand-paper problem with no decisive answer. The field is early in understanding how to make the wall shorter rather than running faster at it.
